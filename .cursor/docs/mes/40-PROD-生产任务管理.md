### 3.3. 生产任务管理模块 (PROD)

**核心功能:** 管理生产计划的接收、分解、排程和调度，确保生产活动有序、高效进行。

#### 3.3.1. 生产计划管理 (Production Planning Management)

* **功能描述:** 接收来自ERP的生产订单或手工创建内部生产计划，进行管理和跟踪。
* **实现逻辑:**
  * **订单接收:** 通过`4.1.1 ERP接口`，定时（如每小时）或由ERP触发，接收生产订单信息。关键字段：`ERP订单号`, `产品编码`, `需求数量` (吨或卷), `计划交期`, `客户信息` (可选), `特殊要求` (文本)。系统将接收到的订单转化为内部生产计划。
  * **手工创建:** 支持计划员在MES界面直接创建生产计划，录入类似信息。
  * **计划管理:** 提供界面展示生产计划列表（包含来源、状态、进度等）。支持对计划进行：
    * `拆分`: 将一个大计划拆分成多个小批次计划。
    * `合并`: 将多个小计划合并（如相同产品）。
    * `调整`: 修改计划数量、交期、优先级。
    * `状态更新`: 计划状态可包括：`已接收`, `已确认`, `部分下达`, `已下达`, `执行中`, `完成`, `取消`。
  * **初步评估:** (可选) 基于`产品编码`关联的`工艺模板`中的大致炉次时间 和 `退火炉`的`容量`，粗略估算所需炉次数和时间，与交期对比，给出预警。
* **操作流程:**
    1. 计划员查看从ERP同步或手工创建的计划列表。
    2. 对`已接收`状态的计划进行审核，可进行拆分/合并/调整操作。
    3. 确认无误后，将计划状态改为`已确认`或`已下达`，使其进入待分解或待排程状态。
    4. 系统根据后续任务执行情况，自动更新计划的进度和最终状态。
* **数据需求:** 生产计划表，记录上述字段及状态、创建/更新信息。
* **界面交互要点:** 计划列表信息全面，状态清晰。提供甘特图可视化展示计划时间安排（可选）。调整操作记录变更历史。
* **关键业务规则:** 从ERP接收的订单号应保持关联，便于后续数据反馈。计划调整需有权限控制和记录。

#### 3.3.2. 退火任务管理 (Annealing Task Management)

* **功能描述:** 将生产计划分解为具体的、可分配给退火炉执行的退火任务。
* **实现逻辑:**
  * **任务创建:**
    * **方式一 (基于计划分解):** 计划员选择一个`已确认`的生产计划，系统根据计划数量、产品对应的标准料框装载量、退火炉容量（约40T），自动建议需要分解成的`退火任务`数量和每个任务大致的物料量。计划员确认或调整。
    * **方式二 (手动创建):** 计划员直接创建退火任务，手动指定关联的`生产计划`（可选）、`产品编码`等。
  * **物料关联:** 任务创建后，需要关联具体的待执行物料。
    * 系统可根据任务指定的`产品编码`和`批次号`（若有），从库存中筛选出状态为`待退火`的料框/料垛列表，供计划员选择关联。
    * 关联时，系统需校验所选物料的总重量是否大致符合炉容（如 35-42T 范围），并提示。
  * **工艺分配:** 系统根据关联物料的`产品编码`，自动从`3.1.6`查找并加载“生效”状态的`标准退火工艺模板ID`，计划员可预览并确认。
  * **任务记录字段:** `任务ID` (唯一), `关联生产计划ID`, `计划执行炉号` (排程后指定), `待退火料框ID列表`, `待退火料垛ID列表`, `产品编码`, `预计总重量`, `关联工艺模板ID`, `计划装炉时间`, `计划出炉时间`, `实际装/出炉时间`, `任务优先级` (可继承计划), `任务状态`。
  * **任务状态机 (示例):** `草稿` → (保存) → `待排程` → (排程算法分配炉号和时间) → `已排程` → (关联物料到达备料区/炉口) → `待装炉` → (执行装炉操作) → `装炉中` → (装炉完成确认) → `待执行` → (PLC反馈退火开始) → `执行中` → (PLC反馈退火完成) → `待出炉` → (执行出炉操作完成) → `已完成`。 异常状态：`挂起`, `取消`, `异常终止`。
* **操作流程:**
    1. 计划员/调度员创建退火任务（通过计划分解或手动）。
    2. 选择并关联具体的待退火料框/料垛。
    3. 确认系统自动匹配的工艺模板。
    4. 保存任务，状态变为`待排程`。
    5. 后续状态由排程模块、执行模块自动更新或操作员确认驱动。
* **数据需求:** 退火任务表，任务-物料关联表。
* **界面交互要点:** 任务列表清晰展示关键信息和状态。创建/编辑界面提供物料选择助手。工艺模板预览方便。
* **关键业务规则:** 每个退火炉的一个完整炉次通常对应一个退火任务。关联的物料必须是`待退火`状态且满足任务要求。必须关联有效的工艺模板。

#### 3.3.3. 退火炉排程 (Annealing Furnace Scheduling)

* **功能描述:** 基于待执行的退火任务、设备资源状况和优化规则，制定详细的炉次排程计划。
* **实现逻辑:**
  * **输入数据获取:**
    * `待排程任务队列`: 获取所有状态为`待排程`的退火任务 (`3.3.2`)，包含其优先级、关联物料、工艺要求、期望完成时间（来自计划交期）。
    * `设备资源状态`: 实时获取所有退火炉的当前状态 (`空闲`, `运行中` - 含预计完成时间, `故障`, `维护计划`) (`3.4.5`)。
    * `物料准备状态`: 获取任务关联物料的当前位置和状态 (`3.2.1`, `3.2.3`)。
    * `配置规则`: 排程算法所需的约束和优化目标配置。
  * **约束条件检查:**
    * `炉子容量`: 任务总重量需在炉子容量范围内（如 35-42T）。
    * `炉子能力`: 任务所需工艺（如最高温度）不能超过炉子能力。
    * `工艺兼容性 (混炉规则)`: 根据配置规则判断哪些不同产品/牌号/工艺类型的任务可以合并到同一炉次执行（需明确具体规则）。
    * `物料可用性`: 排程的计划开始时间必须晚于关联物料预计可到达炉口/备料台的时间（需考虑物流时间）。
    * `设备维护`: 不能将任务排在设备计划维护时间段内。
  * **排程算法 (核心):**
    * 采用合适的调度算法（如基于规则的启发式算法、约束规划、或模拟退火等优化算法）。
    * **算法目标 (可配置优先级):**
            1. **满足交期:** 优先安排交期紧急或优先级高的任务。
            2. **提高炉子利用率:** 尽量减少炉子空闲时间，考虑连续排产。
            3. **提高装载率:** 在满足混炉规则前提下，尽量拼凑满炉任务。
            4. **（可选）降低能耗:** 尽量将工艺相似的任务连续排，减少大幅升降温。
  * **排程结果输出:**
    * 为每个`待排程`任务分配合适的`退火炉ID`和`计划装炉/出炉时间`。
    * 对于允许混炉的情况，将多个兼容的任务合并为一个炉次计划。
    * **可视化展示:** 提供甘特图，以时间轴和炉号为维度，清晰展示每个炉子分配的任务块（包含任务ID、产品、计划时间）。
  * **手动调整与冲突检测:** 允许调度员在甘特图上通过拖拽方式调整任务的分配（换炉、改时间）。系统需实时检查调整后的合法性（是否违反约束），并高亮显示冲突或潜在延期。
* **操作流程:**
    1. 调度员进入排程界面，查看待排程任务列表和设备实时状态甘特图。
    2. 配置排程参数（如时间范围、优化目标侧重）。
    3. 运行自动排程算法。
    4. 系统生成排程计划并展示在甘特图上。
    5. 调度员评审排程结果，进行必要的手动调整。
    6. 确认并“发布”排程计划。发布的计划将驱动后续的物流和执行。
* **数据需求:** 退火任务数据、设备实时状态、维护计划、物料位置/状态、排程规则配置、排程结果数据。
* **界面交互要点:** 交互式甘特图是核心，支持缩放、平移、拖拽、显示详情、冲突预警。提供不同排程方案模拟对比功能（可选）。
* **关键业务规则:** 排程必须严格遵守所有硬性约束（容量、能力、兼容性、物料、维护）。发布的排程是后续作业的依据。

#### 3.3.4. 物流任务生成 (Logistics Task Generation)

* **功能描述:** 根据确定的生产排程计划和库存变动需求，自动生成物料搬运任务，分配给行车或自动料车。
* **实现逻辑:**
  * **触发条件:**
    * `退火炉排程计划`发布或更新时，自动为其涉及的装炉、出炉生成配套的物流任务。
    * `库位分配`完成后，自动生成入库物流任务。
    * 其他需要物料移动的指令，如从`已退火区`移动到`质检区`等。
  * **任务生成规则:**
    * **装炉相关:**
      * `待退火区库位 -> 备料台` (若使用备料台)
      * `待退火区库位 -> 自动料车` (若直接由料车取料)
      * `备料台 -> 自动料车`
      * `自动料车 -> 退火炉炉膛`
    * **出炉相关:**
      * `退火炉炉膛 -> 自动料车`
      * `自动料车 -> 已退火区库位`
    * **其他转运:**
      * `已退火区库位 -> 质检区`
      * `质检区 -> 合格/不合格品区`
* **操作流程:**
    1. 系统根据触发条件自动生成物流任务。
    2. 调度员可在“物流任务管理”界面查看任务列表。
    3. （可选）调度员可手动创建或调整物流任务优先级。
* **数据需求:** 物流任务表。需关联生产排程、物料位置、库位/设备定义。
* **界面交互要点:** 物流任务列表清晰展示任务详情、状态、优先级、分配设备。
* **关键业务规则:** 物流任务的生成逻辑必须与车间实际作业流程和设备能力匹配。任务优先级需合理设定以保障生产顺畅。
