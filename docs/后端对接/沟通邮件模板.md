### 主题：关于Token过期机制的前后端对接确认

Hi [后端负责人姓名]，

我这边对前端的会话管理进行了优化，**禁用了前端的会话超时管理，改为完全依赖后端的Token过期机制**。

### 🎯 修改原因
1. 避免前后端超时时间不同步
2. 简化前端逻辑，提升用户体验
3. 充分利用后端已有的Token刷新机制

### ✅ 前端已完成
- 移除了前端30分钟自动退出逻辑
- 保留了Token自动刷新机制（当后端返回401+TOKEN_EXPIRED时自动刷新）
- 完整的错误处理和用户提示

### ❓ 需要你们确认的事项

为了确保系统正常运行，麻烦确认一下：

**1. Token配置（重要）**
- accessToken有效期是多少？（建议30分钟）
- refreshToken有效期是多少？（建议7天）

**2. 接口实现**
- ✅ `/auth/refresh-tokens` 接口是否已实现？
- ✅ Token过期时返回的错误码是什么？（前端期望：`AUTH_002` 或 `TOKEN_EXPIRED`）

**3. 响应格式**
Token刷新接口的响应格式是否如下：
```json
{
  "success": true,
  "data": {
    "access": {
      "token": "新Token",
      "expires": "2025-01-10T12:00:00Z"
    },
    "refresh": {
      "token": "新refreshToken",
      "expires": "2025-01-17T12:00:00Z"
    }
  }
}
```
