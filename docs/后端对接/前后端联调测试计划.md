## 🧪 测试场景详细说明

### 测试场景1：正常Token刷新 ✅

**目的**：验证accessToken过期后能否自动刷新

#### 测试步骤

1. **登录系统**
   ```bash
   前端操作：访问 http://localhost:9529/login
   输入用户名密码登录
   ```
   
   **检查点**：
   - [ ] 登录成功，跳转到首页
   - [ ] 打开浏览器开发者工具 → Application → LocalStorage
   - [ ] 确认存在 `moses_auth_data`，包含 `token` 和 `refreshToken`

2. **等待Token过期**（两种方式）

   **方式A：修改后端配置（推荐）**
   ```env
   # 后端 .env.development
   JWT_ACCESS_EXPIRATION_MINUTES=1  # 改为1分钟
   ```
   然后重启后端服务，等待1分钟
   
   **方式B：手动修改Token过期时间**
   ```javascript
   // 在浏览器Console中执行
   const authData = JSON.parse(localStorage.getItem('moses_auth_data'));
   authData.token.expiresAt = Date.now() - 1000; // 设置为已过期
   localStorage.setItem('moses_auth_data', JSON.stringify(authData));
   ```

3. **触发API请求**
   ```bash
   前端操作：点击任意菜单，触发API请求
   例如：访问"主数据管理" → "铝箔产品管理"
   ```

4. **观察自动刷新过程**
   
   **打开浏览器Network面板**，观察请求顺序：
   
   ```
   ① 原始请求失败
      Request: GET /v1/...
      Response: 401 + AUTH_004 (Token过期)
      
   ② 自动刷新Token
      Request: POST /v1/auth/refresh-tokens
      Request Body: { refreshToken: "xxx..." }
      Response: 200 + 新Token
      
   ③ 重试原始请求
      Request: GET /v1/...
      Headers: Authorization: Bearer [新Token]
      Response: 200 + 正常数据
   ```

5. **检查控制台日志**
   ```
   期望看到：
   🚀 API Request: ...
   🔄 Token过期，尝试自动刷新...
   ✅ Token刷新成功
   🚀 API Request: ... (重试)
   ```

6. **验证Token已更新**
   ```javascript
   // 浏览器Console检查
   const authData = JSON.parse(localStorage.getItem('moses_auth_data'));
   console.log('新accessToken:', authData.token.accessToken);
   console.log('新refreshToken:', authData.token.refreshToken);
   console.log('过期时间:', new Date(authData.token.expiresAt));
   ```

#### 预期结果

- ✅ 用户无感知，页面正常加载
- ✅ Network面板显示自动刷新流程
- ✅ Console显示 "Token刷新成功"
- ✅ localStorage中Token已更新
- ✅ 原始请求成功返回数据

#### 常见问题处理

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 刷新失败，跳转登录页 | refreshToken也过期了 | 重新登录，使用新Token测试 |
| 没有触发刷新 | Token未真正过期 | 检查过期时间设置 |
| 刷新后原始请求仍失败 | 新Token未正确使用 | 检查请求头更新逻辑 |

### 测试场景2：refreshToken过期 ✅

**目的**：验证refreshToken过期后能否正确提示并跳转登录

#### 测试步骤

1. **登录系统**
   - 同场景1步骤1

2. **模拟refreshToken过期**

   **方式A：修改数据库（后端协助）**
   ```sql
   -- 在后端数据库中执行
   UPDATE tokens 
   SET expires = NOW() - INTERVAL '1 day'
   WHERE user_id = '当前用户ID';
   ```
   
   **方式B：修改LocalStorage**
   ```javascript
   // 浏览器Console执行
   const authData = JSON.parse(localStorage.getItem('moses_auth_data'));
   // 同时让两个Token都过期
   authData.token.accessToken = 'expired_token';
   authData.token.refreshToken = 'expired_refresh_token';
   authData.token.expiresAt = Date.now() - 1000;
   localStorage.setItem('moses_auth_data', JSON.stringify(authData));
   ```

3. **触发刷新Token**
   ```bash
   前端操作：刷新页面或点击任意菜单
   ```

4. **观察错误处理**
   
   **Network面板**：
   ```
   Request: POST /v1/auth/refresh-tokens
   Response: 401 + AUTH_032 (REFRESH_TOKEN_EXPIRED)
   ```
   
   **Console面板**：
   ```
   ❌ Token刷新失败: [Error]
   ⚠️ 登录已过期，请重新登录
   ```

5. **检查页面行为**
   - [ ] 显示提示消息："刷新令牌已过期，请重新登录"
   - [ ] 自动跳转到登录页
   - [ ] localStorage中Token已清除

#### 预期结果

- ✅ 显示友好的错误提示
- ✅ 自动跳转到 `/login` 页面
- ✅ localStorage被清空
- ✅ 后续需要重新登录

### 测试场景3：并发请求Token刷新 ✅

**目的**：验证多个并发请求时只刷新一次Token

#### 测试步骤

1. **准备测试环境**
   ```env
   # 后端配置Token快速过期
   JWT_ACCESS_EXPIRATION_MINUTES=1
   ```

2. **登录并等待Token过期**
   - 登录系统
   - 等待1分钟让Token过期

3. **触发多个并发请求**
   
   **方式A：快速点击多个菜单**
   ```
   操作：在1秒内快速点击多个不同的菜单项
   例如：铝箔产品管理 → 设备管理 → 料框规格管理
   ```
   
   **方式B：在Console手动触发**
   ```javascript
   // 浏览器Console执行
   Promise.all([
     fetch('/v1/users', { 
       headers: { 'Authorization': `Bearer ${expiredToken}` }
     }),
     fetch('/v1/products', { 
       headers: { 'Authorization': `Bearer ${expiredToken}` }
     }),
     fetch('/v1/equipment', { 
       headers: { 'Authorization': `Bearer ${expiredToken}` }
     })
   ]);
   ```

4. **检查Network面板**
   
   **关键观察点**：
   ```
   ✅ 只有一个 POST /v1/auth/refresh-tokens 请求
   ✅ 三个原始请求都在等待
   ✅ Token刷新成功后，三个请求使用新Token重试
   ✅ 三个请求最终都成功返回数据
   ```

5. **检查Console日志**
   ```
   期望看到：
   🔄 Token过期，尝试自动刷新...
   ⏳ 其他请求加入刷新队列...
   ✅ Token刷新成功
   🔄 处理刷新队列中的3个请求...
   ✅ 所有请求重试成功
   ```

#### 预期结果

- ✅ 只发起一次 `/auth/refresh-tokens` 请求
- ✅ 所有并发请求都等待刷新完成
- ✅ 刷新成功后，所有请求使用新Token重试
- ✅ 所有请求最终都成功

#### 技术说明

前端使用 **请求队列机制** 实现：

```javascript
// src/utils/request.js (第28-62行)
let isRefreshingToken = false;
const refreshTokenQueue = [];

// 刷新中时，其他请求加入队列
if (isRefreshingToken) {
  return new Promise((resolve, reject) => {
    addToRefreshQueue(resolve, reject, response.config);
  });
}

// 刷新成功后，处理队列中的所有请求
processRefreshQueue(true, newToken);
```
