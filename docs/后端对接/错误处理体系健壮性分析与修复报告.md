## 🔍 架构分析

### 整体架构

```
请求发起 → 请求拦截器 → 后端API → 响应拦截器 → 业务层catch块
                                         ↓
                                 错误分类处理：
                                 1. 网络错误 → 显示通用提示
                                 2. 认证错误 → Token刷新或跳转登录
                                 3. 系统错误 → 显示通用提示
                                 4. 业务错误 → 传递给业务层
```

### 核心设计原则

1. **职责清晰**：拦截器只处理通用错误（网络、认证、系统），业务错误交给业务层
2. **避免重复**：通过`handledByInterceptor`标志防止重复显示错误消息
3. **错误对象统一**：所有错误都转换为`ApiError`对象，保证属性一致性

## 🐛 发现的Bug及修复方案

### Bug 1：Token刷新失败的重复消息提示

**位置**：`src/utils/api/interceptors/auth.js` 第151行和第179行

**问题描述**：
```javascript
// 拦截器显示消息
showMessage(error.message || '登录已过期，请重新登录', 'warning', 3000)

// 创建错误对象但未标记
const refreshError = new ApiError(...)
// ❌ 缺少：refreshError.handledByInterceptor = true

return Promise.reject(refreshError)
// → 业务层的errorMixin会再次显示消息
```

**影响**：用户看到**两次**"登录已过期，请重新登录"

**修复方案**：
```javascript
// 创建错误对象并标记已处理
const refreshError = new ApiError(...)
refreshError.handledByInterceptor = true // ✅ 添加标记

return Promise.reject(refreshError)
// → 业务层检测到标记，不再显示
```

---

### Bug 2：RefreshToken失效的三重消息提示

**位置**：`src/utils/api/interceptors/auth.js` 第229行、第232行（→第265行）和业务层

**问题描述**：
```javascript
// 第1次显示
showMessage(errorData?.message || '登录已过期，请重新登录', 'warning', 3000)

// 调用handleAuthFailure
await handleAuthFailure(errorData?.message)
  // 第2次显示（handleAuthFailure内部）
  showMessage(message || '认证失败，请重新登录', 'warning', 3000)

// reject错误对象（未标记）
return Promise.reject(new ApiError(...))
// → 第3次显示（业务层）
```

**影响**：用户看到**三次**错误提示

**修复方案**：
```javascript
// 移除第一次showMessage，只保留handleAuthFailure内的提示
await handleAuthFailure(errorData?.message || '登录已过期，请重新登录')

// 创建错误对象并标记已处理
const authError = new ApiError(...)
authError.handledByInterceptor = true // ✅ 添加标记

return Promise.reject(authError)
```

---

### Bug 3：AUTH_001无RefreshToken的重复消息

**位置**：`src/utils/api/interceptors/auth.js` 第91行和第92行

**问题描述**：
```javascript
// 调用handleAuthFailure（显示消息）
handleAuthFailure('登录已过期，请重新登录')

// reject错误对象（未标记）
return Promise.reject(new ApiError('AUTH_001', '未授权访问，请重新登录', 401))
// → 业务层再次显示
```

**影响**：用户看到**两次**错误提示

**修复方案**：
```javascript
handleAuthFailure('登录已过期，请重新登录')

// 创建错误对象并标记已处理
const authError = new ApiError('AUTH_001', '未授权访问，请重新登录', 401)
authError.handledByInterceptor = true // ✅ 添加标记
return Promise.reject(authError)
```

### Bug 4：Token刷新队列fallback使用普通Error

**位置**：`src/utils/api/interceptors/auth.js` 第65行

**问题描述**：
```javascript
// Token刷新队列处理
queue.forEach(({ resolve, reject, config }) => {
  if (isSuccess && newToken) {
    resolve(retryRequest(config))
  } else {
    reject(error || new Error('Token refresh failed'))  // ❌ 普通Error
  }
})
```

**影响**：极端情况下，队列中的请求收到普通`Error`对象，业务层无法访问`error.code`、`error.details`等属性

**修复方案**：
```javascript
// 确保传递ApiError对象，保持错误对象一致性
const apiError = error instanceof ApiError
  ? error
  : new ApiError('REFRESH_QUEUE_FAILED', error?.message || 'Token刷新失败', 401)
apiError.handledByInterceptor = true
reject(apiError)
```

## ✅ 修复验证

### 修复后的错误流程

#### 场景1：网络错误
```
网络故障 → handleNetworkError
         → 创建ApiError + handledByInterceptor = true
         → showMessage("网络连接失败")
         → reject错误对象
         → 业务层检测到标记 → 不再显示
```
**结果**：✅ 用户只看到1次提示

#### 场景2：Token过期（刷新成功）
```
Token过期 → handleAuthError → handleTokenExpired
          → 后台刷新Token（用户无感知）
          → 重试原始请求
          → 业务层正常获取数据
```
**结果**：✅ 用户无感知，体验流畅

#### 场景3：Token过期（刷新失败）
```
Token过期 → handleAuthError → handleTokenExpired
          → 刷新失败 → showMessage("登录已过期")
          → 创建ApiError + handledByInterceptor = true
          → reject错误对象
          → 业务层检测到标记 → 不再显示
          → 跳转到登录页
```
**结果**：✅ 用户只看到1次提示

#### 场景4：RefreshToken失效
```
RefreshToken失效 → handleAuthError
                 → handleAuthFailure（显示消息）
                 → 创建ApiError + handledByInterceptor = true
                 → reject错误对象
                 → 业务层检测到标记 → 不再显示
                 → 跳转到登录页
```
**结果**：✅ 用户只看到1次提示

#### 场景5：业务错误（VAL_*、BIZ_*）
```
业务错误 → createApiError（handledByInterceptor = false）
        → reject错误对象
        → 业务层 → errorMixin显示后端返回的错误消息
```
**结果**：✅ 用户只看到1次具体的业务错误提示
