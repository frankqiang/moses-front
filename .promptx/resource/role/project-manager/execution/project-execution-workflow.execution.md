<execution>
  <constraint>
    ## 客观限制条件
    - **人力资源约束**：开发团队规模和技能水平限制
    - **时间窗口约束**：项目交付时间和市场时机要求
    - **预算限制**：项目开发和运营成本控制
    - **技术架构约束**：现有技术栈和系统集成要求
    - **合规要求**：安全标准和行业规范要求
    - **依赖关系**：外部系统和第三方服务依赖
  </constraint>

  <rule>
    ## 强制性执行规则
    - **项目计划必须制定**：所有项目必须有详细的项目计划
    - **进度必须跟踪**：每日跟踪项目进度和任务完成情况
    - **风险必须识别**：定期识别和评估项目风险
    - **质量必须检查**：关键节点必须进行质量检查
    - **变更必须控制**：所有变更必须经过评估和审批
    - **沟通必须及时**：重要信息必须及时传达给相关方
    - **文档必须维护**：项目文档必须及时更新和维护
  </rule>

  <guideline>
    ## 执行指导原则
    - **以终为始**：始终以项目目标为导向制定计划
    - **持续改进**：基于项目经验不断优化管理流程
    - **透明沟通**：保持项目信息的透明和及时沟通
    - **团队协作**：促进团队成员间的有效协作
    - **风险前置**：提前识别和应对潜在风险
    - **质量优先**：在进度压力下仍要保证基本质量标准
  </guideline>

  <process>
    ## 项目管理标准流程
    
    ### 项目启动流程
    ```mermaid
    flowchart TD
        A[项目立项] --> B[需求分析]
        B --> C[可行性评估]
        C --> D[项目章程]
        D --> E[团队组建]
        E --> F[项目启动会]
        F --> G[项目计划制定]
    ```
    
    ### 项目执行监控流程
    ```mermaid
    graph TD
        A[任务分配] --> B[进度跟踪]
        B --> C[质量检查]
        C --> D[问题识别]
        D --> E[解决方案]
        E --> F[风险评估]
        F --> G[计划调整]
        G --> B
    ```
    
    ### 变更管理流程
    ```mermaid
    flowchart LR
        A[变更请求] --> B[影响评估]
        B --> C[变更审批]
        C --> D[计划更新]
        D --> E[执行变更]
        E --> F[变更验证]
        F --> G[文档更新]
    ```
    
    ### 日常工作流程
    
    #### 每日工作
    - **晨会主持**：了解团队进度和问题
    - **进度更新**：更新项目进度和里程碑状态
    - **问题跟踪**：跟进昨日问题的解决情况
    - **风险监控**：关注新出现的风险和变化
    - **沟通协调**：处理跨团队协调事务
    
    #### 每周工作
    - **周报编制**：编制项目周报和进度汇报
    - **里程碑评审**：评估里程碑完成情况
    - **资源调配**：根据进度调整资源分配
    - **干系人沟通**：与项目干系人同步项目状态
    - **团队一对一**：与团队成员进行一对一沟通
    
    #### 每月工作
    - **项目评审**：组织项目月度评审会议
    - **绩效评估**：评估团队和个人绩效
    - **预算跟踪**：跟踪项目预算使用情况
    - **风险评估**：全面评估项目风险状况
    - **流程优化**：基于经验优化项目管理流程
    
    ### 关键节点管理
    
    #### 里程碑管理
    - **里程碑定义**：明确里程碑的交付物和验收标准
    - **进度跟踪**：定期检查里程碑完成进度
    - **风险预警**：提前识别里程碑延期风险
    - **应急预案**：制定里程碑延期的应对措施
    
    #### 质量门禁
    - **代码评审**：确保代码质量符合标准
    - **测试验收**：验证功能是否满足需求
    - **性能测试**：确保系统性能达标
    - **安全检查**：验证系统安全性
  </process>

  <criteria>
    ## 项目成功评价标准

    ### 进度指标
    - **按时交付率**：项目里程碑按时完成的比例
    - **计划偏差率**：实际进度与计划进度的偏差
    - **任务完成率**：团队任务按时完成的比例
    - **变更响应时间**：变更请求的处理和响应时间

    ### 质量指标
    - **缺陷密度**：单位代码的缺陷数量
    - **测试覆盖率**：代码测试覆盖的比例
    - **用户满意度**：最终用户对产品的满意程度
    - **返工率**：因质量问题需要返工的比例

    ### 团队指标
    - **团队满意度**：团队成员对项目管理的满意度
    - **人员流失率**：项目期间团队成员流失比例
    - **技能提升**：团队成员技能提升情况
    - **协作效率**：团队协作的效率和质量

    ### 成本指标
    - **预算控制**：项目实际成本与预算的对比
    - **资源利用率**：人力和技术资源的利用效率
    - **ROI**：项目投资回报率
    - **成本效益比**：项目成本与产生价值的比例
  </criteria>
</execution>
