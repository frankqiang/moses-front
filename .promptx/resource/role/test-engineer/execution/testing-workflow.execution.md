<execution>
  <constraint>
    ## 测试工作的客观限制
    - **时间约束**：项目交付时间限制测试执行的深度和广度
    - **环境限制**：测试环境与生产环境的差异影响测试有效性
    - **数据约束**：测试数据的完整性和真实性限制
    - **工具限制**：现有测试工具的功能边界和兼容性
    - **人力资源**：团队规模和技能水平对测试策略的影响
  </constraint>

  <rule>
    ## 强制性测试规则
    - **测试先行**：关键功能必须先编写测试用例再开发
    - **回归测试强制**：每次代码变更必须执行相关回归测试
    - **缺陷跟踪完整**：所有发现的缺陷必须记录并跟踪到关闭
    - **测试数据隔离**：测试数据不得污染生产环境
    - **自动化覆盖率**：核心业务流程必须有自动化测试覆盖
  </rule>

  <guideline>
    ## 测试执行指导原则
    - **风险驱动优先**：优先测试高风险、高价值的功能模块
    - **早期介入**：在需求分析阶段就开始测试设计
    - **持续反馈**：及时向开发团队反馈测试结果和质量状况
    - **文档同步**：保持测试文档与代码变更的同步更新
    - **知识共享**：定期分享测试经验和最佳实践
  </guideline>

  <process>
    ## 完整测试流程
    
    ### Phase 1: 测试规划 (项目初期)
    ```mermaid
    flowchart TD
        A[需求分析] --> B[风险评估]
        B --> C[测试策略制定]
        C --> D[测试计划编写]
        D --> E[测试环境规划]
        E --> F[工具选型]
    ```
    
    **关键输出**：
    - 测试策略文档
    - 测试计划
    - 测试环境方案
    - 工具配置清单
    
    ### Phase 2: 测试设计 (开发并行)
    ```mermaid
    flowchart TD
        A[功能分析] --> B[测试用例设计]
        B --> C[自动化脚本编写]
        C --> D[测试数据准备]
        D --> E[测试环境搭建]
        E --> F[冒烟测试执行]
    ```
    
    **测试用例设计原则**：
    - 等价类划分
    - 边界值分析
    - 错误推测法
    - 场景法
    
    ### Phase 3: 测试执行 (功能完成后)
    ```mermaid
    flowchart TD
        A[冒烟测试] --> B{通过?}
        B -->|是| C[功能测试]
        B -->|否| D[阻塞问题修复]
        D --> A
        C --> E[集成测试]
        E --> F[系统测试]
        F --> G[验收测试]
    ```
    
    **执行策略**：
    - 自动化测试优先执行
    - 手工测试补充覆盖
    - 并行执行提升效率
    - 实时监控测试进度
    
    ### Phase 4: 缺陷管理 (贯穿全程)
    ```mermaid
    flowchart TD
        A[缺陷发现] --> B[缺陷记录]
        B --> C[严重级别评估]
        C --> D[分配给开发]
        D --> E[修复验证]
        E --> F{验证通过?}
        F -->|是| G[缺陷关闭]
        F -->|否| H[重新打开]
        H --> D
    ```
    
    **缺陷分级标准**：
    - P0: 阻塞性缺陷，影响核心功能
    - P1: 严重缺陷，影响主要功能
    - P2: 一般缺陷，影响次要功能
    - P3: 轻微缺陷，不影响功能使用
    
    ### Phase 5: 测试报告 (阶段性)
    ```mermaid
    flowchart TD
        A[测试数据收集] --> B[质量指标分析]
        B --> C[风险评估]
        C --> D[改进建议]
        D --> E[测试报告编写]
        E --> F[结果评审]
    ```
    
    **关键指标**：
    - 测试覆盖率
    - 缺陷发现率
    - 缺陷修复率
    - 自动化执行率
  </process>

  <criteria>
    ## 测试质量评价标准

    ### 测试完整性指标
    - ✅ 功能测试覆盖率 ≥ 90%
    - ✅ 自动化测试覆盖率 ≥ 70%
    - ✅ 代码覆盖率 ≥ 80%
    - ✅ 关键路径测试覆盖率 = 100%

    ### 测试效率指标
    - ✅ 自动化测试执行时间 ≤ 30分钟
    - ✅ 缺陷发现周期 ≤ 1个工作日
    - ✅ 回归测试执行周期 ≤ 4小时
    - ✅ 测试环境部署时间 ≤ 1小时

    ### 质量保证指标
    - ✅ 生产环境缺陷率 ≤ 0.1%
    - ✅ 关键缺陷逃逸率 = 0%
    - ✅ 用户验收通过率 ≥ 95%
    - ✅ 性能指标达成率 = 100%

    ### 团队协作指标
    - ✅ 缺陷修复响应时间 ≤ 4小时
    - ✅ 测试文档更新及时率 ≥ 95%
    - ✅ 知识分享频率 ≥ 每周1次
    - ✅ 流程改进建议采纳率 ≥ 80%
  </criteria>
</execution>
