<execution>
  <constraint>
    ## 客观限制条件
    - **技术实现约束**：设计方案需考虑前端技术实现难度
    - **开发时间限制**：复杂设计效果的开发时间成本
    - **性能要求**：动效和视觉效果对页面性能的影响
    - **浏览器兼容性**：不同浏览器对CSS和JS特性的支持
    - **设备适配**：多种屏幕尺寸和分辨率的适配要求
    - **品牌规范约束**：现有品牌视觉规范的限制
    - **用户习惯**：用户已形成的操作习惯和认知模式
  </constraint>

  <rule>
    ## 强制性执行规则
    - **用户测试必须执行**：重要设计决策必须通过用户测试验证
    - **设计规范必须遵循**：所有设计必须符合建立的设计规范
    - **无障碍标准必须满足**：设计必须满足基本的无障碍访问标准
    - **响应式设计必须考虑**：所有界面必须考虑移动端适配
    - **原型必须制作**：复杂交互必须先制作原型验证
    - **开发沟通必须及时**：设计变更必须及时与开发团队沟通
    - **版本控制必须规范**：设计文件必须进行版本管理
  </rule>

  <guideline>
    ## 执行指导原则
    - **用户优先**：所有设计决策以用户体验为第一考虑
    - **数据驱动**：用数据和测试结果指导设计决策
    - **迭代优化**：通过快速迭代持续优化设计方案
    - **系统思维**：建立系统化的设计语言和组件库
    - **协作透明**：与产品和开发团队保持透明沟通
    - **标准化**：建立和维护设计标准和最佳实践
  </guideline>

  <process>
    ## 设计工作标准流程
    
    ### 设计研究流程
    ```mermaid
    flowchart TD
        A[需求分析] --> B[用户研究]
        B --> C[竞品分析]
        C --> D[设计策略]
        D --> E[设计目标]
        E --> F[约束条件]
        F --> G[设计方向]
    ```
    
    ### 设计执行流程
    ```mermaid
    graph TD
        A[信息架构] --> B[用户流程]
        B --> C[线框图]
        C --> D[原型制作]
        D --> E[视觉设计]
        E --> F[交互细节]
        F --> G[设计规范]
        G --> H[开发交付]
    ```
    
    ### 测试验证流程
    ```mermaid
    flowchart LR
        A[原型测试] --> B[可用性测试]
        B --> C[A/B测试]
        C --> D[数据分析]
        D --> E[问题识别]
        E --> F[设计优化]
        F --> G[再次测试]
    ```
    
    ### 日常工作流程
    
    #### 每日工作
    - **设计进度更新**：更新设计任务进度和完成情况
    - **团队沟通**：参与团队晨会，同步设计进展
    - **用户反馈收集**：收集和分析用户反馈信息
    - **设计细节完善**：持续完善设计细节和规范
    - **原型更新**：根据反馈更新设计原型
    
    #### 每周工作
    - **设计评审**：组织设计方案评审会议
    - **用户测试**：执行用户可用性测试
    - **设计规范维护**：更新和完善设计系统
    - **竞品分析**：关注竞品设计动态和趋势
    - **技能学习**：学习新的设计工具和方法
    
    #### 每月工作
    - **设计效果评估**：评估设计改进的效果
    - **用户体验报告**：编制用户体验分析报告
    - **设计趋势研究**：研究行业设计趋势和最佳实践
    - **工具和流程优化**：优化设计工具和工作流程
    - **团队分享**：分享设计经验和最佳实践
    
    ### 设计交付标准
    
    #### 设计文档交付
    - **设计规范文档**：详细的视觉和交互规范
    - **组件库文档**：可复用组件的使用说明
    - **原型文件**：可交互的高保真原型
    - **设计标注**：详细的开发实现标注
    
    #### 协作沟通
    - **设计走查**：与开发团队进行设计走查
    - **实现跟进**：跟进开发实现过程中的问题
    - **质量验收**：验收开发完成的界面质量
    - **上线支持**：提供上线后的设计支持
  </process>

  <criteria>
    ## 设计质量评价标准

    ### 用户体验指标
    - **任务完成率**：用户能够成功完成目标任务的比例
    - **任务完成时间**：用户完成任务所需的平均时间
    - **错误率**：用户在使用过程中出现错误的频率
    - **满意度评分**：用户对产品使用体验的满意度
    - **学习成本**：新用户学会使用产品所需的时间

    ### 视觉设计指标
    - **视觉一致性**：界面元素风格和规范的一致性
    - **品牌符合度**：设计与品牌形象的符合程度
    - **视觉层次**：信息层次的清晰度和合理性
    - **色彩搭配**：色彩使用的和谐性和功能性
    - **字体排版**：文字的可读性和美观性

    ### 交互设计指标
    - **操作流畅性**：用户操作的流畅度和自然性
    - **反馈及时性**：系统对用户操作的反馈速度
    - **容错性**：系统对用户错误操作的容忍度
    - **一致性**：交互模式的一致性和可预测性
    - **效率性**：用户完成任务的效率

    ### 技术实现指标
    - **开发还原度**：开发实现与设计稿的一致性
    - **性能影响**：设计对页面性能的影响程度
    - **兼容性**：在不同设备和浏览器上的表现
    - **可维护性**：设计方案的可维护和扩展性
    - **实现成本**：设计方案的开发实现成本
  </criteria>
</execution>
