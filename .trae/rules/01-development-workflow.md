# 开发流程与规范

## 规则说明与适用范围
本规则定义了前端开发的标准流程、快速开发指南和常见问题解决方案。所有开发人员都需遵循此流程规范。

## 标准开发流程

### 开发前准备
1. **需求分析**
   - 仔细阅读需求文档
   - 与产品经理确认功能细节
   - 设计技术实现方案

2. **开发准备**
   - 创建功能分支
   - 在`docs`目录下创建模块说明文档
   - 设计API接口和数据结构

### 功能开发
3. **功能开发**
   - 按照组件架构规范开发
   - 实现API接口和状态管理
   - 编写单元测试

4. **代码审查**
   - 进行代码自查
   - 提交Pull Request
   - 等待代码审查并修改

5. **测试和部署**
   - 完成功能测试
   - 修复发现的问题
   - 合并到开发分支

## 构建命令

```bash
# 安装依赖
npm install

# 启动开发服务器
npm run dev

# 构建测试环境
npm run build:stage

# 构建生产环境
npm run build:prod

# 运行单元测试
npm run test:unit
```
## 快速开发指南

### 开发前必读检查清单
开始开发前，请确认：
- [ ] 已理解需求文档和技术方案
- [ ] 已创建功能分支
- [ ] 已设计API接口规范
- [ ] 已准备Mock数据方案
- [ ] 已了解相关的业务规则

### 常见问题快速解决

#### Mock接口不生效
1. 确认Mock文件已在 `mock/index.js` 中引入
2. 检查API路径格式是否正确（需要/mes前缀）
3. 验证Mock文件导出格式是否符合要求

#### API请求失败
1. 检查网络请求在开发者工具中的状态
2. 确认API路径拼写是否正确
3. 验证请求参数格式是否符合要求

#### 组件渲染异常
1. 检查控制台是否有错误信息
2. 验证数据结构是否与期望一致
3. 确认组件props类型和默认值设置

## 模块文档规范

为确保系统功能的可维护性和知识传承，每个功能模块开发完成后必须创建标准格式的需求文档。

### 文档位置和命名
- 每个模块必须在其目录下创建`docs`子目录
- 在`docs`目录中创建以"模块名称需求文档.md"命名的文件
- 例如：`src/views/master-data/warehouse/docs/仓库管理需求文档.md`

### 文档内容规范
需求文档必须包含以下章节：
1. **模块概述**：简要描述模块的功能和用途
2. **功能需求**：详细列出模块的所有功能点
3. **数据结构**：描述模块涉及的数据表和字段
4. **接口设计**：列出模块使用的所有API接口，包括请求和响应格式
5. **页面设计**：描述模块的UI页面和交互设计
6. **业务规则**：说明模块的业务逻辑和规则
7. **与其他模块的关联**：描述与其他模块的依赖和交互
8. **权限控制**：列出模块相关的权限设置
9. **非功能需求**：描述性能、安全、可用性等非功能需求
10. **测试要点**：列出模块测试的关键点

### 文档创建流程
1. 模块开发完成后，创建docs目录：`mkdir -p src/views/module-path/docs`
2. 复制参考模板并根据实际功能进行修改
3. 确保文档内容完整、准确，并与实际实现一致
4. 在README.md中更新模块的使用说明
