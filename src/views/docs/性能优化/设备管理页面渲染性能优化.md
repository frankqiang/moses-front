### 设备管理页面渲染性能优化

#### 背景
设备管理模块在打开表单抽屉、展开重型分组以及在键值对编辑器内输入时出现明显卡顿；同类症状在其他模块也可复现（如抽屉型表单、重型折叠面板、输入即搜的搜索表单）。

#### 主要表现
- 打开/关闭抽屉时 CPU 占用瞬时升高，首次渲染较慢。
- 展开“通讯参数”“设备详情”分组时掉帧明显。
- 在键值对编辑器内连续输入时，输入延迟、光标卡顿。
- 搜索表单每次字段改动都会触发搜索，页面频繁重渲染。

#### 根因分析（共性）
1) 重型输入组件采用深度监听 + 即时回写，形成“输入 → 父数据更新 → 子重建 → 再回写”的循环级联更新。
2) 抽屉关闭后表单仍常驻（未卸载），watcher 与校验逻辑持续占用资源；折叠面板用 v-show 仅隐藏未卸载，重型内容仍在内存与依赖追踪中。
3) 搜索表单过多字段启用“改动即搜”，触发频率过高，造成请求与渲染压力。

#### 本次优化方案与实现

一、键值对编辑器 KeyValueEditor（输入期优化）
- 将 `value` 的监听由深度监听改为浅监听，避免每次击键引发全量重建。
- 增加自触发保护 `_isEmitting`，阻断由本组件回写引起的循环触发。
- 使用 150ms 防抖聚合变更（`debounce` 自 `@/utils`），输入过程中合并回写，降低级联渲染频率。
- 行级轻量校验，整体验证在 emit/提交时进行，减少输入期的全量校验成本。

二、表单抽屉 EquipmentFormDrawer（渲染时机优化）
- `EnhancedForm` 使用 `v-if="drawerVisible"` 控制挂载；抽屉关闭即卸载表单，释放 watcher 与校验状态。
- 为表单设置稳定的 `:key="equipmentId || formMode"`，切换设备时重建表单，避免残留状态干扰。
- 重型分组（通讯参数、设备详情）由 `v-show` 改为 `v-if`，收起时直接卸载重型内容，空闲占用更低。
- 显式控制校验行为：
  - `:validate-on-data-change="false"`
  - `:disable-initial-validation="true"`
  - `:clear-validate-on-data-update="true"`

三、搜索组件 EquipmentSearch（触发频率优化）
- 全局 `SearchForm` 设置温和的去抖：` :debounce-time="500"`。
- 仅对少数字段启用改动即搜（高信噪字段），其余字段需点击“查询”：
  - 启用：`equipmentCode`、`status`
  - 关闭：其余字段（多选、日期范围、长文本、远程搜索等）

#### 验收与观测建议
1) 使用浏览器 Performance Monitor/Profiler 观测：
   - 打开抽屉 → 展开重型分组 → 在键值对编辑器连续输入 10 次 → 关闭抽屉。
   - 对比优化前后 CPU、Recalculate Style、Re-render 次数与输入响应体验。
2) 观察网络层：搜索表单仅在关键字段改动时自动发起请求；其他字段需点击“查询”。

#### 兼容性与风险控制
- 卸载/重建会重置未保存的输入。表单在提交/关闭时应明确交互（确认离开/自动保存策略）。
- 防抖会引入轻微延迟（150ms/500ms），但换取了整体流畅度；失焦/提交时会立即同步。
- 对全局组件未作破坏性修改：本次仅优化设备管理模块内的用法与本地组件。

#### 推广建议（其他模块）
- 对使用抽屉型表单的页面：
  - 表单用 `v-if` 控制挂载；为表单设置稳定 `key`；收起的重型分组使用 `v-if` 卸载。
  - 初始化与数据更新阶段关闭自动校验，提交前再整体校验。
- 对包含键值对/大列表输入的组件：
  - 避免深度监听 + 即时回写；采用浅监听 + 防抖回写 + 自触发保护；输入期做行级校验。
- 对搜索表单：
  - 仅为少数字段开启 `searchOnChange`；去抖时间 ≥ 400ms；避免为远程搜索/多选/日期范围开启改动即搜。
