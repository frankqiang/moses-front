#### 3.2.1. 料框/料垛管理 (Bin/Stack Management)

* **功能描述:** 实现料框/料垛从入车间登记、组垛/拆垛到状态变更的全生命周期管理。
* **实现逻辑:**
  * **料框注册 (Bin Registration):**
        1. **场景:** 通常在物料从上游工序（如分切）转运到退火车间入口时执行。
        2. **操作:** 操作员使用手持终端 (PDA) 扫描料框上的二维码。
        3. **系统处理:**
            * 解析二维码获取 `料框ID`。
            * **自动生成ID:** 如果是新料框首次入系统，根据`3.1.3`规则生成唯一ID并提示操作员贴标（或者假设标签已预先贴好，系统验证ID格式和唯一性）。如果ID已存在但状态允许（如 `空闲`），则继续。若ID已存在且状态不对，报错。
            * **关联规格:** 根据ID规则或查询主数据，自动关联并显示`料框规格`信息 (来自`3.1.1`)。
            * **录入信息:** 操作员需录入/确认 `铝箔产品代码` (来自`3.1.2`)、`批次号`、`重量` (kg)。
            * **校验:** 重量 > 0 且 <= 料框最大载重。产品代码有效。
            * **记录:** 自动记录操作员、时间、初始位置（可默认为入口虚拟位或由操作员选择）。
            * **状态设置:** 将料框状态设为初始状态，如 `待入库(退火)`。
            * **保存与反馈:** 保存料框数据，PDA提示“料框 [ID] 注册成功”。
  * **料框状态跟踪 (Bin Status Tracking):**
    * 建立料框状态机模型，明确定义所有可能的状态及转换条件。示例状态流：
            `空闲` → `待入库(退火)` → `待退火` → `待备料` → `待装炉(备料台/料车)` → `装炉中` → `退火中` → `待出炉` → `已退火` → `待检验` → `已检验(合格/不合格)` → `待出库(包装)` → `已出库` → (若料框循环使用) → `空闲`。
    * 状态转换触发条件包括：扫码确认（入库、出入炉、检验）、物流任务完成（移动到特定区域）、PLC信号（退火开始/结束）。
    * 每次状态转换必须记录时间戳、操作员/系统事件、前后状态、位置变更（若有）。非法状态转换必须被阻止。
  * **料垛管理 (Stack Management):**
    * **组垛 (Stacking):**
            1. **场景:** 在待退火区，将符合条件的料框堆叠起来。
            2. **规则:** 待组垛的料框必须具有相同的`料框规格代码`、`铝箔产品代码`、`批次号`（此项根据业务需求确认是否强制）、并且处于**相同的状态**（如都是 `待退火`）。堆叠层数不得超过该规格的`最大堆叠层数`。
            3. **操作:** 操作员在PDA选择“组垛”，（可选）扫描一个预制的`料垛ID`标签，然后逐一扫描要组成此垛的料框二维码（从下往上）。
            4. **系统处理:** 实时校验每个料框是否符合组垛规则。显示已添加列表和当前层数。全部添加后，操作员确认。系统保存料垛记录（`料垛ID`、成员`料框ID列表`、总重、状态、位置），并更新所有成员料框的`关联料垛ID`字段。
    * **拆垛 (Destacking):**
            1. **场景:** 出炉后、检验前或转运到包装前。
            2. **操作:** 操作员扫描`料垛ID`（或垛上任一料框），选择“拆垛”。
            3. **系统处理:** 解除料垛记录与成员料框的关联（料垛记录可标记为“已拆垛”），成员料框恢复独立状态，其`关联料垛ID`字段清空。
    * 料垛作为一个整体进行位置追踪、库位分配、物流任务调度和炉次管理中的装出炉操作。扫描料垛ID等同于操作其包含的所有料框。
* **操作流程:** 详细描述料框注册、状态变更（如扫码确认出炉）、组垛、拆垛的具体步骤。
* **数据需求:** 料框表、料垛表、状态变更历史表。
* **界面交互要点:** PDA界面设计需适配工业环境，操作步骤清晰引导，扫码反馈及时。组垛时实时校验并显示结果。
* **关键业务规则:** 料框ID唯一性；状态转换严格按流程；组垛规则严格执行；料垛操作影响其所有成员料框。

#### 3.2.2. 库存状态管理 (Inventory Status Management)

* **功能描述:** 提供车间实时库存（料框/料垛）信息的查询、统计和可视化。
* **实现逻辑:**
  * **实时库存查询:** 提供多条件组合查询功能：库区、库位、料框/料垛ID、产品代码/牌号/规格、批次号、状态、库龄范围等。结果以列表形式展示，包含关键信息。
  * **库存可视化:** 在车间电子地图 (基于`3.1.4`配置) 上实时展示库位占用情况。使用不同颜色区分库位状态（空闲-绿，占用-蓝，预留-黄，禁用-红）。鼠标悬停或点击库位可显示详细信息（库位ID、存放物料ID、产品、状态、入库时间）。
  * **库存统计分析:** 按需生成统计报表/图表：
    * 按库区/状态统计料框/料垛数量和总重量。
    * 按产品牌号/规格统计库存分布。
    * 计算平均库龄、库存周转率（需定义计算周期和方法）。
  * **库存预警:** 配置预警规则，例如：
    * `待退火区` 占用率 > 90%。
    * 料框/料垛在 `待退火` 状态停留超过 48 小时。
    * `已检验(不合格)` 料框/料垛数量 > 10 个。
    * 触发预警时，系统在看板、消息中心或通过邮件/短信（需配置）通知相关人员。
* **操作流程:** 用户通过PC Web端访问库存查询、统计或可视化地图界面，设置条件或浏览。预警由系统后台自动监控触发。
* **数据需求:** 实时查询库存相关表，预警规则配置表。
* **界面交互要点:** 查询条件组合灵活；结果列表支持排序、导出；地图支持缩放、平移、信息点选；统计图表类型多样（饼图、柱状图等）；预警信息醒目。
* **关键业务规则:** 库存数据必须实时准确反映物料状态和位置。预警规则需灵活可配。

#### 3.2.3. 物料位置追踪 (Material Location Tracking)

* **功能描述:** 实时追踪并记录每个料框/料垛在车间内的物理位置及其移动轨迹。
* **实现逻辑:**
  * **位置更新源:**
    * **自动化设备:** 行车/自动料车完成`物流任务`后，通过`4.2.2`接口上报任务完成状态，包含物料ID和最终位置ID（库位、备料台、炉口）。
    * **PLC:** 退火炉装炉/出炉完成时，通过`4.2.1`接口确认物料进入/离开炉膛（虚拟位置）。
    * **人工扫描确认:** 在关键节点（如入库口、质检台、出库口，或自动化程度不高的转运点），操作员使用PDA扫描`料框/料垛ID`和`目标位置ID`（库位二维码或设备标签）进行确认。
  * **位置变更记录:** 每次位置变化，系统记录：`物料ID` (料框/料垛), `时间戳`, `旧位置ID`, `新位置ID`, `触发类型` (物流任务完成/PLC信号/人工扫描), `操作设备ID` (若适用), `操作员ID` (若适用)。
  * **位置查询:** 提供功能，输入`料框/料垛ID`可查询其当前所在位置。
  * **历史轨迹查询:** 提供功能，输入`料框/料垛ID`可查询其在指定时间范围内的所有位置变更记录，并可在地图上可视化展示移动路径。
* **操作流程:** 位置更新主要由系统自动处理（接口触发）或操作员按需扫描。查询功能由用户在PC或PDA端发起。
* **数据需求:** 物料位置变更历史表。
* **界面交互要点:** 当前位置信息集成在库存查询结果中。历史轨迹查询结果清晰，地图可视化直观。
* **关键业务规则:** 位置信息必须与物料状态同步更新。确保位置数据来源的准确性和及时性。

#### 3.2.4. 库位分配优化 (Storage Location Assignment Optimization)

* **功能描述:** 在物料入库或工序间转运需要入库位时，智能推荐或自动分配最佳库位。
* **实现逻辑:**
  * **触发场景:** 料框注册后需入库、退火/检验完成后需入库、物料在车间内转运需暂存。
  * **候选库位筛选:**
        1. 根据待入库物料的`料框规格`、`产品类型`（可选）、`状态`（如待退火/已退火），筛选出`3.1.4`中`适用规格`匹配、`所属库区`合适（如待退火物料只能去待退火区）、`占用状态`为“空闲”的所有库位。
        2. 同时需满足`承重限制`和`尺寸限制`（若配置）。
  * **优化策略与评分 (示例，需可配置):**
    * 为每个候选库位计算一个综合得分 (Score)，选择得分最高的N个推荐或直接分配最高分。
    * **评分因子 (示例):**
      * `就近原则 (Proximity)`: 计算库位到该物料下一个典型目的地（如待退火物料->对应炉型备料台/炉口；已退火物料->质检区/出库口）的物理距离或路径成本（需库位坐标和路径信息），距离越近得分越高。权重 `w_prox`。
      * `先进先出 (FIFO)`: 考虑库位空闲时长，空闲时间越长的库位得分越高（鼓励利用旧空位，防止死角）。权重 `w_fifo`。
      * `同类聚集 (Affinity)`: 检查库位附近（如同一排/相邻几位）是否已存放相同`产品代码`或`批次号`的物料，若有则得分较高（便于管理和查找）。权重 `w_affin`。
      * `区域填满度 (Utilization)`: 优先填满某个区域或巷道，或考虑是否有利于后续操作（如靠近主通道），给予评分。权重 `w_util`。
      * `堆叠潜力 (Stacking)`: 如果是地面库位且允许堆叠，检查其上方库位是否空闲。若空闲且待入库物料满足堆叠条件（通常同规格），则给予加分。权重 `w_stack`。
    * `Score = w_prox * Score_prox + w_fifo * Score_fifo + ...` (权重可配置)。
  * **分配模式:**
    * **推荐模式:** 系统显示得分最高的N个库位列表（含得分和推荐理由），由操作员最终选择确认。
    * **自动模式:** 系统自动选择最高分库位，将其状态置为“预留”，并直接触发`3.3.4 物流任务生成`，将物料运往该库位。
* **操作流程:**
    1. 系统（或操作员）触发库位分配请求，传入待分配物料信息。
    2. 系统执行筛选和评分算法。
    3. 根据配置模式，显示推荐列表或直接执行分配。
    4. 若为推荐模式，操作员确认选择；若为自动模式，系统自动完成。
    5. 库位状态更新为“预留”或“占用”，物流任务生成。
* **数据需求:** 实时库位状态、库位主数据、物料信息、优化策略配置、库位坐标和距离数据（可选）。
* **界面交互要点:** 推荐列表清晰展示库位ID、得分、理由。可在地图上高亮显示推荐库位。
* **关键业务规则:** 分配的库位必须满足物理和业务规则约束。优化策略应可配置以适应不同场景。自动分配模式下需确保高可靠性。
