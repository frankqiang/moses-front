#### 3.1.1. 料框规格管理 (Bin Specification Management)

* **功能描述:** 维护车间使用的各种料框的基础信息。
* **实现逻辑:**
  * 提供数据维护界面 (CRUD - 创建, 读取, 更新, 禁用)。
  * 记录字段: `规格代码` (唯一, 如 LK001), `规格名称` (如 标准料框), `尺寸` (长/宽/高, 单位cm), `最大载重` (kg), `材质`, `适用产品类型` (可多选, 关联产品主数据), `最大堆叠层数` (整数), `供应商信息` (可选), `状态` (启用/禁用)。
  * **校验规则:** 规格代码全局唯一；尺寸、载重、堆叠层数必须为正数；逻辑删除，已在用的规格（有对应料框实例存在）不能物理删除，只能设为“禁用”。
* **操作流程:**
    1. 管理员登录系统，导航至“主数据 -> 料框规格”。
    2. 查看规格列表，可按代码、名称等搜索或排序。
    3. 点击“新增”，填写规格详情，选择适用产品类型，保存。
    4. 选择已有规格，点击“编辑”，修改信息后保存。
    5. 选择不再使用的规格，点击“禁用”。
* **数据需求:** 输入/输出上述记录字段。
* **界面交互要点:** 列表使用表格展示，支持筛选和排序；编辑表单布局清晰，必填项明确；适用产品类型使用多选控件（如穿梭框）。
* **关键业务规则:** 只有“启用”状态的规格才能在后续料框注册时被引用。

#### 3.1.2. 铝箔产品管理 (Aluminum Foil Product Management)

* **功能描述:** 管理车间生产或处理的铝箔产品的基础信息。
* **实现逻辑:**
  * 提供数据维护界面 (CRUD)。
  * 记录字段: `产品编码` (唯一, 如 AF-1100-H18-0.006x1200), `产品名称` (如 1100合金H18态双零箔), `原材料类型`, `合金牌号` (如 1100, 8011), `状态/硬度` (如 H18, O), `规格-厚度` (mm), `规格-宽度` (mm), `单位重量` (kg/卷 或 kg/m²), `关联标准退火工艺模板ID` (引用`3.1.8`, 可多个备选), `关联质量标准ID` (引用`3.1.9`), `产品生命周期状态` (试产/量产/停产)。
  * **校验规则:** 产品编码全局唯一；厚度、宽度、单位重量为正数；必须关联至少一个“生效”状态的工艺模板和质量标准。
* **操作流程:**
    1. 管理员登录，导航至“主数据 -> 产品管理”。
    2. 查看产品列表，可按牌号、规格、状态筛选。
    3. 点击“新增”，填写产品信息，关联工艺模板和质量标准，保存。
    4. 选择已有产品，编辑信息或更新生命周期状态。
* **数据需求:** 输入/输出上述记录字段。
* **界面交互要点:** 产品列表清晰展示关键规格；编辑表单结构化；关联工艺模板和质量标准时提供下拉选择或搜索弹出框。
* **关键业务规则:** 只有“量产”状态的产品才能用于创建生产计划或退火任务。

#### 3.1.3. 物料编码管理 (Material Code Management)

* **功能描述:** 定义料框ID的生成规则及二维码内容。
* **实现逻辑:**
  * 提供配置界面设定料框ID的生成规则。**强制规则：** 系统必须保证生成的料框ID全局唯一。
  * **规则选项 (示例):**
    * 纯流水号 (如 8位数字，自动递增)。
    * 前缀 + 流水号 (如 `BIN-` + 6位流水号)。
    * 可配置流水号长度、起始值、步长。
  * **二维码内容定义:** 明确二维码中编码的信息。**推荐:** 仅包含唯一的 `料框ID` 字符串。避免包含易变信息。
  * **二维码参数配置:** (可选) 配置生成二维码的参数，如尺寸、纠错级别 (建议 M 或 Q)。
  * **规则版本管理:** (可选) 记录编码规则的变更历史。
* **操作流程:**
    1. 系统管理员进入“系统设置 -> 编码规则”。
    2. 选择“料框编码规则”。
    3. 配置生成规则参数。
    4. 定义二维码内容（通常固定为料框ID）。
    5. 保存规则。
* **数据需求:** 输入/输出编码规则配置参数。
* **界面交互要点:** 提供规则预览功能。
* **关键业务规则:** 料框ID由系统根据配置的规则在注册时**自动生成**并分配。规则一旦启用并生成数据，不应随意修改，以保证历史数据一致性。

#### 3.1.4. 库位主数据管理 (Storage Location Master Data Management)

* **功能描述:** 定义和管理车间内所有物理存储位置的信息。
* **实现逻辑:**
  * 提供界面定义**库区** (如 `DA`-待退火区, `YA`-已退火区, `HC`-缓存区, `ZJ`-质检区, `BLT`-备料台区域) 和**库位**。
  * 记录字段 (库位): `库位ID` (唯一, 如 DA-01-01-A), `所属库区代码`, `库位类型` (地面堆垛区/固定货架/备料台工位/炉口虚拟位), `坐标` (X, Y, Z, 可选，用于可视化和路径计算), `尺寸限制` (长/宽/高, cm, 可选), `承重限制` (kg), `适用料框规格代码` (可多选或不限), `占用状态` (空闲/占用/预留/禁用/维护), `最大堆叠高度` (仅地面库位, 如3层)。
  * **批量生成:** 支持按规则 (如 `库区代码-行号-列号-层号`) 批量创建库位。
  * **可视化配置:** 提供工具将库位数据与上传的车间布局图进行关联映射，支持拖拽放置和属性设置。
  * **校验规则:** 库位ID全局唯一；承重限制为正数。
* **操作流程:**
    1. 管理员进入“主数据 -> 库位管理”。
    2. 先定义库区。
    3. 选择库区，使用“批量生成”或“单个新增”创建库位，填写属性。
    4. (可选) 在“库位地图配置”界面，将库位拖拽到地图上的对应位置。
    5. 保存。
* **数据需求:** 输入/输出库区和库位记录字段。
* **界面交互要点:** 库位列表支持按库区、状态筛选；提供可视化地图编辑器；批量生成工具提供预览。
* **关键业务规则:** 只有`状态`为“空闲”且`类型/规格/承重`匹配的库位才能被`3.2.4 库位分配优化`算法选中。`占用状态`需实时更新。

#### 3.1.5. 设备主数据管理 (Equipment Master Data Management)

* **功能描述:** 管理车间内关键生产及物流设备的基础档案。
* **实现逻辑:**
  * 区分设备类型进行管理 (退火炉, 行车, 自动料车, 备料台)。
  * **退火炉档案:** `设备ID` (唯一), `名称`, `型号`, `规格` (额定容量如40T, 炉膛尺寸), `最大工作温度`, `额定功率`, `安装日期`, `维护周期建议`, `关联PLC通讯地址/节点ID` (关键!)。
  * **行车档案:** `设备ID` (唯一), `名称`, `型号`, `额定起重量`, `运行速度范围`, `服务范围` (坐标限制或区域列表), `关联控制系统接口地址/参数` (关键!)。
  * **自动料车档案:** `设备ID` (唯一), `名称`, `型号`, `载重能力`, `运行速度`, `导航方式` (如激光/磁导), `电池容量`, `低电量阈值`, `充电策略`, `关联控制系统接口地址/参数` (关键!)。
  * **备料台档案:** `设备ID` (唯一), `名称/编号`, `位置描述/坐标`, `承重能力`, `可存放料框/料垛数`, `关联退火炉` (可选)。
  * 提供CRUD界面。
  * **校验规则:** 设备ID全局唯一。通讯接口参数必须按要求填写。
* **操作流程:**
    1. 管理员进入“主数据 -> 设备管理”。
    2. 选择设备类型，查看列表。
    3. 新增或编辑设备，填写详细信息，特别是通讯接口参数。
    4. 保存。
* **数据需求:** 输入/输出各类型设备的记录字段。
* **界面交互要点:** 按设备类型分类显示和管理。表单根据不同设备类型显示不同的特定参数字段。
* **关键业务规则:** 设备主数据是排程、任务分配、状态监控和接口通讯的基础。通讯参数的准确性至关重要。

#### 3.1.6. 设备TPM管理 (Equipment TPM Management)

* **功能描述:** 实施全面生产维护（Total Productive Maintenance, TPM），通过预防性维护计划、故障管理、备件管理等手段提升设备综合效率（OEE），降低设备故障率，延长设备使用寿命。
* **实现逻辑:**
  * **预防性维护计划管理:**
    * 记录字段: `计划ID` (唯一), `关联设备ID` (引用`3.1.5`), `维护类型` (日常保养/定期检查/大修/专项维护), `维护项目` (具体维护内容描述), `维护周期类型` (按时间/按运行时长/按生产批次), `周期参数` (如7天/1000小时/100炉次), `标准工时` (小时), `所需备件清单` (关联备件主数据), `所需技能/资质`, `安全注意事项`, `维护作业指导书附件`, `状态` (启用/禁用)。
    * 支持基于时间、设备运行时长或生产批次自动生成维护任务。
    * 提供维护计划模板功能，支持快速复制和批量应用。
  * **维护任务管理:**
    * 记录字段: `任务ID` (唯一), `关联维护计划ID`, `关联设备ID`, `任务类型` (计划维护/应急抢修/状态检修), `计划执行日期/时间`, `实际开始时间`, `实际完成时间`, `执行人员`, `任务状态` (待执行/执行中/已完成/已延期/已取消), `延期原因` (若延期), `完成确认人`, `备注`。
    * 支持任务派工、进度跟踪、逾期提醒。
    * 任务完成后自动生成维护记录。
  * **维护保养记录:**
    * 记录字段: `记录ID` (唯一), `关联维护任务ID`, `关联设备ID`, `维护日期/时间`, `维护类型`, `维护内容详情`, `发现问题描述`, `处理措施`, `使用备件清单` (备件编码、名称、数量), `维护工时` (小时), `执行人员`, `确认人员`, `维护前设备状态`, `维护后设备状态`, `附件` (照片/报告), `下次维护建议`。
    * 支持维护记录的查询、统计和导出。
    * 关联设备运行记录，形成完整的设备健康档案。
  * **设备故障管理:**
    * 记录字段: `故障ID` (唯一), `关联设备ID`, `故障发生时间`, `故障发现人/报告人`, `故障现象描述`, `故障等级` (I级-严重/II级-重大/III级-一般/IV级-轻微), `影响程度` (停机/性能下降/无影响), `故障原因分析` (初步/详细), `故障类型分类` (机械/电气/液压/控制/其他), `处理开始时间`, `处理完成时间`, `故障处理措施`, `使用备件清单`, `处理人员`, `验证人员`, `是否重复故障` (是/否), `根本原因分析` (5Why/鱼骨图), `预防措施`, `状态` (待处理/处理中/已解决/已验证/已关闭)。
    * 自动计算MTBF（平均故障间隔时间）、MTTR（平均修复时间）。
    * 支持故障统计分析（按设备、按类型、按时间段）、故障趋势分析。
    * 重复故障自动标记和报警。
  * **备件管理:**
    * **备件主数据:** `备件编码` (唯一), `备件名称`, `规格型号`, `适用设备类型/型号`, `供应商信息`, `单价`, `计量单位`, `库存上限`, `库存下限`, `安全库存`, `采购提前期` (天), `存储位置`, `保质期` (月, 可选), `备注`。
    * **备件库存:** 实时库存数量、在途数量、预留数量。
    * **备件出入库记录:** 出入库时间、类型（入库/领用/退库/报废）、数量、经手人、用途（关联维护任务/故障处理）。
    * **备件需求预测:** 基于维护计划和历史消耗统计，自动生成备件采购建议。
    * **库存预警:** 库存低于安全库存时自动报警。
  * **维护知识库 (可选扩展):**
    * 收集和沉淀设备维护经验、常见故障处理方案、技术文档等。
    * 支持关键词搜索和分类浏览。
  * **校验规则:**
    * 计划ID、任务ID、记录ID、故障ID、备件编码全局唯一。
    * 维护周期参数、工时、备件数量必须为正数。
    * 故障等级必须按规则填写。
    * 备件库存数量不能为负数。
* **操作流程:**
  * **创建维护计划:**
    1. 设备管理员登录，进入"设备管理 -> TPM管理 -> 维护计划"。
    2. 选择设备，点击"新增计划"。
    3. 填写维护类型、周期、项目内容、所需备件等信息。
    4. 上传作业指导书（可选）。
    5. 保存并启用计划。
  * **执行维护任务:**
    1. 维护人员在"我的任务"中查看待执行的维护任务。
    2. 点击任务详情，查看维护要求和作业指导。
    3. 领取所需备件（系统记录出库）。
    4. 执行维护，更新任务状态为"执行中"。
    5. 维护完成后，填写维护记录（内容、问题、措施、使用备件）。
    6. 提交记录，任务状态变为"已完成"，等待确认。
  * **故障处理流程:**
    1. 操作人员发现设备故障，在系统中创建故障报告。
    2. 系统根据故障等级自动通知相关维护人员。
    3. 维护人员接单，开始故障诊断和处理。
    4. 记录故障现象、原因、处理措施、使用备件。
    5. 故障处理完成后，进行设备验证。
    6. 验证通过后关闭故障单，系统自动更新MTBF、MTTR统计。
  * **备件管理流程:**
    1. 仓库管理员在"备件管理"中维护备件主数据和库存。
    2. 系统根据维护计划和历史消耗自动生成备件需求预测。
    3. 库存低于安全库存时，系统自动发出采购申请提醒。
    4. 维护人员领用备件时，系统自动更新库存并关联维护任务/故障单。
* **数据需求:** 输入/输出上述维护计划、任务、记录、故障、备件相关字段。
* **界面交互要点:**
  * 维护计划列表按设备、类型筛选，支持批量创建和启用/禁用。
  * 维护任务日历视图和列表视图结合，清晰展示任务分布。
  * 故障处理流程可视化，支持移动端快速报障和处理。
  * 备件库存看板实时展示库存状态和预警信息。
  * 提供设备维护履历查看功能，完整展示设备的维护和故障历史。
  * 数据统计和分析功能，图表化展示OEE、MTBF、MTTR趋势。
* **关键业务规则:**
  * 计划维护任务自动生成时间为计划执行日期前3天（可配置）。
  * 设备处于"维护"状态时，排程系统不能为其分配生产任务。
  * 故障等级为I级（严重）时，必须24小时内完成处理或提供临时解决方案。
  * 备件出库必须关联维护任务或故障单，确保可追溯。
  * 重复故障（相同设备相同故障类型30天内发生2次以上）需要进行根本原因分析。
  * 维护计划修改或停用需要相应权限审批。
  * 与`3.5 设备状态监控`模块集成，设备异常时自动触发故障报告流程。

#### 3.1.7. 工艺参数管理 (Process Parameter Management)

* **功能描述:** 集中管理铝箔退火的标准工艺配方模板，采用固定12段控温结构。
* **实现逻辑:**
  * 建立工艺模板库，支持版本控制。
  * 记录字段 (工艺模板): `模板ID` (唯一), `模板名称`, `版本号`, `状态` (草稿/待审批/生效/历史), `创建/修改人/时间`, `审批记录`, `适用产品范围` (关联`3.1.2`产品编码/牌号/规格范围)。
  * **工艺参数详情:**
    * **固定12段结构:** 每个工艺模板包含固定12个控温段，不可增减。每段包含完整工艺参数：
      * `段序号` (固定1-12)
      * `控温方式` (固定值"定时定温")
      * `炉温设置` (℃, 0-1500)
      * `料温设置` (℃, 0-1500)
      * `时间设置` (小时, 0-999)
      * `运行时间` (小时, 执行时填写)
      * `循环风机` (枚举: 低速/中速/高速)
      * `负压风机` (Hz, 0-100)
      * `吹洗风机` (Hz, 0-100)
      * `吹洗时间` (分钟, 0-999)
    * **预设模板:** 提供标准退火、快速退火、空白模板三种预设配置，便于快速创建。
    * **参数校验:** 自动校验料温不高于炉温、时间和频率在合理范围内。
  * **版本与审批:** 支持创建新版本进行修改。修改后提交审批（审批流程可配置，如一级审批、二级审批）。只有"生效"状态的模板才能被生产任务引用。
  * **校验规则:** 模板ID+版本号唯一。必须包含完整的12段参数。温度、时间、风机频率等参数必须在合理范围及设备能力内。
* **操作流程:**
    1. 工艺工程师登录，进入"主数据 -> 工艺管理"。
    2. 创建新模板（选择预设模板或自定义12段参数）或基于现有模板创建新版本。
    3. 定义适用产品范围（产品ID、合金牌号、厚度范围、宽度范围）。
    4. 配置12段工艺参数（炉温、料温、时间、风机等）。
    5. 保存为"草稿"或"提交审批"。
    6. 审批人在系统中收到通知，审核通过则状态变为"生效"，驳回则退回修改。
* **数据需求:** 输入/输出工艺模板及12段完整参数字段。
* **界面交互要点:**
  * 12段参数表格化编辑，支持批量修改和预设模板选择。
  * 模板列表按状态、产品筛选。
  * 提供版本历史查看与对比功能。
  * 审批流程界面清晰。
* **关键业务规则:**
  * 生产任务必须关联一个"生效"状态的工艺模板。
  * 工艺参数修改必须遵循版本和审批管理。
  * 每个模板必须且仅包含12个控温段，段序号1-12不可跳号。
  * 料温不能高于炉温，参数必须在设备能力范围内。

#### 3.1.8. 工序管理 (Process Operation Management)

* **功能描述:** 管理生产过程中的各种工序定义，包括工序基础信息、参数配置和状态控制。
* **实现逻辑:**
  * **工序主数据管理**: 维护工序基础信息，包括 `工序代码`, `工序名称`, `工序类型` (生产/检验/包装/其他), `工序描述`, `标准工时` (分钟), `所需设备类型`, `技能要求`, `安全注意事项`。
  * **工序参数配置**: 为每个工序定义可配置的参数，如 `温度范围`, `压力范围`, `速度设置`, `质量检查点`, `操作步骤`。支持参数的版本管理和审批流程。
  * **工序状态管理**: 工序状态包括 `草稿`, `待审批`, `生效`, `已归档`, `已停用`。只有"生效"状态的工序可用于工艺路线编排。
  * **工序分类管理**: 支持按工序类型、所属车间、设备类型等维度进行分类管理，便于查找和维护。
  * **校验规则**: 工序代码唯一性校验，参数范围合理性校验，状态变更权限控制。
* **操作流程:**
    1. 工艺工程师登录系统，进入"主数据 -> 工序管理"。
    2. 创建新工序或编辑现有工序基础信息。
    3. 配置工序相关参数和操作要求。
    4. 设置工序状态，提交审批（如需要）。
    5. 审批通过后工序状态变为"生效"，可用于工艺路线配置。
* **数据需求:** 工序主数据表、工序参数配置表、工序状态变更历史表。
* **界面交互要点:** 工序列表支持多条件筛选和排序。工序编辑界面提供参数配置向导。状态变更操作有明确的权限控制和审批流程提示。
* **关键业务规则:** 工序代码全局唯一。参数配置必须符合安全和质量要求。状态变更需要相应权限和审批流程。

#### 3.1.9. 工艺路线编排 (Process Route Configuration)

* **功能描述:** 定义和管理产品的完整工艺路线，包括工序序列、路线版本控制和状态管理。
* **实现逻辑:**
  * **工艺路线定义**: 创建工艺路线，包含 `路线代码`, `路线名称`, `适用产品范围`, `路线类型` (标准/返工/试验), `路线描述`, `创建人`, `创建时间`。
  * **工序序列配置**: 为工艺路线添加工序步骤，定义 `工序代码` (来自3.1.8), `步骤序号`, `是否必需`, `并行工序组`, `前置条件`, `质量检查要求`, `预计工时`。支持工序的串行和并行配置。
  * **路线版本管理**: 支持工艺路线的版本控制，包括 `版本号`, `版本说明`, `生效日期`, `失效日期`。新版本创建时可基于现有版本复制修改。
  * **路线状态控制**: 路线状态包括 `草稿`, `待审批`, `生效`, `已归档`。状态变更需要相应权限，只有"生效"状态的路线可用于生产任务。
  * **业务规则配置**: 根据路线类型应用不同的业务规则，如返工路线必须包含检验工序，试验路线最多10个步骤等。
  * **校验规则**: 路线代码唯一性，工序序列逻辑性检查，版本号递增规则，状态变更合规性验证。
* **操作流程:**
    1. 工艺工程师进入"主数据 -> 工艺路线编排"。
    2. 创建新的工艺路线或基于现有路线创建新版本。
    3. 配置工艺路线基础信息和适用范围。
    4. 添加工序步骤，设置工序序列和参数。
    5. 配置质量检查点和工时预估。
    6. 提交审批，审批通过后路线生效。
    7. 可根据生产反馈持续优化和更新路线。
* **数据需求:** 工艺路线主表、工艺路线工序关联表、路线版本历史表、路线状态变更记录表。
* **界面交互要点:** 路线列表支持按产品、类型、状态等条件筛选。路线编辑提供可视化的工序流程图。版本对比功能便于查看变更内容。审批流程界面清晰明确。
* **关键业务规则:** 生产任务必须关联"生效"状态的工艺路线。路线修改需要版本控制和审批管理。工序序列必须逻辑合理且符合生产实际。

#### 3.1.10. 质量标准配置 (Quality Standard Configuration)

* **功能描述:** 配置不同产品的质量检验标准和判定规则。
* **实现逻辑:**
  * 首先定义**检验项目库**: `项目代码`, `项目名称` (如 硬度, 抗拉强度, 延伸率, 表面质量), `单位`, `检测方法描述`, `数据类型` (数值/布尔/文本)。
  * 然后配置**产品质量标准**: 关联`产品编码` (来自`3.1.2`)，为该产品选择需要检验的`检验项目代码`，并设定`标准值` (如具体数值、上限、下限、范围)、`合格判定规则` (如 `结果 >= 下限 AND 结果 <= 上限` 则合格)。
  * **抽检规则 (可选):** 配置抽检比例或首/中/末件检验规则。
  * 支持质量标准的版本管理（类似工艺参数）。
  * **校验规则:** 检验项目代码唯一。数值标准的上限必须大于等于下限。
* **操作流程:**
    1. 质量工程师登录，进入“主数据 -> 质量标准”。
    2. 维护检验项目库。
    3. 选择目标产品（或产品类别），创建或编辑其质量标准。
    4. 从项目库中添加检验项目，设定标准值和判定规则。
    5. 配置抽检规则（若需要）。
    6. 保存标准（可能需要审批流程）。
* **数据需求:** 输入/输出检验项目、产品质量标准配置记录。
* **界面交互要点:** 检验项目库管理界面。产品-质量标准关联配置界面（可用表格或矩阵）。
* **关键业务规则:** `3.4.6 质量检验执行`模块将依据此处配置的“生效”状态的标准进行检验和自动判定。
