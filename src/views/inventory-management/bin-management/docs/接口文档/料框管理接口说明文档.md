# Moses API 料框管理模块接口文档

## 概述

本文档详细说明了 Moses API 料框管理模块的所有接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。**本文档严格基于实际代码实现编写**，确保前端开发人员能够准确对接。

## 🚨 **文档准确性红线（零容忍原则）**

**接口文档与实际API返回数据必须100%一致，这是前后端协作的基础保障！**

### API 基础信息

- **基础 URL**: `http://localhost:3000/v1` (开发环境)
- **API 版本**: v1
- **认证方式**: JWT Bearer Token
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### Swagger 文档

项目已集成 Swagger 文档，可通过以下地址访问：

- **开发环境**: http://localhost:3000/v1/docs
- **在线文档**: 提供完整的 API 接口说明、参数定义和示例

### 权限约定

- `inv.bin.manage`：料框管理权限，可执行料框注册、批量注册等写操作
- `inv.bin.view`：料框查看权限，可执行料框列表查询、详情查询等读操作
- `inv.bin.status-update`：料框状态更新权限，可执行料框状态变更操作

## 统一响应格式

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

## 料框管理接口详细说明

### 1. 料框注册

**接口路径**: `POST /v1/inv/bins`

**功能描述**: 注册新料框，记录料框基本信息并设置初始状态为"待入库退火"（`PENDING_ANNEALING_STORAGE`）。支持自动生成料框编号或使用扫码录入的编号。注册时会进行完整的业务验证，包括料框规格、产品、重量、库位等信息的验证，并自动记录状态历史。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名             | 类型   | 必填 | 限制                   | 描述                             | 示例                                   |
| ------------------ | ------ | ---- | ---------------------- | -------------------------------- | -------------------------------------- |
| binCode            | string | 否   | 格式：LK-YYYYMMDD-XXXX | 料框编号，可选，不提供则自动生成 | "LK-20250110-0001"                     |
| binSpecificationId | string | 是   | UUID格式               | 料框规格ID，必填                 | "123e4567-e89b-12d3-a456-426614174000" |
| productId          | string | 是   | UUID格式               | 铝箔产品ID，必填                 | "223e4567-e89b-12d3-a456-426614174000" |
| productCode        | string | 是   | 长度1-100字符          | 产品代码，必填                   | "AF-1060-O-0.05x500"                   |
| batchNumber        | string | 否   | 长度最大100字符        | 批次号，可选                     | "BATCH-2025-001"                       |
| weight             | number | 是   | 正数，最多3位小数      | 重量(kg)，必填                   | 250.5                                  |
| currentLocationId  | string | 否   | UUID格式               | 初始位置ID，可选                 | "323e4567-e89b-12d3-a456-426614174000" |
| remarks            | string | 否   | 长度最大500字符        | 备注，可选                       | "入库登记"                             |

### 2. 批量注册料框

**接口路径**: `POST /v1/inv/bins/batch`

**功能描述**: 批量注册多个料框，使用事务确保原子性。如果部分失败会返回详细的错误信息，包括成功和失败的记录详情。支持逐个验证和注册，失败的记录不影响成功的记录。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名 | 类型  | 必填 | 限制    | 描述                                     | 示例 |
| ------ | ----- | ---- | ------- | ---------------------------------------- | ---- |
| bins   | array | 是   | 至少1条 | 料框数据数组，每条数据格式同单个注册接口 | []   |

bins 数组中每个元素的字段说明参考"料框注册"接口的请求参数。

**请求示例**:

```bash
curl -X POST http://localhost:3000/v1/inv/bins/batch \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "bins": [
      {
        "binSpecificationId": "123e4567-e89b-12d3-a456-426614174000",
        "productId": "223e4567-e89b-12d3-a456-426614174000",
```

参考认证模块文档中的通用错误码部分，包括：
- **AUTH_001**: 请先登录（401）
- **AUTH_002**: 权限不足（403）
- **AUTH_003**: 令牌已过期（401）
- **VAL_001**: 参数验证失败（400）

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理
   - `BIN_`: 料框相关错误，检查料框参数和状态
   - `INV_`: 通用库存错误，检查通用参数和权限
   - `AUTH_`: 认证相关错误，可能需要重新登录或刷新令牌
   - `VAL_`: 验证相关错误，需要检查输入参数

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息

4. **错误详情利用**: 使用 `error.details` 中的字段信息，快速定位问题字段

5. **日志记录**: 使用 `traceId` 进行错误追踪和问题排查

## 安全说明

### 认证机制

料框管理接口使用 JWT Bearer Token 认证机制，所有接口都需要在请求头中携带有效的访问令牌：

```
Authorization: Bearer <access_token>
```

令牌获取方式参考登录模块文档。

### 权限控制

料框管理模块实现了细粒度的权限控制：

- **料框管理权限** (`inv.bin.manage`): 可以注册、批量注册料框等写操作
- **料框查看权限** (`inv.bin.view`): 可以查询料框列表、详情和状态历史等读操作
- **料框状态更新权限** (`inv.bin.status-update`): 可以更新料框状态

用户必须具备相应权限才能调用对应的接口，否则会返回403错误。

### 安全特性

1. **数据验证**: 所有输入参数都经过严格的验证，包括格式、类型、长度等
2. **业务规则校验**: 注册时会验证料框规格、产品、重量等业务规则
3. **状态转换控制**: 状态更新时会严格校验状态转换规则
4. **操作审计**: 所有关键操作都会记录操作人、操作时间、IP地址等信息
5. **事务保护**: 涉及多表操作的业务使用事务确保数据一致性
6. **软删除机制**: 使用软删除标志，数据不会真正被删除

### 使用建议

1. 妥善保管访问令牌，不要在前端代码中硬编码
2. 定期刷新令牌，避免令牌过期导致的认证失败
3. 合理使用权限控制，确保用户只能访问授权的资源
4. 注意料框状态转换规则，避免非法的状态转换
5. 批量操作时注意错误处理，检查failedRecords了解失败原因
