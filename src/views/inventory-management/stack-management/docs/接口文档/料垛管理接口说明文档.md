# Moses API 料垛管理模块接口文档

## 概述

本文档详细说明了 Moses API 料垛管理模块的所有接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。**本文档严格基于实际代码实现编写**，确保前端开发人员能够准确对接。

## 🚨 **文档准确性红线（零容忍原则）**

**接口文档与实际API返回数据必须100%一致，这是前后端协作的基础保障！**

### API 基础信息

- **基础 URL**: `http://localhost:3000/v1` (开发环境)
- **API 版本**: v1
- **认证方式**: JWT Bearer Token
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### Swagger 文档

项目已集成 Swagger 文档，可通过以下地址访问：

- **开发环境**: http://localhost:3000/v1/docs
- **在线文档**: 提供完整的 API 接口说明、参数定义和示例

### 权限约定

- `inv.stack.manage`：料垛管理权限，可执行组垛、拆垛等写操作
- `inv.stack.view`：料垛查看权限，可执行料垛列表查询、详情查询、成员查询等读操作

## 统一响应格式

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

## 料垛管理接口详细说明

### 1. 组垛

**接口路径**: `POST /v1/inv/stacks`

**功能描述**: 将符合条件的料框堆叠成料垛。要求所有料框具有相同的料框规格、产品代码、批次号和状态。堆叠层数不得超过规格的最大堆叠层数限制。组垛成功后，料垛状态设置为"活动中"（`ACTIVE`），成员料框会关联到该料垛。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名    | 类型   | 必填 | 限制                        | 描述                                       | 示例                                                     |
| --------- | ------ | ---- | --------------------------- | ------------------------------------------ | -------------------------------------------------------- |
| stackCode | string | 否   | 格式：LD-YYYYMMDD-XXXX      | 料垛编号，可选，不提供则自动生成           | "LD-20250110-0001"                                       |
| binIds    | array  | 是   | UUID数组，至少2个，元素唯一 | 料框ID列表，必填，所有料框必须符合组垛规则 | ["123e4567-e89b-12d3-a456-426614174000", "223e4567-..."] |
| remarks   | string | 否   | 长度最大500字符             | 备注，可选                                 | "组垛备注"                                               |

**组垛规则说明**:
- 所有料框必须具有相同的料框规格
- 所有料框必须具有相同的产品代码
- 所有料框必须具有相同的批次号（可选字段，如果有值则必须一致）
- 所有料框必须具有相同的状态
- 所有料框都不能已经在其他料垛中
- 堆叠层数（料框数量）不得超过规格的最大堆叠层数限制

**请求示例**:

```bash
curl -X POST http://localhost:3000/v1/inv/stacks \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "stackCode": "LD-20250110-0001",
    "binIds": [
      "123e4567-e89b-12d3-a456-426614174000",
      "223e4567-e89b-12d3-a456-426614174001"
    ],
    "remarks": "组垛备注"
  }'
```

### 2. 料垛列表查询

**接口路径**: `GET /v1/inv/stacks`

**功能描述**: 分页查询料垛列表，支持多条件筛选和排序。可按状态、规格代码、产品代码、批次号、位置ID等条件筛选，支持关键词搜索料垛编号和产品代码。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
```

**查询参数**:

| 参数名            | 类型   | 必填 | 限制                        | 描述                                     | 示例                       |
| ----------------- | ------ | ---- | --------------------------- | ---------------------------------------- | -------------------------- |
| status            | string | 否   | 枚举值（ACTIVE, DESTACKED） | 料垛状态筛选                             | "ACTIVE"                   |
| specCode          | string | 否   | 长度最大100字符             | 料框规格代码筛选                         | "SPEC-001"                 |
| productCode       | string | 否   | 长度最大100字符             | 产品代码筛选                             | "AF-1060-O-0.05x500"       |
| batchNumber       | string | 否   | 长度最大100字符             | 批次号筛选                               | "BATCH-2025-001"           |
| currentLocationId | string | 否   | UUID格式                    | 当前位置ID筛选                           | "323e4567-..."             |
| createdAtStart    | string | 否   | ISO 8601日期时间格式        | 创建时间起始                             | "2025-01-01T00:00:00.000Z" |
| createdAtEnd      | string | 否   | ISO 8601日期时间格式        | 创建时间结束                             | "2025-01-31T23:59:59.999Z" |
| searchKeyword     | string | 否   | 长度最大100字符             | 搜索关键词（料垛编号、产品代码模糊匹配） | "LD-20250110"              |
| sortBy            | string | 否   | 格式：字段名:(asc\|desc)    | 排序字段和顺序，默认：createdAt:desc     | "createdAt:desc"           |

### 3. 料垛详情查询

**接口路径**: `GET /v1/inv/stacks/:id`

**功能描述**: 根据料垛ID查询料垛详细信息，包含料垛的规格、产品、位置等关联信息。

**请求头**:


参考料框管理接口文档中的通用认证授权错误码部分，包括：
- **AUTH_001**: 请先登录（401）
- **AUTH_002**: 权限不足（403）
- **AUTH_003**: 令牌已过期（401）
- **VAL_001**: 参数验证失败（400）

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理
   - `STACK_`: 料垛相关错误，检查料垛参数和状态
   - `INV_`: 通用库存错误，检查通用参数和权限
   - `AUTH_`: 认证相关错误，可能需要重新登录或刷新令牌
   - `VAL_`: 验证相关错误，需要检查输入参数

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息

4. **错误详情利用**: 使用 `error.details` 中的字段信息，快速定位问题字段和冲突数据

5. **日志记录**: 使用 `traceId` 进行错误追踪和问题排查

## 安全说明

### 认证机制

料垛管理接口使用 JWT Bearer Token 认证机制，所有接口都需要在请求头中携带有效的访问令牌：

```
Authorization: Bearer <access_token>
```

令牌获取方式参考登录模块文档。

### 权限控制

料垛管理模块实现了细粒度的权限控制：

- **料垛管理权限** (`inv.stack.manage`): 可以组垛、拆垛等写操作
- **料垛查看权限** (`inv.stack.view`): 可以查询料垛列表、详情和成员料框等读操作

用户必须具备相应权限才能调用对应的接口，否则会返回403错误。

### 安全特性

1. **数据验证**: 所有输入参数都经过严格的验证，包括格式、类型、长度等
2. **业务规则校验**: 组垛时会验证料框规格、产品、批次、状态、层数等业务规则
3. **状态控制**: 拆垛时会检查料垛状态，防止重复拆垛
4. **操作审计**: 所有关键操作都会记录操作人、操作时间、IP地址等信息
5. **事务保护**: 组垛和拆垛操作使用事务确保数据一致性
6. **软删除机制**: 使用软删除标志，数据不会真正被删除

### 使用建议

1. 妥善保管访问令牌，不要在前端代码中硬编码
2. 定期刷新令牌，避免令牌过期导致的认证失败
3. 合理使用权限控制，确保用户只能访问授权的资源
4. 组垛前确保所有料框符合组垛规则，避免业务错误
5. 拆垛前确认料垛状态，避免重复拆垛
6. 关注错误详情中的冲突料框信息，快速定位问题
