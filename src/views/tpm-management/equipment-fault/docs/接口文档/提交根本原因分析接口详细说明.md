## 功能概述

### 所有功能

提交根本原因分析（Submit Root Cause Analysis）是设备TPM管理中故障处理流程的关键环节之一，用于对已发生的设备故障进行深入分析，找出根本原因并制定预防措施，以支持持续改进和预防类似故障再次发生的业务场景。

### 关键特性

- ✅ **5Why分析法支持**：支持使用5Why分析法进行逐层深入的根本原因分析
- ✅ **鱼骨图分析**：支持鱼骨图等其他根本原因分析方法的文本记录
- ✅ **预防措施管理**：可以记录针对根本原因制定的预防措施
- ✅ **数据完整性保障**：使用数据库事务确保数据更新的原子性
- ✅ **操作审计追踪**：自动记录操作人员和操作时间，便于审计追踪
- ✅ **灵活性设计**：预防措施为可选字段，支持分阶段完成分析工作

---

### 使用前提

- ✅ 故障记录已存在且状态允许提交根本原因分析
- ✅ 操作人员具有设备故障管理相关权限
- ✅ 故障处理工作基本完成，具备进行根本原因分析的条件
- ✅ 已收集到足够的故障信息和数据用于分析

### 不适用场景

- ❌ 故障记录不存在或已被删除的情况
- ❌ 故障尚未开始处理或处理中，缺乏足够信息的阶段

### 详细步骤说明

#### 步骤1: 接收分析请求
接收客户端提交的根本原因分析请求，包含故障ID和分析内容。

#### 步骤2: 参数格式验证
使用Joi验证器对请求参数进行格式验证：
- failureId必须为有效的UUID格式
- rootCauseAnalysis必须为非空字符串
- preventiveMeasures为可选字符串参数

#### 步骤3: 身份认证和权限校验
验证请求头中的JWT Token有效性，确认操作人员身份和权限。

#### 步骤4: 开启数据库事务
创建数据库事务，确保后续操作的原子性，防止数据不一致。

#### 步骤5: 查询故障记录存在性
在事务中查询指定ID的故障记录是否存在且未被删除，不存在则抛出404错误。

#### 步骤6: 更新根本原因分析和预防措施字段
在事务中更新故障记录的rootCauseAnalysis、preventiveMeasures和updatedBy字段。

#### 步骤7: 提交事务
提交数据库事务，使更新操作生效。如发生异常则回滚事务。

#### 步骤8: 返回更新后的完整故障信息
调用getEquipmentFailureById方法返回包含最新数据的完整故障记录信息。

## 接口文档

### 基本信息

**接口路径**: `POST /v1/mdm/tpm/equipment-failures/{failureId}/root-cause-analysis`

**功能描述**: 提交故障的根本原因分析和预防措施，用于持续改进和预防类似故障再次发生

**认证要求**: Bearer Token认证，需要设备故障管理相关权限

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",

    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }

```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

## 附录

### 故障严重程度等级

| 状态码 | 中文名称 | 说明                     |
| ------ | -------- | ------------------------ |
| 低     | 低等级   | 不影响生产，可计划维修   |
| 中     | 中等级   | 部分影响生产，需及时处理 |
| 高     | 高等级   | 严重影响生产，需紧急处理 |
| 紧急   | 紧急级   | 停产故障，需立即抢修     |

### 故障状态枚举

| 状态码 | 中文名称 | 说明                       |
| ------ | -------- | -------------------------- |
| 待处理 | 待处理   | 故障刚报告，等待开始处理   |
| 处理中 | 处理中   | 正在进行故障修复           |
| 已解决 | 已解决   | 故障已修复，等待验证       |
| 已验证 | 已验证   | 故障修复已验证，可提交分析 |
| 已关闭 | 已关闭   | 故障处理完成，所有流程结束 |

### 状态转换图

```
待处理 --> 处理中 --> 已解决 --> 已验证 --> 已关闭
  |         |         |         |
  ↓         ↓         ↓         ↓
已关闭   已关闭    处理中    处理中
```
