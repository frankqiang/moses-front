## 功能概述

### 所有功能

查询故障列表（Query Equipment Failures）是设备TPM管理-设备故障管理模块中的核心查询接口，用于根据多种条件分页查询设备故障记录，支持故障管理看板、历史记录查询、数据分析等业务场景。

该接口提供灵活的筛选和搜索能力，帮助用户快速定位需要关注的故障记录，支持设备维护人员、管理人员和分析人员从不同维度查看故障数据。返回的数据包含完整的关联信息（设备、报告人、处理人），便于前端直接展示，无需额外查询。

### 关键特性

- ✅ **多维度筛选**：支持按设备、故障等级、故障类型、处理状态、报告人、处理人等多个维度进行组合筛选
- ✅ **时间范围查询**：支持按故障发生时间范围进行筛选，便于时段分析和统计
- ✅ **关键词搜索**：支持在故障编码和故障描述中进行关键词搜索，快速定位特定故障
- ✅ **灵活分页**：支持自定义页码和每页数量，返回完整的分页信息（总页数、总记录数）
- ✅ **自定义排序**：支持按任意字段进行升序或降序排序，默认按故障发生时间倒序
- ✅ **关联数据加载**：自动加载关联的设备信息、报告人信息、处理人信息，减少前端请求次数
- ✅ **重复故障标识**：支持按是否重复故障进行筛选，便于重点关注反复出现的问题
- ✅ **状态组合筛选**：支持同时查询多个状态的故障记录（用逗号分隔），便于工作流管理

---

### 使用前提

- ✅ 用户已通过身份认证，拥有有效的JWT Token
- ✅ 用户具有设备故障查看权限（`mdm.tpm.equipment-failure.view`）
- ✅ 如需查看特定设备的故障，设备必须已在系统中注册
- ✅ 查询参数格式符合验证规则（如日期格式、枚举值等）

### 不适用场景

- ❌ 查询单个故障的完整详情（应使用"查询单个故障详情"接口 GET /v1/mdm/tpm/equipment-failures/{failureId}）
- ❌ 需要故障的完整处理历史和根本原因分析详情（列表接口只返回关键字段，详情需使用详情接口）
- ❌ 需要实时统计分析数据（应使用专门的统计分析接口 GET /v1/mdm/tpm/equipment-failures/statistics）
- ❌ 查询设备的MTTR/MTBF指标（应使用专门的MTTR查询接口 GET /v1/mdm/tpm/equipment-failures/by-equipment/{equipmentId}/mttr）

### 详细步骤说明

#### 步骤1: 接收查询请求
- 接收来自前端的GET请求，包含查询字符串参数
- 解析URL中的所有查询参数（equipmentId、failureLevel、status等）
- 提取分页参数（page、limit）和排序参数（sortBy）

#### 步骤2: 验证用户权限
- 从请求头中提取JWT Token
- 验证Token的有效性（签名、过期时间）
- 检查用户是否具有 `mdm.tpm.equipment-failure.view` 权限
- 如果权限验证失败，返回401或403错误

#### 步骤3: 校验查询参数
- 使用Joi验证器校验所有查询参数的格式和类型
- 验证UUID格式（equipmentId、reporterId、repairerId）
- 验证日期时间格式（startDate、endDate）
- 验证枚举值（failureLevel、failureType、impactDegree）
- 验证分页参数范围（page >= 1, limit >= 1 && limit <= 100）
- 如果验证失败，返回400错误和详细的验证错误信息

#### 步骤4: 构建查询条件
构建Sequelize查询条件对象，按以下规则处理：

**精确匹配条件**：
- equipmentId：精确匹配设备ID
- failureLevel：精确匹配故障等级
- failureType：精确匹配故障类型
- reporterId：精确匹配报告人ID
- repairerId：精确匹配处理人ID
- isRepeatFailure：精确匹配是否重复故障

**状态筛选**：
- 如果status参数存在，按逗号分隔解析为数组
- 使用Sequelize的`Op.in`操作符进行多状态查询
- 示例：status="待处理,处理中" → WHERE status IN ('待处理', '处理中')

**时间范围筛选**：
- 如果startDate存在：WHERE failureTime >= startDate
- 如果endDate存在：WHERE failureTime <= endDate
- 支持单独使用或组合使用

**关键词搜索**：
- 如果search参数存在，使用Sequelize的`Op.or`和`Op.like`
- 在failureCode和failureDescription字段中进行模糊匹配
- 示例：search="电机" → WHERE (failureCode LIKE '%电机%' OR failureDescription LIKE '%电机%')

#### 步骤5: 应用软删除过滤
- 自动添加条件：`isDeleted = false`
- 确保不返回已软删除的故障记录

#### 步骤6: 加载关联数据
使用Sequelize的`include`选项预加载关联数据：

**设备信息（equipment）**：
- 关联模型：Equipment
- 返回字段：id, equipmentCode, equipmentName, equipmentType

**报告人信息（reporter）**：
- 关联模型：User
- 返回字段：id, name, username

**处理人信息（repairer）**：
- 关联模型：User
- 返回字段：id, name, username
- 可为null（待处理状态时）

#### 步骤7: 应用排序规则
- 解析sortBy参数（格式：字段名:排序方向）
- 默认排序：failureTime:desc（故障发生时间倒序）
- 支持的排序字段：failureTime, createdAt, updatedAt, failureLevel等
- 支持的排序方向：asc（升序）、desc（降序）

#### 步骤8: 执行分页查询
- 计算查询偏移量：offset = (page - 1) * limit
- 设置返回数量限制：limit
- 使用Sequelize的`findAndCountAll`方法同时获取数据和总数
- 优化查询性能，避免N+1问题

#### 步骤9: 计算分页元数据
- 总记录数：totalResults = count（从findAndCountAll返回）
- 总页数：totalPages = Math.ceil(totalResults / limit)
- 当前页码：page（来自请求参数）
- 每页数量：limit（来自请求参数）

#### 步骤10: 格式化响应数据
- 将查询结果封装为统一响应格式
- 构建data对象，包含：
  - results：故障记录数组
  - page：当前页码
  - limit：每页数量
  - totalPages：总页数
  - totalResults：总记录数
- 添加成功消息："查询成功"
- 添加meta信息（timestamp、requestId、version）

#### 步骤11: 返回查询结果
- HTTP状态码：200 OK
- 响应体：JSON格式的统一响应结构
- 设置响应头：Content-Type: application/json

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/equipment-failures`

**功能描述**: 根据条件分页查询故障列表，支持按设备、故障等级、故障类型、状态、报告人、处理人、时间范围等多维度筛选，支持关键词搜索。返回的数据包含关联的设备信息、报告人信息和处理人信息，可用于故障管理看板和历史记录查询。

**认证要求**: JWT Bearer Token认证，需要 `mdm.tpm.equipment-failure.view` 权限

**示例1：基础查询（使用默认分页）**

```bash
curl -X GET "http://localhost:3000/v1/mdm/tpm/equipment-failures" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

## 使用示例

### 场景1: 故障管理看板 - 查询待处理和处理中的严重故障

**业务需求**: 在故障管理看板首页显示所有需要紧急关注的故障，即等级为"I级-严重"且状态为"待处理"或"处理中"的故障记录，按故障发生时间倒序显示。

**应用场景**:
- 维护主管登录系统后，看板首页展示需要紧急处理的严重故障
- 实时更新列表，帮助团队快速响应和分配任务
- 点击故障记录可跳转到详情页查看完整信息

### 场景2: 设备故障历史查询 - 查看特定设备的所有故障记录

**业务需求**: 在设备详情页面展示该设备的所有历史故障记录，用于评估设备可靠性和制定维护计划。

**应用场景**:
- 设备管理员查看某台设备的完整故障历史
- 分析故障频率和类型，识别设备的薄弱环节
- 为设备的维护保养计划提供数据支持

### 场景3: 时段故障分析 - 查询指定月份的所有故障

**业务需求**: 生成月度故障报表，统计分析某个月内发生的所有故障，用于管理层汇报和趋势分析。

**应用场景**:
- 每月初生成上个月的故障统计报表
- 按故障等级排序，重点关注严重和重大故障
- 结合其他统计接口分析故障趋势和改进效果

### 场景4: 快速搜索 - 根据关键词查找故障

**业务需求**: 用户在搜索框输入关键词（如"电机"、"异响"等），快速定位相关故障记录。

**应用场景**:
- 用户输入关键词后，前端实时调用接口搜索
- 在故障编码和故障描述中进行模糊匹配
- 快速找到相关故障记录，无需记住完整编码

### 场景5: 重复故障追踪 - 查询特定设备的重复故障

**业务需求**: 质量管理人员需要重点关注重复发生的故障，分析根本原因是否得到解决。

**应用场景**:
- 识别问题解决不彻底的故障
- 重点关注重复故障的根本原因分析和预防措施
- 评估改进措施的有效性

### 场景6: 个人工作任务 - 查询分配给我的待处理故障

**业务需求**: 维护人员登录后查看分配给自己的所有待处理或处理中的故障任务。

**应用场景**:
- 维护人员查看自己的工作任务列表
- 按故障等级排序，优先处理严重故障
- 跟踪自己负责的故障处理进度

## 附录

### 故障等级枚举（failureLevel）

| 故障等级   | 说明                                                 |
| ---------- | ---------------------------------------------------- |
| I级-严重   | 设备完全停机，严重影响生产；存在安全隐患；需立即处理 |
| II级-重大  | 设备功能受损，显著影响生产效率；需在24小时内处理     |
| III级-一般 | 设备部分功能异常，对生产有一定影响；需在48小时内处理 |
| IV级-轻微  | 设备轻微异常，基本不影响生产；可按计划维护处理       |

### 影响程度枚举（impactDegree）

| 影响程度 | 说明                                   |
| -------- | -------------------------------------- |
| 停机     | 设备完全停止运行，无法继续生产         |
| 性能下降 | 设备可以运行但性能降低，生产效率受影响 |
| 无影响   | 故障不影响当前生产，但需要关注和处理   |

### 故障类型枚举（failureType）

| 故障类型 | 说明                                               |
| -------- | -------------------------------------------------- |
| 机械     | 机械部件故障，如轴承磨损、齿轮损坏、传动系统故障等 |
| 电气     | 电气系统故障，如电路故障、电机问题、电源异常等     |
| 液压     | 液压系统故障，如液压油泄漏、压力异常、液压缸故障等 |
| 控制     | 控制系统故障，如PLC故障、传感器异常、软件问题等    |
| 其他     | 其他类型故障，如冷却系统故障、润滑系统故障等       |

### 故障处理状态枚举（status）

| 状态码 | 说明                         |
| ------ | ---------------------------- |
| 待处理 | 故障已报告，等待分配处理人员 |
| 处理中 | 已分配处理人员，正在处理故障 |
| 已解决 | 故障已修复完成，等待验证     |
| 已验证 | 故障处理结果已验证通过       |
| 已关闭 | 故障单已关闭，处理流程完成   |

### 状态转换图

```
待处理 ──────> 处理中 ──────> 已解决 ──────> 已验证 ──────> 已关闭
  │                                                              ▲
  │                                                              │
  └──────────────────────────────────────────────────────────────┘
                    （异常情况下可直接关闭）
```

### 分页和性能优化建议

| 建议项       | 说明                                                     |
| ------------ | -------------------------------------------------------- |
| 默认分页大小 | 建议使用默认的10条/页，适合列表展示                      |
| 最大分页大小 | 不超过100条/页，避免单次查询数据量过大                   |
| 大数据量查询 | 对于历史数据查询，建议结合时间范围缩小查询范围           |
| 排序性能     | failureTime字段已建立索引，按时间排序性能最优            |
| 关联数据加载 | 接口已自动加载设备、报告人、处理人信息，前端无需额外请求 |
| 搜索优化     | 使用search参数进行关键词搜索时，建议至少输入2个字符      |
