# 设备故障管理业务流程说明

## 文档说明

本文档基于设备故障管理模块的实际实现，说明核心业务逻辑和数据管理规则，为前端开发提供业务理解基础。

## 核心概念

### 设备故障定义

**设备故障（EquipmentFailure）**：记录设备故障的完整处理过程，从故障发现、报告、处理、验证到关闭的全生命周期管理，包含故障现象、原因分析、处理措施、MTBF/MTTR统计等详细信息。

### 故障等级

| 等级       | 定义                 | 影响范围             | 处理优先级 |
| ---------- | -------------------- | -------------------- | ---------- |
| I级-严重   | 导致生产停机的故障   | 生产线停止，影响交付 | 最高       |
| II级-重大  | 严重影响生产效率     | 产能下降50%以上      | 高         |
| III级-一般 | 影响生产但可继续运行 | 产能下降50%以下      | 中         |
| IV级-轻微  | 轻微影响或无影响     | 不影响正常生产       | 低         |

### 影响程度

| 影响类型 | 定义               | 设备状态处理       | 生产影响           |
| -------- | ------------------ | ------------------ | ------------------ |
| 停机     | 设备无法运行       | 自动设为维修中状态 | 立即停止生产       |
| 性能下降 | 设备运行但效率降低 | 保持当前状态       | 产能下降           |
| 无影响   | 不影响设备运行     | 保持当前状态       | 正常生产，计划维修 |

### 故障类型

| 类型 | 定义         | 常见问题                      | 处理专业         |
| ---- | ------------ | ----------------------------- | ---------------- |
| 机械 | 机械部件故障 | 轴承磨损、齿轮损坏、传动失效  | 机械维修工程师   |
| 电气 | 电气系统故障 | 电机故障、线路断路、短路      | 电气工程师       |
| 液压 | 液压系统故障 | 油压不足、泄漏、阀门失效      | 液压系统工程师   |
| 控制 | 控制系统故障 | PLC故障、传感器失效、程序错误 | 自动化工程师     |
| 其他 | 其他类型故障 | 环境因素、人为因素等          | 根据具体情况确定 |

### 处理状态

| 状态   | 定义                 | 触发条件           | 允许流转目标状态       |
| ------ | -------------------- | ------------------ | ---------------------- |
| 待处理 | 故障已报告，等待处理 | 故障创建时默认状态 | 处理中、已关闭         |
| 处理中 | 正在处理故障         | 分配处理人员并开始 | 已解决、已关闭         |
| 已解决 | 故障处理完成，待验证 | 处理人员完成处理   | 已验证、处理中、已关闭 |
| 已验证 | 故障处理结果已验证   | 验证人员验证通过   | 已关闭                 |
| 已关闭 | 故障单关闭，流程结束 | 各阶段可关闭       | 无（终态）             |

## 业务流程详解

### 1. 故障报告创建

#### 创建方式
- **人工报告**：现场人员发现故障后手动创建故障报告
- **系统检测**：未来可对接设备监控系统自动创建（预留）

#### 必填信息
- **设备ID**：关联的故障设备，必须是有效设备
- **故障发生时间**：故障实际发生的时间点
- **报告人ID**：发现故障的人员，必须是有效用户
- **故障现象描述**：详细描述故障表现，不能为空
- **故障等级**：I级-严重、II级-重大、III级-一般、IV级-轻微
- **影响程度**：停机、性能下降、无影响
- **故障类型**：机械、电气、液压、控制、其他

#### 可选信息
- **故障编码**：不提供则自动生成（EF-设备编码-时间戳）
- **初步故障原因分析**：报告人的初步判断

#### 自动处理
- **编码生成**：格式 `EF-{设备编码}-{时间戳}`，全局唯一
- **默认状态**：创建后状态为"待处理"
- **设备状态联动**：影响程度为"停机"时，设备状态自动设为"维修中"

### 2. 故障查询

#### 列表查询
- **筛选条件**：
  - 设备ID：查询指定设备的故障记录
  - 故障等级：按等级筛选（I级-严重、II级-重大、III级-一般、IV级-轻微）
  - 故障类型：按类型筛选（机械、电气、液压、控制、其他）
  - 处理状态：按状态筛选，支持多个状态用逗号分隔
  - 报告人ID：按报告人筛选
  - 处理人ID：按处理人筛选
  - 是否重复故障：筛选重复发生的故障
  - 关键词搜索：在故障编码或故障描述中搜索
  - 时间范围：按故障发生时间范围筛选
- **排序**：默认按故障发生时间降序（最新故障在前）
- **分页**：每页10-100条可配置

#### 详情查询
- **包含信息**：
  - 故障基本信息（编码、等级、类型、状态、时间）
  - 关联设备信息（编码、名称、类型、状态）
  - 报告人信息（姓名、邮箱）
  - 处理人信息（姓名、邮箱）
  - 验证人信息（姓名、邮箱）
  - 故障分析（初步原因、详细原因、根本原因分析、预防措施）
  - 处理信息（开始时间、结束时间、处理措施、使用备件）
  - 统计信息（MTTR平均修复时间）
  - 创建人和更新人信息

#### 重复故障查询
- **功能说明**：查询所有标记为重复故障的记录
- **筛选条件**：设备ID、故障类型、时间范围
- **用途**：分析反复出现的故障，制定改进措施

### 3. 故障信息更新

#### 更新权限
- **权限要求**：需要管理权限
- **可更新内容**：除ID外的所有字段均可更新

#### 更新验证
- **设备验证**：更新设备ID时验证设备是否存在
- **人员验证**：更新报告人时验证用户是否存在
- **编码验证**：更新故障编码时验证唯一性

#### 更新时机
- 发现故障信息有误需要修正
- 补充完善故障分析
- 更新故障等级或类型
- 添加初步原因分析

### 4. 故障处理流程

#### 开始处理故障
- **触发条件**：故障状态为"待处理"
- **操作内容**：
  - 分配处理人员（必须是有效用户）
  - 记录处理开始时间（系统自动记录）
  - 更新故障状态为"处理中"
- **设备状态联动**：
  - 影响程度为"停机"时，设备状态设为"维修中"
- **状态流转验证**：只有"待处理"或"已解决"状态可以开始处理

#### 完成故障处理
- **触发条件**：故障状态为"处理中"
- **权限验证**：只有故障处理人员本人才能完成处理
- **必填信息**：
  - 故障处理措施：详细描述处理过程和采取的措施
- **可选信息**：
  - 使用备件清单：记录使用的备件及数量
  - 详细故障原因分析：补充完善故障原因
- **自动处理**：
  - 记录处理完成时间（系统自动记录）
  - 自动计算MTTR（处理完成时间 - 处理开始时间）
  - 更新故障状态为"已解决"

#### 验证故障处理
- **触发条件**：故障状态为"已解决"
- **验证规则**：
  - 验证人员必须是有效用户
  - 验证人员不能是故障处理人员（确保独立验证）
- **操作内容**：
  - 指定验证人员
  - 更新故障状态为"已验证"
- **设备状态恢复**：
  - 影响程度为"停机"时，设备状态恢复为"启用"

#### 关闭故障单
- **允许关闭的状态**：
  - 从"待处理"关闭：强制关闭（记录关闭原因）
  - 从"处理中"关闭：强制关闭（记录关闭原因）
  - 从"已解决"关闭：正常关闭
  - 从"已验证"关闭：正常关闭
- **关闭原因**：
  - 正常关闭：故障已处理并验证完成
  - 强制关闭：需要提供关闭原因（如误报、无需处理等）
- **设备状态确保**：
  - 关闭时确保设备状态已恢复（如果之前设为维修中）

### 5. 根本原因分析

#### 提交时机
- 故障处理完成后，进行深入的根本原因分析

#### 分析内容
- **根本原因分析**：使用5Why分析法或鱼骨图等工具，深入分析故障根本原因
- **预防措施**：根据原因分析，制定预防措施，避免重复发生

#### 分析方法
- **5Why分析法**：连续问"为什么"找出根本原因
- **鱼骨图**：从人、机、料、法、环等方面分析
- **故障树分析**：系统性分析故障发生的各种可能

### 6. MTTR查询

#### 计算方法
- **MTTR定义**：平均修复时间（Mean Time To Repair）
- **计算公式**：MTTR = 处理完成时间 - 处理开始时间（单位：小时）
- **自动计算**：完成故障处理时系统自动计算并保存

#### 查询维度
- **设备维度**：查询指定设备的平均MTTR
- **时间范围**：可指定统计时间段，默认一年
- **结果展示**：
  - 设备信息（ID、编码、名称）
  - MTTR值（小时，保留2位小数）
  - 统计时间段

### 7. 故障统计分析

#### 统计维度
- **按故障等级统计**：各等级故障数量分布
- **按故障类型统计**：各类型故障数量分布
- **按设备统计**：
  - 各设备故障次数
  - 各设备平均MTTR
- **按状态统计**：各处理状态的故障数量
- **重复故障统计**：重复故障数量及占比

#### 筛选条件
- **时间范围**：统计指定时间段的故障数据
- **设备筛选**：统计指定设备的故障情况
- **等级筛选**：统计指定等级的故障数据
- **类型筛选**：统计指定类型的故障数据

#### 统计结果
- **总体数据**：
  - 总故障数
  - 重复故障数
- **按等级分组**：各等级的故障数量
- **按类型分组**：各类型的故障数量
- **按设备分组**：
  - 设备信息（ID、编码、名称）
  - 故障次数
  - 平均MTTR
- **按状态分组**：各状态的故障数量
- **时间范围**：统计的开始和结束日期

### 8. 故障趋势分析

#### 时间粒度
- **日（day）**：按天统计故障趋势
- **周（week）**：按周统计故障趋势
- **月（month）**：按月统计故障趋势（默认）
- **年（year）**：按年统计故障趋势

#### 分析维度
- **故障总数趋势**：各时间段的故障总数变化
- **按等级趋势**：各等级故障数量的时间变化
- **按类型趋势**：各类型故障数量的时间变化

#### 筛选条件
- **时间范围**：分析的起止时间，默认一年
- **设备筛选**：分析指定设备的故障趋势
- **时间粒度**：选择统计粒度（日/周/月/年）

#### 趋势数据
- **时间段标识**：根据粒度生成时间段标识
- **该时间段故障总数**
- **该时间段按等级分布**
- **该时间段按类型分布**

| 字段         | 约束规则                                               |
| ------------ | ------------------------------------------------------ |

| 设备关联     | 设备必须存在且有效，删除时限制（RESTRICT）             |
| 故障发生时间 | 必须是有效日期时间                                     |
| 报告人       | 必须是有效用户，删除时限制（RESTRICT）                 |
| 故障现象描述 | 必填，不能为空，详细描述故障表现                       |
| 故障等级     | 必须是：I级-严重、II级-重大、III级-一般、IV级-轻微之一 |
| 影响程度     | 必须是：停机、性能下降、无影响之一                     |
| 故障类型     | 必须是：机械、电气、液压、控制、其他之一               |
| 处理开始时间 | 可选，开始处理时自动记录                               |
| 处理完成时间 | 可选，完成处理时自动记录                               |
| 处理人员     | 可选，开始处理时指定，必须是有效用户，删除时设为NULL   |
| 验证人员     | 可选，验证时指定，必须是有效用户，删除时设为NULL       |
| 处理状态     | 必须是：待处理、处理中、已解决、已验证、已关闭之一     |
| MTTR         | 自动计算（处理完成时间-处理开始时间），单位小时        |
| 是否重复故障 | 布尔值，默认false                                      |
| 使用备件清单 | JSONB格式，包含备件ID、编码、名称、数量                |

| 当前状态 | 允许流转目标状态       | 说明                 |
| -------- | ---------------------- | -------------------- |

| 已关闭   | 无                     | 终态，不可流转       |

## 权限控制

### 权限设计

| 权限代码                         | 权限说明     | 覆盖操作                                                       |
| -------------------------------- | ------------ | -------------------------------------------------------------- |
| mdm.tpm.equipment-failure.view   | 查看故障记录 | 查询列表、查看详情、查看统计、查看趋势、查询MTTR、查询重复故障 |
| mdm.tpm.equipment-failure.manage | 管理故障记录 | 创建、更新、开始处理、完成处理、验证、关闭、提交根本原因分析   |

### 权限说明

- **view权限**：所有查询类操作，不涉及数据修改
- **manage权限**：创建和修改故障记录，处理故障的全流程操作

### 特殊权限控制

- **完成处理验证**：只有故障处理人员本人才能完成处理
- **验证独立性**：验证人员不能是故障处理人员

## 核心业务规则

1. **故障记录软删除**：故障记录是历史档案，不允许物理删除，只能软删除标记
2. **编码唯一性**：故障编码全局唯一，系统自动生成或手动指定需验证
3. **状态流转验证**：状态变更必须符合流转规则，非法流转将被拒绝
4. **设备状态联动**：
   - 影响程度为"停机"时，开始处理自动将设备状态设为"维修中"
   - 验证通过或关闭时，设备状态恢复为"启用"
5. **处理人权限**：只有故障处理人员才能完成处理
6. **验证独立性**：验证人员不能是处理人员，确保验证的独立性
7. **MTTR自动计算**：完成处理时自动计算MTTR并保存
8. **关联验证**：创建和更新时验证设备、人员的有效性
9. **数据完整性**：必填字段验证，故障描述、处理措施不能为空
10. **事务保护**：创建和更新操作使用数据库事务确保数据一致性
11. **审计追踪**：记录创建人、更新人、创建时间、更新时间

## 典型业务场景

### 场景1：设备停机故障快速处理

1. **故障发现**：
   - 现场操作员发现设备突然停机
   - 创建故障报告：
     - 设备：选择故障设备
     - 故障时间：记录停机时间点
     - 报告人：当前操作员
     - 故障描述："设备主轴突然停转，伴有异响"
     - 故障等级：I级-严重
     - 影响程度：停机
     - 故障类型：机械
     - 初步原因："疑似主轴轴承损坏"

2. **系统自动处理**：
   - 生成故障编码：EF-EQ-001-1704038400000
   - 故障状态：待处理
   - 设备状态：自动设为"维修中"

3. **开始处理**：
   - 维修主管分配维修工程师
   - 记录处理开始时间
   - 状态变更为"处理中"

4. **完成处理**：
   - 维修工程师完成维修
   - 填写处理措施："拆解主轴，更换轴承，添加润滑油，试运行正常"
   - 记录使用备件：轴承 × 2、润滑油 × 3L
   - 详细原因分析："轴承使用时间过长，润滑不足导致磨损严重"
   - 系统自动计算MTTR：2.5小时
   - 状态变更为"已解决"

5. **验证处理**：
   - 质量工程师现场验证
   - 确认设备运行正常
   - 状态变更为"已验证"
   - 设备状态恢复为"启用"

6. **关闭故障单**：
   - 故障单正常关闭
   - 设备恢复生产

### 场景2：设备性能下降持续改进

1. **故障报告**：
   - 发现设备运行速度下降20%
   - 创建故障报告：
     - 故障等级：III级-一般
     - 影响程度：性能下降
     - 故障类型：电气

2. **处理流程**：
   - 分配电气工程师处理
   - 完成处理：清洁电机，调整参数
   - 验证通过

3. **根本原因分析**：
   - 使用5Why分析法：
     - Why1：为什么速度下降？电机转速不足
     - Why2：为什么转速不足？电机负载过大
     - Why3：为什么负载过大？传动系统阻力增加
     - Why4：为什么阻力增加？润滑不足
     - Why5：为什么润滑不足？润滑周期设置不合理
   - 根本原因：润滑周期设置不合理
   - 预防措施：
     - 缩短润滑周期从30天到15天
     - 增加定期润滑检查
     - 更新维护保养计划

4. **后续跟踪**：
   - 如再次发生相同故障，标记为重复故障
   - 重新评估预防措施有效性

### 场景3：故障统计分析与改进

     - III级-一般：20条（44.4%）
     - IV级-轻微：8条（17.8%）

### 场景4：重复故障专项治理

1. **发现重复故障**：
   - 查询重复故障列表
   - 发现某设备液压系统泄漏故障重复发生3次

2. **根本原因分析**：
   - 调取历史故障记录
   - 分析每次处理措施
   - 发现处理只是临时修复，未找到根本原因

3. **深入分析**：
   - 使用鱼骨图分析法
   - 从人、机、料、法、环全面分析
   - 找到根本原因：密封件材质不适合高温环境

4. **制定改进方案**：
   - 更换耐高温密封件
   - 增加散热措施
   - 调整工作参数
   - 更新维护规范

5. **效果跟踪**：
   - 实施改进后持续跟踪
   - 后续无重复故障发生
   - 故障单正常关闭

### 场景5：设备MTTR分析与优化

1. **季度MTTR评估**：
   - 查询各设备的季度MTTR
   - 发现某设备MTTR高达5.2小时，远高于平均水平

2. **原因分析**：
   - 调取该设备的故障记录
   - 分析处理时间分布
   - 发现主要问题：
     - 备件准备时间长
     - 缺少专业维修人员
     - 维修流程不规范

3. **优化措施**：
   - 建立常用备件库存
   - 培训专业维修人员
   - 优化维修流程
   - 准备维修工具包

4. **效果验证**：
   - 实施优化后持续监控
   - MTTR下降到2.8小时
   - 达到行业平均水平
