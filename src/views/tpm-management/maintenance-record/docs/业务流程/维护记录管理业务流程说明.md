# 维护记录管理业务流程说明

## 文档说明

本文档基于维护记录管理模块的实际实现，说明核心业务逻辑和数据管理规则，为前端开发提供业务理解基础。

## 核心概念

### 维护记录定义

**维护记录（MaintenanceRecord）**：记录设备维护保养的完整过程和结果，形成设备健康档案，包含维护内容、发现问题、处理措施、使用备件、工时等详细信息。

### 记录来源

| 来源方式 | 定义                       | 触发方式             | 特点                     |
| -------- | -------------------------- | -------------------- | ------------------------ |
| 任务生成 | 维护任务完成时自动生成记录 | 完成任务操作自动触发 | 关联任务ID，数据自动填充 |
| 手工创建 | 独立创建的维护记录         | 管理人员手动录入     | 无关联任务，记录历史维护 |
| 补录历史 | 补充录入设备历史维护信息   | 管理人员手动录入     | 完善设备维护履历         |

### 维护类型

| 类型     | 定义                     | 适用场景                       | 特点                 |
| -------- | ------------------------ | ------------------------------ | -------------------- |
| 日常保养 | 设备日常清洁、润滑等保养 | 每日或每周例行维护             | 频率高，工作量小     |
| 定期检查 | 按计划进行的设备检查     | 月检、季检、年检               | 周期性，全面检查     |
| 大修     | 设备全面拆解检修         | 设备运行一定时间后进行大修     | 工作量大，停机时间长 |
| 专项维护 | 针对特定部件的专项维护   | 发现特定问题或执行专项改造任务 | 目标明确，针对性强   |

## 业务流程详解

### 1. 记录创建

#### 自动生成（任务完成）
- **触发方式**：维护任务完成时系统自动创建
- **自动填充**：记录编码（MR-任务编码-时间戳）、任务ID、设备ID、维护类型、执行人员、维护内容等
- **数据来源**：任务完成时填写的维护详情
- **优势**：数据完整，与任务关联，可追溯

#### 手工创建
- **触发方式**：管理员或维护人员通过界面录入
- **必填信息**：设备ID、维护日期时间、维护类型、维护内容、执行人员ID
- **可选信息**：
  - 记录编码（自动生成：MR-设备编码-时间戳）
  - 关联任务ID
  - 发现问题描述
  - 处理措施
  - 使用备件清单
  - 维护工时
  - 确认人员ID
  - 维护前后设备状态
  - 下次维护建议
- **用途**：补录历史记录、记录非计划维护

### 2. 记录查询

#### 列表查询
- **筛选条件**：
  - 设备ID：查询指定设备的维护记录
  - 任务ID：查询关联维护任务的记录
  - 维护类型：按日常保养、定期检查、大修、专项维护筛选
  - 执行人ID：按执行人员筛选
  - 关键词搜索：在记录编码或维护内容中搜索
  - 时间范围：按维护日期范围筛选
- **排序**：默认按维护日期降序（最新记录在前）
- **分页**：每页10-100条可配置

#### 详情查询
- **包含信息**：
  - 记录基本信息（编码、类型、日期、内容）
  - 关联设备信息（编码、名称、类型、状态）
  - 关联任务信息（任务编码、标题、类型）
  - 执行人员信息（姓名、邮箱）
  - 确认人员信息（姓名、邮箱）
  - 创建人和更新人信息
- **用途**：查看完整的维护记录详情

#### 设备维护履历
- **功能说明**：查询指定设备的完整维护历史
- **数据包含**：设备基本信息 + 维护记录列表
- **排序**：按维护日期降序（最近维护在前）
- **用途**：设备健康档案、维护历史追溯、故障分析参考

### 3. 记录更新

#### 更新条件
- **权限要求**：需要管理权限
- **可更新内容**：除ID外的所有字段均可更新
- **更新时机**：
  - 发现记录信息有误需要修正
  - 补充完善维护详情
  - 更新设备状态信息
  - 添加维护建议

#### 更新验证
- **设备验证**：更新设备ID时验证设备是否存在
- **人员验证**：更新执行人员或确认人员时验证用户是否存在
- **编码验证**：更新记录编码时验证唯一性
- **任务验证**：更新任务ID时验证任务是否存在

### 4. 附件管理

#### 附件上传
- **支持格式**：照片、PDF报告、Excel数据等
- **附件信息**：URL、文件名、文件类型
- **存储方式**：JSONB数组格式存储
- **操作方式**：批量上传，追加到现有附件列表
- **用途**：保存维护现场照片、检测报告、数据记录等

#### 附件查询
- **返回内容**：记录基本信息 + 附件列表
- **附件信息**：URL、文件名、文件类型
- **用途**：查看维护过程的图片和文档资料

#### 附件删除
- **删除方式**：根据附件在数组中的索引删除
- **验证**：验证索引有效性
- **操作结果**：从附件列表中移除指定附件

### 5. 统计分析

#### 统计维度
- **按维护类型统计**：各类型维护记录数量分布
- **按设备统计**：各设备维护次数和工时统计
- **工时统计**：总维护工时、平均工时
- **问题统计**：发现问题的记录数量占比

#### 筛选条件
- **时间范围**：统计指定时间段的维护数据
- **设备筛选**：统计指定设备的维护情况
- **类型筛选**：统计指定类型的维护数据

#### 统计结果
- **总体数据**：
  - 总记录数
  - 总工时
  - 发现问题的记录数
- **按类型分组**：各维护类型的记录数量
- **按设备分组**：
  - 设备信息（ID、编码、名称）
  - 维护次数
  - 总工时
- **时间范围**：统计的开始和结束日期

## 数据约束规则

### 记录约束

| 字段     | 约束规则                                           |
| -------- | -------------------------------------------------- |
| 记录编码 | 自动生成（MR-设备编码-时间戳）或用户指定（需唯一） |
| 设备关联 | 设备必须存在且有效，删除时限制（RESTRICT）         |
| 维护日期 | 必须是有效日期时间                                 |
| 维护类型 | 必须是：日常保养、定期检查、大修、专项维护之一     |
| 维护内容 | 必填，不能为空，记录详细维护过程                   |
| 执行人员 | 必须是有效用户，删除时限制（RESTRICT）             |
| 确认人员 | 可选，如提供必须是有效用户                         |
| 任务关联 | 可选，如提供必须是有效任务，任务删除时设为NULL     |
| 维护工时 | 可选，如提供必须≥0                                 |
| 备件清单 | JSONB格式，包含备件ID、编码、名称、数量            |
| 附件列表 | JSONB格式，包含URL、文件名、文件类型               |

### 编码生成规则

- **格式**：`MR-{设备编码}-{时间戳}`
- **示例**：`MR-EQ-001-1704038400000`
- **唯一性**：系统自动保证唯一性，手动指定需验证

### 关联关系约束

| 关联表            | 外键字段    | 删除策略 | 更新策略 | 说明                       |
| ----------------- | ----------- | -------- | -------- | -------------------------- |
| equipments        | equipmentId | RESTRICT | CASCADE  | 设备不能删除（有维护记录） |
| maintenance_tasks | taskId      | SET NULL | CASCADE  | 任务删除时记录保留         |
| users             | executorId  | RESTRICT | CASCADE  | 执行人不能删除             |
| users             | confirmerId | SET NULL | CASCADE  | 确认人删除时设为NULL       |
| users             | createdBy   | SET NULL | CASCADE  | 创建人删除时设为NULL       |
| users             | updatedBy   | SET NULL | CASCADE  | 更新人删除时设为NULL       |

## 权限控制

### 权限设计

| 权限代码                          | 权限说明     | 覆盖操作                                     |
| --------------------------------- | ------------ | -------------------------------------------- |
| mdm.tpm.maintenance-record.view   | 查看维护记录 | 查询列表、查看详情、查看履历、查看统计、导出 |
| mdm.tpm.maintenance-record.manage | 管理维护记录 | 创建、更新、附件管理                         |

### 权限说明

- **view权限**：所有查询类操作，不涉及数据修改
- **manage权限**：创建和修改维护记录，包括附件的上传和删除

## 核心业务规则

1. **记录不可删除**：维护记录是历史档案，不允许删除，只能软删除标记
2. **编码唯一性**：记录编码全局唯一，系统自动生成或手动指定需验证
3. **关联验证**：创建和更新时验证设备、任务、人员的有效性
4. **工时非负**：维护工时必须≥0
5. **数据完整性**：必填字段验证，维护内容不能为空
6. **附件管理**：附件采用追加方式，删除不影响其他附件
7. **事务保护**：创建和更新操作使用数据库事务确保数据一致性
8. **审计追踪**：记录创建人、更新人、创建时间、更新时间

## 模块集成关系

| 关联模块   | 集成方式                               | 说明                       |
| ---------- | -------------------------------------- | -------------------------- |
| 设备主数据 | 必须关联有效设备，维护记录形成设备档案 | 设备健康管理、维护历史追溯 |
| 维护任务   | 任务完成时自动生成记录，可选关联       | 任务执行结果的记录和归档   |
| 用户管理   | 关联执行人员和确认人员                 | 责任人追溯、工作量统计     |
| 备件管理   | 记录使用的备件清单                     | 成本统计、库存消耗跟踪     |
| 文件存储   | 存储维护过程的照片和文档               | 现场证据、检测报告存档     |

## 典型业务场景

### 场景1：任务完成自动生成记录
1. 维护人员执行维护任务
2. 完成任务时填写维护详情：
   - 维护内容：更换轴承、添加润滑油
   - 发现问题：轴承磨损严重，有异响
   - 处理措施：更换新轴承，添加高温润滑油
   - 使用备件：轴承 × 2、润滑油 × 5L
   - 维护工时：2.5小时
3. 系统自动创建维护记录并关联任务
4. 记录归入设备维护履历

### 场景2：手工补录历史维护
1. 设备从其他工厂转入，需补录历史维护信息
2. 管理员创建维护记录：
   - 设备：选择已导入的设备
   - 维护日期：2024-01-15（历史日期）
   - 维护类型：定期检查
   - 维护内容：年度大检，各项指标正常
   - 执行人员：选择当时的维护人员
3. 上传历史维护报告作为附件
4. 完善设备维护履历

### 场景3：设备维护履历查询
1. 设备出现故障，需要查看历史维护情况
2. 维修人员查询设备维护履历：
   - 选择故障设备
   - 查看按时间排序的维护记录
   - 重点查看最近3次维护：
     - 维护内容
     - 发现的问题
     - 处理措施
     - 使用备件
3. 根据历史记录分析故障原因
4. 制定维修方案

### 场景4：维护统计分析
1. 月度设备管理会议，需要维护数据统计
2. 设备管理员生成统计报告：
   - 时间范围：2024年第一季度
   - 统计结果显示：
     - 总维护记录：156条
     - 总工时：312.5小时
     - 按类型分布：日常保养65%、定期检查20%、大修10%、专项维护5%
     - 发现问题的记录：38条（24%）
     - 按设备排名：工时最高的前5台设备
3. 根据统计分析制定下季度维护计划

### 场景5：维护记录附件管理
1. 维护人员完成设备大修
2. 上传维护记录附件：
   - 维护前设备照片（3张）
   - 维护过程照片（5张）
   - 维护后设备照片（3张）
   - 检测报告PDF（1个）
3. 质量部门查看附件进行审核
4. 发现部分照片不清晰，维护人员删除后重新上传

## 接口使用建议

### 核心接口

| 接口类型 | 接口路径                                                        | 说明                           |
| -------- | --------------------------------------------------------------- | ------------------------------ |
| 创建     | `POST /v1/mdm/tpm/maintenance-records`                          | 创建维护记录                   |
| 查询列表 | `GET /v1/mdm/tpm/maintenance-records`                           | 分页查询记录列表，支持多种筛选 |
| 查询详情 | `GET /v1/mdm/tpm/maintenance-records/:recordId`                 | 获取记录完整信息和关联数据     |
| 更新     | `PATCH /v1/mdm/tpm/maintenance-records/:recordId`               | 更新维护记录信息               |
| 设备履历 | `GET /v1/mdm/tpm/maintenance-records/by-equipment/:equipmentId` | 查询设备维护履历               |
| 统计分析 | `GET /v1/mdm/tpm/maintenance-records/statistics`                | 维护记录统计分析               |

### 附件管理接口

| 接口名称 | 接口路径                                                                     | 说明             |
| -------- | ---------------------------------------------------------------------------- | ---------------- |
| 上传附件 | `POST /v1/mdm/tpm/maintenance-records/:recordId/attachments`                 | 上传维护记录附件 |
| 查询附件 | `GET /v1/mdm/tpm/maintenance-records/:recordId/attachments`                  | 查询附件列表     |
| 删除附件 | `DELETE /v1/mdm/tpm/maintenance-records/:recordId/attachments/:attachmentId` | 删除指定附件     |

### 常见错误码

| 错误码                 | 说明               | 处理建议             |
| ---------------------- | ------------------ | -------------------- |
| MAINTENANCE_RECORD_001 | 维护记录编码已存在 | 使用自动生成的编码   |
| MAINTENANCE_RECORD_002 | 维护记录不存在     | 检查记录ID           |
| MAINTENANCE_RECORD_003 | 附件不存在         | 检查附件索引         |
| EQUIPMENT_001          | 设备不存在         | 检查设备ID           |
| MAINTENANCE_TASK_002   | 维护任务不存在     | 检查任务ID           |
| USER_001               | 用户不存在         | 检查执行人或确认人ID |
| VALIDATION_ERROR       | 参数验证失败       | 检查请求参数         |

### 前端展示建议

#### 维护类型标签颜色映射
- 日常保养：蓝色（default）
- 定期检查：绿色（success）
- 大修：橙色（warning）
- 专项维护：紫色（processing）

#### 列表显示字段建议
- 记录编码
- 设备名称
- 维护类型
- 维护日期
- 执行人员
- 维护工时
- 是否发现问题（图标标识）
- 关联任务（如有）
- 操作按钮

#### 详情页建议布局
1. **基本信息区**：记录编码、维护类型、维护日期、执行人员、确认人员
2. **设备信息区**：设备编码、设备名称、设备类型、设备状态
3. **维护内容区**：维护内容详情、发现问题、处理措施、下次建议
4. **资源使用区**：使用备件清单、维护工时、成本统计
5. **状态对比区**：维护前设备状态、维护后设备状态
6. **附件区**：维护照片、检测报告、相关文档
7. **关联信息区**：关联维护任务（如有）
8. **审计信息区**：创建人、创建时间、更新人、更新时间

#### 统计图表建议
- **饼图**：维护类型分布
- **柱状图**：按设备统计维护次数
- **折线图**：维护工时趋势
- **表格**：按设备分组的详细统计
