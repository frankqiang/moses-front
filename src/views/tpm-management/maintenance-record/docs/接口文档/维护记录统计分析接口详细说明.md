## 功能概述

### 所有功能

维护记录统计分析（Maintenance Record Statistics）是设备TPM管理中的数据分析功能，用于对维护保养记录进行多维度统计分析，为设备维护决策提供数据支持，支持设备健康状态评估、维护计划优化、成本控制等业务场景。

### 关键特性

- ✅ **多维度统计**：支持按维护类型、设备、时间等多个维度进行数据统计和分组分析
- ✅ **工时统计**：自动汇总维护工时数据，支持按设备分组统计总工时和平均工时
- ✅ **问题跟踪**：统计发现问题的维护记录数量，识别设备高频故障和维护趋势
- ✅ **灵活筛选**：支持时间范围、设备ID、维护类型等多种条件组合筛选统计数据
- ✅ **设备排名**：按设备统计维护次数和工时，帮助识别高维护成本设备
- ✅ **实时计算**：基于实际维护记录数据实时统计，确保数据准确性和时效性

---

### 使用前提

- ✅ 系统中已存在维护记录数据
- ✅ 用户已通过认证并具有查看维护记录的权限
- ✅ 相关设备信息完整且关联关系正确
- ✅ 筛选条件（如设备ID、维护类型）合法有效

### 不适用场景

- ❌ 需要查询维护记录详细信息时（应使用查询维护记录列表接口）
- ❌ 需要进行复杂的预测性分析或趋势预测时（统计接口仅提供基础统计数据）
- ❌ 数据量极大且需要导出完整报表时（建议使用专门的报表导出功能）

### 详细步骤说明

#### 步骤1: 接收统计请求
系统接收客户端发送的统计分析请求，提取查询参数包括：
- `startDate`: 统计开始日期（可选）
- `endDate`: 统计结束日期（可选）
- `equipmentId`: 设备ID筛选（可选）
- `maintenanceType`: 维护类型筛选（可选）

#### 步骤2: 验证筛选参数
使用Joi验证器对请求参数进行验证：
- **日期格式校验**：确保startDate和endDate符合ISO 8601日期格式
- **日期逻辑校验**：验证endDate不早于startDate
- **UUID格式校验**：验证equipmentId为有效的UUID格式
- **枚举值校验**：验证maintenanceType为系统支持的维护类型（日常保养、定期检查、大修、专项维护）

#### 步骤3: 构建查询条件
根据验证通过的参数构建数据库查询条件：
```javascript
whereClause = {
  isDeleted: false,  // 排除已删除记录
  // 条件性添加以下过滤条件
  equipmentId: equipmentId,  // 如果提供
  maintenanceType: maintenanceType,  // 如果提供
  maintenanceDate: {
    [Op.gte]: startDate,  // 如果提供
    [Op.lte]: endDate     // 如果提供
  }
}
```

#### 步骤4: 查询维护记录数据
执行数据库查询获取符合条件的所有维护记录：
- 关联查询设备信息（equipmentCode、name）
- 获取维护工时数据（workHours字段）
- 获取问题描述数据（problemFound字段）
- 获取维护类型（maintenanceType字段）

#### 步骤5: 多维度统计计算
对查询结果进行多维度统计分析：

**5.1 总记录数统计**
```javascript
totalRecords = records.length
```

**5.2 按维护类型分组统计**
```javascript
byType = {
  "日常保养": count,
  "定期检查": count,
  "大修": count,
  "专项维护": count
}
```

**5.3 按设备分组统计**
```javascript
byEquipment = [{
  equipmentId: "设备ID",
  equipmentCode: "设备编码",
  equipmentName: "设备名称",
  count: 维护次数,
  totalWorkHours: 总工时
}]
```

**5.4 总工时汇总**
```javascript
totalWorkHours = sum(records.workHours)
```

**5.5 问题记录统计**
```javascript
recordsWithProblems = count(records where problemFound is not empty)
```

#### 步骤6: 数据格式化处理
对统计结果进行格式化：
- **数值精度处理**：工时数据保留2位小数
- **对象结构转换**：将Map/Object转换为数组格式（byEquipment）
- **空值处理**：确保所有字段都有合理的默认值

#### 步骤7: 返回统计结果
封装统计数据并返回：
```javascript
{
  totalRecords: 总记录数,
  totalWorkHours: 总工时,
  recordsWithProblems: 问题记录数,
  byType: 按类型统计,
  byEquipment: 按设备统计,
  dateRange: 时间范围
}
```

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/maintenance-records/statistics`

**功能描述**: 对维护保养记录进行统计分析，返回多维度统计数据，包括总记录数、总工时、问题记录数、按维护类型统计、按设备统计等，支持时间范围和条件筛选。

**认证要求**: Bearer Token认证，需要具有查看维护记录的权限

```json
  "success": false,

    "code": "ERROR_CODE",

    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }

```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号


**请求头**:

```
Authorization: Bearer <access_token>

```

### 查询参数

| 参数名          | 类型   | 必填 | 限制                | 描述                                         | 默认值 | 示例                         |
| --------------- | ------ | ---- | ------------------- | -------------------------------------------- | ------ | ---------------------------- |
| startDate       | string | 否   | ISO 8601日期格式    | 统计开始日期，筛选维护日期在此时间之后的记录 | null   | "2024-01-01T00:00:00.000Z"   |
| endDate         | string | 否   | ISO 8601日期格式    | 统计结束日期，筛选维护日期在此时间之前的记录 | null   | "2024-01-31T23:59:59.999Z"   |
| equipmentId     | string | 否   | UUID格式            | 设备ID，筛选指定设备的维护记录统计           | null   | "550e8400-e29b-41d4-a716..." |
| maintenanceType | string | 否   | 见附录-维护类型枚举 | 维护类型，筛选指定类型的维护记录统计         | null   | "日常保养"                   |

**查询参数说明**：
- 所有查询参数均为可选，不提供任何参数时统计所有未删除的维护记录
- `startDate` 和 `endDate` 可以单独使用或组合使用
- `endDate` 必须大于或等于 `startDate`
- 多个筛选条件之间为"与"关系（AND逻辑）

## 常见问题

### Q1: 统计结果为空（totalRecords为0）怎么办？

**可能原因**：
1. 筛选条件过于严格，没有匹配的维护记录
2. 时间范围内确实没有维护记录
3. 指定的设备ID或维护类型不存在相关记录

**解决方案**：
- 检查筛选条件是否正确
- 放宽时间范围重新查询
- 先使用查询维护记录列表接口确认是否有数据
- 去除部分筛选条件，逐步缩小范围定位问题

---

### Q2: byEquipment数组中设备名称显示"未知设备"？

**可能原因**：
1. 维护记录关联的设备已被删除
2. 设备信息不完整
3. 数据库关联关系异常

**解决方案**：
- 检查设备基础数据是否完整
- 使用设备管理接口验证设备是否存在
- 联系技术支持修复数据关联关系

---

### Q3: totalWorkHours统计结果与预期不符？

**可能原因**：
1. 部分维护记录未填写工时（workHours为null或0）
2. 工时数据录入错误
3. 筛选条件导致部分记录未被统计

**解决方案**：
- 检查维护记录是否完整填写工时信息
- 使用查询维护记录列表接口验证工时数据
- 确保所有维护记录都规范填写工时字段

---

### Q4: 如何统计特定时间段内某个设备的维护频率？

**解决方案**：
使用组合筛选条件：
```bash
GET /v1/mdm/tpm/maintenance-records/statistics?equipmentId={设备ID}&startDate={开始时间}&endDate={结束时间}
```
响应中的`totalRecords`即为该设备在指定时间段的维护次数

---

### Q5: byType统计中缺少某些维护类型？

**这是正常现象**：
- byType对象仅包含有实际记录的维护类型
- 如果某个维护类型在筛选范围内没有记录，则不会出现在统计结果中
- 这种设计避免了无意义的零值数据

---

### Q6: 如何导出统计数据为Excel报表？

**当前接口不直接支持导出功能**，建议：
1. 前端接收JSON响应后使用JS库（如SheetJS）导出Excel
2. 或调用专门的报表导出接口（如果系统提供）
3. 或使用BI工具连接数据库直接生成报表

---

### Q7: 统计数据的实时性如何保证？

**实时性说明**：
- 统计数据基于实际维护记录实时计算，不使用缓存
- 数据准确性完全取决于维护记录的录入时效
- 建议在维护完成后及时录入记录以确保统计准确
