## 功能概述

### 所有功能

查询维护记录附件列表（Get Maintenance Record Attachments）是设备TPM管理中的查询辅助功能，用于获取指定维护记录的所有附件信息（包括现场照片、维护报告、检测数据等），以支持维护记录的可视化展示、证据查阅和归档追溯的业务场景。该接口返回维护记录的基本信息和完整的附件列表，帮助用户快速定位和访问维护过程中的相关文件。

### 关键特性

- ✅ **快速查询**：通过维护记录ID快速获取所有附件信息
- ✅ **精简响应**：只返回记录ID、记录编码和附件列表，避免不必要的数据传输
- ✅ **完整信息**：每个附件包含URL、文件名和文件类型完整信息
- ✅ **无权限限制**：仅需JWT认证即可查询，无需特殊权限
- ✅ **空列表友好**：记录存在但无附件时返回空数组，不会报错
- ✅ **高效查询**：仅查询必要字段，减少数据库负载

---

### 使用前提

- ✅ 用户已通过JWT认证，持有有效的Bearer Token
- ✅ 维护记录必须已在系统中存在且未被删除
- ✅ 提供正确的维护记录ID（UUID格式）

### 不适用场景

- ❌ 维护记录不存在或已被删除 - 接口将返回404错误
- ❌ 需要下载附件文件 - 该接口仅返回附件信息，不提供文件下载功能
- ❌ 需要查询多个维护记录的附件 - 接口仅支持单个记录查询

### 详细步骤说明

#### 步骤1: 接收查询请求
- **触发条件**：前端或客户端发送GET请求到接口
- **输入参数**：URL路径参数中的recordId
- **初始化**：从请求头中提取JWT Token，验证用户身份

#### 步骤2: 参数验证
**验证规则**：
- `recordId` 必须存在
- `recordId` 必须是有效的UUID v4格式
- 如果验证失败，返回400错误

**验证内容**：
```javascript
// 使用Joi验证器进行参数校验
{
  params: Joi.object().keys({
    recordId: Joi.string().uuid().required()
  })
}
```

#### 步骤3: 查询维护记录
**查询条件**：
- 按recordId精确查询
- 仅查询未删除的记录（isDeleted: false）
- 仅查询必要字段：id、recordCode、attachmentUrls

**SQL查询示例**：
```sql
SELECT id, record_code, attachment_urls
FROM maintenance_records
WHERE id = :recordId AND is_deleted = false
LIMIT 1;
```

**性能优化**：
- 使用字段过滤减少数据传输量
- 利用主键索引提高查询效率

#### 步骤4: 记录存在性判断
**判断逻辑**：
- 如果查询结果为null或undefined
- 抛出ApiError异常，HTTP状态码404
- 错误码：MAINTENANCE_RECORD_002
- 错误消息："维护记录不存在"

#### 步骤5: 提取附件信息
**数据提取**：
- 从查询结果中提取id字段作为recordId
- 提取recordCode字段作为记录编码
- 提取attachmentUrls字段作为附件数组
- 如果attachmentUrls为null或空，使用空数组[]

**字段处理**：
```javascript
{
  recordId: record.id,
  recordCode: record.recordCode,
  attachments: record.attachmentUrls || []
}
```

#### 步骤6: 格式化响应数据
**响应结构**：
- recordId：维护记录的唯一标识
- recordCode：维护记录的业务编码
- attachments：附件数组，每个元素包含：
  - url：附件文件的访问URL
  - fileName：原始文件名
  - fileType：文件类型/MIME类型

#### 步骤7: 返回成功响应
**响应格式**：
- HTTP状态码：200
- 使用统一响应格式包装数据
- 包含success、data、message、meta等标准字段
- 记录操作日志

**日志记录内容**：
- 操作类型：查询维护记录附件
- 记录ID
- 操作人ID
- 操作时间

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/maintenance-records/:recordId/attachments`

**功能描述**: 查询指定维护记录的所有附件信息，返回包含附件URL、文件名和文件类型的完整列表。

**认证要求**: JWT Bearer Token认证，无需特殊权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

## 常见问题

### Q1: 接口返回的attachments数组为空，是什么原因？

**A**: 有以下几种可能：
1. ✅ **正常情况**：该维护记录确实没有上传过任何附件
2. ✅ **附件已删除**：之前上传的附件已通过删除接口全部删除
3. ✅ **数据迁移**：历史数据中attachmentUrls字段为null

**解决方案**：
- 确认是否需要上传附件，使用POST接口上传
- 检查是否有删除操作记录
- 空数组是正常响应，不需要特殊处理

**A**: 通过`fileType`字段判断：

### Q3: attachments数组中的顺序是什么？

**A**: 附件按照上传时间的顺序排列：
- 最早上传的附件在数组开头（索引0）
- 最新上传的附件在数组末尾
- 这个顺序在删除附件时会影响attachmentId的计算

### Q4: 接口返回404错误，但我确定记录ID是对的？

**A**: 可能的原因：
1. 记录已被软删除（isDeleted = true）
2. 记录ID格式错误（不是UUID格式）
3. 数据库连接问题

**排查步骤**：
```bash
# 1. 验证UUID格式
node -e "console.log(/^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i.test('your-record-id'))"

# 2. 检查数据库记录
psql -d moses_db -c "SELECT id, record_code, is_deleted FROM maintenance_records WHERE id = 'your-record-id';"
```

### Q6: 接口性能如何？查询1000个附件会慢吗？

**A**: 性能特点：
- ✅ 查询速度快：只查询3个字段，使用主键索引
- ✅ 网络传输：attachments是JSONB字段，一次性返回
- ⚠️ 大量附件：如果单个记录有100+附件，响应体会较大

**优化建议**：
- 前端实现虚拟滚动，不一次渲染所有附件
- 图片使用缩略图，点击后加载原图
- 考虑对附件列表进行分页（需要后端支持）

### Q7: 能否同时查询多个维护记录的附件？

**A**: 当前接口不支持批量查询，需要多次调用。

### Q8: 附件URL失效了怎么办？

**A**: 可能的原因和解决方案：
1. **存储服务URL已变更**：需要批量更新attachmentUrls字段
2. **临时URL过期**：如果使用OSS临时URL，需要重新生成
3. **文件已删除**：需要重新上传或从备份恢复
