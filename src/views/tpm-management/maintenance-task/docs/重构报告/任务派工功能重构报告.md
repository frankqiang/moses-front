## 📝 重构内容

### 1. AssignTaskDialog 组件重构

#### 1.1 移除不符合接口文档的字段

**问题**: 原实现包含 `remark`（派工备注）字段，但接口文档中不支持此参数

**修改**:
- ✅ 移除表单中的"派工备注"输入框
- ✅ 移除 `formData.remark` 字段
- ✅ 更新 `resetForm` 方法，移除 remark 字段重置

**接口文档参考**:
```json
// POST /v1/mdm/tpm/maintenance-tasks/:taskId/assign
// 请求参数
{
  "assignedTo": "c3d4e5f6-a7b8-9012-cdef-123456789012"  // 仅此一个参数
}
```

#### 1.2 优化人员选择器实现

**问题**: 原实现使用远程搜索功能，但接口文档中人员筛选接口不支持关键词搜索

**修改**:
- ✅ 移除 `remote` 和 `remote-method` 属性
- ✅ 移除 `searchPersonnel` 方法
- ✅ 移除 `handlePersonnelFocus` 方法
- ✅ 改为一次性加载人员列表（limit: 100），使用前端筛选（filterable）

**接口文档参考**:
```
GET /v1/mdm/tpm/maintenance-tasks/personnel
支持的查询参数: departmentId, positionId, roleIds, limit, sortBy
不支持: search 参数
```

#### 1.3 添加状态验证

**问题**: 原实现未在前端进行状态验证

**修改**:
- ✅ 在 `initDialog` 方法中添加状态验证
- ✅ 只有"待执行"状态的任务才能派工
- ✅ 其他状态显示警告提示并关闭对话框

**代码实现**:
```javascript
// 状态验证：只有待执行状态的任务才能派工
if (this.taskInfo && this.taskInfo.status !== '待执行') {
  this.$message.warning('只有待执行状态的任务才能派工')
  this.handleClose()
  return
}
```

**接口文档参考**:
- 错误码 `TPM_TASK_010`: "只有待执行状态的任务才能派工"

#### 1.4 完善错误处理

**问题**: 原实现使用硬编码的错误消息

**修改**:
- ✅ 使用后端返回的 `error.message` 字段
- ✅ 使用后端返回的 `message` 字段（成功提示）
- ✅ 保留备用消息以确保用户体验

**代码实现**:
```javascript
// 成功提示
this.$message.success(response.message || '派工成功')

// 错误提示
this.$message.error(error.message || '派工失败，请重试')
```

#### 1.5 优化用户体验

**新增功能**:
- ✅ 在二次确认对话框中显示执行人员姓名
- ✅ 提供更友好的确认提示

**代码实现**:
```javascript
const selectedPerson = this.personnelList.find(p => p.id === this.formData.assignedTo)
const personnelName = selectedPerson ? selectedPerson.name : '选定的执行人员'

await this.$confirm(
  `确认将任务"${this.taskInfo.taskTitle}"派发给 ${personnelName} 吗？`,
  '确认派工',
  { confirmButtonText: '确定', cancelButtonText: '取消', type: 'warning' }
)
```

## 📊 接口对接情况

### 派工接口

**接口路径**: `POST /v1/mdm/tpm/maintenance-tasks/:taskId/assign`

**请求参数**: ✅ 完全符合
```json
{
  "assignedTo": "c3d4e5f6-a7b8-9012-cdef-123456789012"
}
```

**响应处理**: ✅ 完全符合
- 使用 `response.message` 显示成功提示
- 使用 `response.data` 传递更新后的任务数据
- 触发 `@success` 事件通知父组件

**错误处理**: ✅ 完全符合
- `TPM_TASK_001`: 维护任务不存在
- `TPM_TASK_010`: 只有待执行状态的任务才能派工
- `USER_001`: 执行人员不存在
- `VALIDATION_ERROR`: 请求参数验证失败
- `UNAUTHORIZED`: 未授权
- `FORBIDDEN`: 权限不足

### 人员筛选接口

**接口路径**: `GET /v1/mdm/tpm/maintenance-tasks/personnel`

**查询参数**: ✅ 完全符合
```javascript
{
  limit: 100,        // 符合接口文档
  sortBy: 'name:asc' // 符合接口文档
}
```

**响应处理**: ✅ 完全符合
- 使用 `response.data` 获取人员列表
- 正确处理人员对象结构（id, name, email, status, profile）

### 负载分析接口

**接口路径**: `GET /v1/mdm/tpm/maintenance-tasks/workload`

**使用情况**: ✅ 正常使用
- 用于显示人员当前任务负载
- 计算公式：待执行 + 执行中 + 已延期
