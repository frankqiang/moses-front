## 功能概述

### 所有功能

**任务派工**（Task Assignment）是维护任务管理模块中的核心操作之一，用于将处于待执行状态的维护任务派发给指定的维护人员，以支持精细化的任务调度和人员负载均衡的业务场景。

派工操作是维护任务生命周期中的关键环节，它连接了任务计划和任务执行两个阶段。通过派工，管理员或调度员可以根据维护人员的技能、工作负载和可用性，将不同的维护任务分配给最适合的人员，从而提高维护效率和工作质量。

### 关键特性

- ✅ **智能派工控制**：只有待执行状态的任务才能派工，确保派工流程的正确性和业务规则的完整性
- ✅ **灵活重派工**：支持对已派工的任务重新派工到不同的维护人员，适应业务需求变化
- ✅ **人员有效性验证**：自动验证执行人员存在且处于激活状态，避免派工给无效用户
- ✅ **任务完整性返回**：派工完成后返回完整的任务详情（包含关联的设备、执行人、创建人等），无需额外查询
- ✅ **原子性操作**：派工操作在事务保护下执行，确保数据一致性和操作的原子性
- ✅ **操作日志记录**：自动记录派工人员、派工时间和执行人信息，便于后续追溯和审计

### 使用前提

- ✅ 维护任务存在且ID有效（需为有效的UUID格式）
- ✅ 维护任务当前状态为"待执行"（状态为其他值时派工会失败）
- ✅ 指定的执行人员存在且用户状态为"激活"（inactive用户无法接收派工）
- ✅ 当前操作用户具有管理权限（mdm.tpm.maintenance-task.manage）
- ✅ 持有有效的JWT认证令牌，且令牌未过期

### 不适用场景

- ❌ 任务已处于执行中状态的派工——应使用取消后重新创建或联系管理员处理
- ❌ 任务已完成或已取消的派工——这些是终态，不允许任何操作
- ❌ 派工给不存在或已禁用的用户——系统会返回用户不存在错误
- ❌ 派工给非维护人员——建议先确认用户权限和岗位设置

### 详细步骤说明

#### 步骤1: 权限验证
- **验证内容**：检查当前登录用户是否拥有 `mdm.tpm.maintenance-task.manage` 权限
- **失败处理**：无权限时返回 403 Forbidden 错误
- **说明**：派工是管理操作，只有具有管理权限的用户才能执行

#### 步骤2: 任务查询与状态验证
- **验证内容**：查询指定ID的维护任务，验证任务存在且状态为"待执行"
- **失败处理**：
  - 任务不存在：返回 404 错误（TPM_TASK_001）
  - 任务状态不是待执行：返回 400 错误（TPM_TASK_010）
- **说明**：只有待执行的任务才符合派工条件，其他状态说明任务已在其他生命周期阶段

#### 步骤3: 执行人员验证
- **验证内容**：查询指定ID的用户，验证用户存在且状态为"激活"
- **失败处理**：用户不存在或非激活状态返回 404 错误（USER_001）
- **说明**：确保派工到的是一个有效的、可以接收任务的用户

#### 步骤4: 事务开启
- **内容**：开启数据库事务，确保派工操作的原子性
- **说明**：如果派工过程中发生异常，事务会自动回滚，保证数据一致性

#### 步骤5: 任务更新
- **更新字段**：
  - `assignedTo`：设置为指定的执行人员ID
  - `updatedBy`：设置为当前操作用户ID
  - `updatedAt`：设置为当前时间
- **说明**：记录派工信息和操作审计数据

#### 步骤6: 事务提交
- **内容**：提交数据库事务，确保更新操作持久化
- **说明**：事务提交成功后，派工操作不可逆

#### 步骤7: 数据查询与响应
- **内容**：查询更新后的完整任务信息，包括关联的设备、执行人、创建人等
- **说明**：返回的完整信息可供前端直接展示，无需额外查询

## 接口文档

### 基本信息

**接口路径**: `POST /v1/mdm/tpm/maintenance-tasks/:taskId/assign`

**功能描述**: 将维护任务派发给指定的执行人员。只有待执行状态的任务才能派工。支持重新派工，即对已派工的任务更换执行人员。

**认证要求**: JWT Bearer Token 认证，需要 `mdm.tpm.maintenance-task.manage` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 路径参数

| 参数名 | 类型   | 必填 | 限制     | 描述       | 示例                                   |
| ------ | ------ | ---- | -------- | ---------- | -------------------------------------- |
| taskId | string | 是   | UUID格式 | 维护任务ID | "d4e5f6a7-b8c9-0123-def0-234567890123" |

### 请求参数

| 参数名     | 类型   | 必填 | 限制     | 描述       | 示例                                   |
| ---------- | ------ | ---- | -------- | ---------- | -------------------------------------- |
| assignedTo | string | 是   | UUID格式 | 执行人员ID | "c3d4e5f6-a7b8-9012-cdef-123456789012" |

#### JavaScript/axios 示例

```javascript
import axios from 'axios';

const api = axios.create({
  baseURL: 'http://localhost:3000/v1',
  headers: {
    'Content-Type': 'application/json',
  },
});

async function assignMaintenanceTask(taskId, assignedTo, token) {
  try {
    const response = await api.post(
      `/mdm/tpm/maintenance-tasks/${taskId}/assign`,
      { assignedTo },
      {
        headers: {
          Authorization: `Bearer ${token}`,
        },
      }
    );

    console.log('派工成功:', response.data.data);
    return response.data.data;
  } catch (error) {
    console.error('派工失败:', error.response.data);
    throw error;
  }
}
```

}

### 错误响应

| HTTP状态码 | 错误码           | 错误消息                     | 说明                             | 处理建议                   |
| ---------- | ---------------- | ---------------------------- | -------------------------------- | -------------------------- |
| 400        | VALIDATION_ERROR | 请求参数验证失败             | 请求参数格式或值不符合规范       | 检查请求参数格式和必填字段 |
| 400        | VALIDATION_ERROR | assignedTo 必填              | 未提供执行人员ID                 | 添加 assignedTo 字段       |
| 400        | VALIDATION_ERROR | assignedTo 必须是UUID格式    | assignedTo 格式不正确            | 提供正确的UUID格式ID       |
| 400        | TPM_TASK_010     | 只有待执行状态的任务才能派工 | 任务当前状态不允许派工           | 检查任务当前状态           |
| 401        | UNAUTHORIZED     | 未授权，Token无效或过期      | 未提供认证Token或Token已失效     | 重新登录获取有效Token      |
| 403        | FORBIDDEN        | 无权限                       | 缺少 manage 权限                 | 联系管理员授予权限         |
| 404        | TPM_TASK_001     | 维护任务不存在               | 请求的维护任务ID不存在或已被删除 | 检查任务ID是否正确         |
| 404        | USER_001         | 执行人员不存在               | 指定的执行人员ID不存在或已禁用   | 检查执行人员ID是否正确     |

## 常见问题

### Q1: 派工后任务还在待执行状态，这是正常的吗？

**A**: 是的，这是正常的。派工操作只是将任务分配给执行人员，任务状态仍为"待执行"。执行人员接单后状态才会保持待执行（直到开始执行变为执行中）。这个设计允许：
- 执行人员选择接单还是拒绝
- 管理员可以重新派工
- 任务可以被取消或延期

### Q2: 为什么派工给一个存在的用户却返回USER_001错误？

**A**: 用户存在但可能处于以下状态之一：
- 用户账户已被禁用（status != 'active'）
- 用户已被删除（逻辑删除）
- 用户未激活

请检查用户的激活状态。管理员可以在用户管理页面确认用户状态。

### Q3: 能否派工给不存在的任务？

**A**: 不能。如果任务ID无效或任务已被删除，会返回404错误（TPM_TASK_001）。请确保：
- 任务ID格式正确（UUID格式）
- 任务存在且未被删除
- 复制ID时没有多余空格

### Q4: 已派工的任务能否重新派工？

**A**: 可以，只要任务仍处于"待执行"状态。一旦任务开始执行（状态变为"执行中"），则不能通过派工接口修改执行人，必须先取消再重新创建或联系管理员。

### Q5: 派工操作是否会改变任务的其他字段？

**A**: 不会。派工操作只会改变以下字段：
- `assignedTo`：设置为新的执行人员ID
- `updatedBy`：设置为当前操作人ID
- `updatedAt`：设置为当前时间

其他字段（任务标题、描述、计划时间等）保持不变。

### Q6: 如何获取可用的维护人员列表进行派工？

**A**: 可以调用"按组织架构筛选维护人员"接口：
```
GET /v1/mdm/tpm/maintenance-tasks/personnel?departmentId=xxx&limit=50
```
该接口返回符合条件的可用维护人员列表，可在派工对话框中展示。

### Q7: 派工权限的具体要求是什么？

**A**: 执行派工操作需要满足：
- 用户已登录且Token有效
- 用户具有 `mdm.tpm.maintenance-task.manage` 权限
- 管理员、调度员通常具有此权限
- 普通维护人员通常只有 `execute` 权限，无法派工

### Q8: 派工失败后如何重试？

**A**: 根据不同的错误码进行处理：
- **VALIDATION_ERROR**：检查参数格式，修正后重试
- **TPM_TASK_001**：确认任务存在，必要时刷新列表
- **TPM_TASK_010**：检查任务状态，必要时刷新获取最新状态
- **USER_001**：确认执行人存在且激活，选择其他人员
- **FORBIDDEN**：权限问题，需要管理员授权
- **UNAUTHORIZED**：重新登录获取新的Token

### 日期时间格式说明

所有涉及时间的字段都使用 ISO 8601 标准格式：

- **格式**: `YYYY-MM-DDTHH:mm:ss.sssZ`
- **示例**: `2024-01-20T08:30:00.000Z`
- **说明**: Z 表示 UTC 时区，即零时区
- **时区转换**: 前端需要根据本地时区显示时间
