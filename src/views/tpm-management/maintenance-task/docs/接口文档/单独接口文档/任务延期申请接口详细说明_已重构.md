## 功能概述

### 所有功能

**任务延期申请**（Postpone Maintenance Task）是设备TPM管理模块中的重要执行操作之一，用于执行人员在无法按计划时间完成维护任务时申请延期，以支持灵活的维护任务管理和工作安排调整的业务场景。

延期申请功能允许维护人员在面临客观困难或资源障碍时主动申请延期，系统自动将任务状态变更为"已延期"，并记录延期原因和新的计划开始时间，为后续任务重新调度提供依据。

### 关键特性

- ✅ **灵活的延期支持**：待执行和执行中状态的任务都可以申请延期，适应不同的业务场景需求
- ✅ **原因追溯机制**：强制记录延期原因，为后续问题分析和流程改进提供重要数据
- ✅ **计划时间调整**：支持指定新的计划开始时间，精细化的任务重新规划
- ✅ **自动状态迁移**：延期成功后，任务状态自动变更为"已延期"，系统状态保持一致
- ✅ **权限严格控制**：只有任务执行人才能申请延期，防止权限混乱和责任不清
- ✅ **完整的审计记录**：自动记录申请时间、申请人和原因信息，便于后续追踪和审计

---

### 使用前提

- ✅ 维护任务必须存在且ID有效（需为有效的UUID格式）
- ✅ 维护任务当前状态为"待执行"或"执行中"（其他状态无法申请延期）
- ✅ 当前操作用户必须是任务的执行人员（assignedTo字段值相同）
- ✅ 当前操作用户具有执行权限（mdm.tpm.maintenance-task.execute）
- ✅ 持有有效的JWT认证令牌，且令牌未过期
- ✅ 延期原因必须提供，不能为空字符串

### 不适用场景

- ❌ 任务已完成或已取消——这些是终态，不允许任何操作
- ❌ 任务已被其他人接单——当前用户不是执行人时无法申请延期
- ❌ 申请人没有执行维护任务的权限——需要先获得相应权限
- ❌ 不提供延期原因——延期原因是必填字段

### 详细步骤说明

#### 步骤1: 权限验证
- **验证内容**：检查当前登录用户是否拥有 `mdm.tpm.maintenance-task.execute` 权限
- **失败处理**：无权限时返回 403 Forbidden 错误
- **说明**：延期申请是执行操作，只有具有执行权限的用户才能申请

#### 步骤2: 任务查询与状态验证
- **验证内容**：查询指定ID的维护任务，验证任务存在且状态为"待执行"或"执行中"
- **失败处理**：
  - 任务不存在：返回 404 错误（TPM_TASK_001）
  - 任务状态不符合：返回 400 错误（TPM_TASK_014）
- **说明**：只有待执行或执行中的任务符合延期条件，其他状态说明任务已进入终态

#### 步骤3: 执行人员权限验证
- **验证内容**：检查当前用户是否为任务的执行人员（assignedTo 字段）
- **失败处理**：如果当前用户不是执行人员，返回 403 错误（TPM_TASK_016）
- **说明**：确保只有被派工或已接单的人才能申请延期，防止权限混乱

#### 步骤4: 请求参数验证
- **验证内容**：检查延期原因不为空，检查新计划开始时间格式（如提供）
- **失败处理**：参数不符合要求返回 400 错误（VALIDATION_ERROR 或 TPM_TASK_014）
- **说明**：确保提供了必要的业务信息用于后续处理和追踪

#### 步骤5: 事务处理
- **开启事务**：确保后续操作的原子性
- **更新任务**：
  - 将任务状态设置为"已延期"
  - 记录延期原因
  - 如果提供了新的计划开始时间，更新该字段
  - 更新 updatedBy 和 updatedAt 字段
- **提交事务**：所有修改一起提交，保证数据一致性

#### 步骤6: 返回完整任务信息
- **查询详情**：查询更新后的完整任务信息（包含所有关联对象）
- **返回响应**：返回 200 状态码和完整的任务数据结构

## 接口文档

### 基本信息

**接口路径**: `POST /v1/mdm/tpm/maintenance-tasks/:taskId/postpone`

**功能描述**: 执行人员申请延期维护任务，需要提供延期原因。只有待执行或执行中状态的任务才能申请延期，任务状态将变更为"已延期"。

**认证要求**: JWT Bearer Token，需要 `mdm.tpm.maintenance-task.execute` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 路径参数

| 参数名 | 类型   | 必填 | 限制         | 描述       | 示例                                   |
| ------ | ------ | ---- | ------------ | ---------- | -------------------------------------- |
| taskId | string | 是   | 有效UUID格式 | 维护任务ID | "d4e5f6a7-b8c9-0123-def0-234567890123" |

### 请求参数

| 参数名              | 类型   | 必填 | 限制                           | 描述             | 示例                       |
| ------------------- | ------ | ---- | ------------------------------ | ---------------- | -------------------------- |
| delayReason         | string | 是   | 不能为空，不超过500字符        | 延期原因         | "设备配件未到货"           |
| newPlannedStartTime | string | 否   | ISO 8601格式，不能早于当前时间 | 新的计划开始时间 | "2024-01-22T08:00:00.000Z" |

### 请求示例

#### cURL 命令

```bash
curl -X POST http://localhost:3000/v1/mdm/tpm/maintenance-tasks/d4e5f6a7-b8c9-0123-def0-234567890123/postpone \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "delayReason": "设备配件未到货",
    "newPlannedStartTime": "2024-01-22T08:00:00.000Z"
  }'
```

#### JSON 请求体

```json
{
  "delayReason": "设备配件未到货",
  "newPlannedStartTime": "2024-01-22T08:00:00.000Z"
}
```

#### 最小请求（仅提供延期原因）

```json
{
  "delayReason": "由于维修工具故障，无法按时开始"
}
```

## 使用示例

### 场景1: 执行中的任务申请延期（设备配件未到）

**业务需求**: 张三正在进行"退火炉日常维护"任务，但发现需要的配件未到货，需要申请延期

**前置条件**:
- 任务ID: "d4e5f6a7-b8c9-0123-def0-234567890123"
- 任务状态: 执行中
- 执行人员: 张三 (ID: c3d4e5f6-a7b8-9012-cdef-123456789012)
- 张三已登录获得有效token

**请求**:
```bash
curl -X POST http://localhost:3000/v1/mdm/tpm/maintenance-tasks/d4e5f6a7-b8c9-0123-def0-234567890123/postpone \
```

## 常见问题

### Q1: 任务延期后，如何重新调度？

**A**: 任务延期后，管理员可以通过以下方式处理：
1. 查询已延期的任务列表
2. 根据延期原因和新的计划时间评估是否需要重新派工
3. 可以取消原任务或等待执行人在新时间开始执行

### Q2: 是否可以多次申请延期？

**A**: 系统允许多次申请延期。每次延期申请都会记录新的延期原因和计划时间，所有历史记录都可以用于后续审计和分析。

### Q3: 新的计划开始时间必须填写吗？

**A**: 不是必需的。newPlannedStartTime 是可选参数。如果不提供，系统将保持原有的计划时间，由管理员后续手动调整。

### Q4: 延期后任务是否还能重新开始执行？

**A**: 可以的。任务延期后状态为"已延期"，执行人可以在新时间调用"开始执行"接口重新开始任务（假设系统支持从"已延期"状态跳转到"执行中"）。

### Q5: 如果任务在执行中申请延期，设备状态会改变吗？

**A**: 不会。任务在执行中时申请延期，设备状态保持"维护中"不变。直到任务最终完成或取消，设备状态才会恢复为"空闲"。

### Q6: 什么时候应该使用延期而不是取消任务？

**A**:
- **使用延期**：当任务确实需要继续完成，只是时间需要调整时
- **使用取消**：当任务不再需要执行、被其他方式处理或无法完成时

### Q7: 能否为没有派工的任务申请延期？

**A**: 不能。任务必须是"待执行"或"执行中"状态，但通常"待执行"状态的任务要么已派工给执行人，要么已被执行人接单。如果任务完全未派工且未被接单，执行人无法申请延期。
