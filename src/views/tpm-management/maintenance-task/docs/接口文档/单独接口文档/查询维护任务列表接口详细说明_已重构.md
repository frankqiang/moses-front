## 功能概述

### 所有功能

查询维护任务列表（Query Maintenance Tasks）是设备TPM管理模块中的核心查询接口，用于根据多种条件分页查询维护任务，以支持任务管理、任务监控、数据统计等业务场景。

本接口提供强大的筛选和排序能力，能够满足不同角色用户（管理员、调度员、维护人员）的多样化查询需求，帮助用户快速定位和管理维护任务。

### 关键特性

- ✅ **多维度筛选**：支持按设备、维护计划、任务类型、任务状态、执行人等多个维度进行精确筛选
- ✅ **关键词搜索**：支持通过任务编码或任务标题进行模糊搜索，快速定位目标任务
- ✅ **时间范围查询**：支持按计划开始时间范围筛选任务，便于按时间段查看和管理任务
- ✅ **多状态组合查询**：支持同时查询多个状态的任务（如同时查询"待执行"和"执行中"的任务）
- ✅ **灵活的分页和排序**：支持自定义分页大小、页码，以及多字段排序
- ✅ **完整的关联信息**：返回结果包含设备信息、维护计划信息、执行人信息等完整的关联数据

## 业务场景

### 适用场景

1. **任务监控看板**
   - 管理员或调度员需要实时查看所有维护任务的执行情况
   - 通过状态筛选快速定位"待执行"、"执行中"、"逾期"等关键状态的任务

2. **设备维护追踪**
   - 查询特定设备的所有维护任务历史
   - 通过设备ID筛选，查看某台设备的维护频率和完成情况

3. **人员工作量统计**
   - 查询特定维护人员的任务分配情况
   - 通过执行人ID筛选，评估人员工作负载

4. **计划执行监控**
   - 查询某个维护计划下生成的所有任务
   - 通过计划ID筛选，监控计划的执行进度

5. **任务搜索和定位**
   - 通过任务编码或标题关键词快速查找特定任务
   - 支持模糊搜索，提高查询效率

6. **时间段任务统计**
   - 查询某个时间段内的所有维护任务
   - 用于月度、季度、年度的维护数据统计和分析

### 使用前提

- ✅ 用户已登录并具有 `mdm.tpm.maintenance-task.view` 权限
- ✅ 查询参数符合验证规则（如分页参数、日期格式等）
- ✅ 关联的筛选条件（如设备ID、计划ID、执行人ID）在系统中存在

### 不适用场景

- ❌ 需要查询单个任务的完整详细信息：应使用"查询单个维护任务"接口（包含更多关联数据）
- ❌ 只需要当前用户自己的任务：应使用"查询我的任务"接口（更简洁高效）
- ❌ 需要实时监控逾期任务：应使用"查询逾期任务"接口（专门优化）

### 详细步骤说明

#### 步骤1: 验证查询参数
- **验证内容**：
  - 分页参数：page 最小值为1，limit 最小值为1、最大值为100
  - 日期格式：startDate 和 endDate 必须是有效的 ISO 8601 格式
  - 日期逻辑：endDate 不能早于 startDate
  - UUID格式：equipmentId、planId、assignedTo 必须是有效的 UUID 格式
  - 状态值：status 必须是有效的任务状态值
  - 任务类型：taskType 必须是"计划维护"、"应急抢修"或"状态检修"之一
- **失败响应**：HTTP 400，错误码 `VALIDATION_ERROR`
- **特殊说明**：所有查询参数都是可选的，不提供参数时返回所有任务

#### 步骤2: 构建查询条件
- **操作内容**：根据提供的查询参数，构建 Sequelize 查询条件对象
- **技术实现**：
  - equipmentId：精确匹配设备ID
  - planId：精确匹配维护计划ID
  - taskType：精确匹配任务类型
  - status：支持逗号分隔的多个状态，使用 `IN` 查询
  - assignedTo：精确匹配执行人ID
  - search：使用 `LIKE` 模糊查询任务编码或标题
  - startDate/endDate：使用 `BETWEEN` 查询计划开始时间范围
- **特殊处理**：所有查询都排除软删除的记录（`isDeleted: false`）

#### 步骤3: 应用排序规则
- **排序格式**：`字段名:排序方向`，多个排序条件用逗号分隔
- **默认排序**：`plannedStartTime:asc`（按计划开始时间升序）
- **支持的排序字段**：
  - plannedStartTime：计划开始时间
  - createdAt：创建时间
  - updatedAt：更新时间
  - taskCode：任务编码
- **排序方向**：asc（升序）、desc（降序）

#### 步骤4: 执行分页查询
- **查询内容**：
  - 先查询满足条件的总记录数
  - 再查询当前页的数据（根据 page 和 limit 计算偏移量）
- **技术实现**：使用 Sequelize 的 `paginate` 方法
- **性能优化**：使用索引字段进行筛选，避免全表扫描

#### 步骤5: 加载关联数据
- **关联查询**：使用 Sequelize 的 `include` 功能，一次性加载所有关联数据
- **包含的关联数据**：
  - equipment：设备信息（id、equipmentCode、name、equipmentType、status）
  - maintenancePlan：维护计划信息（id、planCode、planName、maintenanceType）
  - assignee：执行人信息（id、name、email）
- **特殊说明**：关联数据可能为 null（如未指定执行人、未关联维护计划）

#### 步骤6: 格式化并返回结果
- **返回内容**：
  - results：任务列表数组
  - page：当前页码
  - limit：每页数量
  - totalPages：总页数
  - totalResults：总记录数
- **数据结构**：符合统一响应格式，包含 success、data、message、meta

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/maintenance-tasks`

**功能描述**: 根据多种条件分页查询维护任务列表，支持设备、维护计划、任务类型、状态、执行人等多维度筛选，支持关键词搜索和时间范围查询，适用于任务监控、数据统计、任务管理等场景。

**认证要求**: JWT Bearer Token，需要 `mdm.tpm.maintenance-task.view` 权限

**请求头**:

```
Authorization: Bearer <access_token>
```

### 查询参数

| 参数名      | 类型   | 必填 | 限制                            | 描述                                            | 默认值                 | 示例                                   |
| ----------- | ------ | ---- | ------------------------------- | ----------------------------------------------- | ---------------------- | -------------------------------------- |
| equipmentId | string | 否   | UUID格式                        | 设备ID筛选                                      | null                   | "b2c3d4e5-f6a7-8901-bcde-f12345678901" |
| planId      | string | 否   | UUID格式                        | 维护计划ID筛选                                  | null                   | "a1b2c3d4-e5f6-7890-abcd-ef1234567890" |
| taskType    | string | 否   | 计划维护/应急抢修/状态检修      | 任务类型筛选                                    | null                   | "计划维护"                             |
| status      | string | 否   | 支持逗号分隔多个状态            | 任务状态筛选                                    | null                   | "待执行,执行中"                        |
| assignedTo  | string | 否   | UUID格式                        | 执行人ID筛选                                    | null                   | "c3d4e5f6-a7b8-9012-cdef-123456789012" |
| search      | string | 否   | 无限制                          | 搜索关键词（任务编码或标题）                    | null                   | "退火炉"                               |
| startDate   | string | 否   | ISO 8601格式                    | 计划开始时间起始范围                            | null                   | "2024-01-20T00:00:00.000Z"             |
| endDate     | string | 否   | ISO 8601格式，不能早于startDate | 计划开始时间结束范围                            | null                   | "2024-01-31T23:59:59.999Z"             |
| page        | number | 否   | 最小值1，默认1                  | 页码                                            | 1                      | 1                                      |
| limit       | number | 否   | 最小值1，最大值100，默认10      | 每页数量                                        | 10                     | 10                                     |
| sortBy      | string | 否   | 默认plannedStartTime:asc        | 排序字段（格式：字段名:asc/desc，逗号分隔多个） | "plannedStartTime:asc" | "plannedStartTime:asc"                 |


### 状态转换图

```
待执行 ──────────────────> 执行中 ──────> 已完成
  │                          │
  │                          │
  ▼                          ▼
已延期 ──────────────────> 已取消
  │
  │
  ▼
执行中
```

**状态转换规则**:
- `待执行` → `执行中`: 任务开始执行
- `待执行` → `已延期`: 任务申请延期
- `待执行` → `已取消`: 任务被取消
- `执行中` → `已完成`: 任务执行完成
- `执行中` → `已取消`: 任务被中止
- `已延期` → `执行中`: 延期后重新开始执行
- `已延期` → `已取消`: 延期任务被取消

### 排序字段说明

| 字段名           | 说明         | 排序方向 | 使用场景               |
| ---------------- | ------------ | -------- | ---------------------- |
| plannedStartTime | 计划开始时间 | asc/desc | 按计划时间排序（默认） |
| createdAt        | 创建时间     | asc/desc | 按创建顺序排序         |
| updatedAt        | 更新时间     | asc/desc | 按最近更新排序         |
| taskCode         | 任务编码     | asc/desc | 按编码字母顺序排序     |
