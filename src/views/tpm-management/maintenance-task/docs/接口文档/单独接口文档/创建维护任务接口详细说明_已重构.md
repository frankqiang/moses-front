## 功能概述

### 所有功能

创建维护任务（Create Maintenance Task）是设备TPM管理模块中的核心操作之一，用于手动创建维护任务，支持计划维护、应急抢修、状态检修三种任务类型，以支持企业设备全生命周期管理的业务场景。

该接口允许管理员或调度员根据设备维护需求创建任务，可以选择性地指定执行人员，如果不指定则需要后续派工或人员自主接单。任务编码支持手动指定或系统自动生成。

### 关键特性

- ✅ **多任务类型支持**：支持计划维护、应急抢修、状态检修三种任务类型，满足不同维护场景
- ✅ **灵活的人员分配**：可以在创建时指定执行人员，也可以留空后续派工或自主接单
- ✅ **智能编码生成**：任务编码可手动指定或系统自动生成，格式为 `MT-{设备编码}-{时间戳}`
- ✅ **维护计划关联**：支持关联维护计划ID，便于追溯计划维护任务来源
- ✅ **完整的审计跟踪**：自动记录创建人、创建时间、更新人、更新时间等审计信息
- ✅ **关联数据查询**：创建成功后自动返回关联的设备、维护计划、人员等完整信息

## 业务场景

### 适用场景

1. **计划维护场景**
   - 根据维护计划定期创建的维护任务
   - 例如：每月一次的退火炉日常维护任务，系统会关联维护计划ID

2. **应急抢修场景**
   - 设备突发故障时需要立即创建的紧急维修任务
   - 例如：生产线退火炉突然出现温控异常，需要立即派工处理

3. **状态检修场景**
   - 根据设备运行状态触发的预防性检修任务
   - 例如：设备状态监控系统检测到退火炉加热元件老化，需要提前安排检修

4. **批量任务创建**
   - 多台同类设备需要同时进行维护时，可批量创建任务
   - 例如：年度设备大检修，需要为10台退火炉同时创建维护任务

### 使用前提

- ✅ 设备必须已在系统中注册，状态为有效
- ✅ 执行人员（如指定）必须是已激活的用户
- ✅ 维护计划（如关联）必须是有效的计划记录
- ✅ 操作人员必须具有 `mdm.tpm.maintenance-task.manage` 权限

### 不适用场景

- ❌ 设备尚未录入系统时无法创建任务，需先完成设备档案建立
- ❌ 任务编码重复时无法创建，建议使用系统自动生成功能

### 详细步骤说明

#### 步骤1: 验证请求参数
- **验证内容**：检查必填字段（equipmentId、taskType、taskTitle、plannedStartTime）是否提供，验证字段格式、长度限制
- **失败响应**：HTTP 400，错误码 `VALIDATION_ERROR`
- **特殊说明**：taskTitle长度限制为1-200字符，plannedEndTime如果提供则不能早于plannedStartTime

#### 步骤2: 验证设备是否存在
- **操作内容**：查询设备表，验证equipmentId对应的设备是否存在且未被删除
- **技术实现**：执行SQL查询 `SELECT * FROM equipment WHERE id = ? AND isDeleted = false`
- **失败情况**：设备不存在时返回HTTP 404，错误码 `EQUIPMENT_001`

#### 步骤3: 验证维护计划（如提供）
- **校验规则**：如果请求中包含planId，验证对应的维护计划是否存在且状态有效
- **容差范围**：planId为可选参数，不提供时跳过此步骤
- **失败响应**：HTTP 404，错误码 `MAINTENANCE_PLAN_002`

#### 步骤4: 验证执行人员（如提供）
- **校验规则**：如果请求中包含assignedTo，验证对应的用户是否存在且状态为激活
- **容差范围**：assignedTo为可选参数，不提供时任务将处于待派工状态
- **失败响应**：HTTP 404，错误码 `USER_001`

#### 步骤5: 生成或验证任务编码
- **操作逻辑**：
  - 如果请求中提供了taskCode，检查编码是否已存在
  - 如果未提供，自动生成格式为 `MT-{设备编码}-{时间戳}` 的唯一编码
- **失败情况**：编码重复时返回HTTP 400，错误码 `TPM_TASK_002`

#### 步骤6: 创建维护任务记录
- **操作内容**：在事务中插入维护任务记录到数据库
- **关键字段**：
  - status初始值为"待执行"
  - createdBy和updatedBy设置为当前登录用户ID
  - createdAt和updatedAt设置为当前时间
- **技术实现**：使用Sequelize ORM的create方法

#### 步骤7: 记录操作日志
- **记录内容**：记录任务创建操作，包含操作人ID、操作时间、操作类型（CREATE）
- **日志级别**：INFO级别
- **日志格式**：`创建维护任务成功 - 任务ID: {taskId}, 设备ID: {equipmentId}, 创建人: {userId}`

#### 步骤8: 查询并返回完整任务信息
- **返回内容**：返回创建成功的任务完整信息，包含关联的设备、维护计划、执行人员、创建人等
- **数据结构**：符合统一响应格式，包含success、data、message、meta字段

## 接口文档

### 基本信息

**接口路径**: `POST /v1/mdm/tpm/maintenance-tasks`

**功能描述**: 手动创建维护任务，支持计划维护、应急抢修、状态检修三种任务类型。可以选择性地指定执行人员，如果不指定则需要后续派工或人员自主接单。任务编码可以手动指定或系统自动生成。

**认证要求**: JWT Bearer Token，需要 `mdm.tpm.maintenance-task.manage` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 请求参数

| 参数名           | 类型   | 必填 | 限制                                   | 描述                                 | 示例                                   |
| ---------------- | ------ | ---- | -------------------------------------- | ------------------------------------ | -------------------------------------- |
| taskCode         | string | 否   | 最大100字符                            | 任务编码（不提供则自动生成）         | "MT-EQ001-1729012345678"               |
| planId           | string | 否   | UUID格式                               | 关联维护计划ID（计划维护时建议填写） | "a1b2c3d4-e5f6-7890-abcd-ef1234567890" |
| equipmentId      | string | 是   | UUID格式                               | 关联设备ID                           | "b2c3d4e5-f6a7-8901-bcde-f12345678901" |
| taskType         | string | 是   | 计划维护/应急抢修/状态检修             | 任务类型                             | "计划维护"                             |
| taskTitle        | string | 是   | 1-200字符                              | 任务标题                             | "退火炉日常维护"                       |
| taskDescription  | string | 否   | 无限制                                 | 任务描述                             | "检查加热元件、清洁炉体、测试温控系统" |
| plannedStartTime | string | 是   | ISO 8601格式                           | 计划开始时间                         | "2024-01-20T08:00:00.000Z"             |
| plannedEndTime   | string | 否   | ISO 8601格式，不能早于plannedStartTime | 计划结束时间                         | "2024-01-20T12:00:00.000Z"             |
| assignedTo       | string | 否   | UUID格式                               | 执行人员ID                           | "c3d4e5f6-a7b8-9012-cdef-123456789012" |
| remark           | string | 否   | 无限制                                 | 备注                                 | "请注意安全操作"                       |

### 错误响应

| HTTP状态码 | 错误码               | 错误消息                | 说明                         | 处理建议                   |
| ---------- | -------------------- | ----------------------- | ---------------------------- | -------------------------- |
| 400        | VALIDATION_ERROR     | 请求参数验证失败        | 请求参数不符合验证规则       | 检查请求参数格式和必填字段 |
| 400        | TPM_TASK_002         | 维护任务编码已存在      | 任务编码与已有任务重复       | 更换任务编码或使用自动生成 |

| 执行中   | 执行中   | 任务正在执行         |

| 已取消   | 已取消   | 任务已取消           |

### 任务状态转换图

```
[待执行] ──────────> [执行中] ──────────> [已完成]
   │                    │
   │                    │
   ▼                    ▼
[已延期] ──────────> [执行中]
   │                    │
   │                    │
   ▼                    ▼
[已取消] <──────────[已取消]
```

**说明**：
- 待执行 → 执行中：调用"开始执行任务"接口
- 执行中 → 已完成：调用"完成任务"接口
- 待执行 → 已延期：调用"任务延期申请"接口
- 已延期 → 执行中：调用"开始执行任务"接口
- 任何状态 → 已取消：调用"取消任务"接口（执行中、已完成除外）
