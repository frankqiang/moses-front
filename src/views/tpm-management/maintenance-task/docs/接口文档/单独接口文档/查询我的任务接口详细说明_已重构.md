## 功能概述

### 所有功能

查询我的任务（Query My Tasks）是维护任务管理模块中的核心个人任务查询接口,用于查询当前登录用户的维护任务列表,以支持维护人员快速查看和管理分配给自己的任务的业务场景。该接口自动根据登录用户的身份筛选任务,确保用户只能查看自己的任务,同时提供了丰富的筛选条件和排序方式,满足不同的任务管理需求。

### 关键特性

- ✅ **用户隔离**：自动根据当前登录用户的ID筛选任务,确保数据安全和隐私保护
- ✅ **分页查询**：支持自定义分页大小和页码,默认每页10条记录,高效处理大数据量场景
- ✅ **多维度筛选**：支持按任务状态、日期范围等多个维度进行精确筛选
- ✅ **全文搜索**：通过 `search` 参数实现对任务编码、任务标题等关键字段的模糊搜索
- ✅ **灵活排序**：支持按计划开始时间、创建时间等字段进行升序或降序排序,支持多字段组合排序
- ✅ **关联数据加载**：自动关联查询设备信息、维护计划、执行人等完整的任务上下文信息

---

### 使用前提

- ✅ **权限要求**：用户必须具有 `mdm.tpm.maintenance-task.view` 或 `mdm.tpm.maintenance-task.execute` 权限
- ✅ **认证要求**：需要提供有效的 JWT Token 进行身份认证
- ✅ **任务存在性**：系统中已存在分配给当前用户的维护任务数据
- ✅ **参数合法性**：查询参数必须符合验证规则（如日期格式、枚举值范围等）

### 不适用场景

- ❌ **查看所有任务**：如需查看所有维护任务（不限于当前用户）,应使用 `GET /v1/mdm/tpm/maintenance-tasks` 接口
- ❌ **详细信息查询**：如需获取单个任务的详细信息（包括所有关联数据）,应使用 `GET /v1/mdm/tpm/maintenance-tasks/:taskId` 接口
- ❌ **任务操作**：如需对任务进行接单、开始、完成等操作,应使用对应的专用接口
- ❌ **逾期任务统计**：如需查询所有逾期任务的统计信息,应使用 `GET /v1/mdm/tpm/maintenance-tasks/overdue` 接口

### 详细步骤说明

#### 步骤1: JWT Token 验证和用户身份提取
- **验证内容**：验证请求头中的 `Authorization: Bearer <token>` 是否有效且未过期
- **用户提取**：从JWT Token的payload中提取当前登录用户的ID（userId）
- **失败响应**：HTTP 401（Token无效/过期）
- **特殊说明**：认证验证由 `auth` 中间件自动完成,用户ID存储在 `req.user.userId` 中

#### 步骤2: 权限检查
- **权限要求**：检查用户是否具有 `mdm.tpm.maintenance-task.view` 或 `mdm.tpm.maintenance-task.execute` 权限
- **权限说明**：
  - `view` 权限：允许查看所有任务信息
  - `execute` 权限：允许执行任务操作,同时具备查看自己任务的权限
- **失败响应**：HTTP 403（权限不足）
- **技术实现**：权限验证由路由层的 `auth()` 中间件配置完成

#### 步骤3: 请求参数验证
- **验证内容**：使用 Joi 验证器验证查询参数的类型、格式和取值范围
- **验证规则**：
  - `status`: 支持逗号分隔的多个状态值,每个值必须是合法的任务状态枚举值（如 待执行、执行中、已完成等）
  - `search`: 模糊搜索关键词,最大100字符
  - `startDate/endDate`: 符合 ISO 8601 日期格式,且结束时间不能早于开始时间
  - `page`: 正整数,默认为 1
  - `limit`: 正整数,默认为 10,最大为 100
  - `sortBy`: 排序字段和方向,格式为 `field:asc` 或 `field:desc`,支持多字段用逗号分隔
- **失败响应**：HTTP 400,错误码 `VALIDATION_ERROR`,附带具体的验证错误信息
- **技术实现**：参考 `src/validations/modules/mdm/tpm/maintenanceTask.validation.js` 中的验证规则

#### 步骤4: 构建筛选条件
- **操作内容**：从查询参数中提取有效的筛选条件,构建 Sequelize WHERE 子句
- **自动添加用户过滤**：强制添加 `assignedTo = req.user.userId` 条件,确保只查询分配给当前用户的任务
- **筛选逻辑**：
  - **状态筛选**：`status` 参数支持逗号分隔的多个状态,使用 `Op.in` 运算符
  - **模糊搜索**：`search` 参数对 `taskCode`、`taskTitle` 进行 OR 查询,使用 `Op.like`
  - **日期范围**：`startDate/endDate` 对应 `plannedStartTime` 字段的范围查询,使用 `Op.between` 或 `Op.gte/Op.lte`
- **技术实现**：使用 Sequelize Op 运算符构建复杂查询条件

#### 步骤5: 配置分页和排序
- **分页参数**：
  - `limit`: 每页记录数,默认10,最大100
  - `offset`: 偏移量,计算公式为 `(page - 1) * limit`
- **排序参数**：
  - 默认排序：`plannedStartTime:asc`（按计划开始时间升序）
  - 支持多字段排序：如 `plannedStartTime:asc,createdAt:desc`
  - 解析 `sortBy` 参数,拆分为字段名和排序方向,构建 Sequelize `order` 子句
- **技术实现**：统一的分页排序参数解析函数

#### 步骤6: 执行数据库查询
- **查询方法**：使用 Sequelize 的 `findAndCountAll` 方法同时获取记录数和数据
- **关联查询**：
  - 关联 `Equipment` 模型（别名 `equipment`）,加载设备信息（设备编码、名称、类型、状态）
  - 关联 `MaintenancePlan` 模型（别名 `maintenancePlan`）,加载维护计划信息
  - 关联 `User` 模型（别名 `assignee`）,加载执行人信息（姓名、邮箱）
  - 使用 `required: false` 实现 LEFT JOIN,避免无关联数据的任务被过滤
- **去重处理**：设置 `distinct: true` 确保分页计数准确（避免关联查询导致的重复计数）
- **性能优化**：
  - 利用数据库索引（`assigned_to`、`status`、`planned_start_time`、`task_code`、`task_title`）
  - 仅加载必要的字段,避免加载敏感字段
- **失败情况**：数据库连接异常或查询超时时,抛出 `ApiError.internal` 错误

#### 步骤7: 格式化响应数据
- **数据格式化**：
  - 格式化日期时间字段为 ISO 8601 格式
  - 过滤敏感字段,参考模型的 `toJSON` 方法
  - 转换枚举值为用户友好的中文描述（如需要）
- **关联数据处理**：
  - 设备信息：仅返回必要的字段（id、equipmentCode、name、equipmentType、status）
  - 维护计划：仅返回必要的字段（id、planCode、planName、maintenanceType）
  - 执行人信息：仅返回必要的字段（id、name、email）
- **代码参考**：统一的数据格式化工具函数

#### 步骤8: 构建分页元信息
- **元信息内容**：
  - `page`: 当前页码
  - `limit`: 每页记录数
  - `totalPages`: 总页数,计算公式为 `Math.ceil(count / limit)`
  - `totalResults`: 符合条件的总记录数
- **特殊说明**：即使查询结果为空,也会返回完整的分页元信息

#### 步骤9: 返回成功响应
- **返回内容**：包含查询结果、分页元信息和成功消息的统一响应格式
- **HTTP 状态码**：200 OK
- **响应格式**：符合系统统一的成功响应格式

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/maintenance-tasks/my-tasks`

**功能描述**: 查询当前登录用户的维护任务列表,自动根据用户身份筛选任务,支持多维度筛选、排序和分页

**认证要求**: JWT Bearer Token,需要 `mdm.tpm.maintenance-task.view` 或 `mdm.tpm.maintenance-task.execute` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 查询参数

| 参数名    | 类型   | 必填 | 限制                                                                | 描述                                                | 默认值                 | 示例                       |
| --------- | ------ | ---- | ------------------------------------------------------------------- | --------------------------------------------------- | ---------------------- | -------------------------- |
| status    | string | 否   | 支持逗号分隔的多个状态值,每个值必须是合法的任务状态枚举值（见附录） | 任务状态筛选                                        | null                   | "待执行,执行中"            |
| search    | string | 否   | 最大100字符                                                         | 模糊搜索（对任务编码、任务标题进行全文搜索）        | null                   | "退火炉"                   |
| startDate | string | 否   | ISO 8601日期格式                                                    | 计划开始时间范围查询-开始日期                       | null                   | "2024-01-20T00:00:00.000Z" |
| endDate   | string | 否   | ISO 8601日期格式,必须晚于或等于 `startDate`                         | 计划开始时间范围查询-结束日期                       | null                   | "2024-01-31T23:59:59.999Z" |
| page      | number | 否   | 正整数,最小值为1                                                    | 当前页码                                            | 1                      | 2                          |
| limit     | number | 否   | 正整数,最小值1,最大值100                                            | 每页记录数                                          | 10                     | 20                         |
| sortBy    | string | 否   | 格式为 `field:direction`,支持多字段用逗号分隔,direction为asc或desc  | 排序规则（支持字段: plannedStartTime, createdAt等） | "plannedStartTime:asc" | "plannedStartTime:asc"     |

## 常见问题

### Q1: 为什么查询不到某个任务?

**A**: 请检查以下几点:
1. **任务归属**：该接口只返回分配给当前登录用户的任务,如果任务分配给其他人或未分配,则不会出现在结果中
2. **筛选条件**：检查是否设置了 `status`、`startDate/endDate` 等筛选条件,导致任务被过滤
3. **分页问题**：任务可能在其他页,请检查 `totalResults` 和 `totalPages` 字段
4. **软删除**：已删除的任务不会出现在查询结果中

### Q2: 如何查询特定日期范围内的任务?

**A**: 使用 `startDate` 和 `endDate` 参数:
- `startDate`: 计划开始时间的起始范围（包含）
- `endDate`: 计划开始时间的结束范围（包含）
- 示例: `?startDate=2024-01-20T00:00:00.000Z&endDate=2024-01-31T23:59:59.999Z`

### Q3: 如何查询多个状态的任务?

**A**: `status` 参数支持逗号分隔的多个状态值:
- 示例: `?status=待执行,执行中,已延期`
- 会返回所有匹配这些状态之一的任务

### Q4: 排序规则如何使用?

**A**: 使用 `sortBy` 参数,格式为 `字段名:方向`:
- **单字段排序**: `?sortBy=plannedStartTime:asc`（按计划开始时间升序）
- **多字段排序**: `?sortBy=status:asc,plannedStartTime:asc`（先按状态升序,再按时间升序）
- **可用字段**: `plannedStartTime`、`createdAt`、`updatedAt`、`status`
- **方向**: `asc`（升序）或 `desc`（降序）

### Q5: 如何实现模糊搜索?

**A**: 使用 `search` 参数:
- 会对 `taskCode`（任务编码）和 `taskTitle`（任务标题）进行模糊匹配
- 示例: `?search=退火炉` 会匹配所有编码或标题中包含"退火炉"的任务
- 搜索不区分大小写（根据数据库配置）

### Q6: 接口返回的任务是否包含其他人的任务?

**A**: 不会。该接口会自动根据JWT Token中的用户ID筛选任务,只返回 `assignedTo` 字段等于当前登录用户ID的任务。这是一个安全机制,确保用户只能查看自己的任务。

### Q7: 如何获取任务的完整详情?

**A**: 该接口返回的是任务列表的基本信息,如需获取单个任务的完整详情（包括所有关联数据和操作历史）,请使用:
- `GET /v1/mdm/tpm/maintenance-tasks/:taskId` 接口

### Q8: 为什么有些任务没有 maintenancePlan 信息?

**A**: 原因可能是:
1. **手动创建的任务**：手动创建的任务没有关联维护计划,`planId` 为 `null`
2. **计划已删除**：关联的维护计划已被删除
3. 在这种情况下,`maintenancePlan` 字段会返回 `null`

### Q9: 分页参数的最大限制是多少?

**A**:
- `page`: 无上限,但建议不要超过1000页（性能考虑）
- `limit`: 最小值1,最大值100
- 如果需要导出大量数据,建议使用导出接口而非大分页查询

### Q10: 如何判断任务是否逾期?

**A**:
1. 比较 `plannedStartTime` 与当前时间
2. 如果当前时间已过计划开始时间,且任务状态为"待执行"或"已延期",则为逾期任务
3. 也可以使用专门的逾期任务接口: `GET /v1/mdm/tpm/maintenance-tasks/overdue`

         ┌─────────────┐

                │         │

- **已完成** 和 **已取消** 为终态,不可再转换
