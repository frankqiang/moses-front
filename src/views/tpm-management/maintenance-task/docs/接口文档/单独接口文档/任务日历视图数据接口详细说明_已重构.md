## 功能概述

### 所有功能

任务日历视图数据（Calendar View Data）是设备TPM管理模块中的数据转换接口，用于将维护任务数据转换为适合日历展示的格式，以支持前端日历组件（如 FullCalendar、日程日历等）的数据渲染，实现维护任务的可视化管理。

本接口主要用于日历展示场景，将不同状态和类型的维护任务按照计划时间进行组织，提供清晰的任务时间分布视图。

### 关键特性

- ✅ **标准日历格式转换**：将任务数据转换为 iCalendar 兼容格式，支持主流日历组件（FullCalendar、Google Calendar、Outlook 等）
- ✅ **灵活的时间范围筛选**：支持按开始日期和结束日期范围查询，方便按月份、季度、年度进行查看
- ✅ **多维度筛选**：支持按设备、执行人员进行筛选，方便特定场景的日历查看
- ✅ **完整的任务关联信息**：返回结果包含任务标题、状态、类型、设备信息、执行人信息等完整数据
- ✅ **已取消任务自动过滤**：自动排除已取消的任务，确保日历数据的准确性
- ✅ **按计划时间排序**：结果按计划开始时间升序排列，便于日历展示

## 业务场景

### 适用场景

1. **维护计划日历展示**
   - 前端日历组件需要展示所有维护任务的时间分布
   - 用户通过日历快速浏览某个时间段的所有维护任务
   - 支持按月、周、日等不同视图切换

2. **个人工作日历管理**
   - 维护人员查看自己负责的所有维护任务的时间表
   - 通过 `assignedTo` 筛选器获取个人任务日历
   - 便于工作计划和任务调度

3. **设备维护日历追踪**
   - 查询特定设备在某个时间段内的所有维护任务
   - 通过 `equipmentId` 筛选器获取设备维护日历
   - 帮助预测设备停机时间和维护成本

4. **时间段业务分析**
   - 获取某个月份或季度内的所有维护任务数据
   - 通过 `startDate` 和 `endDate` 定义时间范围
   - 用于维护成本核算、工作量统计等

5. **日历事件导出**
   - 将维护任务导出为通用的日历格式（iCalendar）
   - 集成到第三方日程应用（Outlook、Google Calendar 等）
   - 支持多应用间的信息同步

### 使用前提

- ✅ 用户已登录并具有 `mdm.tpm.maintenance-task.view` 权限
- ✅ 时间范围参数（如 `startDate`、`endDate`）为有效的 ISO 8601 格式
- ✅ 筛选参数（如 `equipmentId`、`assignedTo`）为有效的 UUID 格式

### 不适用场景

- ❌ 需要完整的分页数据列表：应使用"查询维护任务列表"接口（支持完整筛选和分页）
- ❌ 需要单个任务的详细信息：应使用"查询单个维护任务"接口（包含更多关联数据）
- ❌ 需要任务负载统计和分析：应使用"任务负载分析"接口（提供统计数据）

### 详细步骤说明

#### 步骤1: 验证查询参数
- **验证内容**：
  - 日期格式：`startDate` 和 `endDate` 必须是有效的 ISO 8601 格式（如 "2024-01-20T08:00:00.000Z"）
  - UUID格式：`equipmentId` 和 `assignedTo` 必须是有效的 UUID 格式
  - 日期逻辑：如果同时提供 `startDate` 和 `endDate`，则 `endDate` 不能早于 `startDate`
- **失败响应**：HTTP 400，错误码 `VALIDATION_ERROR`
- **特殊说明**：所有查询参数都是可选的，不提供时返回所有有效的维护任务

#### 步骤2: 构建查询条件
- **操作内容**：根据提供的查询参数构建 Sequelize 查询条件
- **技术实现**：
  - 基础条件：`isDeleted: false`（排除软删除）且 `status: { [Op.notIn]: ['已取消'] }`（排除已取消）
  - `equipmentId`：精确匹配设备ID
  - `assignedTo`：精确匹配执行人ID
  - `startDate/endDate`：使用 `BETWEEN` 查询计划开始时间范围
- **特殊说明**：已取消的任务会被自动排除，不在日历中显示

#### 步骤3: 查询数据库
- **查询内容**：
  - 查询所有符合条件的维护任务
  - 加载关联的设备信息和执行人信息
- **技术实现**：
  - 使用 Sequelize 的 `findAll` 方法
  - 使用 `include` 加载 Equipment 和 User 关联
  - 按 `plannedStartTime` 升序排列
- **性能优化**：使用索引字段进行筛选，避免全表扫描

#### 步骤4: 格式转换
- **转换规则**：
  - 将任务的 `plannedStartTime` 映射为日历事件的 `start`
  - 将任务的 `plannedEndTime` 映射为日历事件的 `end`（如不存在则使用 `plannedStartTime`）
  - 提取任务的标题、状态、类型等核心信息
  - 提取关联的设备和执行人信息
- **结果结构**：每个日历事件都包含完整的任务信息，便于前端展示和交互

#### 步骤5: 返回数据
- **返回内容**：
  - 日历事件数组
  - 每个事件包含：id、title、start、end、status、taskType、equipment、assignee
- **数据结构**：符合统一响应格式，包含 success、data、message、meta

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/maintenance-tasks/calendar`

**功能描述**: 获取维护任务的日历视图数据，将任务数据转换为适合日历组件展示的格式，支持按时间范围、设备、执行人等维度进行筛选，用于日历视图展示、任务规划等场景。

**认证要求**: JWT Bearer Token，需要 `mdm.tpm.maintenance-task.view` 权限

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功

- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号


### 任务状态枚举

| 状态码 | 中文名称 | 说明                 | 备注                     |
| ------ | -------- | -------------------- | ------------------------ |
| 待执行 | 待执行   | 任务已创建，等待执行 | 日历中以灰色显示         |
| 执行中 | 执行中   | 任务正在执行中       | 日历中以琥珀色显示       |
| 已完成 | 已完成   | 任务已完成           | 日历中以绿色显示         |
| 已延期 | 已延期   | 任务已申请延期       | 日历中以橙色显示         |
| 已取消 | 已取消   | 任务已取消，不再执行 | 日历中不显示（自动过滤） |

| 类型码   | 中文名称 | 说明                       | 日历显示方式 |
| -------- | -------- | -------------------------- | ------------ |
| 计划维护 | 计划维护 | 根据维护计划定期执行的任务 | 蓝色事件     |

| 状态检修 | 状态检修 | 根据设备状态触发的检修任务 | 绿色事件     |

| 格式       | 描述             | 示例                       | 备注           |
| ---------- | ---------------- | -------------------------- | -------------- |

| 日期       | 仅日期部分       | "2024-01-20"               | 系统会自动转换 |
