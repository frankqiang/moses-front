> - `mdm.tpm.maintenance-task.manage`：管理维护任务（创建、派工、取消等管理操作）

## 维护任务管理业务流程说明

### 业务流程概述

```
步骤1：创建维护任务
   ↓
步骤2：任务派工（可选）
   ↓
步骤3：任务接单
   ↓
步骤4：开始执行任务
   ↓
步骤5：完成任务 → 自动生成维护记录
   ↓
（可选分支）
步骤6a：任务延期申请
步骤6b：取消任务
```

### 流程说明

- **步骤1**：管理员或调度员手动创建维护任务，支持计划维护、应急抢修、状态检修三种类型
- **步骤2**：管理员将任务派发给指定的维护人员（可选，也可以由人员自主接单）
- **步骤3**：维护人员接收任务
- **步骤4**：维护人员开始执行任务，设备状态自动更新为"维护中"
- **步骤5**：维护人员完成任务，记录维护详情，系统自动生成维护记录，设备状态恢复为"空闲"
- **步骤6a**：如需延期，维护人员可申请延期并说明原因
- **步骤6b**：如需取消，可取消任务并说明原因

## 维护任务管理接口详细说明

### 1. 创建维护任务

**接口路径**: `POST /v1/mdm/tpm/maintenance-tasks`

**功能描述**: 手动创建维护任务，支持计划维护、应急抢修、状态检修三种任务类型。可以选择性地指定执行人员，如果不指定则需要后续派工或人员自主接单。任务编码可以手动指定或系统自动生成。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名           | 类型   | 必填 | 限制                                   | 描述                                 | 示例                                   |
| ---------------- | ------ | ---- | -------------------------------------- | ------------------------------------ | -------------------------------------- |
| taskCode         | string | 否   | 最大100字符                            | 任务编码（不提供则自动生成）         | "MT-EQ001-1729012345678"               |
| planId           | string | 否   | UUID格式                               | 关联维护计划ID（计划维护时建议填写） | "a1b2c3d4-e5f6-7890-abcd-ef1234567890" |
| equipmentId      | string | 是   | UUID格式                               | 关联设备ID                           | "b2c3d4e5-f6a7-8901-bcde-f12345678901" |
| taskType         | string | 是   | 计划维护/应急抢修/状态检修             | 任务类型                             | "计划维护"                             |
| taskTitle        | string | 是   | 1-200字符                              | 任务标题                             | "退火炉日常维护"                       |
| taskDescription  | string | 否   | 无限制                                 | 任务描述                             | "检查加热元件、清洁炉体、测试温控系统" |
| plannedStartTime | string | 是   | ISO 8601格式                           | 计划开始时间                         | "2024-01-20T08:00:00.000Z"             |
| plannedEndTime   | string | 否   | ISO 8601格式，不能早于plannedStartTime | 计划结束时间                         | "2024-01-20T12:00:00.000Z"             |
| assignedTo       | string | 否   | UUID格式                               | 执行人员ID                           | "c3d4e5f6-a7b8-9012-cdef-123456789012" |
| remark           | string | 否   | 无限制                                 | 备注                                 | "请注意安全操作"                       |

### 3. 查询维护任务列表

**接口路径**: `GET /v1/mdm/tpm/maintenance-tasks`

**功能描述**: 根据条件分页查询维护任务列表，支持按设备、计划、任务类型、状态、执行人等条件筛选，支持关键词搜索和时间范围筛选。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
```

## 错误码说明

系统使用统一的错误码体系，便于客户端处理和日志追踪。错误码格式：模块前缀\_数字编号。

| TPM_TASK_002 | 400         | 维护任务编码已存在                           | 任务编码与已有任务重复           | 更换任务编码或使用自动生成 |

| TPM_TASK_011 | 400         | 只有待执行状态的任务才能接单                 | 任务当前状态不允许接单           | 检查任务状态               |

### 通用错误码

**参考认证模块文档中的通用错误码部分，包括：**
- 认证相关错误码 (AUTH_xxx)
- 验证相关错误码 (VAL_xxx / VALIDATION_ERROR)
- 业务逻辑错误码 (BIZ_xxx)
- 系统错误码 (SYS_xxx)

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理
   - `AUTH_`: 认证相关错误，可能需要重新登录或刷新令牌
   - `VAL_` / `VALIDATION_ERROR`: 验证相关错误，需要检查输入参数
   - `TPM_TASK_`: 维护任务业务错误，需要根据业务规则处理
   - `SYS_`: 系统错误，通常需要重试或联系支持

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息

4. **重试机制**: 对于包含 `retryAfter` 字段的错误，应按照指定时间后重试

5. **日志记录**: 使用 `traceId` 进行错误追踪和问题排查

- 所有数据变更记录操作人和操作时间
- 支持软删除，重要数据不会物理删除

### 使用建议

1. 妥善保管访问令牌，不要在前端代码中硬编码
2. 及时处理逾期任务，避免影响设备维护计划
3. 完成任务时详细记录维护内容，便于后续追溯
4. 合理使用延期功能，并说明延期原因
