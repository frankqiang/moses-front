## 功能概述

### 所有功能

获取维护计划执行率统计（Get Maintenance Plan Rate Statistics）是TPM统计分析模块中的核心统计操作之一,用于统计指定时间段内维护计划的执行率,支持按设备、设备类型和时间粒度筛选。该接口分析维护任务的完成情况,提供总体执行率和按时间段的详细统计,帮助管理者评估维护管理效率、识别执行延迟和瓶颈,为维护资源调配提供数据依据。

### 关键特性

- ✅ **总体执行率统计**:计算整个统计期内的总任务数、已完成任务数和总体执行率,提供宏观概览
- ✅ **时间段详细分析**:按日/周/月/年粒度分组统计各时间段的执行率,支持趋势分析和对比
- ✅ **多维度筛选**:支持按设备ID、设备类型筛选,实现不同维度的执行率统计
- ✅ **灵活时间粒度**:支持日/周/月/年四种时间粒度,适应不同周期的统计需求
- ✅ **百分比格式化**:执行率自动格式化为百分比形式,总体统计带%符号,明细数据不带%方便前端处理
- ✅ **软删除过滤**:自动排除已软删除的维护任务,确保统计数据的准确性

---

### 使用前提

- ✅ 用户已登录系统,持有有效的 JWT Token
- ✅ 用户具有TPM统计查看权限(`mdm.tpm.statistics.view`)
- ✅ 系统中已存在维护任务数据(若无数据则返回零值统计)
- ✅ 提供有效的时间范围参数(开始日期和结束日期必填,结束日期不能早于开始日期)

### 不适用场景

- ❌ 需要查询单个维护任务的详细信息,应使用维护任务查询接口
- ❌ 需要统计维护人员的工作量分布,应使用维护工作量统计接口
- ❌ 需要分析维护任务的延期情况,应使用维护任务管理模块的延期查询接口

### 详细步骤说明

#### 步骤1: 接收统计请求

- 接收客户端发送的 GET 请求
- 解析查询参数:时间范围(startDate、endDate)、设备筛选(equipmentId、equipmentType)、时间粒度(timePeriod)
- 提取请求头中的 Authorization Token

#### 步骤2: 验证用户身份和权限

- 验证 JWT Token 的有效性(签名、过期时间)
- 从 Token 中提取用户信息(用户 ID、角色等)
- 校验用户是否具有 `mdm.tpm.statistics.view` 权限
- 如果验证失败,返回 401(未授权)或 403(权限不足)错误

#### 步骤3: 验证统计参数

**必填参数校验**:
- `startDate`: 必填,必须是有效的ISO日期格式(YYYY-MM-DD)
- `endDate`: 必填,必须是有效的ISO日期格式,且不能早于startDate
- 如果缺少必填参数或格式错误,返回 400 验证错误

**可选参数校验**:
- `equipmentId`: 如果提供,必须是有效的UUID格式
- `equipmentType`: 如果提供,必须是有效的枚举值(退火炉/行车/自动料车/备料台)
- `timePeriod`: 如果提供,必须是有效的枚举值(日/周/月/年),默认为"月"

**日期范围合理性检查**:
- 验证结束日期 >= 开始日期
- 建议时间跨度不超过1年,避免查询性能问题

#### 步骤4: 构建筛选条件

**基础筛选条件**:
- 任务创建时间在 startDate 和 endDate 之间
- `isDeleted = false`: 排除软删除的任务

**设备筛选条件(可选)**:
- 如果提供 `equipmentId`: 添加条件 `equipmentId = :equipmentId`
- 如果提供 `equipmentType`: 关联设备表,添加条件 `equipment.equipmentType = :equipmentType`

**时间粒度处理**:
- 根据 `timePeriod` 参数确定 PostgreSQL 的 DATE_TRUNC 函数参数:
  - "日" → `DATE_TRUNC('day', createdAt)`
  - "周" → `DATE_TRUNC('week', createdAt)`
  - "月" → `DATE_TRUNC('month', createdAt)` (默认)
  - "年" → `DATE_TRUNC('year', createdAt)`

#### 步骤5: 统计总体数据

**执行总体统计查询**:
- 使用构建的筛选条件查询 `maintenance_tasks` 表
- 如果按设备类型筛选,关联 `equipment` 表

**统计指标计算**:
- `totalTasks`: 统计符合条件的任务总数 `COUNT(*)`
- `completedTasks`: 统计状态为"已完成"的任务数 `COUNT(*) WHERE status = '已完成'`
- `overallExecutionRate`: 计算总体执行率 = (completedTasks / totalTasks) × 100%
  - 如果 totalTasks = 0,执行率为 "0.00%"
  - 保留两位小数,带%符号

#### 步骤6: 按时间粒度分组统计

**分组查询**:
- 使用 DATE_TRUNC 函数按时间粒度对任务进行分组
- 对每个时间段统计:
  - `period`: 时间段起始时间(ISO格式)
  - `totalTasks`: 该时间段的总任务数
  - `completedTasks`: 该时间段的已完成任务数
  - `executionRate`: 该时间段的执行率(不带%符号)

**时间段排序**:
- 按时间段升序排列(从早到晚)
- 确保时间序列的连续性

#### 步骤7: 计算执行率百分比

**总体执行率计算**:
- 公式: `(completedTasks / totalTasks) × 100`
- 格式化为字符串,保留2位小数,添加%符号
- 示例: "90.00%"

**明细执行率计算**:
- 对每个时间段应用相同公式
- 格式化为字符串,保留2位小数,不带%符号(方便前端图表使用)
- 示例: "90.00"
- 如果某时间段 totalTasks = 0,执行率为 "0.00"

**数值精度控制**:
- 使用 `toFixed(2)` 确保两位小数
- 避免浮点数精度问题

#### 步骤8: 构建响应数据

**响应结构构建**:

1. **summary 对象(总体摘要)**:
   - `totalTasks`: 统计期内总任务数
   - `completedTasks`: 统计期内已完成任务数
   - `overallExecutionRate`: 总体执行率(带%符号)

2. **details 数组(时间段明细)**:
   - 每个元素包含:
     - `period`: 时间段起始时间(ISO格式)
     - `totalTasks`: 该时间段总任务数
     - `completedTasks`: 该时间段已完成任务数
     - `executionRate`: 该时间段执行率(不带%符号)
   - 按时间顺序排列

3. **timePeriod 字段**:
   - 返回本次统计使用的时间粒度(日/周/月/年)

**空数据处理**:
- 如果没有任何任务数据:
  - summary 中的数值为 0
  - overallExecutionRate 为 "0.00%"
  - details 为空数组 []

#### 步骤9: 返回统计结果

- 构建统一成功响应格式
- `success: true`
- `data`: 包含 summary、details 和 timePeriod
- `message`: "获取维护计划执行率统计成功"
- `meta`: 响应元信息(时间戳、请求ID、API版本)

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/statistics/maintenance-plan-rate`

**功能描述**: 统计指定时间段内维护计划的执行率,支持按设备和设备类型筛选,支持按日/周/月/年粒度分组统计。返回总体执行率摘要和按时间段的详细执行率统计,帮助管理者评估维护管理效率。

**认证要求**: JWT Bearer Token,需要 `mdm.tpm.statistics.view` 权限

### 查询参数

| 参数名        | 类型   | 必填 | 限制                             | 描述                  | 默认值 | 示例                                   |
| ------------- | ------ | ---- | -------------------------------- | --------------------- | ------ | -------------------------------------- |
| startDate     | string | 是   | ISO日期格式(YYYY-MM-DD)          | 开始日期              | 无     | "2024-01-01"                           |
| endDate       | string | 是   | ISO日期格式,不能早于开始日期     | 结束日期              | 无     | "2024-03-31"                           |
| equipmentId   | string | 否   | UUID格式                         | 设备ID筛选            | null   | "123e4567-e89b-12d3-a456-426614174000" |

  - "周": 按周分组(周一为起始),适用于1-3个月的周度分析
  - "月": 按月分组,适用于季度、半年度、年度分析(默认)
  - "年": 按年分组,适用于多年长期趋势分析

### 时间粒度说明

| 粒度 | 中文名称 | DATE_TRUNC参数 | 时间段起始点       | 适用场景           | 示例                       |
| ---- | -------- | -------------- | ------------------ | ------------------ | -------------------------- |
| 日   | 按天     | 'day'          | 当天00:00:00       | 1-2周短期分析      | "2024-03-15T00:00:00.000Z" |
| 周   | 按周     | 'week'         | 该周周一00:00:00   | 1-3个月周度分析    | "2024-03-11T00:00:00.000Z" |

  - 日粒度: ≤ 2周
  - 周粒度: ≤ 3个月
  - 月粒度: ≤ 2年
  - 年粒度: 不限

### 维护任务状态说明

| 状态码 | 中文名称   | 说明                   | 是否计入完成数 |
| ------ | ---------- | ---------------------- | -------------- |
| 待执行 | Pending    | 任务已创建,等待执行    | 否             |
| 执行中 | InProgress | 任务正在执行           | 否             |
| 已完成 | Completed  | 任务已成功完成         | **是**         |
| 已延期 | Overdue    | 任务未在计划时间内完成 | 否             |
| 已取消 | Cancelled  | 任务被取消             | 否             |

**重要说明**:
- 只有状态为"已完成"的任务才计入 `completedTasks`
- "已延期"的任务如果后续完成,状态会变更为"已完成",此时才计入完成数
- "已取消"的任务仍计入 `totalTasks`,但不计入完成数

### 执行率计算公式

**总体执行率**:
```
overallExecutionRate = (completedTasks / totalTasks) × 100%
```

**时间段执行率**:
```
executionRate = (该时间段completedTasks / 该时间段totalTasks) × 100
```

**特殊情况处理**:
- 当 `totalTasks = 0` 时,执行率为 `0.00%` 或 `0.00`
- 数值保留2位小数,使用四舍五入
- 总体摘要中带%符号,明细数据中不带%符号

### 常见问题 FAQ

**Q1: 执行率统计的时间基准是什么?**
A: 统计基于维护任务的创建时间(`createdAt`),而非计划执行时间或实际完成时间。这样可以评估计划制定后的实际执行情况。

**Q2: "已延期"的任务是否计入完成率?**
A: "已延期"状态的任务不计入已完成任务数。只有状态为"已完成"的任务才计入完成数。如果延期任务后续完成,状态会变为"已完成",此时才会计入。

**Q3: 为什么总体执行率和各时间段执行率加权平均不一致?**
A: 总体执行率是基于整个时间段的总任务数和总完成数直接计算的,而各时间段的执行率是各时间段独立计算的。由于各时间段任务数不同,加权平均可能略有差异,但总体执行率是准确的整体指标。

**Q4: 如何理解周粒度的时间段起始点?**
A: 周粒度遵循ISO 8601标准,周一为一周的开始。例如3月15日(周五)属于3月11日(周一)开始的那一周,其 `period` 为 "2024-03-11T00:00:00.000Z"。

**Q5: 查询指定设备时,equipmentId和equipmentType能否同时使用?**
A: 建议只使用其中一个。如果同时提供,系统会优先使用equipmentId。通常:
- 查询单设备用equipmentId
- 查询同类设备用equipmentType

**Q6: 返回的执行率有的带%有的不带,为什么?**
A: 这是有意的设计:
- `summary.overallExecutionRate` 带%符号,直接展示给用户
- `details[].executionRate` 不带%符号,方便前端图表库使用(大多数图表库需要纯数值)

**Q7: 如果查询时间段内没有任何任务怎么办?**
A: 接口会正常返回,但:
- `summary.totalTasks = 0`
- `summary.completedTasks = 0`
- `summary.overallExecutionRate = "0.00%"`
- `details = []` (空数组)

**Q8: 可以查询历史很久以前的数据吗?**
A: 技术上可以,但:
- 建议查询时间跨度不超过1年
- 查询远古数据可能较慢
- 对于长期趋势,建议使用"年"粒度
