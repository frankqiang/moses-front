## 功能概述

### 所有功能

获取TPM综合看板数据（Dashboard Overview）是TPM统计分析模块中的核心接口之一，用于提供设备全生命周期管理（Total Productive Maintenance）的整体状况视图，以支持管理驾驶舱、生产监控和决策分析的业务场景。

该接口聚合了设备状态、维护任务、故障处理、备件管理等多个维度的关键指标，为管理者提供TPM管理的全局视图和实时洞察。

### 关键特性

- ✅ **多维度数据聚合**：整合设备、维护、故障、备件四大维度的关键指标，提供全面的TPM管理视图
- ✅ **实时数据统计**：基于当前月份的实时数据，反映最新的TPM管理状况
- ✅ **智能指标计算**：自动计算设备可用率、任务完成率、故障解决率等关键KPI指标
- ✅ **灵活筛选能力**：支持按设备类型筛选，满足不同管理维度的查看需求
- ✅ **低库存预警**：实时监控备件库存状况，识别低库存备件数量
- ✅ **清晰数据结构**：按业务模块组织响应数据，便于前端展示和数据可视化

---

### 使用前提

- ✅ **认证要求**：用户必须已登录并持有有效的JWT访问令牌
- ✅ **权限要求**：用户必须具备 `mdm.tpm.statistics.view` 权限
- ✅ **数据基础**：系统中需要有设备、维护任务、故障、备件等基础数据
- ✅ **时间范围**：接口默认统计当前月份数据（从当月1号到当前日期）

### 不适用场景

- ❌ **历史数据对比分析**：本接口仅提供当月数据，不支持自定义时间范围，如需历史对比请使用专项统计接口
- ❌ **设备明细查询**：本接口仅提供汇总统计数据，不包含设备列表明细，如需查看设备详情请使用设备管理接口
- ❌ **数据导出功能**：本接口为实时查询接口，不支持数据导出，如需导出请联系管理员

### 详细步骤说明

#### 步骤1: 接收并验证请求参数
- **功能**: 接收客户端请求，获取可选的设备类型筛选参数
- **验证规则**:
  - equipmentType: 可选，如提供必须是有效的枚举值（退火炉/行车/自动料车/备料台）
  - timePeriod: 可选参数，当前版本保留但不影响统计范围
- **异常处理**: 参数格式错误时返回400错误

#### 步骤2: 验证用户认证
- **功能**: 验证请求头中的JWT Token是否有效
- **验证内容**:
  - Token格式是否正确
  - Token是否在有效期内
  - Token是否已被撤销或加入黑名单
- **异常处理**: 认证失败返回401 UNAUTHORIZED错误

#### 步骤3: 验证用户权限
- **功能**: 检查当前用户是否具有查看TPM统计数据的权限
- **权限代码**: `mdm.tpm.statistics.view`
- **验证逻辑**: 查询用户角色权限表，验证是否包含所需权限
- **异常处理**: 权限不足返回403 FORBIDDEN错误

#### 步骤4: 确定统计时间范围
- **功能**: 自动计算当前月份的统计时间范围
- **计算逻辑**:
  - 开始时间: 当前月份第1天的00:00:00
  - 结束时间: 当前日期的23:59:59
  - 示例: 2024-10-15查询时，范围为 2024-10-01 00:00:00 至 2024-10-15 23:59:59
- **筛选条件**: 如提供equipmentType参数，则在查询中增加设备类型筛选条件

#### 步骤5: 并行查询设备状态统计
- **查询内容**:
  - 统计各状态设备数量（运行/停机/维护/故障）
  - 如有设备类型筛选，仅统计该类型设备
- **计算指标**:
  - totalEquipment: 设备总数
  - runningEquipment: 运行状态设备数
  - maintenanceEquipment: 维护状态设备数
  - faultEquipment: 故障状态设备数
  - availabilityRate: 设备可用率 = (运行设备数 + 停机设备数) / 设备总数 × 100%
- **数据来源**: equipment表（设备主数据表）

#### 步骤6: 并行查询维护任务统计
- **查询条件**: 计划维护时间在统计范围内的任务
- **统计内容**:
  - totalTasks: 本月维护任务总数
  - completedTasks: 已完成状态的任务数
  - inProgressTasks: 执行中状态的任务数
  - overdueTasks: 已延期状态的任务数（计划完成时间已过但未完成）
- **计算指标**:
  - completionRate: 任务完成率 = 已完成任务数 / 总任务数 × 100%
- **数据来源**: maintenance_tasks表（维护任务表）

#### 步骤7: 并行查询故障处理统计
- **查询条件**: 故障发生时间在统计范围内的记录
- **统计内容**:
  - totalFailures: 本月故障总数
  - severeFailures: I级严重故障数（故障等级='I级-严重'）
  - resolvedFailures: 已解决的故障数（状态='已解决'）
- **计算指标**:
  - resolutionRate: 故障解决率 = 已解决故障数 / 故障总数 × 100%
- **数据来源**: failure_records表（故障记录表）

#### 步骤8: 并行查询备件消耗统计
- **查询条件**: 领用时间在统计范围内的备件记录
- **统计内容**:
  - totalTransactions: 本月备件领用记录数
  - totalQuantity: 本月备件领用总数量（sum of quantity）
  - totalCost: 本月备件消耗总成本（sum of quantity × unit_price）
  - lowStockCount: 当前低库存备件数量（库存量 ≤ 安全库存量的备件数）
- **数据来源**:
  - spare_part_transactions表（备件领用记录表）
  - spare_parts表（备件主数据表）

#### 步骤9: 计算关键KPI指标
- **设备可用率**:
  - 公式: (runningEquipment + idleEquipment) / totalEquipment × 100
  - 精度: 保留2位小数
  - 格式: 不带%符号的字符串（如"80.00"）
- **任务完成率**:
  - 公式: completedTasks / totalTasks × 100
  - 精度: 保留2位小数
  - 特殊处理: 当totalTasks=0时，返回"0.00"
- **故障解决率**:
  - 公式: resolvedFailures / totalFailures × 100
  - 精度: 保留2位小数
  - 特殊处理: 当totalFailures=0时，返回"100.00"

#### 步骤10: 组装响应数据
- **数据结构**: 按四大模块组织数据
  - equipmentOverview: 设备状态概览
  - maintenanceOverview: 维护任务概览
  - failureOverview: 故障处理概览
  - sparePartOverview: 备件管理概览
  - reportPeriod: 报告时间范围
- **数据格式化**:
  - 百分比字段使用字符串类型，保留2位小数，不带%符号
  - 成本字段使用字符串类型，保留2位小数
  - 日期字段使用ISO 8601标准格式
- **元数据添加**: 添加timestamp、requestId、version等元信息

#### 步骤11: 返回成功响应
- **HTTP状态码**: 200 OK
- **响应格式**: 统一的成功响应格式
- **日志记录**: 记录查询成功日志，包含用户ID、统计范围、响应时间等信息

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/dashboard`

**功能描述**: 获取TPM管理的综合看板数据，包括设备状态、维护任务、故障处理、备件管理四大维度的关键指标，默认统计当前月份的数据，为管理驾驶舱提供实时的TPM管理全局视图。

**认证要求**: JWT Bearer Token，需要 `mdm.tpm.statistics.view` 权限

## 统一响应格式说明

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",

```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号


**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

#### 设备状态概览字段（equipmentOverview 对象）

| 字段名               | 类型    | 说明                                                                   | 示例值  |
| -------------------- | ------- | ---------------------------------------------------------------------- | ------- |
| totalEquipment       | integer | 设备总数（筛选范围内）                                                 | 20      |
| runningEquipment     | integer | 运行状态的设备数量                                                     | 16      |
| maintenanceEquipment | integer | 维护状态的设备数量                                                     | 2       |
| faultEquipment       | integer | 故障状态的设备数量                                                     | 2       |
| availabilityRate     | string  | 设备可用率，计算公式：(运行数+停机数)/总数×100，保留2位小数，不带%符号 | "80.00" |

**可用率计算说明**:
- 可用设备 = 运行状态 + 停机状态（停机是正常状态，设备可随时启动）
- 不可用设备 = 维护状态 + 故障状态
- 可用率 = 可用设备数 / 设备总数 × 100%

#### 维护任务概览字段（maintenanceOverview 对象）

| 字段名          | 类型    | 说明                                                                    | 示例值  |
| --------------- | ------- | ----------------------------------------------------------------------- | ------- |
| totalTasks      | integer | 本月维护任务总数（计划维护时间在当月的任务）                            | 45      |
| completedTasks  | integer | 本月已完成的任务数                                                      | 40      |
| inProgressTasks | integer | 本月执行中的任务数                                                      | 3       |
| overdueTasks    | integer | 本月已延期的任务数（计划完成时间已过但未完成）                          | 2       |
| completionRate  | string  | 本月任务完成率，计算公式：已完成数/总任务数×100，保留2位小数，不带%符号 | "88.89" |

**任务统计说明**:
- 统计范围: 计划维护时间（plannedMaintenanceDate）在当月的所有任务
- 状态判断: 基于任务的status字段（待执行/执行中/已完成/已延期/已取消）
- 完成率计算: 只统计已完成任务，不包括已取消任务

#### 故障处理概览字段（failureOverview 对象）

| 字段名           | 类型    | 说明                                                                    | 示例值  |
| ---------------- | ------- | ----------------------------------------------------------------------- | ------- |
| totalFailures    | integer | 本月故障总数（故障发生时间在当月）                                      | 15      |
| severeFailures   | integer | 本月严重故障数（故障等级='I级-严重'）                                   | 2       |
| resolvedFailures | integer | 本月已解决的故障数                                                      | 12      |
| resolutionRate   | string  | 本月故障解决率，计算公式：已解决数/总故障数×100，保留2位小数，不带%符号 | "80.00" |

**故障统计说明**:
- 统计范围: 故障发生时间（failureDate）在当月的所有故障记录
- 严重故障: 故障等级为'I级-严重'的故障，需要重点关注
- 解决率: 已处理完成的故障数占总故障数的比例

#### 备件管理概览字段（sparePartOverview 对象）

| 字段名            | 类型    | 说明                                               | 示例值     |
| ----------------- | ------- | -------------------------------------------------- | ---------- |
| totalTransactions | integer | 本月备件领用记录总数                               | 58         |
| totalQuantity     | integer | 本月备件领用总数量（所有领用记录的数量之和）       | 125        |
| totalCost         | string  | 本月备件消耗总成本（数量×单价的总和），保留2位小数 | "18650.00" |
| lowStockCount     | integer | 当前低库存备件数量（库存量≤安全库存量的备件数）    | 5          |

**备件统计说明**:
- 领用统计: 基于备件领用记录的领用时间（issueDate）在当月
- 成本计算: sum(quantity × unitPrice)
- 低库存: 当前库存量（currentStock）≤ 安全库存量（safetyStock）的备件

#### 报告时间范围字段（reportPeriod 对象）

| 字段名     | 类型   | 说明                                         | 示例值       |
| ---------- | ------ | -------------------------------------------- | ------------ |
| startDate  | string | 统计开始日期（当月1日），YYYY-MM-DD格式      | "2024-10-01" |
| endDate    | string | 统计结束日期（当月最后一日），YYYY-MM-DD格式 | "2024-10-31" |
| timePeriod | string | 时间粒度，当前固定为"月"                     | "月"         |

#### 响应元信息（meta 对象）

| 字段名    | 类型   | 说明                       | 示例值                     |
| --------- | ------ | -------------------------- | -------------------------- |
| timestamp | string | 响应时间戳（ISO 8601格式） | "2024-01-21T09:00:00.000Z" |
| requestId | string | 请求追踪ID                 | "req-1234567890-abcdef"    |
| version   | string | API版本号                  | "v1"                       |

### 错误响应

| HTTP状态码 | 错误码           | 错误消息                | 说明                         | 处理建议                                  |
| ---------- | ---------------- | ----------------------- | ---------------------------- | ----------------------------------------- |
| 400        | VALIDATION_ERROR | 请求参数验证失败        | 请求参数不符合验证规则       | 检查equipmentType参数是否为有效枚举值     |
| 400        | VALIDATION_ERROR | 设备类型参数无效        | 设备类型不在允许的枚举值范围 | 使用正确的设备类型枚举值                  |
| 401        | UNAUTHORIZED     | 未授权，Token无效或过期 | 未提供认证Token或Token已失效 | 重新登录获取有效Token                     |
| 403        | FORBIDDEN        | 无权限执行此操作        | 当前用户没有查看统计的权限   | 联系管理员分配mdm.tpm.statistics.view权限 |

## 常见问题

### Q1: 为什么接口只返回当月数据，不支持自定义时间范围？

**A**: 本接口设计为快速展示当前TPM管理状况的看板接口，聚焦于"当前"状态和"本月"趋势。如需查询历史数据或自定义时间范围，请使用专项的统计分析接口：
- 维护计划执行率统计：`GET /v1/mdm/tpm/statistics/maintenance-plan-rate`
- 故障汇总统计：`GET /v1/mdm/tpm/statistics/failure-summary`
- MTTR趋势分析：`GET /v1/mdm/tpm/statistics/mttr-trend`
- 备件消耗分析：`GET /v1/mdm/tpm/statistics/spare-part-consumption`

### Q2: 设备可用率是如何计算的？

**A**: 设备可用率计算公式如下：
```
可用率 = (运行中设备数 + 停机设备数) / 设备总数 × 100%
```

**说明**：
- 可用设备：运行状态 + 停机状态（停机是正常状态，设备可随时启动投入使用）
- 不可用设备：维护状态 + 故障状态（设备无法立即投入使用）
- 例如：总20台，运行16台，停机0台，维护2台，故障2台
  - 可用率 = (16 + 0) / 20 × 100% = 80.00%

### Q3: 响应中的百分比字段为什么不带%符号？

**A**: 为了便于前端进行数值计算和比较，响应中的百分比字段（如availabilityRate、completionRate等）采用不带%符号的字符串格式（如"80.00"）。前端可以：
- 直接用于数值比较：`parseFloat(availabilityRate) >= 85`
- 展示时添加%符号：`${availabilityRate}%`
- 用于图表绘制：直接转换为数值使用

### Q4: 如何理解"低库存备件"的定义？

**A**: 低库存备件是指当前库存量已低于或等于安全库存量的备件：
```
低库存条件：当前库存量 ≤ 安全库存量
```

**安全库存量**是在备件主数据中预先设置的最低库存警戒线，用于确保关键备件不会断货。当备件库存低于此值时，系统会将其标记为低库存状态，提醒管理员及时补充。

**示例**：
- 备件A：当前库存5个，安全库存10个 → 低库存（5 ≤ 10）
- 备件B：当前库存15个，安全库存10个 → 正常（15 > 10）

### Q5: 接口返回数据的时效性如何？是实时数据吗？

**A**: 是的，接口返回的是实时数据：
- 设备状态：查询设备表的当前状态字段，反映设备的实时状态
- 维护任务：统计本月所有维护任务的最新状态
- 故障记录：统计本月所有故障的最新处理状态
- 备件领用：统计本月所有备件领用记录

数据从数据库实时查询，不使用缓存，确保展示的数据是最新的。对于高频访问场景（如管理驾驶舱），建议在前端实现适当的缓存策略（如每5-10分钟刷新一次）。

### Q6: 如果某个统计维度没有数据会返回什么？

**A**: 如果某个统计维度没有数据，会返回零值或空数据，不会省略该字段：

这样可以确保响应结构的一致性，前端无需进行字段存在性判断。

### Q7: 按设备类型筛选时，备件统计会受影响吗？

**A**: 会的，当提供equipmentType参数时，所有统计维度都会受到筛选的影响：

- **设备状态统计**：仅统计该类型设备
- **维护任务统计**：仅统计该类型设备的维护任务
- **故障处理统计**：仅统计该类型设备的故障记录
- **备件消耗统计**：仅统计用于该类型设备的备件领用记录

**示例**：
```
GET /v1/mdm/tpm/dashboard?equipmentType=退火炉
```
返回的所有数据都只包含退火炉相关的统计信息。

### Q8: 任务完成率为何计算时不包括已取消任务？

**A**: 任务完成率的计算遵循以下逻辑：
```
完成率 = 已完成任务数 / 总任务数 × 100%
```

**总任务数**包括所有状态的任务（待执行、执行中、已完成、已延期、已取消），因为：
- **已取消任务**也需要纳入统计，反映实际的任务管理情况
- 如果大量任务被取消，会导致完成率下降，这正是管理层需要关注的指标
- 区分"已完成"和"已取消"，可以帮助分析任务执行效率和计划的合理性

如果需要排除已取消任务的统计，可以使用专项的维护计划执行率统计接口，并通过参数控制统计范围。

### Q9: 响应时间慢怎么办？

**A**: 如果接口响应时间较长，可以采取以下优化措施：

**前端优化**：
- 实现数据缓存，避免频繁请求
- 使用Loading状态提升用户体验
- 在非关键页面使用懒加载

**后端优化**（需联系技术团队）：
- 数据库索引优化
- 添加Redis缓存层
- 优化SQL查询语句
- 使用数据库物化视图

**架构优化**：
- 对于大屏展示等高频场景，可考虑使用WebSocket推送机制
- 实现服务器端缓存，定期预计算统计数据
