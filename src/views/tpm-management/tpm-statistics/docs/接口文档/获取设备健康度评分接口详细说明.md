## 功能概述

### 所有功能

获取设备健康度评分（Equipment Health Score）是设备TPM管理模块中TPM统计分析子模块的核心接口之一,用于基于故障频率、维护完成率、修复时间等多个维度综合评估设备健康状况,以支持设备预防性维护决策、设备状态监控、维护资源优化分配等业务场景。

该接口通过科学的评分算法,将设备的各项运行和维护指标量化为0-100分的健康度评分,并根据评分划分为优秀、良好、一般、差四个等级,帮助管理者快速识别需要重点关注的设备,实现从被动维修到主动维护的转变。

### 关键特性

- ✅ **多维度综合评估**：基于故障频率、维护完成率、平均修复时间、距离上次维护天数、设备当前状态等5个维度进行综合评分,全面反映设备健康状况
- ✅ **科学评分算法**：采用扣分制评分模型,初始分100分,根据各项指标的风险等级进行相应扣分,评分逻辑清晰透明可追溯
- ✅ **智能健康分级**：自动将评分划分为优秀(90-100分)、良好(75-89分)、一般(60-74分)、差(0-59分)四个等级,便于快速识别问题设备
- ✅ **灵活筛选排序**：支持按设备ID、设备类型筛选,支持按健康评分、设备编码、最近维护时间排序,满足不同管理场景需求
- ✅ **统计汇总分析**：提供设备总数、平均健康度评分、各健康等级设备数量统计,帮助把握整体设备健康状况
- ✅ **详细指标展示**：返回每台设备的故障次数、维护完成率、平均修复时间、距离上次维护天数等详细指标,支持深度分析

---

### 使用前提

- ✅ **权限要求**：用户需具备 `mdm.tpm.statistics.view` 权限,能够查看TPM统计数据
- ✅ **认证要求**：请求必须携带有效的JWT Bearer Token进行身份认证
- ✅ **数据要求**：系统中需要有设备基础数据、故障记录、维护任务记录等历史数据,否则评分可能不准确
- ✅ **时间范围**：健康度评分基于最近3个月的数据计算,建议系统运行3个月以上后使用该接口

### 不适用场景

- ❌ **新设备评估**：刚投入使用不足3个月的设备,因缺少足够的历史数据,评分可能不够准确,建议参考其他指标
- ❌ **已报废设备**：已标记为报废或停用的设备不参与健康度评分统计

### 详细步骤说明

#### 步骤1: 接收查询请求与权限验证

**功能描述**：
- 接收客户端发送的GET请求
- 验证JWT Token的有效性
- 检查用户是否具备 `mdm.tpm.statistics.view` 权限

**校验规则**：
- Token必须有效且未过期
- 用户必须拥有查看TPM统计数据的权限

**异常处理**：
- Token无效或过期：返回401 UNAUTHORIZED
- 权限不足：返回403 FORBIDDEN

#### 步骤2: 参数验证

**功能描述**：
- 验证查询参数的格式和取值范围
- 设置默认值

**参数验证规则**：
- `equipmentId`：如提供必须是有效的UUID格式
- `equipmentType`：如提供必须是枚举值之一(退火炉/行车/自动料车/备料台)
- `limit`：如提供必须在1-100之间,默认20
- `sortBy`：如提供必须是枚举值之一(healthScore/equipmentCode/lastMaintenance),默认healthScore
- `sortOrder`：如提供必须是asc或desc,默认asc

**异常处理**：
- 参数格式错误：返回400 VALIDATION_ERROR
- 参数取值超出范围：返回400 VALIDATION_ERROR

#### 步骤3: 查询设备列表

**功能描述**：
- 根据筛选条件查询设备列表
- 关联查询设备的基础信息

**查询逻辑**：
- 如指定equipmentId,则只查询该设备
- 如指定equipmentType,则查询该类型的所有设备
- 未指定任何筛选条件,则查询所有设备
- 排除已报废和已停用的设备

**数据库操作**：
```sql
SELECT * FROM equipment
WHERE
  (equipmentId = :equipmentId OR :equipmentId IS NULL)
  AND (equipmentType = :equipmentType OR :equipmentType IS NULL)
  AND status NOT IN ('已报废', '已停用')
```

#### 步骤4: 开启事务

**功能描述**：
- 开启数据库事务确保数据一致性
- 为后续的多表查询和计算提供事务保护

**事务特性**：
- 隔离级别：READ COMMITTED
- 事务范围：包括所有统计查询和计算

#### 步骤5: 计算健康度评分

**功能描述**：
- 针对每台设备,基于多个维度进行健康度评分
- 采用扣分制,初始100分

**评分维度详解**：

##### 5.1 故障次数评估
- 统计最近3个月的故障总数
- 扣分规则：
  - 0-3次：不扣分
  - 4-6次：扣15分
  - 7次以上：扣30分

##### 5.2 维护完成率评估
- 计算最近3个月维护任务完成率
- 扣分规则：
  - 95%以上：不扣分
  - 80-94%：扣10分
  - 80%以下：扣20分

##### 5.3 修复时间评估
- 计算平均故障修复时间(MTTR)
- 扣分规则：
  - 8小时以内：不扣分
  - 8-24小时：扣5分
  - 24小时以上：扣15分

##### 5.4 维护间隔评估
- 计算距离上次维护的天数
- 扣分规则：
  - 90天以内：不扣分
  - 90-180天：扣10分
  - 180天以上：扣15分

##### 5.5 设备状态评估
- 评估当前设备状态
- 扣分规则：
  - 运行/停机：不扣分
  - 维护中：扣5分
  - 故障中：扣20分

**计算示例**：
某设备评分计算过程：
- 初始分：100分
- 故障次数8次：-30分
- 维护完成率75%：-20分
- 平均修复时间12小时：-5分
- 距离上次维护95天：-10分
- 当前状态运行：-0分
- 最终评分：100-30-20-5-10-0 = 35分

#### 步骤6: 划分健康等级

**功能描述**：
- 根据计算出的健康度评分划分健康等级

**等级划分规则**：
- 优秀：90-100分
- 良好：75-89分
- 一般：60-74分
- 差：0-59分

#### 步骤7: 统计汇总计算

**功能描述**：
- 计算所有设备的统计汇总数据

**汇总指标**：
- 设备总数：参与评分的设备数量
- 平均健康度评分：所有设备评分的算术平均值
- 各等级设备数量：统计优秀、良好、一般、差各等级的设备数量

#### 步骤8: 应用排序规则和数量限制

**功能描述**：
- 根据sortBy和sortOrder参数对结果排序
- 根据limit参数限制返回数量

**排序规则**：
- sortBy=healthScore：按健康度评分排序
- sortBy=equipmentCode：按设备编码排序
- sortBy=lastMaintenance：按最近维护时间排序
- sortOrder=asc：升序排列
- sortOrder=desc：降序排列

**应用场景**：
- 查找最健康的设备：sortBy=healthScore, sortOrder=desc
- 查找最需要关注的设备：sortBy=healthScore, sortOrder=asc
- 查找最久未维护的设备：sortBy=lastMaintenance, sortOrder=asc

#### 步骤9: 提交事务

**功能描述**：
- 提交数据库事务
- 释放数据库资源

#### 步骤10: 返回评分结果

**功能描述**：
- 将统计汇总和设备健康度详情封装为统一响应格式
- 返回给客户端

**响应内容**：
- summary：统计汇总信息
- equipmentHealth：设备健康度详情列表

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/statistics/equipment-health`

**功能描述**: 基于多维度指标评估设备健康状况,计算健康度评分(0-100分)并划分健康等级,支持按设备筛选和多种排序方式,帮助识别需要重点关注的设备。评分基于最近3个月的数据计算。

**认证要求**: JWT Bearer Token,需要 `mdm.tpm.statistics.view` 权限

### 查询参数

| 参数名        | 类型    | 必填 | 限制                                            | 描述                       | 默认值      | 示例                                 |
| ------------- | ------- | ---- | ----------------------------------------------- | -------------------------- | ----------- | ------------------------------------ |
| equipmentId   | string  | 否   | UUID格式                                        | 设备ID筛选                 | null        | 123e4567-e89b-12d3-a456-426614174000 |
| equipmentType | string  | 否   | 枚举：退火炉/行车/自动料车/备料台               | 设备类型筛选               | null        | 退火炉                               |
| limit         | integer | 否   | 最小值：1，最大值：100                          | 返回数量限制               | 20          | 50                                   |
| sortBy        | string  | 否   | 枚举：healthScore/equipmentCode/lastMaintenance | 排序字段                   | healthScore | healthScore                          |
| sortOrder     | string  | 否   | 枚举：asc/desc                                  | 排序方式，asc升序/desc降序 | asc         | asc                                  |

**查询参数说明**：

- **equipmentId**：指定具体设备ID时,只返回该设备的健康度评分
- **equipmentType**：按设备类型筛选,如只查看退火炉的健康度评分
- **limit**：控制返回结果数量,用于分页或仅查看重点设备
- **sortBy**：
  - `healthScore`：按健康度评分排序,适用于查找最健康或最不健康的设备
  - `equipmentCode`：按设备编码排序,适用于按设备编号顺序查看
  - `lastMaintenance`：按最近维护时间排序,适用于查找最久未维护的设备
- **sortOrder**：
  - `asc`：升序,健康度评分从低到高(用于查找最需关注的设备)
  - `desc`：降序,健康度评分从高到低(用于查找最健康的设备)

## 常见问题

### Q1: 健康度评分的计算周期是多久？

**A**: 健康度评分基于最近3个月的数据计算。具体包括：
- 故障次数：统计最近3个月的故障总数
- 维护完成率：计算最近3个月维护任务的完成率
- 平均修复时间：计算最近3个月所有故障的平均修复时间
- 距离上次维护：从最近一次维护日期到当前日期的天数
- 设备状态：实时的设备当前状态

建议系统运行3个月以上后再使用该接口，以确保评分的准确性。

### Q2: 为什么某些设备的健康度评分很低？

**A**: 健康度评分采用扣分制，主要从以下5个维度评估：

1. **故障频率高**：最近3个月故障7次以上会扣30分
2. **维护完成率低**：维护任务完成率低于80%会扣20分
3. **修复时间长**：平均修复时间超过24小时会扣15分
4. **维护间隔过长**：距离上次维护超过180天会扣15分
5. **设备状态异常**：设备处于故障状态会扣20分

建议查看具体设备的各项指标（failureCount、maintenanceCompletionRate、avgMTTR、daysSinceLastMaintenance、status），找出影响评分的主要因素，针对性改善。

### Q3: 如何解读不同的健康等级？

**A**: 健康等级分为4级，对应不同的管理策略：

| 健康等级 | 评分范围 | 设备状况     | 管理建议                                     |
| -------- | -------- | ------------ | -------------------------------------------- |
| 优秀     | 90-100分 | 状态良好     | 维持现有维护计划，作为标杆设备               |
| 良好     | 75-89分  | 正常运行     | 继续执行常规维护，注意监控趋势变化           |
| 一般     | 60-74分  | 需要关注     | 增加维护频次，制定改善计划，定期复查         |
| 差       | 0-59分   | 存在重大风险 | 立即安排全面检查，制定专项改善计划，重点监控 |

### Q4: sortBy和sortOrder参数如何选择？

**A**: 根据不同的业务场景选择合适的排序方式：

| 业务场景             | sortBy          | sortOrder | 说明                     |
| -------------------- | --------------- | --------- | ------------------------ |
| 查找最需关注的设备   | healthScore     | asc       | 健康度最低的设备排在前面 |
| 查找最健康的设备     | healthScore     | desc      | 健康度最高的设备排在前面 |
| 按设备编号顺序查看   | equipmentCode   | asc/desc  | 按设备编码字母或数字顺序 |
| 查找最久未维护的设备 | lastMaintenance | asc       | 最久未维护的设备排在前面 |
| 查找最近维护过的设备 | lastMaintenance | desc      | 最近维护的设备排在前面   |

### Q5: limit参数应该设置为多少？

**A**: 根据使用场景选择合适的limit值：

| 使用场景       | 建议limit值 | 说明                                |
| -------------- | ----------- | ----------------------------------- |
| 管理驾驶舱看板 | 10-20       | 显示重点关注的设备                  |
| 设备健康度报表 | 50-100      | 显示所有设备或某类设备的完整列表    |
| 移动端列表展示 | 10-20       | 适应小屏幕显示，支持分页加载        |
| 详细数据分析   | 100         | 获取完整数据用于深度分析            |
| 单设备查询     | 1           | 指定equipmentId时，limit设置为1即可 |

最大支持100条，如需查询更多数据，请联系后端开发团队评估性能影响。

### Q6: 如何提高设备的健康度评分？

**A**: 根据评分算法，可以从以下方面改善：

1. **降低故障频率**：
   - 加强预防性维护，提前发现和解决潜在问题
   - 分析故障模式，采取针对性改善措施
   - 目标：将3个月故障次数控制在3次以内

2. **提高维护完成率**：
   - 优化维护计划，确保维护任务按时完成
   - 合理分配维护资源，避免任务堆积
   - 目标：将维护完成率提升到95%以上

3. **缩短修复时间**：
   - 提升维修人员技能水平
   - 优化备件管理，减少等待时间
   - 改进故障诊断流程
   - 目标：将平均修复时间控制在8小时以内

4. **定期执行维护**：
   - 严格执行维护计划，避免维护延期
   - 建立维护提醒机制
   - 目标：确保维护间隔不超过90天

5. **及时处理故障**：
   - 发现故障立即响应，避免设备长期处于故障状态
   - 对故障设备优先安排维修资源

### Q7: 新投入使用的设备健康度评分为什么不准确？

**A**: 健康度评分基于最近3个月的历史数据计算，新设备由于历史数据不足，评分可能不够准确。具体影响：

- **数据量不足**：故障次数、维护次数等统计样本小
- **评分偏高**：由于缺少故障记录，评分可能虚高
- **建议**：新设备建议至少运行3个月后，再将健康度评分作为主要参考指标

对于新设备，建议结合其他指标综合评估：
- 设备当前状态
- 运行时长
- 制造商质保期
- 同型号设备的历史表现

### Q8: 接口返回的数据量大吗？会影响性能吗？

**A**: 接口性能优化说明：

- **数据量控制**：limit参数最大100，单次请求返回数据量可控
- **查询优化**：后端使用索引和查询优化，响应时间通常在100-300ms
- **缓存策略**：
  - 建议客户端缓存数据5-10分钟
  - 健康度评分不是实时数据，适度缓存不影响准确性
- **分批查询**：如需查询大量设备，建议按设备类型分批查询

### Q9: 如何在前端展示健康度评分？

**A**: 提供多种前端展示方案：

**1. 评分数字展示**

**2. 进度条/仪表盘展示**

**3. 列表展示（带筛选和排序）**

**4. 统计卡片展示**

### Q10: 接口支持批量查询多台设备吗？

**A**: 当前接口不直接支持批量传入多个equipmentId，但提供了两种方案：

**方案1：按设备类型查询**

**方案2：不传筛选条件，获取所有设备**

**方案3：前端多次请求（不推荐）**

如有批量查询的强烈需求，请联系后端团队评估是否需要新增批量查询接口。

### 健康度评分算法详细说明

#### 评分模型

采用扣分制，初始分100分，根据5个维度的风险等级进行扣分：

```
最终评分 = 100 - 故障次数扣分 - 维护完成率扣分 - 修复时间扣分 - 维护间隔扣分 - 设备状态扣分
```

#### 各维度扣分规则

##### 1. 故障次数扣分（最近3个月）

| 故障次数 | 风险等级 | 扣分 | 说明                     |
| -------- | -------- | ---- | ------------------------ |
| 0-3次    | 低风险   | 0分  | 设备运行稳定，故障率正常 |
| 4-6次    | 中风险   | 15分 | 故障频率偏高，需要关注   |
| 7次以上  | 高风险   | 30分 | 故障频繁，存在系统性问题 |

##### 2. 维护完成率扣分（最近3个月）

| 完成率    | 风险等级 | 扣分 | 说明                       |
| --------- | -------- | ---- | -------------------------- |
| 95%及以上 | 低风险   | 0分  | 维护计划执行良好           |
| 80%-94%   | 中风险   | 10分 | 维护计划执行一般，有待改善 |
| 80%以下   | 高风险   | 20分 | 维护计划执行不力，存在隐患 |

##### 3. 平均修复时间扣分（MTTR）

| 修复时间   | 风险等级 | 扣分 | 说明                     |
| ---------- | -------- | ---- | ------------------------ |
| 8小时以内  | 低风险   | 0分  | 故障处理及时，修复能力强 |
| 8-24小时   | 中风险   | 5分  | 故障处理一般，有改进空间 |
| 24小时以上 | 高风险   | 15分 | 故障处理缓慢，影响生产   |

##### 4. 维护间隔扣分

| 距离上次维护天数 | 风险等级 | 扣分 | 说明                       |
| ---------------- | -------- | ---- | -------------------------- |
| 90天以内         | 低风险   | 0分  | 维护及时，符合计划         |
| 90-180天         | 中风险   | 10分 | 维护间隔偏长，需要关注     |
| 180天以上        | 高风险   | 15分 | 维护严重滞后，存在重大隐患 |

##### 5. 设备状态扣分

| 设备状态 | 风险等级 | 扣分 | 说明                           |
| -------- | -------- | ---- | ------------------------------ |
| 运行     | 低风险   | 0分  | 设备正常运行                   |
| 停机     | 低风险   | 0分  | 计划停机，正常状态             |
| 维护     | 中风险   | 5分  | 设备正在维护，暂时不可用       |
| 故障     | 高风险   | 20分 | 设备处于故障状态，需要紧急处理 |

#### 评分计算示例

**示例1：健康设备**
- 故障次数：2次 → 扣0分
- 维护完成率：98% → 扣0分
- 平均修复时间：6小时 → 扣0分
- 距离上次维护：45天 → 扣0分
- 设备状态：运行 → 扣0分
- **最终评分：100分，等级：优秀**

**示例2：一般状态设备**
- 故障次数：5次 → 扣15分

- 距离上次维护：70天 → 扣0分
- 设备状态：运行 → 扣0分
- **最终评分：70分，等级：一般**

**示例3：问题设备**

### 业务术语

| 术语       | 英文                         | 说明                                           |
| ---------- | ---------------------------- | ---------------------------------------------- |
| TPM        | Total Productive Maintenance | 全员生产维护，一种设备维护管理方法             |
| 健康度评分 | Health Score                 | 综合评估设备健康状况的量化指标，范围0-100分    |
| MTTR       | Mean Time To Repair          | 平均修复时间，衡量设备故障处理效率的指标       |
| 维护完成率 | Maintenance Completion Rate  | 已完成维护任务占计划维护任务的比例             |
| 预防性维护 | Preventive Maintenance       | 按计划定期执行的维护活动，目的是预防故障发生   |
| 故障频率   | Failure Frequency            | 单位时间内设备发生故障的次数                   |
| 设备可用率 | Equipment Availability       | 设备可用时间占总时间的比例，反映设备运行稳定性 |

### 技术参考

#### 数据统计周期

- **健康度评分统计周期**：最近3个月（90天）
- **数据更新频率**：实时计算，无缓存
- **统计基准时间**：以接口请求时间为基准向前推算3个月

#### 性能指标

- **接口响应时间**：平均100-300ms
- **并发支持**：支持50 QPS
- **数据量限制**：单次最多返回100条设备数据
- **查询超时**：10秒

#### 数据精度

- **健康度评分**：保留1位小数（如65.0）
- **维护完成率**：保留1位小数（如75.0）
- **平均修复时间**：保留2位小数（如12.50）
- **平均健康度评分**：保留1位小数（如82.5）
