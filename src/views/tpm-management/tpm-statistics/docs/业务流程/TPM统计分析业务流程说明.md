# TPM统计分析业务流程说明

## 文档说明

本文档基于TPM统计分析模块的实际实现，说明核心业务逻辑和数据分析规则，为前端开发提供业务理解基础。

## 核心概念

### 统计分析定义

**TPM统计分析（TPM Statistics）**：为设备全生命周期管理（TPM）提供多维度数据统计和分析支持，包括维护计划执行情况、故障趋势、设备健康度、备件消耗、工作量分布等关键指标的统计分析，支持管理决策和持续改进。

### 时间粒度

| 粒度 | 定义             | 适用场景           | SQL实现                         |
| ---- | ---------------- | ------------------ | ------------------------------- |
| 日   | 按天统计         | 短期详细分析       | `DATE_TRUNC('day', 日期字段)`   |
| 周   | 按周统计         | 周度趋势跟踪       | `DATE_TRUNC('week', 日期字段)`  |
| 月   | 按月统计（默认） | 月度报告和对比     | `DATE_TRUNC('month', 日期字段)` |
| 年   | 按年统计         | 年度总结和长期趋势 | `DATE_TRUNC('year', 日期字段)`  |

### 统计维度

| 维度       | 定义                 | 应用场景               |
| ---------- | -------------------- | ---------------------- |
| 时间维度   | 按时间粒度分组统计   | 趋势分析、同比环比     |
| 设备维度   | 按设备或设备类型统计 | 设备对比、问题设备识别 |
| 人员维度   | 按维护人员统计       | 工作量分析、绩效评估   |
| 类型维度   | 按故障类型、维护类型 | 问题分类、资源优化     |
| 健康度维度 | 基于多指标综合评分   | 设备状态评估、风险预警 |

### 关键指标定义

| 指标           | 定义                             | 计算公式                               | 单位 |
| -------------- | -------------------------------- | -------------------------------------- | ---- |
| 维护计划执行率 | 已完成维护任务占计划任务的比例   | (已完成任务数 / 总任务数) × 100%       | %    |
| 设备可用率     | 运行状态设备占总设备的比例       | (运行设备数 / 总设备数) × 100%         | %    |
| 故障解决率     | 已解决故障占总故障的比例         | (已解决故障数 / 总故障数) × 100%       | %    |
| MTTR           | 平均修复时间                     | 故障修复总时长 / 故障次数              | 小时 |
| 备件消耗成本   | 备件领用的总成本                 | Σ(领用数量 × 单价)                     | 元   |
| 维护工作时长   | 维护任务实际执行时长             | Σ实际工时（优先）或标准工时            | 小时 |
| 设备健康度评分 | 基于多维度计算的设备健康状态评分 | 100分 - 故障扣分 - 维护扣分 - 状态扣分 | 分   |

## 业务流程详解

### 1. 维护计划执行率统计

#### 统计目的
- 评估维护计划的执行情况
- 识别执行延迟和瓶颈
- 为维护资源调配提供依据

#### 筛选条件
- **设备筛选**：
  - 按设备ID：查询指定设备的执行率
  - 按设备类型：查询指定类型设备的执行率
- **时间范围**：
  - 开始日期（必填）：统计起始日期
  - 结束日期（必填）：统计截止日期
  - 时间粒度（可选）：日/周/月/年，默认按月
- **数据范围**：
  - 仅统计未被软删除的维护任务
  - 按任务创建时间筛选

#### 统计内容

**总体摘要**：
- 总任务数：统计时间段内的总维护任务数
- 已完成任务数：状态为"已完成"的任务数
- 总体执行率：(已完成任务数 / 总任务数) × 100%

**时间段明细**：
- 时间段标识：根据时间粒度生成
- 该时间段总任务数
- 该时间段已完成任务数
- 该时间段执行率百分比

#### 数据来源
- **主表**：维护任务表（MaintenanceTask）
- **关联表**：设备表（Equipment）- 用于设备类型筛选
- **状态判断**：status = '已完成' 为完成任务

#### 计算规则
1. 按时间粒度分组统计任务数量
2. 统计每个时间段内"已完成"状态的任务数
3. 计算各时间段执行率并格式化为百分比（保留2位小数）
4. 汇总总体统计数据

#### 应用场景
- **月度执行率评估**：评估当月维护计划完成情况
- **趋势对比分析**：对比不同时间段的执行率变化
- **设备类型对比**：对比不同设备类型的维护执行情况
- **资源调配依据**：根据执行率低的时段调配维护资源

### 2. 故障汇总统计

#### 统计目的
- 全面了解设备故障发生情况
- 识别高发故障类型和问题设备
- 为故障预防和改进提供数据支持

#### 筛选条件
- **设备筛选**：
  - 按设备ID：查询指定设备的故障情况
  - 按设备类型：查询指定类型设备的故障情况
- **故障筛选**：
  - 按故障类型：机械、电气、液压、控制、其他
- **时间范围**：
  - 开始日期（必填）：按故障发生时间筛选
  - 结束日期（必填）：按故障发生时间筛选
  - 时间粒度（可选）：日/周/月/年，默认按月

#### 统计内容

**总体摘要**：
- 总故障数：统计时间段内的总故障数
- 严重故障数：I级-严重故障的数量
- 统计时间粒度

**时间统计**：
- 按时间段分组统计故障数量
- 各时间段按故障等级分布：
  - I级-严重故障数量
  - II级-重大故障数量
  - III级-一般故障数量
  - IV级-轻微故障数量

**类型统计**：
- 按故障类型分组统计
- 各类型故障数量
- 按故障数量降序排列

**设备统计**（TOP 10）：
- 设备编码和名称
- 该设备故障次数
- 该设备平均MTTR（小时）
- 按故障次数降序排列，显示前10名

#### 数据来源
- **主表**：设备故障表（EquipmentFailure）
- **关联表**：设备表（Equipment）- 设备信息和类型筛选
- **统计字段**：
  - failureTime：故障发生时间
  - failureLevel：故障等级
  - failureType：故障类型
  - repairStartTime、repairCompletionTime：计算MTTR

#### 计算规则
1. 按时间粒度分组统计故障总数和各等级数量
2. 按故障类型分组统计数量
3. 按设备分组统计故障次数
4. 计算设备平均MTTR：AVG((修复完成时间 - 修复开始时间) / 3600秒)
5. 所有统计仅包含未软删除的故障记录

#### 应用场景
- **月度故障分析会议**：全面展示故障发生情况
- **问题设备识别**：识别故障频发的设备进行重点关注
- **故障类型分析**：识别高发故障类型，制定预防措施
- **趋势监控**：跟踪故障数量变化趋势

### 3. MTTR趋势分析

#### 统计目的
- 分析设备平均修复时间的变化趋势
- 评估维修效率和能力
- 识别修复时间异常的设备或时期

#### 筛选条件
- **设备筛选**：
  - 按设备ID：查询指定设备的MTTR趋势
  - 按设备类型：查询指定类型设备的MTTR趋势
- **时间范围**：
  - 开始日期（必填）：按故障发生时间筛选
  - 结束日期（必填）：按故障发生时间筛选
  - 时间粒度（可选）：日/周/月/年，默认按月
- **数据条件**：
  - 只统计有修复完成时间的故障记录
  - 排除未完成修复的故障

#### 统计内容

**总体摘要**：
- 总故障数：有完整修复时间的故障数
- 总体平均MTTR：所有故障的平均修复时间
- 统计时间粒度

**趋势数据**：
- 按时间段分组统计：
  - 该时间段故障数量
  - 平均MTTR（小时）
  - 最小MTTR（小时）
  - 最大MTTR（小时）
- 按时间顺序排列

**等级统计**：
- 按故障等级分组统计：
  - 故障等级（I级-严重、II级-重大、III级-一般、IV级-轻微）
  - 该等级故障数量
  - 该等级平均MTTR
- 按等级排序

#### 数据来源
- **主表**：设备故障表（EquipmentFailure）
- **关联表**：设备表（Equipment）- 设备类型筛选
- **计算字段**：
  - MTTR = (repairCompletionTime - repairStartTime) / 3600秒
  - 转换为小时单位

#### 计算规则
1. 筛选有修复完成时间的故障记录
2. 按时间粒度分组计算：
   - 平均值：AVG(修复时长)
   - 最小值：MIN(修复时长)
   - 最大值：MAX(修复时长)
3. 按故障等级分组计算平均MTTR
4. 所有时间值保留2位小数

#### 应用场景
- **维修效率评估**：评估维修团队的修复效率
- **趋势监控**：跟踪MTTR变化趋势，识别效率提升或下降
- **等级对比**：对比不同等级故障的修复时间差异
- **资源优化**：根据MTTR数据优化备件储备和人员配置

### 4. 备件消耗分析

#### 统计目的
- 分析备件的消耗情况和成本
- 识别高消耗备件和高成本项目
- 为备件采购和库存管理提供依据

#### 筛选条件
- **备件筛选**：
  - 按备件ID：查询指定备件的消耗情况
- **设备筛选**：
  - 按设备ID：查询指定设备相关的备件消耗
  - 按设备类型：查询指定类型设备的备件消耗
- **时间范围**：
  - 开始日期（必填）：按交易时间筛选
  - 结束日期（必填）：按交易时间筛选
  - 时间粒度（可选）：日/周/月/年，默认按月
- **排序方式**：
  - totalQuantity：按总消耗量排序（默认）
  - totalCost：按总成本排序
  - frequency：按使用频次排序
- **交易类型**：
  - 仅统计"领用"类型的交易
  - 排除退库、调拨等其他交易类型

#### 统计内容

**总体摘要**：
- 总消耗数量：所有备件领用的总数量
- 总交易次数：领用交易的总次数
- 涉及备件种类数：使用过的不同备件数量
- 总成本：Σ(领用数量 × 单价)
- 统计时间粒度

**趋势数据**：
- 按时间段分组统计：
  - 该时间段消耗总量
  - 该时间段交易次数
  - 该时间段涉及备件种类数
- 按时间顺序排列

**备件明细**（TOP 20）：
- 备件编码和名称
- 单位和单价
- 总消耗数量
- 使用频次（领用次数）
- 总成本（数量 × 单价）
- 按指定排序方式排序

#### 数据来源
- **主表**：备件交易表（SparePartTransaction）
- **关联表**：
  - 备件表（SparePart）- 备件信息和单价
  - 维护任务表（MaintenanceTask）- 关联设备
  - 设备表（Equipment）- 设备类型筛选

#### 计算规则
1. 筛选交易类型为"领用"的记录
2. 按时间粒度分组统计：
   - 总数量：SUM(quantity)
   - 交易次数：COUNT(*)
   - 备件种类：COUNT(DISTINCT sparePartId)
3. 按备件分组统计：
   - 消耗量、频次、成本
   - 成本 = SUM(quantity × unitPrice)
4. 金额保留2位小数

#### 应用场景
- **成本控制**：识别高成本备件，优化采购策略
- **库存管理**：根据消耗趋势调整安全库存
- **采购计划**：基于历史消耗数据制定采购计划
- **预算编制**：为备件预算编制提供数据支持

### 5. TPM综合看板

#### 统计目的
- 提供TPM管理的全局视图
- 展示关键指标和整体状态
- 支持管理层快速决策

#### 筛选条件
- **设备筛选**：
  - 按设备类型：查询指定类型设备的综合数据
- **时间粒度**：
  - 可选：日/周/月/年，默认按月
- **统计范围**：
  - 固定统计当前月（从1号到月末）
  - 不支持自定义时间范围

#### 统计内容

**设备状态概览（equipmentOverview）**：
- 设备总数
- 运行中设备数：status = '运行'
- 维护中设备数：status = '维护'
- 故障设备数：status = '故障'
- 设备可用率：(运行设备数 / 设备总数) × 100%

**维护任务概览（maintenanceOverview）**：
- 本月总任务数
- 已完成任务数：status = '已完成'
- 执行中任务数：status = '执行中'
- 已延期任务数：status = '已延期'
- 任务完成率：(已完成任务数 / 总任务数) × 100%

**故障处理概览（failureOverview）**：
- 本月总故障数
- 严重故障数：failureLevel = 'I级-严重'
- 已解决故障数：status = '已解决'
- 故障解决率：(已解决故障数 / 总故障数) × 100%

**备件管理概览（sparePartOverview）**：
- 本月总交易次数：领用类型交易
- 总消耗数量
- 总消耗成本：Σ(数量 × 单价)
- 低库存备件数：当前库存 ≤ 安全库存的备件数量

**报告时间范围（reportPeriod）**：
- 开始日期：当月1号
- 结束日期：当月最后一天
- 时间粒度

#### 数据来源
- **设备表**（Equipment）：设备状态统计
- **维护任务表**（MaintenanceTask）：维护任务统计
- **设备故障表**（EquipmentFailure）：故障统计
- **备件交易表**（SparePartTransaction）：备件消耗统计
- **备件表**（SparePart）+ **备件库存表**（SparePartInventory）：低库存统计

#### 计算规则
1. 固定统计当前月数据
2. 各模块独立统计并汇总
3. 百分比指标保留2位小数
4. 低库存判断：currentQuantity ≤ safetyStock

#### 应用场景
- **管理驾驶舱**：为管理层提供一站式概览
- **月度例会**：快速展示月度TPM关键指标
- **KPI监控**：实时监控设备可用率、任务完成率等KPI
- **快速决策**：基于综合数据快速识别问题和机会

### 6. 设备健康度评分

#### 统计目的
- 综合评估设备的健康状况
- 识别健康度较差的设备
- 为设备维护和更新决策提供依据

#### 筛选条件
- **设备筛选**：
  - 按设备ID：查询指定设备的健康度
  - 按设备类型：查询指定类型设备的健康度
- **数量限制**：
  - limit：返回设备数量，默认20，最大100
- **排序方式**：
  - sortBy：healthScore（健康度）、equipmentCode（设备编码）、lastMaintenance（最后维护时间），默认healthScore
  - sortOrder：asc（升序）、desc（降序），默认asc
- **评估周期**：
  - 固定评估最近3个月的数据

#### 健康度评分算法

**基础分值**：100分

**扣分规则**：

1. **故障次数影响**（最近3个月）：
   - 故障7次及以上：扣30分
   - 故障4-6次：扣15分
   - 故障0-3次：不扣分

2. **维护完成率影响**：
   - 完成率 < 80%：扣20分
   - 完成率 80%-95%：扣10分
   - 完成率 ≥ 95%：不扣分

3. **平均修复时间影响**：
   - MTTR > 24小时：扣15分
   - MTTR 8-24小时：扣5分
   - MTTR ≤ 8小时：不扣分

4. **距离上次维护时间影响**：
   - 超过180天：扣15分
   - 超过90天：扣10分
   - 90天以内：不扣分

5. **设备当前状态影响**：
   - 故障状态：扣20分
   - 维护状态：扣5分
   - 其他状态：不扣分

**最终分数**：确保在0-100范围内

**健康等级判定**：
- 90-100分：优秀
- 75-89分：良好
- 60-74分：一般
- 0-59分：差

#### 统计内容

**总体摘要**：
- 统计设备总数
- 平均健康度评分
- 各健康等级设备数量：
  - 优秀设备数
  - 良好设备数
  - 一般设备数
  - 差设备数

**设备健康度明细**：
- 设备ID、编码、名称
- 设备类型和当前状态
- 健康度评分（0-100分）
- 健康等级（优秀/良好/一般/差）
- 故障次数（最近3个月）
- 维护完成率（%）
- 平均MTTR（小时）
- 距离上次维护天数
- 最后维护日期

#### 数据来源
- **主表**：设备表（Equipment）
- **关联统计**：
  - 设备故障表（EquipmentFailure）- 故障次数、平均MTTR
  - 维护任务表（MaintenanceTask）- 维护完成率
  - 维护记录表（MaintenanceRecord）- 最后维护时间
- **统计周期**：最近3个月

#### 计算规则
1. 查询设备基本信息
2. 使用子查询统计最近3个月的：
   - 故障次数
   - 维护完成率
   - 平均MTTR
   - 最后维护时间
3. 计算距离上次维护天数
4. 应用健康度评分算法
5. 判定健康等级
6. 按指定字段和顺序排序

#### 应用场景
- **设备状态评估**：全面评估设备健康状况
- **风险预警**：识别健康度差的设备，预防故障
- **维护优先级**：优先维护健康度低的设备
- **设备更新决策**：为设备更新或报废提供依据
- **绩效考核**：评估设备管理团队的工作成效

### 7. 维护工作量统计

#### 统计目的
- 分析维护人员的工作量分布
- 评估工作负荷的均衡性
- 为人员配置和绩效考核提供依据

#### 筛选条件
- **人员筛选**：
  - 按维护人员ID：查询指定人员的工作量
- **设备筛选**：
  - 按设备类型：查询指定类型设备的维护工作量
- **时间范围**：
  - 开始日期（必填）：按计划执行时间筛选
  - 结束日期（必填）：按计划执行时间筛选
  - 时间粒度（可选）：日/周/月/年，默认按月
- **分组方式**：
  - assignee：按维护人员分组（默认）
  - equipmentType：按设备类型分组
  - maintenanceType：按维护类型分组

#### 统计内容

**总体摘要**：
- 总任务数
- 已完成任务数
- 总工作时长（小时）
- 活跃维护人员数（去重）
- 任务完成率：(已完成任务数 / 总任务数) × 100%
- 统计时间粒度
- 分组方式

**分组工作量统计**：
- 根据分组方式显示：
  - 按人员：人员姓名和ID
  - 按设备类型：设备类型
  - 按维护类型：维护类型
- 各分组的统计数据：
  - 总任务数
  - 已完成任务数
  - 总工作时长（小时）
  - 平均任务时长（小时）
  - 任务完成率（%）
- 按总任务数降序排列

**工作量趋势**：
- 按时间段分组统计：
  - 该时间段总任务数
  - 该时间段已完成任务数
  - 该时间段总工作时长
- 按时间顺序排列

#### 数据来源
- **主表**：维护任务表（MaintenanceTask）
- **关联表**：
  - 设备表（Equipment）- 设备类型筛选
  - 维护计划表（MaintenancePlan）- 维护类型
  - 用户表（User）- 维护人员信息
- **工时计算**：
  - 优先使用实际工时（actualDurationHours）
  - 实际工时为空时使用标准工时（standardDurationHours）
  - 仅统计已完成任务的工时

#### 计算规则
1. 按分组字段和时间粒度分别统计
2. 工时计算：
   - 已完成任务：优先actualDurationHours，否则standardDurationHours
   - 未完成任务：不计入工时统计
3. 平均时长 = 总工时 / 已完成任务数
4. 完成率 = (已完成任务数 / 总任务数) × 100%
5. 所有时长保留1位小数，百分比保留2位小数

#### 应用场景
- **工作量评估**：评估各维护人员的工作负荷
- **资源调配**：识别工作量不均，优化人员配置
- **绩效考核**：基于工作量和完成率进行绩效评估
- **能力分析**：通过平均时长分析人员技能水平
- **维护计划优化**：根据历史工作量数据优化维护计划

## 核心业务规则

1. **只读统计**：统计模块只读数据，不修改任何业务数据
2. **实时计算**：所有统计数据实时计算，不缓存结果
3. **软删除过滤**：所有统计自动排除软删除的记录
4. **时间边界**：结束日期不能早于开始日期，系统自动验证
5. **默认值处理**：
   - 时间粒度默认为"月"
   - 没有数据时返回0或空数组，不报错
   - 百分比计算避免除零错误
6. **精度控制**：
   - 金额保留2位小数
   - 百分比保留2位小数
   - 工时保留1位小数
   - 健康度评分保留1位小数
7. **关联查询优化**：
   - 使用INNER JOIN确保数据完整性
   - 使用LEFT JOIN支持可选关联
   - 合理使用索引提升查询性能
8. **分组统计规则**：
   - 按时间分组使用DATE_TRUNC函数
   - 按维度分组使用GROUP BY子句
   - 聚合函数包括COUNT、SUM、AVG、MIN、MAX
9. **健康度评分**：
   - 评分算法固定，不可自定义
   - 评估周期固定为3个月
   - 评分范围0-100分
   - 等级判定标准固定
10. **综合看板**：
    - 固定统计当前月
    - 不支持历史月份查询
    - 数据实时更新

## 典型业务场景

### 场景1：月度TPM报告生成

**背景**：每月初需要生成上月的TPM综合报告

**操作流程**：

1. **查看综合看板**：
   - 访问TPM综合看板接口
   - 获取上月整体概况：
     - 设备状态分布和可用率
     - 维护任务完成情况
     - 故障处理情况
     - 备件消耗统计

2. **查询执行率**：
   - 查询上月维护计划执行率
   - 时间粒度：周
   - 分析各周执行率变化

3. **故障分析**：
   - 查询上月故障汇总统计
   - 时间粒度：周
   - 识别故障高发时段和设备

4. **MTTR分析**：
   - 查询上月MTTR趋势
   - 对比各故障等级的修复时间
   - 评估维修效率

5. **生成报告**：
   - 汇总各项数据
   - 对比同期和环比
   - 提出改进建议

### 场景2：设备健康度评估与预防性维护

**背景**：定期评估设备健康状况，制定预防性维护计划

**操作流程**：

1. **健康度排查**：
   - 查询所有设备健康度评分
   - 排序方式：按健康度升序
   - 识别健康度"差"和"一般"的设备

2. **问题设备分析**：
   - 对健康度低的设备逐一分析：
     - 故障次数是否偏高
     - 维护完成率是否不足
     - MTTR是否过长
     - 距离上次维护是否过久

3. **制定维护计划**：
   - 针对问题设备制定专项维护计划
   - 优先安排健康度"差"的设备
   - 增加维护频次

4. **跟踪评估**：
   - 实施维护后持续跟踪健康度变化
   - 下月再次评估，验证改进效果

### 场景3：备件库存优化

**背景**：根据历史消耗数据优化备件库存和采购计划

**操作流程**：

1. **消耗趋势分析**：
   - 查询最近6个月备件消耗分析
   - 时间粒度：月
   - 筛选条件：所有设备

2. **识别高消耗备件**：
   - 排序方式：按总消耗量
   - 识别TOP 20高消耗备件
   - 记录各备件的消耗趋势

3. **成本分析**：
   - 排序方式：按总成本
   - 识别高成本备件项目
   - 分析成本占比

4. **库存调整**：
   - 高消耗备件：增加安全库存
   - 低消耗备件：减少库存或按需采购
   - 高成本备件：寻找替代方案或批量采购

5. **采购计划**：
   - 基于月均消耗量制定采购计划
   - 考虑采购周期和批量折扣
   - 设置合理的补货点

### 场景4：维护团队绩效评估

**背景**：季度维护团队绩效评估

**操作流程**：

1. **工作量统计**：
   - 查询本季度维护工作量统计
   - 时间粒度：月
   - 分组方式：按维护人员

2. **人员对比分析**：
   - 对比各人员的：
     - 总任务数（工作量）
     - 已完成任务数（执行力）
     - 任务完成率（可靠性）
     - 平均任务时长（效率）
     - 总工作时长（工作强度）

3. **趋势分析**：
   - 查看月度工作量趋势
   - 识别工作量波动原因
   - 评估工作负荷均衡性

4. **设备类型分析**：
   - 分组方式：按设备类型
   - 了解不同设备类型的维护工作量
   - 评估专业技能需求

5. **绩效评定**：
   - 综合工作量、完成率、效率
   - 识别优秀维护人员
   - 制定培训和激励计划

### 场景5：故障改进专项分析

**背景**：某设备类型故障频发，需要专项改进

**操作流程**：

1. **故障汇总**：
   - 查询最近6个月故障汇总统计
   - 筛选条件：指定设备类型
   - 时间粒度：月

2. **趋势判断**：
   - 查看时间统计，判断故障趋势
   - 识别故障高发时段
   - 分析故障数量变化

3. **类型分析**：
   - 查看类型统计
   - 识别高发故障类型（机械/电气/液压/控制）
   - 确定改进重点方向

4. **设备排查**：
   - 查看设备统计
   - 识别故障最多的TOP 10设备
   - 查看各设备的平均MTTR

5. **MTTR分析**：
   - 查询MTTR趋势分析
   - 了解修复时间变化
   - 评估维修效率

6. **健康度评估**：
   - 查询该设备类型的健康度评分
   - 识别健康度低的设备
   - 制定预防性维护计划

7. **制定改进方案**：
   - 针对高发故障类型制定预防措施
   - 对问题设备进行专项检修
   - 优化维护计划和频次
   - 加强人员培训

8. **效果跟踪**：
   - 实施改进后持续监控
   - 对比改进前后数据
   - 评估改进效果
