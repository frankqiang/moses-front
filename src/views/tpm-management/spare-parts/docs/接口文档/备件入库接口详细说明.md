## 功能概述

### 所有功能

备件入库（SparePart In-Stock）是备件管理模块中的核心操作之一，用于执行采购入库、调拨入库等补充库存的业务操作，以支持设备维护备件的库存管理和供应保障的业务场景。

### 关键特性

- ✅ **自动库存更新**：入库成功后自动增加备件的当前库存数量，无需手动维护
- ✅ **智能单号生成**：支持手动提供入库单号或系统自动生成（格式：SP-IN-时间戳）
- ✅ **完整记录追踪**：创建详细的入库流水记录，包含经手人、时间、用途等信息
- ✅ **事务保护机制**：使用数据库事务确保入库记录和库存更新的原子性操作
- ✅ **实时库存反馈**：接口响应同时返回入库记录详情和更新后的最新库存状态
- ✅ **低库存预警解除**：入库后如果库存高于安全库存，自动解除低库存预警状态

---

### 使用前提

- ✅ 备件主数据必须已存在（需要先通过创建备件接口创建备件）
- ✅ 用户必须拥有 `mdm.tpm.spare-part.manage` 权限
- ✅ 入库数量必须为正整数（≥ 1）
- ✅ 如果手动提供入库单号，该单号在系统中必须唯一

### 不适用场景

- ❌ 备件领用后的退库操作（应使用备件出库接口，类型选择"退库"）
- ❌ 修改已创建的入库记录（入库记录创建后不可修改，只能查询）
- ❌ 备件主数据的创建或更新（应使用相应的备件管理接口）

### 详细步骤说明

#### 步骤1: 参数验证
**验证内容**：
- **必填字段检查**：验证入库数量（quantity）是否提供
- **数值范围验证**：确保入库数量 ≥ 1
- **格式验证**：
  - 备件ID必须是有效的UUID格式
  - 入库单号（如提供）长度不超过100字符
  - 用途说明和备注为可选文本字段

**验证失败处理**：
- 返回 400 错误，错误码 `VALIDATION_ERROR`
- 提供具体的字段验证失败信息

#### 步骤2: 备件存在性验证
**验证逻辑**：
- 根据路径参数中的备件ID查询备件主数据表
- 检查备件是否存在且未被软删除（isDeleted = false）

**验证失败处理**：
- 如果备件不存在或已删除，返回 404 错误
- 错误码：`TPM_SPARE_001`
- 错误消息：「备件不存在」

#### 步骤3: 入库单号处理
**处理逻辑**：

**情况1：用户提供入库单号**
- 自动转换为大写字母
- 在出入库记录表中验证单号的全局唯一性
- 如果单号已存在，返回错误

**情况2：用户未提供入库单号**
- 系统自动生成格式化单号：`SP-IN-{当前时间戳}`
- 示例：`SP-IN-1705836000000`
- SP = SparePart（备件）
- IN = In-Stock（入库）

**唯一性验证失败处理**：
- 返回 400 错误，错误码 `TPM_SPARE_015`
- 错误消息：「入库/出库单号已存在」
- 处理建议：使用系统自动生成的单号

#### 步骤4: 创建入库记录
**记录内容**：
- **基本信息**：
  - 入库单号（transactionCode）
  - 备件ID（sparePartId）
  - 出入库类型（transactionType）：固定为「入库」
  - 数量（quantity）
  - 出入库时间（transactionTime）：当前时间
- **人员信息**：
  - 经手人ID（operatorId）：从认证Token获取当前用户ID
  - 创建人（createdBy）：当前用户ID
  - 更新人（updatedBy）：当前用户ID
- **辅助信息**：
  - 用途说明（purpose）：可选
  - 备注（remark）：可选
  - 关联维护任务ID（relatedTaskId）：入库时为 null
  - 关联故障单ID（relatedFailureId）：入库时为 null
- **状态标记**：
  - 软删除标记（isDeleted）：false

**注意事项**：
- 入库操作不需要关联维护任务或故障单
- 所有时间字段使用 ISO 8601 格式存储

#### 步骤5: 更新库存数量
**更新逻辑**：
- 查询备件对应的库存记录（inventory表）
- 将入库数量加到当前库存（currentQuantity）
  ```
  新库存 = 原库存 + 入库数量
  ```
- 更新最后更新时间（lastUpdatedAt）为当前时间

**数据一致性保障**：
- 使用数据库事务确保入库记录和库存更新同时成功或同时失败
- 如果库存记录不存在，返回 404 错误（错误码：TPM_SPARE_004）

#### 步骤6: 查询最新库存
**查询内容**：
- 获取更新后的库存详细信息：
  - 当前库存（currentQuantity）
  - 在途数量（inTransitQuantity）
  - 预留数量（reservedQuantity）
- 关联查询备件主数据（用于显示备件基础信息）

**计算字段**：
- **可用库存**：当前库存 - 预留数量
  ```
  availableQuantity = currentQuantity - reservedQuantity
  ```
- **低库存状态**：判断是否低于安全库存
  ```
  isLowStock = currentQuantity <= safetyStock
  ```

**返回信息**：
- 完整的库存状态（包含计算字段）
- 备件基础信息（编码、名称、单位、库存上下限等）

#### 步骤7: 返回响应数据
**响应结构**：
```json
{
  "success": true,
  "data": {
    "transaction": { ... },  // 入库记录详情
    "inventory": { ... }     // 更新后的库存信息
  },
  "message": "备件入库成功",
  "meta": { ... }
}
```

**HTTP状态码**：201 Created

**业务价值**：
- 前端可以同时获取入库记录和最新库存状态
- 无需额外请求即可显示完整的操作结果
- 支持实时库存展示和低库存预警提示

## 接口文档

### 基本信息

**接口路径**: `POST /v1/mdm/tpm/spare-parts/:id/in-stock`

**功能描述**: 执行备件入库操作，自动更新库存数量并创建入库流水记录。适用于采购入库、调拨入库等补充库存的业务场景。入库单号可以手动提供（系统会验证唯一性），也可以由系统自动生成。

**认证要求**: Bearer Token 认证，需要 `mdm.tpm.spare-part.manage` 权限

## 统一响应格式说明

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号


**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 错误响应

| HTTP状态码 | 错误码           | 错误消息                | 说明                                   | 处理建议                       |
| ---------- | ---------------- | ----------------------- | -------------------------------------- | ------------------------------ |
| 400        | VALIDATION_ERROR | 请求参数验证失败        | 请求参数不符合验证规则（如数量≤0）     | 检查请求参数格式和必填字段     |
| 400        | TPM_SPARE_015    | 入库/出库单号已存在     | 系统中已存在相同的入库单号             | 更换入库单号或使用系统自动生成 |
| 401        | UNAUTHORIZED     | 未授权，Token无效或过期 | 未提供认证Token或Token已失效           | 重新登录获取有效Token          |

## 常见问题

### Q1: 入库单号是必填的吗？

**答**：不是必填的。
- **不提供单号**：系统会自动生成格式化的入库单号（格式：`SP-IN-{时间戳}`）
- **提供单号**：系统会验证单号的唯一性，如果单号已存在会返回错误

**推荐做法**：
- 一般采购入库：使用系统自动生成（方便快捷）
- 关联ERP采购单：手动提供单号（便于对账）
- 调拨入库：手动提供统一单号（便于追溯）

### Q2: 入库后库存为什么还是显示低库存？

**答**：可能原因：
1. **入库数量不足**：入库后的库存仍然 ≤ 安全库存
   - 解决方案：检查安全库存设置，适当增加入库数量

2. **安全库存设置过高**：当前库存已超过实际需求
   - 解决方案：通过更新备件接口调整安全库存阈值

3. **响应数据未刷新**：前端缓存了旧的库存数据
   - 解决方案：重新查询库存或使用接口返回的最新库存数据

**判断逻辑**：
```
isLowStock = currentQuantity <= safetyStock
```

### Q3: 能否修改已创建的入库记录？

**答**：不能修改。入库记录一旦创建就不可修改，只能查询。

**原因**：
- 出入库流水是审计追溯的重要依据
- 修改记录会破坏数据的完整性和可追溯性

**如果入库数量错误怎么办**：
1. **数量少了**：再次执行入库操作补充差额
2. **数量多了**：执行出库操作（类型选择「报废」或其他）减少库存

### Q4: 为什么入库时不能关联维护任务？

**答**：业务逻辑设计决定。

**区分场景**：
- **入库操作**：补充库存，来源是采购、调拨等，不涉及具体的维护任务
- **领用操作**：消耗库存，必须关联维护任务或故障单，明确责任归属

**数据模型**：
- 入库记录的 `relatedTaskId` 和 `relatedFailureId` 固定为 `null`
- 只有领用类型的出库记录才会填充这两个字段

### Q5: 入库单号重复时如何处理？

**答**：系统会返回 400 错误（错误码：`TPM_SPARE_015`）

**处理建议**：
1. **使用系统自动生成**：删除请求中的 `transactionCode` 字段
2. **修改单号后重试**：使用不同的单号（如添加后缀：`-V2`）
3. **检查是否已入库**：查询出入库记录确认是否重复提交

**避免重复的最佳实践**：
- 采用系统自动生成单号（推荐）
- 如需手动提供，建议使用唯一性强的格式（如包含时间戳、批次号等）

### Q6: 入库操作失败但库存已更新怎么办？

**答**：不会发生这种情况。

**原因**：
- 接口使用数据库事务（Transaction）保护
- 创建入库记录和更新库存是原子操作
- 任何一步失败都会回滚，保证数据一致性

**如果怀疑数据不一致**：
1. 查询出入库记录确认是否有对应的入库单号
2. 查询库存历史变更记录
3. 联系技术支持进行数据一致性检查

### Q7: 能否一次入库多个不同的备件？

**答**：本接口不支持批量入库多个不同备件。

**原因**：
- 接口设计为单备件操作，确保数据准确性
- 每个备件的入库信息（数量、用途、备注）可能不同

**如需批量入库**：
- **方案1**：前端循环调用接口，逐个备件入库
- **方案2**：等待批量入库接口开发（未来功能）

### Q8: 入库后如何查看库存变化历史？

**答**：使用出入库记录查询接口。

**查询方式**：
```bash
GET /v1/mdm/tpm/spare-parts/transactions?sparePartId={备件ID}&transactionType=入库&sortBy=transactionTime:desc
```

**获取信息**：
- 所有入库记录（按时间倒序）
- 每次入库的数量、单号、经手人
- 入库时间、用途说明、备注

**业务价值**：
- 追溯库存变化原因
- 分析采购频率和数量
- 审计检查入库操作

| 生成方式 | 格式                 | 示例                  | 说明                      |

| 手动提供 | 自定义（自动转大写） | TRANSFER-20240121-A01 | 需确保全局唯一性          |

**时间戳说明**：
- 使用 Unix 毫秒时间戳（13位数字）
- 示例：1705836000000 对应 2024-01-21T16:40:00.000Z

### 库存状态计算公式

| ----------------- | ---------------------------------- | ------------------ |
| availableQuantity | currentQuantity - reservedQuantity | 可实际使用的库存量 |
| isLowStock        | currentQuantity <= safetyStock     | 是否需要补货       |
