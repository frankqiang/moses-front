## 功能概述

### 所有功能

查询出入库记录（Query Spare Part Transactions）是备件管理模块中的核心查询接口之一，用于根据多种条件筛选和查询备件的历史出入库记录，以支持备件使用追溯、库存审计、维护成本分析等业务场景。

该接口提供强大的筛选、分页和排序功能，可以帮助管理人员快速定位特定备件的使用情况，分析出入库模式，追踪备件流向，为库存优化和采购决策提供数据支持。

### 关键特性

- ✅ **多维度筛选**：支持按备件ID、出入库类型、单号、时间范围等多个维度组合筛选
- ✅ **完整关联信息**：自动关联备件信息、经手人信息、维护任务和故障单信息，提供完整的业务上下文
- ✅ **灵活排序**：支持按出入库时间、单号、数量等字段升序或降序排列
- ✅ **高效分页**：支持分页查询，每页最多100条记录，适应大数据量场景
- ✅ **模糊查询**：单号支持模糊查询，方便快速定位
- ✅ **时间范围筛选**：支持灵活的时间范围查询，可单独设置开始日期或结束日期

---

### 使用前提

- ✅ 已通过认证并获取有效的JWT Token
- ✅ 当前用户具有 `mdm.tpm.spare-part.view` 权限
- ✅ 系统中已存在备件出入库记录数据
- ✅ 查询参数符合验证规则要求

### 不适用场景

- ❌ 需要创建或修改出入库记录（应使用入库/出库接口）
- ❌ 需要实时库存数量查询（应使用查询备件库存接口）
- ❌ 需要备件主数据信息（应使用查询备件详情接口）

### 详细步骤说明

#### 步骤1: 接收查询请求
系统接收来自客户端的GET请求，提取URL中的查询参数（sparePartId、transactionType、transactionCode、startDate、endDate、page、limit、sortBy、sortOrder）。

#### 步骤2: 验证JWT Token
验证请求头中的Bearer Token：
- 检查Token是否存在
- 验证Token签名是否有效
- 检查Token是否过期
- 提取Token中的用户信息

**失败处理**：Token无效或过期时，返回401错误。

#### 步骤3: 检查用户权限
验证当前用户是否具有 `mdm.tpm.spare-part.view` 权限：
- 查询用户的角色信息
- 检查角色是否包含所需权限

**失败处理**：无权限时，返回403错误。

#### 步骤4: 验证查询参数
使用Joi验证器进行参数验证：
- **page**：必须是>=1的整数，默认为1
- **limit**：必须是1-100之间的整数，默认为10
- **sparePartId**：可选，必须是有效的UUID v4格式
- **transactionType**：可选，必须是"入库"、"领用"、"退库"、"报废"之一
- **transactionCode**：可选，字符串类型，支持空字符串
- **startDate**：可选，必须是ISO格式日期
- **endDate**：可选，必须是ISO格式日期，且不能早于startDate
- **sortBy**：可选，必须是"transactionTime"、"transactionCode"或"quantity"之一，默认为"transactionTime"
- **sortOrder**：可选，必须是"asc"或"desc"之一，默认为"desc"

**失败处理**：参数不符合验证规则时，返回400错误并说明具体错误信息。

#### 步骤5: 构建查询条件
根据验证通过的参数构建数据库查询条件：
- **基础条件**：`isDeleted = false`（排除已删除记录）
- **备件ID筛选**：如果提供sparePartId，添加 `sparePartId = :sparePartId`
- **出入库类型筛选**：如果提供transactionType，添加 `transactionType = :transactionType`
- **单号模糊查询**：如果提供transactionCode，添加 `transactionCode ILIKE '%:transactionCode%'`（不区分大小写）
- **时间范围筛选**：
  - 如果同时提供startDate和endDate：`transactionTime BETWEEN :startDate AND :endDate`
  - 如果只提供startDate：`transactionTime >= :startDate`
  - 如果只提供endDate：`transactionTime <= :endDate`

#### 步骤6: 执行数据库查询
执行Sequelize查询，包含以下关联：
- **sparePart**（备件信息）：必选关联，查询字段：`sparePartCode, sparePartName, unit`
- **operator**（经手人信息）：必选关联，查询字段：`id, name, email`
- **maintenanceTask**（维护任务信息）：可选关联（LEFT JOIN），查询字段：`id, taskCode, taskTitle, status`
- **equipmentFailure**（故障单信息）：可选关联（LEFT JOIN），查询字段：`id, failureCode, failureDescription, status`

应用分页和排序：
- **limit**：限制返回记录数
- **offset**：计算偏移量 = (page - 1) * limit
- **order**：按指定字段和顺序排序

#### 步骤7: 计算分页元数据
根据查询结果计算分页信息：
- **totalResults**：总记录数
- **totalPages**：总页数 = Math.ceil(totalResults / limit)
- **page**：当前页码
- **limit**：每页数量

#### 步骤8: 格式化响应数据
将查询结果封装为统一响应格式：
- **success**: true
- **data**: 包含results数组和分页信息
- **message**: "获取出入库记录成功"
- **meta**: 包含时间戳、请求ID和版本号

#### 步骤9: 返回查询结果
返回HTTP 200状态码和格式化后的响应数据。

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/spare-parts/transactions`

**功能描述**: 根据条件分页查询出入库记录，支持按备件ID、出入库类型、单号、时间范围等条件筛选。返回结果包含出入库记录详情、备件信息、经手人信息、关联的维护任务和故障单信息。

**认证要求**: JWT Bearer Token，需要 `mdm.tpm.spare-part.view` 权限

## 统一响应格式说明

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号


**请求头**:

```
Authorization: Bearer <access_token>
```

## 使用示例

### 场景1: 查询特定备件的所有出入库记录

**业务需求**: 管理员需要查看编码为"SP-001"的液压油滤芯的所有历史出入库记录，以分析使用频率和库存变化趋势。

**实现步骤**:
1. 先通过查询备件列表接口获取备件ID
2. 使用备件ID查询出入库记录

**响应数据分析**:
- 通过 `transactionType` 字段统计入库和出库次数
- 通过 `quantity` 字段计算总入库量和总出库量
- 通过 `transactionTime` 字段分析使用频率和周期

**业务需求**: 财务部门需要统计本月（2024年1月）所有备件的领用情况，用于成本核算。

**数据处理建议**:
- 遍历所有页面获取完整数据
- 根据 `sparePart.sparePartName` 分组统计
- 结合备件单价计算总成本

## 附录

### 出入库类型枚举

| 类型码 | 中文名称 | 说明                         | 对库存影响 |
| ------ | -------- | ---------------------------- | ---------- |
| 入库   | 入库     | 备件采购或归还后入库         | 增加       |
| 领用   | 领用     | 维护人员领用备件用于维护任务 | 减少       |
| 退库   | 退库     | 未使用的备件退回仓库         | 增加       |
| 报废   | 报废     | 备件损坏或过期后报废处理     | 减少       |

### 排序字段说明

| 字段名          | 说明       | 适用场景                 |
| --------------- | ---------- | ------------------------ |
| transactionTime | 出入库时间 | 按时间顺序查看出入库记录 |
| transactionCode | 出入库单号 | 按单号顺序查看           |
| quantity        | 出入库数量 | 查看大额出入库或异常数量 |

### 分页最佳实践

1. **首次查询**: 使用默认分页参数（page=1, limit=10），获取第一页数据和总记录数
2. **翻页处理**: 根据 `totalPages` 字段判断是否需要翻页
3. **大数据量**: 如果 `totalResults` 很大，建议增加筛选条件缩小范围
4. **性能优化**: 每页限制不超过100条，避免单次查询数据量过大

### 日期格式说明

- **输入格式**: ISO 8601标准，如 "2024-01-21" 或 "2024-01-21T16:50:00.000Z"
- **输出格式**: 统一返回UTC时间，格式为 "2024-01-21T16:50:00.000Z"
- **时区处理**: 前端需根据用户时区进行本地化显示
