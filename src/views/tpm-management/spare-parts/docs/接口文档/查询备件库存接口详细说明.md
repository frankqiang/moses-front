## 功能概述

### 所有功能

查询备件库存（Get Spare Part Inventory）是备件管理模块中的核心查询接口之一,用于实时获取指定备件的库存状态信息,以支持库存监控、低库存预警、采购计划制定等业务场景。该接口不仅返回基础的库存数据,还提供智能计算的可用库存和库存状态分析。

### 关键特性

- ✅ **实时库存查询**：查询指定备件的当前库存数量、在途数量和预留数量,确保数据实时准确
- ✅ **可用库存计算**：自动计算可用库存（当前库存 - 预留数量）,为出库操作提供决策依据
- ✅ **低库存预警**：智能判断当前库存是否低于安全库存,自动返回库存状态标识
- ✅ **完整配置信息**：返回备件的库存配置参数（安全库存、上下限）,便于库存管理决策
- ✅ **备件基础信息关联**：同时返回备件编码、名称、计量单位等基础信息,无需二次查询
- ✅ **历史追踪**：提供库存最后更新时间,便于追踪库存变更历史

---

### 使用前提

- ✅ 备件主数据已创建且未被删除
- ✅ 用户已通过身份认证,持有有效的JWT Token
- ✅ 用户拥有 `mdm.tpm.spare-part.view` 查询权限
- ✅ 提供的备件ID必须为有效的UUID格式

### 不适用场景

- ❌ 不适用于批量查询多个备件的库存（应使用备件列表接口,可返回库存摘要信息）
- ❌ 不适用于修改库存数量（应使用备件入库/出库接口）
- ❌ 不适用于查询历史库存数据（当前仅支持实时库存查询）

### 详细步骤说明

#### 步骤1: 接收查询请求
- **操作**: 控制器层接收HTTP GET请求,从路径参数中提取备件ID
- **验证**: 通过Joi验证器检查备件ID是否为有效的UUID格式
- **日志**: 记录查询操作日志,包含备件ID和操作人信息
- **异常**: 如果ID格式不正确,返回400错误和验证失败信息

#### 步骤2: 身份认证与权限校验
- **Token验证**: 中间件验证请求头中的JWT Token是否有效
- **权限检查**: 验证用户是否拥有 `mdm.tpm.spare-part.view` 权限
- **用户信息提取**: 从Token中提取用户ID,用于日志记录
- **异常**:
  - Token无效或过期: 返回401 UNAUTHORIZED
  - 权限不足: 返回403 FORBIDDEN

#### 步骤3: 查询库存记录
- **数据库查询**: 服务层调用 `SparePartInventory.findOne()` 查询库存记录
- **查询条件**: `WHERE sparePartId = :id`
- **关联查询**: 同时关联查询备件主数据表,获取备件基础信息
- **软删除过滤**: 确保只查询未被删除的备件（`isDeleted = false`）

#### 步骤4: 关联查询备件信息
- **关联对象**: 通过Sequelize的include机制关联查询SparePart表
- **返回字段**:
  - sparePartCode: 备件编码
  - sparePartName: 备件名称
  - unit: 计量单位
  - safetyStock: 安全库存
  - minStock: 库存下限
  - maxStock: 库存上限
- **异常**: 如果库存记录不存在或备件已删除,抛出404错误

#### 步骤5: 计算可用库存
- **计算逻辑**: `availableQuantity = currentQuantity - reservedQuantity`
- **业务含义**: 可用库存表示实际可以出库的数量,已扣除预留数量
- **数据类型**: 整数,不可为负数（如果出现负数说明数据异常）
- **实现位置**: 服务层动态计算,不存储在数据库

#### 步骤6: 判断库存状态
- **判断逻辑**: 调用库存模型的 `isLowStock()` 实例方法
- **判断规则**: `currentQuantity <= safetyStock` 返回true,否则返回false
- **业务含义**: true表示需要及时补充库存,false表示库存充足
- **实现位置**: 模型层方法,服务层调用

#### 步骤7: 组装响应数据
- **数据整合**: 将数据库查询结果转换为JSON对象
- **添加计算字段**:
  - 添加 `availableQuantity` 可用库存
  - 添加 `isLowStock` 库存状态标识
- **数据结构**: 包含库存数据、备件信息和计算字段的完整对象
- **格式化**: 确保日期时间字段符合ISO 8601格式

#### 步骤8: 返回统一响应格式
- **HTTP状态码**: 200 OK
- **响应结构**: 符合系统统一的成功响应格式
- **响应内容**:
  - `success: true` 表示操作成功
  - `data` 包含完整的库存详情
  - `message` 提供操作成功的描述信息
  - `meta` 包含时间戳、请求ID和版本信息

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/spare-parts/:id/inventory`

**功能描述**: 获取指定备件的库存详情,包含当前库存数量、在途数量、预留数量、可用库存（当前库存-预留数量）和库存状态（是否低于安全库存）。同时返回备件的基本信息和库存配置,无需二次查询。

**认证要求**: Bearer Token认证,需要 `mdm.tpm.spare-part.view` 权限

**请求头**:

```
Authorization: Bearer <access_token>
```

## 使用示例

### 场景1: 出库前检查库存充足性

**业务需求**: 在执行备件出库操作之前,先查询库存确认是否有足够的可用库存,避免出库失败。

### 场景2: 库存监控看板实时展示

**业务需求**: 在库存管理看板上实时展示各备件的库存状态,标识低库存备件,提醒采购人员。

### 场景3: 采购计划制定

**业务需求**: 根据当前库存、在途数量和安全库存,计算采购需求量,制定采购计划。

## 附录

### 库存数量字段说明

| 字段名            | 中文名称 | 说明                                            | 更新时机                    |
| ----------------- | -------- | ----------------------------------------------- | --------------------------- |
| currentQuantity   | 当前库存 | 仓库中实际拥有的备件数量                        | 入库时增加,出库时减少       |
| inTransitQuantity | 在途数量 | 已采购但尚未入库的备件数量                      | 创建采购订单时设置          |
| reservedQuantity  | 预留数量 | 已分配给维护任务但尚未实际出库的数量            | 维护任务创建时预留          |
| availableQuantity | 可用库存 | 当前可以实际出库的数量（计算字段,不存储数据库） | 实时计算: 当前库存-预留数量 |

### 库存配置参数说明

| 参数名      | 中文名称 | 说明                                | 推荐设置                       |
| ----------- | -------- | ----------------------------------- | ------------------------------ |
| safetyStock | 安全库存 | 低库存预警阈值,低于此值将触发预警   | 根据使用频率和采购周期综合确定 |
| minStock    | 库存下限 | 库存管理下限,建议保持库存不低于此值 | 通常设置为安全库存的1.5-2倍    |
| maxStock    | 库存上限 | 库存管理上限,避免积压过多库存       | 根据仓储空间和资金占用综合确定 |

### 库存状态枚举

| 状态标识           | 中文名称 | 判断条件                       | 建议操作          |
| ------------------ | -------- | ------------------------------ | ----------------- |
| isLowStock = true  | 低库存   | currentQuantity <= safetyStock | 紧急采购补充库存  |
| isLowStock = false | 正常库存 | currentQuantity > safetyStock  | 正常使用,定期监控 |

### 库存计算公式

**可用库存**:
```
availableQuantity = currentQuantity - reservedQuantity
```

**预期库存**（考虑在途数量）:
```
expectedQuantity = currentQuantity + inTransitQuantity - reservedQuantity
```

**是否低库存**:
```
isLowStock = (currentQuantity <= safetyStock)
```

### 常见问题

**Q1: availableQuantity 和 currentQuantity 有什么区别?**
A1: currentQuantity是仓库中实际拥有的数量,而availableQuantity是扣除了预留数量后实际可以出库的数量。例如当前库存15件,预留2件,可用库存为13件。

**Q2: 为什么需要inTransitQuantity（在途数量）?**
A2: 在途数量表示已采购但尚未入库的备件,可以用于采购计划制定。例如当前库存偏低但有10件在途,可以不必紧急采购。

**Q3: isLowStock 是如何判断的?**
A3: 系统会比较当前库存（currentQuantity）和安全库存（safetyStock）,如果当前库存小于或等于安全库存,则isLowStock为true,需要及时补充。

**Q4: 如果库存记录不存在会返回什么错误?**
A4: 会返回404错误,错误码为TPM_SPARE_004,提示"库存记录不存在"。这通常说明备件主数据创建时未正确创建库存记录,需要检查数据一致性。

**Q5: 查询库存接口是否会锁定库存?**
A5: 不会。该接口仅用于查询,不会对库存数据进行任何修改或锁定操作。
