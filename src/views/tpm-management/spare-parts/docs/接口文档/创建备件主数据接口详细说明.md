## 功能概述

### 所有功能

创建备件主数据（Create Spare Part）是备件管理模块的起始操作，用于在系统中新建备件的基础信息和库存管理策略，为后续的备件入库、领用和库存管理提供数据基础。该接口支持完整的备件属性定义，包括编码规范、规格参数、供应商信息、库存策略等，并在创建时自动初始化库存记录。

### 关键特性

- ✅ **自动初始化库存**：创建备件时自动生成对应的库存记录，初始库存为0，无需单独创建
- ✅ **编码唯一性保障**：备件编码全局唯一且自动转大写，确保系统内标识的一致性和可追溯性
- ✅ **灵活的供应商管理**：支持结构化的供应商信息（名称、联系人、电话、邮箱），便于采购协调
- ✅ **完善的库存策略**：可设置库存上下限、安全库存和采购提前期，为自动预警和采购计划提供依据
- ✅ **设备关联能力**：支持定义适用设备类型（逗号分隔多个），快速匹配设备维护所需备件
- ✅ **全生命周期属性**：支持保质期、存储位置等全生命周期管理属性，确保备件质量和可用性

---

### 使用前提

- ✅ 用户已通过认证获得有效的 Bearer Token
- ✅ 用户具有 `mdm.tpm.spare-part.create` 权限
- ✅ 备件编码尚未在系统中使用（全局唯一性验证）
- ✅ 如设置库存上下限，需确保上限 ≥ 下限

### 不适用场景

- ❌ 备件编码已存在时无法创建，应使用更新接口修改现有备件信息
- ❌ 不支持批量创建备件，需要逐个调用接口创建
- ❌ 不能通过此接口直接设置初始库存数量，创建后需使用入库接口添加库存

### 详细步骤说明

#### 步骤1: 接收创建备件请求
- 接收前端通过 POST 方法发送的备件数据
- 解析 JSON 格式的请求体
- 提取 Bearer Token 进行身份认证

#### 步骤2: 验证请求参数
- **必填字段检查**：
  - `sparePartCode`（备件编码）
  - `sparePartName`（备件名称）
  - `unit`（计量单位）
- **数据类型验证**：
  - 字符串类型：编码、名称、规格等
  - 数字类型：单价、库存上下限、采购提前期等
  - 对象类型：供应商信息（如提供）
- **格式规范验证**：
  - 字符串长度限制
  - 邮箱格式（supplierInfo.email）
  - 数字精度（单价最多2位小数）

#### 步骤3: 业务规则验证
- **备件编码唯一性**：
  - 将输入编码转大写后查询数据库
  - 如已存在同编码备件，返回错误 `SPARE_PART_001`
- **库存策略验证**：
  - 检查库存上限 ≥ 库存下限（如两者都提供）
  - 不满足则返回错误 `SPARE_PART_003`
- **数值非负验证**：
  - 单价、库存上下限、安全库存、采购提前期、保质期等必须 ≥ 0

#### 步骤4: 数据预处理
- **编码转大写**：自动将 `sparePartCode` 转为大写格式
- **默认值填充**：
  - `safetyStock` 默认为 0
  - `createdBy` 设置为当前登录用户ID
  - `createdAt` 设置为当前时间

#### 步骤5-6: 开启事务并创建备件主数据记录
- 开启数据库事务确保原子性
- 向 `spare_parts` 表插入新记录
- 包含所有提供的字段和自动填充的审计字段
- 生成 UUID 作为备件唯一标识

#### 步骤7: 自动创建库存记录
- 向库存表插入对应记录
- 设置以下初始值：
  - `sparePartId`：关联刚创建的备件ID
  - `currentQuantity`：0（初始库存为0）
  - `inTransitQuantity`：0
  - `reservedQuantity`：0
  - `lastUpdated`：当前时间

#### 步骤8: 提交事务
- 验证事务中所有操作均成功
- 提交事务，持久化备件和库存数据
- 如任何步骤失败，自动回滚所有操作

#### 步骤9: 查询完整备件信息
- 关联查询创建人信息（姓名、邮箱）
- 获取库存初始状态
- 构建完整的响应数据结构

#### 步骤10: 返回成功响应
- HTTP 状态码：201 Created
- 返回备件完整数据，包括：
  - 生成的UUID
  - 所有备件属性
  - 创建人详细信息
  - 初始库存状态
  - 审计信息（创建时间）

## 接口文档

### 基本信息

**接口路径**: `POST /v1/mdm/tpm/spare-parts`

**功能描述**: 创建新的备件主数据，包含备件基础信息（编码、名称、规格等）和库存配置（安全库存、上下限等）。系统会自动创建对应的库存记录，初始库存为0。适用于新备件入库前的信息登记和库存策略设置。

**认证要求**: Bearer Token 认证，需要 `mdm.tpm.spare-part.create` 权限

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",

      "field": "发生错误的字段名（可选）",

    }

    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null

- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

## 常见问题

### Q1: 为什么创建备件时不能直接设置初始库存数量？

**A**: 这是基于数据完整性和审计追溯的设计原则：
- 创建备件时自动创建库存记录，初始库存统一为0
- 实际库存增加必须通过入库接口，生成入库单和流水记录
- 每次库存变化都有可追溯的单据和操作记录
- 如需添加库存，使用 `POST /v1/mdm/tpm/spare-parts/:id/in-stock` 接口

### Q2: 备件编码命名有什么建议？

**A**: 推荐以下编码规范：
- **格式**: `SP-[类别]-[子类别]-[序号]`
- **示例**:
  - `SP-BEARING-001`（轴承类）
  - `SP-FILTER-AIR-001`（空气滤芯类）
  - `SP-OIL-HYD-001`（液压油类）
  - `SP-BOLT-M8-001`（M8螺栓类）
- **优点**:
  - 分类清晰，便于管理
  - 编码即可判断备件类别
  - 支持按类别筛选和统计

### Q3: 库存上限、下限、安全库存如何设置？

**A**: 建议设置策略：
- **安全库存（safetyStock）**: 触发预警的阈值，通常为日均消耗量 × 采购提前期
  - 示例：日均消耗2件，提前期7天，安全库存 = 2 × 7 = 14件
- **库存下限（minStock）**: 低于此值应启动采购，通常为安全库存的1.5倍
  - 示例：安全库存14件，下限 = 14 × 1.5 = 21件
- **库存上限（maxStock）**: 避免库存积压，通常为月均消耗量
  - 示例：月均消耗60件，上限 = 60件
- **关系**: `安全库存 ≤ 库存下限 ≤ 库存上限`

### Q4: 供应商信息必须填写吗？

**A**:
- **不是必填**，但强烈建议填写关键备件的供应商信息
- **优点**:
  - 快速联系供应商采购
  - 比价和供应商评估
  - 应急情况快速响应
- **建议**: 至少填写供应商名称和联系电话

### Q5: 创建备件失败，提示"备件编码已存在"怎么办？

**A**: 处理步骤：
1. 使用 `GET /v1/mdm/tpm/spare-parts?sparePartCode=XXX` 查询是否已存在
2. 如果存在：
   - 如需修改信息，使用 `PATCH /v1/mdm/tpm/spare-parts/:id` 更新
   - 如果是软删除的备件，可联系管理员恢复
3. 如果不存在：
   - 可能是编码转大写后冲突（如 `sp-001` 和 `SP-001`）
   - 使用不同的备件编码

### Q6: 适用设备类型如何填写？

**A**:
- **格式**: 多个设备类型用英文逗号分隔
- **示例**: `"退火炉,行车,冷轧机"`
- **用途**:
  - 维护任务规划时快速查找所需备件
  - 按设备类型统计备件消耗
  - 设备故障时推荐可用备件
- **建议**: 填写设备大类，不要过于细化

### Q7: 创建备件后如何修改信息？

**A**:
- 使用 `PATCH /v1/mdm/tpm/spare-parts/:id` 接口更新
- **可修改**: 除备件编码外的所有字段
- **不可修改**: 备件编码（唯一标识，创建后不可变）
- **需要权限**: `mdm.tpm.spare-part.manage`

### Q8: 保质期为0或不填写有什么区别？

**A**:
- **不填写（null）**: 表示备件无保质期限制
- **填写0**: 表示保质期数据暂未明确，后续补充
- **填写具体月数**: 系统可用于过期提醒（如有此功能）
- **建议**:
  - 润滑油、密封胶等易变质备件必须填写
  - 金属件、标准件等可不填写
