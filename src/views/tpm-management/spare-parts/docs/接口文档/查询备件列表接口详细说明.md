## 功能概述

### 所有功能

查询备件列表（Query Spare Parts List）是备件管理模块中的核心查询操作之一，用于根据多种条件分页查询备件主数据及库存信息，以支持备件查询、库存监控、采购计划制定等业务场景。该接口提供灵活的筛选条件和排序方式，满足不同业务场景下的备件数据查询需求。

### 关键特性

- ✅ **多条件模糊查询**：支持按备件编码、备件名称、适用设备类型进行模糊查询，快速定位所需备件
- ✅ **低库存预警筛选**：支持筛选当前库存低于或等于安全库存的备件，便于及时发现需要补货的备件
- ✅ **灵活排序方式**：支持按备件编码、备件名称、创建时间、更新时间进行升序或降序排序
- ✅ **分页查询**：支持自定义每页数量（1-100条），提供完整的分页信息（当前页、总页数、总记录数）
- ✅ **库存信息联查**：返回结果自动包含每个备件的实时库存信息（当前库存、在途数量、预留数量）
- ✅ **创建人信息**：返回结果包含备件创建人的基本信息（姓名、邮箱），便于追溯数据来源

---

### 使用前提

- ✅ 用户已登录系统，持有有效的 JWT Token
- ✅ 用户具有备件查看权限（`mdm.tpm.spare-part.view`）
- ✅ 系统中已存在备件主数据（若无数据则返回空列表）
- ✅ 备件创建时已自动创建对应的库存记录

### 不适用场景

- ❌ 需要获取单个备件的完整详细信息（包括更新人信息），应使用 `GET /v1/mdm/tpm/spare-parts/:id` 接口
- ❌ 需要查询备件的出入库流水记录，应使用 `GET /v1/mdm/tpm/spare-parts/transactions` 接口

### 详细步骤说明

#### 步骤1: 接收查询请求

- 接收客户端发送的 GET 请求
- 解析查询参数（筛选条件、分页参数、排序参数）
- 提取请求头中的 Authorization Token

#### 步骤2: 验证用户身份和权限

- 验证 JWT Token 的有效性（签名、过期时间）
- 从 Token 中提取用户信息（用户 ID、角色等）
- 校验用户是否具有 `mdm.tpm.spare-part.view` 权限
- 如果验证失败，返回 401 或 403 错误

#### 步骤3: 验证查询参数

**参数格式校验**：
- `page`: 必须 ≥ 1，默认值 1
- `limit`: 必须在 1-100 之间，默认值 10
- `sortBy`: 必须是允许的字段之一（sparePartCode/sparePartName/createdAt/updatedAt）
- `sortOrder`: 必须是 asc 或 desc
- `lowStock`: 必须是布尔值（true/false）

**参数合理性校验**：
- 字符串类型的筛选条件不为空
- 如果验证失败，返回 400 错误

#### 步骤4: 构建查询条件

**筛选条件构建**：
- `sparePartCode`: 如果提供，使用 LIKE 模糊查询（不区分大小写）
- `sparePartName`: 如果提供，使用 LIKE 模糊查询
- `applicableEquipmentTypes`: 如果提供，使用 LIKE 模糊查询
- `lowStock=true`: 添加条件 `inventory.currentQuantity <= safetyStock`
- `isDeleted=false`: 固定条件，排除软删除的备件

**排序规则**：
- 按指定的 `sortBy` 字段排序
- 使用指定的 `sortOrder` 方向（升序/降序）
- 默认按 `createdAt` 降序排序（最新创建的在前）

**分页计算**：
- 计算偏移量 `offset = (page - 1) × limit`
- 设置查询限制 `limit`

#### 步骤5: 查询备件主数据

**数据库查询**：
- 使用构建的查询条件查询 `spare_parts` 表
- 关联查询 `spare_part_inventories` 表（LEFT JOIN，获取库存信息）
- 关联查询 `users` 表（LEFT JOIN，获取创建人信息，关联字段 `createdBy`）
- 只返回未软删除的备件记录（`isDeleted = false`）

**查询优化**：
- 使用数据库索引加速查询（备件编码、备件名称、创建时间等字段）
- 关联查询使用合适的 JOIN 类型避免 N+1 问题

#### 步骤6: 计算分页信息

- 执行总数查询 `COUNT(*)`，获取符合条件的总记录数
- 计算总页数 `totalPages = Math.ceil(totalResults / limit)`
- 如果 `totalResults = 0`，返回空列表，`totalPages = 0`

#### 步骤7: 格式化响应数据

**备件数据格式化**：
- 每个备件对象包含完整的主数据字段
- 嵌套 `inventory` 对象（库存信息）
- 嵌套 `creator` 对象（创建人信息）
- 日期时间字段格式化为 ISO 8601 格式
- `unitPrice` 格式化为两位小数的字符串

**分页信息格式化**：
- `results`: 备件对象数组
- `page`: 当前页码
- `limit`: 每页数量
- `totalPages`: 总页数
- `totalResults`: 总记录数

#### 步骤8: 返回查询结果

- 构建统一成功响应格式
- `success: true`
- `data`: 包含 `results` 和分页信息
- `message`: "获取备件列表成功"
- `meta`: 响应元信息（时间戳、请求 ID、API 版本）

## 接口文档

### 基本信息

**接口路径**: `GET /v1/mdm/tpm/spare-parts`

**功能描述**: 根据条件分页查询备件列表，支持按备件编码、名称、适用设备类型进行模糊查询，支持低库存筛选（只显示低于安全库存的备件），支持按多个字段排序。返回结果包含备件基础信息、库存信息和创建人信息。

**认证要求**: JWT Bearer Token，需要 `mdm.tpm.spare-part.view` 权限

## 使用示例

### 场景1: 查询所有备件列表（默认排序）

**业务需求**: 仓库管理员需要查看系统中所有备件的列表，按创建时间倒序排列，每页显示10条。

**请求示例**:

```bash
curl -X GET http://localhost:3000/v1/mdm/tpm/spare-parts \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

**关键要点**:
- 不传递任何查询参数，使用默认值
- 默认第1页，每页10条
- 默认按 `createdAt` 降序排序（最新创建的在前）

### 场景2: 按备件名称模糊查询

**业务需求**: 维护人员需要查找所有名称中包含"滤芯"的备件，以便进行定期更换。

**请求示例**:

```bash
curl -X GET "http://localhost:3000/v1/mdm/tpm/spare-parts?sparePartName=滤芯&page=1&limit=20" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

**关键要点**:
- 使用 `sparePartName=滤芯` 进行模糊查询
- 查询结果将包含所有名称中包含"滤芯"的备件（如"液压油滤芯"、"空气滤芯"等）
- 增加 `limit=20` 每页显示更多结果

### 场景3: 查询低库存备件（预警列表）

**业务需求**: 采购部门需要每日检查低库存备件，制定采购补货计划。

**请求示例**:

```bash
curl -X GET "http://localhost:3000/v1/mdm/tpm/spare-parts?lowStock=true&sortBy=sparePartName&sortOrder=asc" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

**关键要点**:
- 使用 `lowStock=true` 筛选库存不足的备件
- 只返回 `currentQuantity <= safetyStock` 的备件
- 按备件名称升序排序，便于按字母顺序查看
- 通过 `inventory.currentQuantity` 和 `safetyStock` 字段判断紧急程度

### 场景4: 按适用设备类型筛选

**业务需求**: 退火炉维护工程师需要查看所有适用于退火炉的备件，提前准备维护所需物料。

**请求示例**:

```bash
curl -X GET "http://localhost:3000/v1/mdm/tpm/spare-parts?applicableEquipmentTypes=退火炉&sortBy=sparePartCode&sortOrder=asc" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

**关键要点**:
- 使用 `applicableEquipmentTypes=退火炉` 筛选适用设备
- 查询结果包含所有 `applicableEquipmentTypes` 字段中包含"退火炉"的备件
- 按备件编码升序排序，便于按编码顺序查看

### 场景5: 组合查询（多条件筛选）

**业务需求**: 仓库管理员需要查找所有适用于行车的低库存备件，优先处理补货。

**请求示例**:

```bash
curl -X GET "http://localhost:3000/v1/mdm/tpm/spare-parts?applicableEquipmentTypes=行车&lowStock=true&sortBy=createdAt&sortOrder=desc&limit=50" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

**关键要点**:
- 同时使用设备类型筛选和低库存筛选
- 结果为两个条件的交集（AND 逻辑）
- 按创建时间降序，优先显示新添加的备件
- 每页显示50条，减少翻页次数

## 常见问题

### Q1: 为什么查询结果中的 `inventory` 对象可能为 null？

**回答**:
正常情况下不会出现 `inventory` 为 null 的情况，因为创建备件时系统会自动创建对应的库存记录。如果出现 `inventory` 为 null，说明数据存在异常，可能的原因包括：
- 数据迁移时未同步创建库存记录
- 库存记录被误删除

**处理建议**: 联系系统管理员修复数据，确保每个备件都有对应的库存记录。

### Q2: 低库存筛选（lowStock=true）的判断标准是什么？

**回答**:
低库存筛选的判断标准为：`当前库存数量 <= 安全库存`

- `currentQuantity`: 库存记录中的当前库存数量
- `safetyStock`: 备件主数据中的安全库存设置

**示例**:
- 备件A：当前库存5件，安全库存5件 → 低库存（5 <= 5）
- 备件B：当前库存6件，安全库存5件 → 正常库存（6 > 5）
- 备件C：当前库存0件，安全库存0件 → 低库存（0 <= 0）

### Q3: 模糊查询是否区分大小写？

**回答**:
不区分大小写。所有字符串类型的模糊查询（`sparePartCode`、`sparePartName`、`applicableEquipmentTypes`）均不区分大小写。

**示例**:
- 查询 `sparePartCode=sp` 可以匹配到 `SP-001`、`sp-002`、`Sp-003`
- 查询 `sparePartName=滤芯` 可以匹配到 "液压油滤芯"、"空气滤芯" 等

### Q4: 分页参数如何正确使用？

**回答**:

**基本规则**:
- `page`: 页码，从 1 开始计数（不是从 0 开始）
- `limit`: 每页数量，范围 1-100，默认 10
- `totalPages`: 总页数，由后端计算返回
- `totalResults`: 总记录数，由后端计算返回

**计算公式**:
```
偏移量 = (page - 1) × limit
总页数 = Math.ceil(totalResults / limit)
```

**分页示例**:
假设总记录数为 25 条，每页 10 条：
- 第1页: `page=1&limit=10` → 返回第 1-10 条记录
- 第2页: `page=2&limit=10` → 返回第 11-20 条记录
- 第3页: `page=3&limit=10` → 返回第 21-25 条记录（最后一页，不足10条）

### Q5: 排序字段 sortBy 支持哪些选项？

**回答**:

支持以下4个字段的排序：

| 字段名        | 说明     | 适用场景                   |
| ------------- | -------- | -------------------------- |
| sparePartCode | 备件编码 | 按编码顺序浏览（字典序）   |
| sparePartName | 备件名称 | 按名称顺序浏览（字典序）   |
| createdAt     | 创建时间 | 按创建时间查看（默认选项） |
| updatedAt     | 更新时间 | 查看最近更新的备件         |

**排序方向**:
- `asc`: 升序（从小到大，从旧到新）
- `desc`: 降序（从大到小，从新到旧）

**默认排序**: `sortBy=createdAt&sortOrder=desc`（最新创建的备件在前）

### Q6: 如何获取备件的详细信息（包括更新人信息）？

**回答**:
查询列表接口返回的数据中不包含 `updater`（更新人信息）。如果需要查看完整的备件详细信息，应使用单个备件详情查询接口：

```bash
GET /v1/mdm/tpm/spare-parts/:id
```

详情接口返回的数据包含：
- 完整的备件主数据
- 库存信息（inventory）
- 创建人信息（creator）
- 更新人信息（updater）

### Q7: 查询结果为空时返回什么数据？

**回答**:
当没有符合筛选条件的备件时，接口仍然返回 200 状态码，但 `results` 数组为空：

```json
{
  "success": true,
  "data": {
    "results": [],
    "page": 1,
    "limit": 10,
    "totalPages": 0,
    "totalResults": 0
  },
  "message": "获取备件列表成功",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**关键特征**:
- `results`: 空数组 `[]`
- `totalPages`: 0
- `totalResults`: 0
- `success`: `true`（查询成功，只是结果为空）

### Q8: 如何理解 inventory 对象中的各个库存字段？

**回答**:

| 字段名            | 含义         | 说明                                       |
| ----------------- | ------------ | ------------------------------------------ |
| currentQuantity   | 当前库存     | 仓库中实际可用的库存数量                   |
| inTransitQuantity | 在途数量     | 已采购但尚未到货的数量（未来扩展功能）     |
| reservedQuantity  | 预留数量     | 已被预留但未实际领用的数量（未来扩展功能） |
| lastUpdatedAt     | 最后更新时间 | 库存最后一次变更的时间                     |

**可用库存计算**:
```
可用库存 = currentQuantity - reservedQuantity
```

**当前实现**:
在当前版本中，`inTransitQuantity` 和 `reservedQuantity` 通常为 0，主要使用 `currentQuantity` 字段判断库存状态。

### Q9: creator 对象为 null 的情况如何处理？

**回答**:
`creator` 对象可能为 null 的情况包括：
- 创建人账号已被删除（用户表中不存在）
- `createdBy` 字段为 null（数据异常）

**前端处理建议**:
```javascript
const creatorName = sparePart.creator ? sparePart.creator.name : "未知用户";
```

**业务影响**: 不影响备件数据的正常使用，仅影响创建人信息的显示。
