本文档详细说明了 Moses API 退火任务管理模块的所有接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。**本文档严格基于实际代码实现编写**，确保前端开发人员能够准确对接。

## 🔔 重要变更记录

### 2025-10-15：工艺模板状态验证规则更新 🆕

**变更原因**：适配工艺管理模块重构，修复工艺模板状态查询BUG，统一使用状态常量

**变更内容**：工艺模板关联验证规则明确化，修复错误的状态值

**影响接口**：
- ✅ `POST /v1/prod/annealing-tasks` - 创建退火任务（手工创建和基于计划批次生成）

**修复的BUG**：
- 🐛 修复了使用 `status: 'active'` 错误状态值导致无法查询工艺模板的问题
- 🐛 修复了硬编码状态值 `'生效'` 的问题

**工艺模板状态要求**（重要）：

| 字段                | 状态要求                      | 说明                            |
| ------------------- | ----------------------------- | ------------------------------- |
| `processTemplateId` | 工艺模板状态必须为 **`生效`** | 模板主记录状态需为"生效"        |
| 工艺模板最新版本    | 最新版本状态必须为 **`生效`** | latestVersion.status 需为"生效" |

**具体影响场景**：
1. **手工创建任务时**：指定的 `processTemplateId` 必须是生效状态
2. **从计划批次生成任务时**：
   - 如果计划批次关联了工艺模板，该模板必须是生效状态
   - 如果未关联，系统会从产品关联的工艺模板中自动选择生效的模板

**错误码说明**：

| 错误码               | 错误信息                 | 触发条件               |
| -------------------- | ------------------------ | ---------------------- |
| `RESOURCE_NOT_FOUND` | 工艺模板不存在           | 指定的工艺模板ID不存在 |
| `INVALID_STATUS`     | 工艺模板状态不是生效状态 | 工艺模板状态不是"生效" |

**前端处理建议**：
1. **创建任务时**：工艺模板选择器应只展示状态为"生效"的工艺模板
2. **错误提示**：收到错误时，提示用户选择已生效的工艺模板
3. **数据校验**：在提交前检查工艺模板状态

**后端实现变更**：
- 从错误的状态值 `'active'` 改为正确的常量 `PROCESS_TEMPLATE_STATUS.ACTIVE` (值为"生效")
- 从硬编码字符串 `'生效'` 改为使用常量 `PROCESS_TEMPLATE_STATUS.ACTIVE`

### 权限约定

退火任务管理模块涉及以下权限点：

- **prod.annealing-task.view**: 查看权限 - 允许查询退火任务列表、查看任务详情、查看任务进度、查看待排程任务列表
- **prod.annealing-task.manage**: 管理权限 - 允许创建退火任务、更新任务状态、绑定物料
- **prod.annealing-task.schedule**: 排程权限 - 允许应用排程结果、锁定/释放任务、获取待排程任务列表

## 统一响应格式

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

## 退火任务业务流程说明

### 业务流程概述

退火任务管理模块支持两种任务创建方式，并完整覆盖从任务创建到完成的全生命周期：

```
步骤1：任务创建
   ├─ 方式1：基于生产计划批次自动生成（推荐）
   │   ├─ 预览模拟装炉方案（可选）
   │   └─ 确认生成任务
   └─ 方式2：手工创建退火任务
       ├─ 填写产品信息和重量
       └─ 选择工艺模板（可选）
   ↓
步骤2：任务准备
   ├─ 绑定待退火物料（料框/料垛）
   ├─ 校验重量范围（35-42吨）
   ├─ 确认装炉顺序
   └─ 状态变更：draft → pending-schedule
   ↓
步骤3：任务排程
   ├─ 排程模块获取待排程任务列表
   ├─ 锁定任务防止重复排程
   ├─ 执行排程算法分配炉号和时间
   ├─ 应用排程结果回写
   └─ 状态变更：pending-schedule → scheduled
   ↓
步骤4：任务执行
   ├─ 装炉阶段：waiting-loading → loading → waiting-execute
   ├─ 执行阶段：in-progress（实时同步PLC数据）
   ├─ 出炉阶段：waiting-unload
   └─ 完成：completed
   ↓
步骤5：进度监控
   ├─ 实时查询任务执行进度
   ├─ 统计装炉/执行/出炉各阶段进度
   └─ 计算预计剩余时间和能耗
```

### 状态流转规则

退火任务包含以下状态：

| 状态代码           | 状态名称 | 说明                   | 允许的下一状态                                               |
| ------------------ | -------- | ---------------------- | ------------------------------------------------------------ |
| `draft`            | 草稿     | 任务已创建但未完成准备 | `pending-schedule`, `cancelled`                              |
| `pending-schedule` | 待排程   | 任务已准备好，等待排程 | `scheduled`, `draft`, `cancelled`                            |
| `scheduled`        | 已排程   | 已分配炉号和时间       | `waiting-loading`, `pending-schedule`, `paused`, `cancelled` |
| `waiting-loading`  | 待装炉   | 等待开始装炉           | `loading`, `paused`, `cancelled`                             |
| `loading`          | 装炉中   | 正在装炉               | `waiting-execute`, `waiting-loading`, `paused`, `terminated` |
| `waiting-execute`  | 待执行   | 装炉完成，等待PLC启动  | `in-progress`, `paused`, `terminated`                        |
| `in-progress`      | 执行中   | 退火炉正在执行工艺     | `waiting-unload`, `paused`, `terminated`                     |
| `waiting-unload`   | 待出炉   | 工艺完成，等待出炉     | `completed`, `paused`, `terminated`                          |
| `completed`        | 已完成   | 任务执行完成           | 无（终态）                                                   |
| `paused`           | 已暂停   | 任务暂停               | 可恢复到暂停前状态、`cancelled`、`terminated`                |
| `cancelled`        | 已取消   | 任务取消               | 无（终态）                                                   |
| `terminated`       | 异常终止 | 任务异常结束           | 无（终态）                                                   |

### 任务来源和优先级

**任务来源（source）**:
- `plan-split`: 基于生产计划批次自动拆分生成
- `manual`: 手工创建

**任务优先级（priority）**:
- `emergency`: 紧急（最高优先级）
- `high`: 高优先级
- `normal`: 正常优先级（默认）
- `low`: 低优先级

### 物料类型

**物料类型（materialType）**:
- `basket`: 料框（单个料框）
- `stack`: 料垛（多个料框堆叠）

### 1. 模拟装炉方案（预览）

**接口路径**: `POST /v1/prod/annealing-tasks/simulate`

**功能描述**: 根据计划批次和炉容量参数，模拟输出建议装炉方案供前端预览，不实际创建任务。用于在正式生成任务前，让用户预览拆分策略，根据炉容范围（35-42吨）智能计算建议任务数，支持用户调整任务数量后重新预览。

**认证要求**: 需要 Bearer Token

**权限要求**: `prod.annealing-task.view`

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名         | 类型   | 必填 | 限制          | 描述                             | 示例                                   |
| -------------- | ------ | ---- | ------------- | -------------------------------- | -------------------------------------- |
| planItemId     | string | 是   | UUID格式      | 生产计划批次ID                   | "554e4422-beac-48bd-a22b-43b38a3c212b" |
| taskCount      | number | 否   | 整数，1-50    | 指定生成任务数量，不填则自动计算 | 3                                      |
| targetCapacity | number | 否   | 浮点数，35-42 | 目标炉容量（吨），默认40         | 40                                     |

**请求示例**:

```bash
curl -X POST http://localhost:3000/v1/prod/annealing-tasks/simulate \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "planItemId": "554e4422-beac-48bd-a22b-43b38a3c212b",
    "taskCount": 3,
    "targetCapacity": 40
  }'
```


### 2. 获取待排程任务列表

**接口路径**: `GET /v1/prod/annealing-tasks/scheduling/pending`

**功能描述**: 输出待排程任务列表供排程模块使用，包含任务属性、可混炉标识、重量、工艺参数、物料明细。支持按产品编码、合金牌号、混炉分组、计划装炉时间、重量范围、优先级等条件筛选，默认按优先级升序、计划装炉时间升序、任务编号升序排序。

**认证要求**: 需要 Bearer Token

**权限要求**: `prod.annealing-task.schedule`

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**查询参数**:

| 参数名                | 类型    | 必填 | 限制                 | 描述                            | 示例                       |
| --------------------- | ------- | ---- | -------------------- | ------------------------------- | -------------------------- |
| productCode           | string  | 否   | 最大100字符          | 产品编码筛选                    | "AF-1060-O-0.05"           |
| alloyGrade            | string  | 否   | 最大60字符           | 合金牌号筛选                    | "1060"                     |
| mixingGroupCode       | string  | 否   | 最大60字符           | 混炉分组编码筛选                | "MG-001"                   |
| plannedLoadingFrom    | string  | 否   | ISO 8601日期格式     | 计划装炉开始时间                | "2024-01-20T00:00:00.000Z" |
| plannedLoadingTo      | string  | 否   | ISO 8601日期格式     | 计划装炉结束时间                | "2024-01-25T23:59:59.000Z" |
| minWeight             | number  | 否   | 浮点数，>0           | 最小重量（吨）                  | 35                         |
| maxWeight             | number  | 否   | 浮点数，>0           | 最大重量（吨）                  | 42                         |
| priorities            | string  | 否   | 逗号分隔的优先级列表 | 优先级筛选                      | "emergency,high,normal"    |
| includeScheduleLocked | boolean | 否   | true/false           | 是否包含已锁定的任务，默认false | false                      |
| limit                 | number  | 否   | 整数，1-500          | 返回记录数量限制，默认10        | 50                         |
| offset                | number  | 否   | 整数，>=0            | 记录偏移量，默认0               | 0                          |

**请求示例**:

```bash
curl -X GET "http://localhost:3000/v1/prod/annealing-tasks/scheduling/pending?productCode=AF-1060-O-0.05&priorities=high,normal&limit=20" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

### 8. 更新退火任务状态

**接口路径**: `PATCH /v1/prod/annealing-tasks/:taskId/status`

**功能描述**: 更新任务状态，校验合法流转，记录日志，联动时间字段。系统会自动根据状态流转规则校验状态变更是否合法，并根据新状态自动更新相应的时间字段（如装炉开始时间、执行开始时间等）。对于某些敏感状态变更（如暂停、取消、异常终止），必须提供变更原因。

**认证要求**: 需要 Bearer Token

**权限要求**: `prod.annealing-task.manage`

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**路径参数**:

| 参数名 | 类型   | 必填 | 描述                 | 示例                                   |
| ------ | ------ | ---- | -------------------- | -------------------------------------- |
| taskId | string | 是   | 退火任务ID，UUID格式 | "554e4422-beac-48bd-a22b-43b38a3c212b" |

**请求参数**:

| 参数名         | 类型   | 必填     | 限制             | 描述                                   | 示例                                   |
| -------------- | ------ | -------- | ---------------- | -------------------------------------- | -------------------------------------- |
| status         | string | 是       | 有效的任务状态值 | 目标状态                               | "in-progress"                          |
| remarks        | string | 否       | 最大1000字符     | 备注说明                               | "开始执行退火工艺"                     |
| reason         | string | 条件必填 | 最大500字符      | 状态变更原因，暂停/取消/异常终止时必填 | "设备故障需要暂停"                     |
| additionalData | object | 否       | JSON对象         | 附加数据                               | {"operator": "张三", "comment": "..."} |

**状态流转规则** - 允许的状态变更：

| 当前状态         | 允许的下一状态                                       |
| ---------------- | ---------------------------------------------------- |
| draft            | pending-schedule, cancelled                          |
| pending-schedule | scheduled, draft, cancelled                          |
| scheduled        | waiting-loading, pending-schedule, paused, cancelled |
| waiting-loading  | loading, paused, cancelled                           |
| loading          | waiting-execute, waiting-loading, paused, terminated |
| waiting-execute  | in-progress, paused, terminated                      |
| in-progress      | waiting-unload, paused, terminated                   |
| waiting-unload   | completed, paused, terminated                        |
| paused           | 可恢复到暂停前状态、cancelled、terminated            |
| completed        | 无（终态）                                           |
| cancelled        | 无（终态）                                           |
| terminated       | 无（终态）                                           |

| 参数名 | 类型   | 必填 | 描述                 | 示例                                   |
| ------ | ------ | ---- | -------------------- | -------------------------------------- |

### 10. 应用排程结果（排程回写）

**接口路径**: `POST /v1/prod/annealing-tasks/:taskId/schedule`

**功能描述**: 接收排程模块回传的炉号、计划装炉/出炉时间，并落库、更新状态、记录日志。排程模块完成任务排程后，调用此接口将排程结果回写到退火任务，系统会自动校验时间合法性、校验任务状态、记录排程日志、并支持自动更新任务状态为已排程（可选）。

## 错误码说明

系统使用统一的错误码体系，便于客户端处理和日志追踪。错误码格式：模块前缀\_数字编号。

### 通用错误码

| 错误码             | HTTP 状态码 | 错误消息                | 说明                         | 处理建议                       |
| ------------------ | ----------- | ----------------------- | ---------------------------- | ------------------------------ |
| PARAM_ERROR        | 400         | 请求参数错误            | 请求参数不符合验证规则       | 检查请求参数格式和必填字段     |
| VALIDATION_ERROR   | 400         | 请求参数验证失败        | Joi验证器校验失败            | 检查请求参数格式和限制         |
| UNAUTHORIZED       | 401         | 未授权，Token无效或过期 | 未提供认证Token或Token已失效 | 重新登录获取有效Token          |
| FORBIDDEN          | 403         | 无权限执行此操作        | 当前用户没有该操作的权限     | 联系管理员分配相应权限         |
| RESOURCE_NOT_FOUND | 404         | 资源不存在              | 请求的资源未找到             | 检查资源ID是否正确             |
| INVALID_STATUS     | 400         | 状态不合法              | 状态流转或状态值不合法       | 检查状态参数和流转规则         |
| RESOURCE_CONFLICT  | 409         | 资源冲突                | 资源状态冲突或重复           | 检查资源状态和唯一性约束       |
| INTERNAL_ERROR     | 500         | 服务器内部错误          | 服务器处理请求时发生错误     | 查看日志定位问题或联系技术支持 |

### 退火任务特定错误码

退火任务模块主要使用以下通用错误码，并通过错误消息提供详细的业务上下文。系统未为退火任务模块定义独立的错误码前缀，而是复用通用错误码体系，通过`error.message`和`error.details`提供详细的业务错误信息。

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码进行模式识别处理
   - `PARAM_ERROR` / `VALIDATION_ERROR`: 验证相关错误，需要检查输入参数
   - `INVALID_STATUS`: 状态相关错误，需要根据业务规则处理
   - `RESOURCE_CONFLICT`: 资源冲突错误，需要检查资源状态
   - `RESOURCE_NOT_FOUND`: 资源不存在，需要检查资源ID
   - `UNAUTHORIZED` / `FORBIDDEN`: 权限相关错误，需要重新认证或申请权限
   - `INTERNAL_ERROR`: 系统错误，通常需要重试或联系支持

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息

4. **错误详情处理**: 使用 `error.details` 字段获取详细的错误上下文信息

5. **日志记录**: 使用 `traceId` 或 `requestId` 进行错误追踪和问题排查

## 数据模型

### 退火任务（AnnealingTask）模型

退火任务主表，记录从任务创建到完成的全生命周期信息。

**核心字段**:
- `id`: UUID，主键
- `taskCode`: 任务编号，格式：AT-YYYYMMDD-HHmmssSSS-XXX
- `taskName`: 任务名称
- `status`: 任务状态（参见状态流转规则）
- `priority`: 任务优先级（emergency/high/normal/low）
- `source`: 任务来源（plan-split/manual）

**产品和工艺字段**:
- `productId`: 关联的产品ID
- `productCode`: 产品编码副本
- `productName`: 产品名称副本
- `alloyGrade`: 合金牌号
- `processTemplateId`: 工艺模板ID
- `processTemplateVersionId`: 工艺模板版本ID

**计划关联字段**:
- `planId`: 关联的生产计划ID
- `planItemId`: 关联的生产计划批次ID
- `planPriority`: 继承的计划优先级

**重量和数量字段**:
- `plannedWeight`: 计划重量（吨）
- `plannedQuantity`: 计划数量
- `actualWeight`: 实际重量（吨）
- `materialCount`: 物料数量

**排程相关字段**:
- `schedulePlanId`: 排程方案ID
- `plannedFurnaceId`: 计划执行退火炉ID
- `plannedFurnaceCode`: 计划执行退火炉编号
- `plannedLoadingAt`: 计划装炉时间
- `plannedUnloadingAt`: 计划出炉时间
- `expectedDurationMinutes`: 预计执行时长（分钟）
- `estimatedEnergyConsumption`: 预计能耗（kWh）
- `schedulePublishedAt`: 排程发布时间
- `scheduleLockedUntil`: 排程锁定截至时间
- `scheduleContext`: 排程上下文信息（JSONB）

**执行时间字段**:
- `actualLoadingStartedAt`: 实际装炉开始时间
- `actualLoadingCompletedAt`: 实际装炉完成时间
- `executionStartedAt`: PLC反馈退火开始时间
- `executionCompletedAt`: PLC反馈退火完成时间
- `actualUnloadingStartedAt`: 实际出炉开始时间
- `actualUnloadingCompletedAt`: 实际出炉完成时间

**混炉相关字段**:
- `mixingGroupCode`: 混炉分组编码
- `mixingRuleDescription`: 混炉兼容规则描述

**其他字段**:
- `remarks`: 任务备注（对外可见）
- `statusUpdatedAt`: 状态最近更新时间
- `createdAt`: 创建时间
- `updatedAt`: 更新时间
- `createdBy`: 创建人ID
- `updatedBy`: 更新人ID

### 退火任务物料（AnnealingTaskMaterial）模型

退火任务与物料关联表，记录任务绑定的所有料框/料垛。

**核心字段**:
- `id`: UUID，主键
- `taskId`: 关联的退火任务ID
- `materialId`: 物料ID（料框或料垛）
- `materialCode`: 物料编码
- `materialType`: 物料类型（basket/stack）

**重量和装炉字段**:
- `expectedWeight`: 预计重量（吨）
- `actualWeight`: 实际称重重量（吨）
- `loadSequence`: 装炉顺序
- `loadPosition`: 装炉位置描述（如层位）
- `isPrimary`: 是否主料框

**批次和位置字段**:
- `batchNumber`: 物料批次号
- `warehouseId`: 当前所在仓库或库区ID
- `warehouseLocationId`: 当前库位ID
- `warehouseLocationCode`: 库位编码

**状态和来源字段**:
- `statusSnapshot`: 关联物料在绑定时的状态
- `weightSource`: 重量来源（标准装载/实时称重/人工录入）

**其他字段**:
- `remarks`: 备注信息
- `createdAt`: 创建时间
- `updatedAt`: 更新时间
- `createdBy`: 关联操作人ID
- `updatedBy`: 最后更新人ID

### 字段说明

**日期时间格式**:
- 所有日期时间字段均使用 ISO 8601 格式：`YYYY-MM-DDTHH:mm:ss.sssZ`
- 示例：`"2024-01-20T10:30:00.000Z"`

**炉容范围**:
- 最小容量：35吨
- 最大容量：42吨
- 目标容量：40吨（默认）
- 容差：0.01吨
