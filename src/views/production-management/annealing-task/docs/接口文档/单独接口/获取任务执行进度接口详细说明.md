## 功能概述

### 所有功能

获取任务执行进度（Get Task Progress）是退火任务管理模块中的核心监控接口之一，用于实时获取指定退火任务的详细执行进度信息，以支持生产监控、进度追踪、预警提醒等业务场景。

本接口通过任务ID实时计算并返回任务的多维度进度信息，包括：
- **装炉阶段进度**：装炉开始/完成时间、进度百分比、当前状态
- **执行阶段进度**：执行开始/完成时间、已用时长、剩余时长、进度百分比
- **出炉阶段进度**：出炉开始/完成时间、进度百分比、当前状态
- **物料统计进度**：总物料数、已装炉数、执行中数、已出炉数
- **整体进度汇总**：综合进度百分比、当前阶段标识
- **时间信息汇总**：所有关键时间节点的计划与实际时间

### 关键特性

- ✅ **实时进度计算**：基于任务当前状态和实际执行时间动态计算各阶段进度
- ✅ **多维度进度展示**：提供装炉、执行、出炉三个独立阶段的详细进度信息
- ✅ **智能时长预估**：根据工艺模板预期时长和实际执行时间计算剩余时长
- ✅ **物料状态统计**：实时统计任务中物料的装炉、执行、出炉状态分布
- ✅ **整体进度汇总**：计算任务从创建到完成的综合进度百分比
- ✅ **时间节点追踪**：完整记录计划时间与实际时间的对比信息
- ✅ **高频查询优化**：轻量级查询设计，支持高频轮询场景

---

### 使用前提

- ✅ **权限要求**：用户必须具有 `prod.annealing-task.view` 权限
- ✅ **任务存在**：指定的任务ID必须对应有效的退火任务记录
- ✅ **认证要求**：请求必须携带有效的JWT访问令牌

### 不适用场景

- ❌ **批量进度查询**：本接口仅支持单个任务进度查询，批量查询应使用专门的批量接口或任务列表接口
- ❌ **历史进度记录**：本接口返回当前实时进度，不包含历史进度变更记录
- ❌ **详细工艺参数**：如需查看详细的工艺执行参数（温度、压力等），应使用PLC数据接口

### 详细步骤说明

#### 步骤1: 权限验证

**功能说明**：验证请求用户是否具有查看退火任务的权限。

**验证内容**：
- 检查JWT Token有效性
- 验证用户是否具有 `prod.annealing-task.view` 权限

**失败处理**：
- Token无效或过期：返回401 Unauthorized
- 权限不足：返回403 Forbidden

---

#### 步骤2: 参数验证

**功能说明**：验证请求参数的格式和有效性。

**验证规则**：
- `taskId`：必须为有效的UUID v4格式

**失败处理**：
- 参数格式错误：返回400 Bad Request，提示参数格式不正确

---

#### 步骤3: 查询任务记录

**功能说明**：从数据库查询任务基本信息和关联物料。

**查询内容**：
- 任务基本信息（状态、时间、编号等）
- 关联的物料明细（用于统计物料数量）

**失败处理**：
- 任务不存在：返回404 Not Found，错误码 `RESOURCE_NOT_FOUND`

---

#### 步骤4: 计算装炉阶段进度

**计算逻辑**：

```
如果任务状态 = 'loading' (装炉中):
  状态 = 'in-progress'
  进度 = 50%

否则如果 actualLoadingCompletedAt 不为空 或
        状态 ∈ ['waiting-execute', 'in-progress', 'waiting-unload', 'completed']:
  状态 = 'completed'
  进度 = 100%

否则:
  状态 = 'not-started'
  进度 = 0%
```

**输出字段**：
- `percentage`：装炉进度百分比（0/50/100）
- `status`：装炉状态（not-started/in-progress/completed）
- `startedAt`：实际装炉开始时间
- `completedAt`：实际装炉完成时间

---

#### 步骤5: 计算执行阶段进度

**计算逻辑**：

```
如果 executionStartedAt 存在:
  计算已用时长 = (executionCompletedAt 或 当前时间) - executionStartedAt

  如果 executionCompletedAt 存在:
    状态 = 'completed'
    进度 = 100%
    剩余时长 = 0

  否则如果任务状态 = 'in-progress':
    状态 = 'in-progress'

    如果 expectedDurationMinutes > 0:
      进度 = min((已用时长 / 预期时长) * 100, 99)
      剩余时长 = max(0, 预期时长 - 已用时长)
    否则:
      进度 = 50%  // 未知预期时长时的默认值
      剩余时长 = 预期时长

否则:
  状态 = 'not-started'
  进度 = 0%
  剩余时长 = 预期时长
```

**输出字段**：
- `percentage`：执行进度百分比（0-100）
- `status`：执行状态（not-started/in-progress/completed）
- `startedAt`：执行开始时间
- `completedAt`：执行完成时间
- `elapsedMinutes`：已用时长（分钟）
- `remainingMinutes`：剩余时长（分钟）

**特殊说明**：
- 进度最高显示99%，避免在未完成时显示100%
- 剩余时长不会为负数，最小为0

---

#### 步骤6: 计算出炉阶段进度

**计算逻辑**：

```
如果任务状态 = 'waiting-unload' (待出炉):
  状态 = 'waiting'
  进度 = 0%

否则如果 actualUnloadingStartedAt 存在 且 actualUnloadingCompletedAt 不存在:
  状态 = 'in-progress'
  进度 = 50%

否则如果 actualUnloadingCompletedAt 存在 或 任务状态 = 'completed':
  状态 = 'completed'
  进度 = 100%

否则:
  状态 = 'not-started'
  进度 = 0%
```

**输出字段**：
- `percentage`：出炉进度百分比（0/50/100）
- `status`：出炉状态（not-started/waiting/in-progress/completed）
- `startedAt`：实际出炉开始时间
- `completedAt`：实际出炉完成时间

---

#### 步骤7: 统计物料状态分布

**统计逻辑**：

```
总数 = task.materialCount

如果任务状态 = 'completed':
  已装炉数 = 总数
  执行中数 = 总数
  已出炉数 = 总数

否则如果任务状态 ∈ ['in-progress', 'waiting-unload']:
  已装炉数 = 总数
  执行中数 = 总数
  已出炉数 = 0

否则如果任务状态 ∈ ['waiting-execute', 'loading']:
  已装炉数 = 总数
  执行中数 = 0
  已出炉数 = 0

否则:
  已装炉数 = 0
  执行中数 = 0
  已出炉数 = 0
```

**输出字段**：
- `totalCount`：总物料数
- `loadedCount`：已装炉物料数
- `inProgressCount`：执行中物料数
- `unloadedCount`：已出炉物料数

---

#### 步骤8: 计算整体进度

**计算逻辑**：根据任务当前状态映射到整体进度百分比。

```
任务状态映射表：
  draft / pending-schedule    → 0%,  阶段: 'preparation'
  scheduled / waiting-loading → 10%, 阶段: 'scheduled'
  loading                     → 20%, 阶段: 'loading'
  waiting-execute             → 30%, 阶段: 'waiting-execution'
  in-progress                 → 30% + (执行进度 * 0.5), 阶段: 'execution'
  waiting-unload              → 85%, 阶段: 'waiting-unloading'
  completed                   → 100%, 阶段: 'completed'
  paused                      → 保持当前进度, 阶段: 'paused'
  cancelled                   → 保持当前进度, 阶段: 'cancelled'
  terminated                  → 保持当前进度, 阶段: 'terminated'
```

**输出字段**：
- `percentage`：整体进度百分比（0-100）
- `currentPhase`：当前阶段标识

**阶段说明**：
- `preparation`：准备阶段（草稿、待排程）
- `scheduled`：已排程（已排程、待装炉）
- `loading`：装炉阶段
- `waiting-execution`：待执行阶段
- `execution`：执行阶段（执行进度30%-80%）
- `waiting-unloading`：待出炉阶段
- `completed`：已完成
- `paused`：已暂停
- `cancelled`：已取消
- `terminated`：异常终止

---

#### 步骤9: 汇总时间信息

**功能说明**：汇总任务的所有关键时间节点，包括计划时间和实际时间。

**输出字段**：
- `plannedLoadingAt`：计划装炉时间
- `plannedUnloadingAt`：计划出炉时间
- `actualLoadingStartedAt`：实际装炉开始时间
- `actualLoadingCompletedAt`：实际装炉完成时间
- `executionStartedAt`：执行开始时间
- `executionCompletedAt`：执行完成时间
- `actualUnloadingStartedAt`：实际出炉开始时间
- `actualUnloadingCompletedAt`：实际出炉完成时间

---

#### 步骤10: 返回进度数据

**功能说明**：将计算完成的进度数据按照统一响应格式返回给客户端。

**响应结构**：
- 成功响应：HTTP 200，包含完整的进度信息
- 失败响应：根据错误类型返回相应的HTTP状态码和错误信息

**日志记录**：
```
记录信息：同步退火任务进度: 任务编号={taskCode}, 整体进度={percentage}%, 当前阶段={currentPhase}
日志级别：INFO
```

## 接口文档

### 基本信息

**接口路径**: `GET /v1/prod/annealing-tasks/:taskId/progress`

**功能描述**: 实时获取指定退火任务的详细执行进度，包括装炉、执行、出炉各阶段进度、物料统计、整体进度和时间信息，用于生产监控和进度追踪。

**认证要求**: JWT Bearer Token 认证，需要 `prod.annealing-task.view` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 路径参数

| 参数名 | 类型   | 必填 | 限制         | 描述       | 示例                                   |

### 错误响应

| HTTP状态码 | 错误码             | 错误消息           | 说明               | 处理建议                 |
| ---------- | ------------------ | ------------------ | ------------------ | ------------------------ |
| 400        | PARAM_ERROR        | 任务ID格式不正确   | taskId不是有效UUID | 检查taskId格式是否正确   |
| 400        | PARAM_ERROR        | 退火任务ID不能为空 | 未提供taskId参数   | 确保提供有效的taskId参数 |
| 401        | UNAUTHORIZED       | 未授权             | Token无效或过期    | 重新登录获取新Token      |
| 403        | FORBIDDEN          | 无权限             | 缺少view权限       | 联系管理员分配相应权限   |
| 404        | RESOURCE_NOT_FOUND | 退火任务不存在     | 指定ID的任务不存在 | 检查任务ID是否正确       |
| 500        | INTERNAL_ERROR     | 服务器内部错误     | 系统异常           | 联系技术支持             |

## 使用示例

### 场景1: 监控执行中任务的实时进度

**业务需求**: 生产管理人员需要实时监控正在执行的退火任务进度，包括已执行时间和预计剩余时间。

**实现方式**: 每30秒轮询一次进度接口，获取最新的执行进度。

**预期结果**:
- 界面实时显示任务整体进度（如：52%）
- 显示当前阶段（如：执行中）
- 显示已用时长（如：4小时30分钟）
- 显示预计剩余时长（如：5小时30分钟）
- 任务完成时自动停止轮询并提示

---

### 场景2: 计算任务延期预警

**业务需求**: 系统需要根据实际执行进度判断任务是否可能延期，提前发出预警。

**实现方式**: 对比计划完成时间与预计实际完成时间，如果超出阈值则发出预警。

**预期结果**:
- 如果预计延期超过30分钟，系统发送预警通知
- 显示预计延期时长
- 显示预计完成时间与计划完成时间的对比

---

### 场景3: 生成任务进度报表

**业务需求**: 管理人员需要查看多个任务的进度汇总，生成进度报表。

**实现方式**: 批量获取多个任务的进度信息，汇总统计。

**预期结果**:
- 生成包含所有任务的进度汇总报表
- 按阶段统计任务分布
- 计算平均进度
- 统计总物料数和已完成数

---

### 场景4: 进度可视化展示

**业务需求**: 在看板页面以图形化方式展示任务进度，包括三个阶段的进度条和物料统计。

**实现方式**: 获取进度数据后渲染进度条和统计图表。
**预期结果**:
- 显示整体进度环形图（52%）
- 显示三个阶段的进度条（装炉100%、执行45%、出炉0%）
- 显示物料统计柱状图
- 显示时间轴对比计划与实际时间
- 自动更新进度状态的颜色和图标

### 整体进度计算规则

| 任务状态         | 整体进度百分比         | 当前阶段          |
| ---------------- | ---------------------- | ----------------- |
| draft            | 0%                     | preparation       |
| pending-schedule | 0%                     | preparation       |
| scheduled        | 10%                    | scheduled         |
| waiting-loading  | 10%                    | scheduled         |
| loading          | 20%                    | loading           |
| waiting-execute  | 30%                    | waiting-execution |

| cancelled        | 保持取消前进度         | cancelled         |
| terminated       | 保持终止前进度         | terminated        |
