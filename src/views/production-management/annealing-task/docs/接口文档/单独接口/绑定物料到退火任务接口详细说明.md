## 📝 版本更新记录

### v1.2 (2025-10-31) - 移除重量范围校验

**重要变更**：
- 🔄 **移除物料绑定时的重量范围校验** - 不再校验总重量是否在 35-42 吨范围内
- ❌ **移除 `skipWeightValidation` 参数** - 该参数已被移除，不再支持
- ✅ **简化职责边界** - 物料绑定仅校验物料状态和重复绑定，重量匹配由排程系统根据分配的炉子进行精确校验

**变更原因**：
- 绑定物料时尚未分配炉子，无法知道具体炉子的容量
- 硬编码的 35-42 吨范围无法适配不同容量的设备（30吨、40吨、50吨炉）
- 排程系统会根据任务重量智能选择合适的炉子，提前限制重量范围会降低灵活性

**升级影响**：
- ⚠️ **行为变化**：之前绑定 45 吨物料会被拒绝，现在会成功
- ✅ **向后兼容**：即使传入 `skipWeightValidation` 参数也会被忽略，不会报错
- ⚠️ **后续校验**：提交排程后，排程系统会根据实际炉子容量进行精确校验

## 功能概述

### 所有功能

绑定物料到退火任务（Bind Materials to Annealing Task）是退火任务管理模块中的核心操作之一，用于将待退火的料框或料垛关联到具体的退火任务，以支持生产执行和物料追溯的业务场景。该接口确保物料与任务的准确绑定，并进行严格的状态校验和并发控制。

### 关键特性

- ✅ **多物料批量绑定**：支持一次绑定1-100个物料（料框或料垛）到同一退火任务
- ✅ **并发冲突检测**：自动检测物料是否已被其他未完成任务绑定，防止重复占用
- ✅ **重复绑定保护**：防止同一物料在同一任务中重复绑定，在 Joi 验证层即拦截重复物料ID
- ✅ **物料类型验证**：严格校验物料类型（basket/stack）和实际重量的合法性
- ✅ **事务保证**：使用数据库事务和行锁确保绑定操作的原子性和一致性
- ✅ **自动聚合更新**：绑定成功后自动更新任务的实际重量和物料数量统计
- ✅ **完整操作日志**：记录每个物料的绑定操作，包含操作人、时间、物料信息等审计信息
- ℹ️ **重量范围由排程系统校验**：本接口不校验重量范围，由排程系统根据分配的炉子容量进行精确匹配

---

### 使用前提

- ✅ **权限要求**：需要 `prod.annealing-task.manage` 权限
- ✅ **认证要求**：需要有效的 JWT Token
- ✅ **任务状态要求**：退火任务状态必须为 `draft`（草稿）或 `pending-schedule`（待排程）
- ✅ **物料状态要求**：物料未被其他未完成的退火任务占用

### 不适用场景

- ❌ **任务已排程或执行中**：状态为 `scheduled`、`in-progress`、`completed` 等的任务不能绑定物料
- ❌ **物料已被占用**：物料已绑定到其他未完成任务时不能重复绑定
- ❌ **物料类型不合法**：物料类型必须是 `basket`（料框）或 `stack`（料垛）

### ℹ️ 关于重量范围

**本接口不校验重量范围**，允许绑定任意重量的物料。重量匹配由排程系统负责：
- 排程系统会根据任务实际重量选择合适容量的炉子
- 如果没有合适的炉子，排程会失败并返回明确的原因和建议
- 这种设计提供了更大的灵活性，支持不同容量的设备（30吨、40吨、50吨炉等）

### 详细步骤说明

#### 步骤1: 基础参数校验
- 验证任务ID为有效的UUID v4格式
- 验证物料列表为非空数组且长度在1-100之间
- 验证操作人ID非空
- 如果校验失败，抛出 `PARAM_ERROR` 错误

#### 步骤2: 开启数据库事务
- 创建数据库事务对象
- 后续所有数据库操作都在此事务中执行
- 保证数据一致性，失败时自动回滚

#### 步骤3: 查询并锁定退火任务
- 使用 `LOCK.UPDATE` 加排他锁防止并发修改
- 查询任务基本信息
- 如果任务不存在，抛出 `RESOURCE_NOT_FOUND` 错误

#### 步骤4: 校验任务状态
- 只允许 `draft` 或 `pending-schedule` 状态的任务绑定物料
- 其他状态（如已排程、执行中、已完成）不允许绑定
- 如果状态不合法，抛出 `INVALID_STATUS` 错误

#### 步骤5: 检查物料并发冲突
- 查询所有待绑定物料是否已被其他任务占用
- 排除已完成（`completed`）和已取消（`cancelled`）的任务
- 如果发现冲突，抛出 `RESOURCE_CONFLICT` 错误并返回冲突详情
- **防止场景**：两个任务同时绑定同一批物料

#### 步骤6: 检查重复绑定
- 查询当前任务中是否已包含待绑定的物料
- 如果发现重复，抛出 `RESOURCE_CONFLICT` 错误
- **防止场景**：同一物料在同一任务中被多次添加

#### 步骤7: 校验物料数据
- **物料类型校验**：必须是 `basket`（料框）或 `stack`（料垛）
- **重量校验**：`actualWeight` 必须 > 0
- **唯一性校验**：物料列表中不能有重复的 `materialId`（在 Joi 验证层检查）
- 任何校验失败都抛出 `VAL_001` 或 `PARAM_ERROR` 错误

#### 步骤8: 计算总重量
- 使用 `normalizeWeight()` 函数标准化所有重量值
- 累加所有待绑定物料的 `actualWeight`
- 加上任务当前的 `actualWeight`
- 得到绑定后的预期总重量
- 记录信息日志（任务编号、新增重量、总重量）
- **不进行重量范围校验**，由排程系统根据分配的炉子容量进行精确匹配

#### 步骤9: 批量创建绑定记录
- 使用 `reduce` 确保顺序执行，避免 ESLint 的 `no-await-in-loop` 错误
- 为每个物料创建 `AnnealingTaskMaterial` 记录
- 记录字段包括：
  - `materialId`, `materialCode`, `materialType`
  - `actualWeight`, `expectedWeight`
  - `loadSequence`, `isPrimary`
  - `warehouseId`, `warehouseLocationCode`
  - `statusSnapshot`, `weightSource`
  - `createdBy`, `updatedBy`

#### 步骤10: 记录操作日志
- 每个物料绑定都记录一条日志
- 日志动作：`material-bound`
- 日志内容包含：
  - 物料ID、编码、类型
  - 实际重量
  - 是否主料框
  - 操作人信息（ID、姓名、IP）

#### 步骤11: 更新任务聚合统计
- 调用 `AnnealingTask.recalculateAggregations()` 方法
- 重新计算任务的 `actualWeight`（所有绑定物料的实际重量之和）
- 重新计算任务的 `materialCount`（绑定的物料总数）
- 确保统计数据与明细数据一致

#### 步骤12: 重新加载任务数据
- 使用 `task.reload()` 刷新任务对象
- 获取更新后的重量和数量统计
- 为返回结果提供最新数据

#### 步骤13: 提交事务
- 如果所有步骤成功，提交数据库事务
- 所有数据变更永久生效

#### 步骤14: 记录成功日志
- 记录绑定操作成功的日志
- 包含任务编号、物料数量、操作人ID
- 用于审计和问题排查

#### 步骤15: 返回绑定结果
- 返回任务信息（包含更新后的重量和数量）
- 返回绑定的物料列表
- 返回统计摘要（总物料数、总重量等）

### 异常处理
- 任何步骤失败都会触发事务回滚
- 记录详细的错误日志
- 返回友好的错误信息给前端

## 接口文档

### 基本信息

**接口路径**: `POST /v1/prod/annealing-tasks/:taskId/materials`

**功能描述**: 将待退火的料框或料垛批量绑定到指定的退火任务，并进行重量校验、并发控制和状态校验。

**认证要求**: 需要 Bearer Token 认证，需要 `prod.annealing-task.manage` 权限

### 统一响应格式

#### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

#### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

## 使用示例

### 场景1: 绑定2个料框到新创建的任务

**业务需求**: 任务刚创建完成，需要绑定2个料框（总重量4.8吨）

**预期结果**:
- 返回200状态码
- 任务的 `actualWeight` 更新为 4.8
- 任务的 `materialCount` 更新为 2
- 返回2条物料绑定记录

---

### 场景2: 批量绑定多个料垛到任务

**业务需求**: 需要将10个料垛（每个约4吨）绑定到同一任务
**预期结果**:
- 返回200状态码
- 任务的 `actualWeight` 更新为 40.0
- 任务的 `materialCount` 更新为 10
- 返回10条物料绑定记录

---

### 场景3: 绑定物料时包含仓储信息

**业务需求**: 绑定物料同时记录其仓储位置信息，便于追溯

**预期结果**:
- 返回200状态码
- 物料绑定记录包含完整的仓储信息
- 便于后续追溯物料来源

---

### 场景4: 跳过重量校验绑定物料（分批装炉）

**业务需求**: 特殊情况下需要绑定超重或欠重的物料（如试生产、特殊工艺、分批装炉）

**请求示例**:

```json
{
  "materials": [
    {
      "materialId": "8ae62322-e7e2-455f-9dbc-07001b75d74d",
      "materialCode": "LD-20251021-0002",
      "materialType": "stack",
      "actualWeight": 1,
      "loadSequence": 1,
      "isPrimary": false,
      "batchNumber": "pc003"
    },
    {
      "materialId": "4a87ce9c-353d-4ce3-ada4-b042eaa2ffcc",
      "materialCode": "LD-20251021-0001",
      "materialType": "stack",
      "actualWeight": 1,
      "loadSequence": 2,
      "isPrimary": false,
      "batchNumber": "pc001"
    }
  ],
  "skipWeightValidation": true
}
```

**预期结果**:
- 返回200状态码
- 即使总重量仅为2吨（远小于最小炉容35吨），绑定依然成功
- 日志中会记录跳过重量校验的信息
- 适用于分批装炉、测试场景或需要手动控制装炉量的特殊情况

> **重要**: 上述示例中物料总重量仅为 2吨，在 `skipWeightValidation: false`（默认值）时会验证失败并抛出 `VAL_001` 错误。设置为 `true` 后可以成功绑定。

---

### 场景5: 混合绑定料框和料垛

**业务需求**: 同一任务中既有料框又有料垛

**预期结果**:
- 返回200状态码
- 支持混合物料类型
- 总重量为 2.5 + 4.0 + 2.3 = 8.8吨

### 任务状态（Task Statuses）

| 状态码           | 中文名称 | 说明                           | 是否允许绑定物料 |
| ---------------- | -------- | ------------------------------ | ---------------- |
| draft            | 草稿     | 任务刚创建，尚未确认           | ✅ 允许           |
| pending-schedule | 待排程   | 任务等待排程系统分配炉号和时间 | ✅ 允许           |
| scheduled        | 已排程   | 任务已分配炉号和计划时间       | ❌ 不允许         |
| waiting-loading  | 待装炉   | 任务等待装炉操作               | ❌ 不允许         |
| loading          | 装炉中   | 正在进行装炉操作               | ❌ 不允许         |
| waiting-execute  | 待执行   | 装炉完成，等待退火开始         | ❌ 不允许         |
| in-progress      | 执行中   | 退火过程进行中                 | ❌ 不允许         |
| waiting-unload   | 待出炉   | 退火完成，等待出炉             | ❌ 不允许         |
| completed        | 已完成   | 任务全部完成                   | ❌ 不允许         |
| paused           | 已暂停   | 任务暂停执行                   | ❌ 不允许         |
| cancelled        | 已取消   | 任务已取消                     | ❌ 不允许         |
