## 功能概述

### 所有功能

获取退火任务列表（Get Annealing Tasks）是退火任务管理模块中的核心查询接口之一，用于分页查询退火任务列表，并支持多维度筛选条件（状态、炉号、产品编码、优先级等），以满足生产计划执行、任务监控、排程调度等业务场景的需求。

### 关键特性

- ✅ **分页查询**：支持灵活的分页参数，可自定义每页数量和页码
- ✅ **多维度筛选**：支持按状态、炉号、产品编码、合金牌号、任务编号、计划编号、优先级、来源等多个维度组合筛选
- ✅ **时间范围查询**：支持按计划装炉时间范围和创建时间范围筛选
- ✅ **关键词搜索**：支持按任务编号或任务名称进行模糊搜索
- ✅ **灵活排序**：支持多字段组合排序，默认按创建时间倒序
- ✅ **关联信息**：自动关联生产计划、计划批次、工艺模板等相关信息
- ✅ **排程状态计算**：自动生成 `schedulingStatus` 字段，提供任务的排程状态和锁定信息

---

### 使用前提

- ✅ 用户已通过认证（JWT Token 有效）
- ✅ 用户具有 `prod.annealing-task.view` 权限
- ✅ 系统中已存在退火任务数据
- ✅ 请求参数符合验证规则

### 不适用场景

- ❌ 不适用于获取单个任务的详细信息（应使用"获取退火任务详情"接口）
- ❌ 不适用于获取待排程任务列表（应使用"获取待排程任务列表"接口）
- ❌ 不适用于导出全量数据（需使用专门的导出接口）

### 详细步骤说明

#### 步骤1: 接收请求参数
- 从查询字符串（query string）中提取筛选条件和分页参数
- 筛选条件包括：状态、炉号、产品编码、合金牌号、任务编号、计划编号、优先级、来源、时间范围、关键词搜索
- 分页参数包括：sortBy（排序字段）、limit（每页数量）、page（页码）

#### 步骤2: 权限验证
- 通过 `auth('prod.annealing-task.view')` 中间件验证用户权限
- 验证 JWT Token 的有效性
- 确认用户具有查看退火任务的权限

#### 步骤3: 参数验证
- 使用 Joi 验证器进行参数格式验证
- 验证筛选条件的数据类型和取值范围
- 验证分页参数的合法性（limit 范围、page 最小值等）
- 验证时间范围参数的格式（ISO 8601）

#### 步骤4: 构建查询条件
- **状态筛选**：精确匹配任务状态
- **炉号筛选**：精确匹配计划执行炉号（自动转大写）
- **产品编码筛选**：精确匹配产品编码（自动转大写）
- **合金牌号筛选**：精确匹配合金牌号（自动转大写）
- **任务编号筛选**：模糊匹配任务编号（LIKE）
- **优先级筛选**：精确匹配任务优先级
- **来源筛选**：精确匹配任务来源
- **时间范围筛选**：使用 `Op.gte` 和 `Op.lte` 构建时间范围条件
- **关键词搜索**：使用 `Op.or` 对任务编号和任务名称进行模糊匹配
- **计划编号筛选**：通过关联查询 `ProductionPlan` 表进行匹配

#### 步骤5: 配置分页参数
- **每页数量（limit）**：默认为 10，必须大于 0
- **页码（page）**：默认为 1，必须大于 0
- **偏移量（offset）**：计算公式为 `(page - 1) * limit`

#### 步骤6: 配置排序规则
- **默认排序**：按创建时间倒序（`createdAt:desc`）
- **多字段排序**：支持逗号分隔的多个排序字段（如 `priority:asc,createdAt:desc`）
- **排序方向**：`asc`（升序）或 `desc`（降序）

#### 步骤7: 查询数据库
- 使用 `AnnealingTask.findAndCountAll()` 方法同时获取数据和总数
- **关联查询**：
  - 关联 `ProductionPlan`（生产计划）：获取计划编号、优先级、订单号、交付日期
  - 关联 `ProductionPlanItem`（计划批次）：获取批次编号、计划重量、计划数量、状态
  - 关联 `ProcessTemplate`（工艺模板）：获取模板编码和名称
- **条件关联**：当筛选了计划编号时，将生产计划设为必需关联（`required: true`）

#### 步骤8: 格式化响应数据
- 调用 `task.toJSON()` 方法格式化任务数据
- 自动转换 DECIMAL 类型为浮点数（plannedWeight、actualWeight 等）
- 自动过滤敏感字段（systemRemarks、dispatchFingerprint、deletedAt）
- 计算分页元数据：
  - `totalPages`：总页数，计算公式为 `Math.ceil(count / limit)`
  - `totalResults`：总记录数
  - `page`：当前页码
  - `limit`：每页数量

#### 步骤9: 记录操作日志
- 使用 `logger.info()` 记录成功的查询操作
- 日志内容包括：查询到的任务数量、总数、筛选条件、分页参数

#### 步骤10: 返回统一响应
- 使用 `sendSuccess()` 工具函数封装响应
- 响应包含：
  - `success`: true
  - `data`: 任务列表和分页信息
  - `message`: "获取退火任务列表成功"
  - `meta`: 时间戳、请求ID、版本号

## 接口文档

### 基本信息

**接口路径**: `GET /v1/prod/annealing-tasks`

**功能描述**: 分页查询退火任务列表，支持状态、炉号、产品编码等多维度筛选，并自动关联生产计划、计划批次、工艺模板等相关信息。

**认证要求**: Bearer Token（JWT），需要 `prod.annealing-task.view` 权限

**查询参数说明**：

- **状态筛选（status）**：可选值详见附录"任务状态枚举"
- **炉号筛选（plannedFurnaceCode）**：自动转换为大写后进行精确匹配
- **产品编码筛选（productCode）**：自动转换为大写后进行精确匹配
- **任务编号筛选（taskCode）**：支持模糊匹配（LIKE），例如输入 "AT-20250118" 可以匹配 "AT-20250118-001" 等
- **计划编号筛选（planNumber）**：通过关联查询 ProductionPlan 表进行模糊匹配
- **关键词搜索（search）**：同时对任务编号和任务名称进行模糊搜索（OR 条件）
- **排除已关联排程方案的任务（excludeSchedulePlanned）**：设置为 `true` 时，只返回未被任何排程方案使用的任务（`schedulePlanId` 为 null）
- **按排程状态筛选（schedulingStatus）**：
  - `not_scheduled`：未排程，没有关联排程方案
  - `plan_created`：已生成排程方案但未发布，有排程方案ID但没有计划装炉时间
  - `scheduled`：已发布排程，有排程方案ID且有计划装炉时间
- **时间范围筛选**：支持单独指定开始时间或结束时间，也可以同时指定形成闭区间
- **排序规则（sortBy）**：
  - 格式：`字段名:方向`，例如 `createdAt:desc`
  - 多字段排序：用逗号分隔，例如 `priority:asc,createdAt:desc`
  - 方向：`asc`（升序）或 `desc`（降序），默认 `desc`
  - 常用排序字段：`createdAt`、`updatedAt`、`status`、`priority`、`plannedLoadingAt`、`taskCode`

### 任务状态枚举

| 状态码           | 中文名称 | 说明                                 |
| ---------------- | -------- | ------------------------------------ |
| draft            | 草稿     | 任务已创建，尚未提交排程             |
| pending-schedule | 待排程   | 任务已提交，等待排程系统分配炉号时间 |
| scheduled        | 已排程   | 已分配炉号和时间，等待装炉           |
| waiting-loading  | 待装炉   | 排程已确认，等待物料到位开始装炉     |
| loading          | 装炉中   | 正在进行装炉操作                     |
| waiting-execute  | 待执行   | 装炉完成，等待退火炉开始执行         |
| in-progress      | 执行中   | 退火炉正在执行退火工艺               |
| waiting-unload   | 待出炉   | 退火完成，等待出炉操作               |
| completed        | 已完成   | 出炉完成，任务结束                   |
| paused           | 已暂停   | 任务执行过程中暂停（可恢复）         |
| cancelled        | 已取消   | 任务取消（不可恢复）                 |
| terminated       | 异常终止 | 任务因异常情况终止（不可恢复）       |

| ---------- | -------- | ------------------------ |
| emergency  | 紧急     | 最高优先级，需要立即处理 |
| high       | 高       | 高优先级，优先安排       |
| normal     | 正常     | 正常优先级，按顺序处理   |
| low        | 低       | 低优先级，可延后处理     |

| 来源代码   | 中文名称 | 说明                       |
| ---------- | -------- | -------------------------- |

### 状态转换图

```
draft (草稿)
  ↓
pending-schedule (待排程)
  ↓
scheduled (已排程)
  ↓
waiting-loading (待装炉)
  ↓
loading (装炉中)
  ↓
waiting-execute (待执行)
  ↓
in-progress (执行中) ←→ paused (已暂停)
  ↓
waiting-unload (待出炉)
  ↓
completed (已完成)

任何状态都可转换到：
- cancelled (已取消)
- terminated (异常终止)
```
