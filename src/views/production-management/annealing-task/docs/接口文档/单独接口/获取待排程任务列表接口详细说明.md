## 功能概述

### 所有功能

获取待排程任务列表（Get Pending Tasks for Scheduling）是退火任务管理模块中排程流程的核心接口之一，用于查询所有可以参与排程的退火任务，为排程算法提供数据源。接口支持多维度筛选（产品、合金牌号、混炉分组、时间范围、重量范围、优先级等），并提供灵活的分页控制，以支持排程系统的任务选择和优化决策。

### 关键特性

- ✅ **多维度筛选**：支持按产品编码、合金牌号、混炉分组、计划装炉时间范围、重量范围、优先级等多个维度进行组合筛选
- ✅ **智能状态过滤**：默认仅返回 `pending-schedule`（待排程）状态的任务，确保只获取可排程的任务
- ✅ **排程锁定控制**：支持通过 `includeScheduleLocked` 参数控制是否包含已被排程锁定的任务，避免重复排程
- ✅ **完整关联信息**：返回任务关联的物料清单、生产计划信息、工艺模板信息，便于排程算法进行决策
- ✅ **智能排序**：自动按优先级、计划装炉时间、任务编号排序，确保紧急任务优先、计划性强的任务有序
- ✅ **分页支持**：支持 limit 和 offset 参数，适配大批量任务查询和分页加载场景

---

### 使用前提

- ✅ **权限要求**：需要 `prod.annealing-task.schedule` 权限（排程权限）
- ✅ **任务状态**：任务必须处于 `pending-schedule`（待排程）状态
- ✅ **认证要求**：需要有效的 JWT Bearer Token
- ✅ **排程流程**：通常在排程算法启动前调用，获取待排程任务池

### 不适用场景

- ❌ **查询所有任务**：此接口专门用于排程场景，不适合查询所有状态的任务（应使用 `GET /v1/prod/annealing-tasks`）
- ❌ **任务详情查询**：不适合获取单个任务的完整详情（应使用 `GET /v1/prod/annealing-tasks/:taskId`）
- ❌ **执行中任务监控**：不适合查询正在执行的任务（应使用任务进度接口）

### 详细步骤说明

#### 步骤1: 接收查询请求
- 接收客户端发送的 GET 请求
- 解析查询参数（query parameters）
- 提取筛选条件和分页参数

#### 步骤2: 参数验证
- **格式校验**：验证日期格式、UUID格式、数值范围
- **类型校验**：确保参数类型正确（字符串、数字、布尔值等）
- **范围校验**：
  - `plannedLoadingTo` 必须大于 `plannedLoadingFrom`
  - `maxWeight` 必须大于 `minWeight`
  - `limit` 范围：1-500
  - `offset` 必须 ≥ 0
- **优先级格式**：验证 `priorities` 为逗号分隔的优先级值

#### 步骤3: 构建查询条件
- **状态筛选**：默认仅查询 `pending-schedule` 状态
- **产品筛选**：如提供 `productCode`，进行精确匹配（大写转换）
- **合金牌号筛选**：如提供 `alloyGrade`，进行精确匹配（大写转换）
- **混炉分组筛选**：如提供 `mixingGroupCode`，进行精确匹配（大写转换）
- **时间范围筛选**：根据 `plannedLoadingFrom` 和 `plannedLoadingTo` 筛选计划装炉时间
- **重量范围筛选**：根据 `minWeight` 和 `maxWeight` 筛选计划重量
- **优先级筛选**：如提供 `priorities` 数组，筛选指定优先级的任务
- **锁定状态筛选**：
  - 如 `includeScheduleLocked=false`（默认），排除已锁定任务
  - 如 `includeScheduleLocked=true`，包含所有任务

#### 步骤4: 查询任务列表
- 使用 Sequelize ORM 执行数据库查询
- **关联查询**：
  - 关联 `AnnealingTaskMaterial` 获取物料清单
  - 关联 `ProductionPlan` 获取生产计划信息
  - 关联 `ProductionPlanItem` 获取计划批次信息
  - 关联 `ProcessTemplate` 获取工艺模板信息
- **排序规则**：
  1. 按优先级升序（emergency → high → normal → low）
  2. 按计划装炉时间升序（早装炉的优先）
  3. 按任务编号升序（相同优先级和时间时，按编号排序）

#### 步骤5: 统计总数
- 使用相同的 `where` 条件统计符合条件的任务总数
- 用于前端分页控制和数据统计

#### 步骤6: 数据格式化
- 转换每个任务为标准响应格式
- **主任务字段**：id、taskCode、taskName、status、priority、重量、产品信息等
- **物料信息**：materials 数组，包含物料编码、类型、重量、装炉顺序等
- **计划信息**：planInfo 对象，包含计划编号、优先级、客户、交期
- **批次信息**：planItemInfo 对象，包含批次编号、计划重量、数量、状态
- **工艺模板**：processTemplateInfo 对象，包含模板编码、名称

#### 步骤7: 返回结果
- 构建标准响应格式：
  - `tasks`：格式化后的任务列表
  - `totalCount`：符合条件的任务总数
  - `filters`：筛选条件回显（便于前端调试和确认）
- 记录日志：查询到的任务数量和总数
- 返回 HTTP 200 成功响应

## 接口文档

### 基本信息

**接口路径**: `GET /v1/prod/annealing-tasks/scheduling/pending`

**功能描述**: 查询所有处于待排程状态的退火任务，支持多维度筛选和分页，为排程算法提供任务数据源。

**认证要求**: JWT Bearer Token，需要 `prod.annealing-task.schedule` 权限

所有错误的 API 调用都会返回以下统一格式：

```json
    "version": "v1"

```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号


**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 查询参数

| 参数名                | 类型    | 必填 | 限制               | 描述                                                  | 默认值 | 示例                       |
| --------------------- | ------- | ---- | ------------------ | ----------------------------------------------------- | ------ | -------------------------- |
| productCode           | string  | 否   | 最大100字符        | 产品编码（精确匹配，自动转大写）                      | null   | "AF-1060-O-0.05"           |
| alloyGrade            | string  | 否   | 最大60字符         | 合金牌号（精确匹配，自动转大写）                      | null   | "1060"                     |
| mixingGroupCode       | string  | 否   | 最大60字符         | 混炉分组编码（精确匹配，自动转大写）                  | null   | "MIX-1060-A"               |
| plannedLoadingFrom    | string  | 否   | ISO 8601日期格式   | 计划装炉时间起始（包含）                              | null   | "2024-01-20T00:00:00.000Z" |
| plannedLoadingTo      | string  | 否   | ISO 8601日期格式   | 计划装炉时间截止（包含），必须晚于 plannedLoadingFrom | null   | "2024-01-25T23:59:59.999Z" |
| minWeight             | number  | 否   | 正数，单位：吨     | 最小计划重量（包含）                                  | null   | 35                         |
| maxWeight             | number  | 否   | 正数，单位：吨     | 最大计划重量（包含），必须大于 minWeight              | null   | 42                         |
| priorities            | string  | 否   | 逗号分隔的优先级值 | 优先级筛选，多个值用逗号分隔                          | null   | "emergency,high"           |
| includeScheduleLocked | boolean | 否   | true 或 false      | 是否包含已被排程锁定的任务                            | false  | true                       |
| limit                 | number  | 否   | 整数，1-500        | 每页返回的任务数量                                    | null   | 50                         |
| offset                | number  | 否   | 整数，≥0           | 分页偏移量（跳过的任务数量）                          | null   | 0                          |

**参数说明**：
- `productCode`、`alloyGrade`、`mixingGroupCode` 会自动转为大写进行精确匹配
- `plannedLoadingFrom` 和 `plannedLoadingTo` 可以单独使用或组合使用
- `minWeight` 和 `maxWeight` 可以单独使用或组合使用
- `priorities` 支持的值：`emergency`、`high`、`normal`、`low`（见附录）
- `includeScheduleLocked=false` 时，排除 `scheduleLockedUntil` 大于当前时间的任务
- 不传 `limit` 和 `offset` 时，返回所有符合条件的任务

## 使用示例

### 场景1: 获取所有待排程任务

**业务需求**: 排程系统启动时，获取所有待排程任务，不进行任何筛选

```bash
curl -X GET "http://localhost:3000/v1/prod/annealing-tasks/scheduling/pending" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

**返回结果**: 所有 `pending-schedule` 状态且未锁定的任务

---

### 场景2: 按产品和时间范围筛选

**业务需求**: 查询特定产品在未来一周内需要排程的任务

```bash
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

**返回结果**: 产品编码为 `AF-1060-O-0.05`，计划装炉时间在 2024-01-20 到 2024-01-27 之间的任务

### 任务状态枚举

| 状态代码           | 中文名称 | 说明                   |
| ------------------ | -------- | ---------------------- |
| `draft`            | 草稿     | 任务已创建但未完成准备 |
| `pending-schedule` | 待排程   | 任务已准备好，等待排程 |
| `scheduled`        | 已排程   | 已分配炉号和时间       |
| `waiting-loading`  | 待装炉   | 等待开始装炉           |
| `loading`          | 装炉中   | 正在装炉               |
| `waiting-execute`  | 待执行   | 装炉完成，等待PLC启动  |
| `in-progress`      | 执行中   | 退火炉正在执行工艺     |
| `waiting-unload`   | 待出炉   | 工艺完成，等待出炉     |
| `completed`        | 已完成   | 任务执行完成           |
| `paused`           | 已暂停   | 任务暂停               |
| `cancelled`        | 已取消   | 任务取消               |
| `terminated`       | 异常终止 | 任务异常结束           |

**注意**: 本接口仅返回 `pending-schedule` 状态的任务

### 任务优先级枚举

| 优先级代码  | 中文名称 | 说明       | 排序权重 |
| ----------- | -------- | ---------- | -------- |
| `emergency` | 紧急     | 最高优先级 | 1        |
| `high`      | 高       | 高优先级   | 2        |
| `normal`    | 普通     | 正常优先级 | 3        |
| `low`       | 低       | 低优先级   | 4        |

**使用说明**:
- priorities 参数支持多个优先级，用逗号分隔，如 `priorities=emergency,high`
- 返回结果按优先级排序（emergency 优先于 high，high 优先于 normal）

### 排序规则

接口返回的任务列表按以下优先级排序：

1. **优先级排序**（第一优先级）：emergency > high > normal > low
2. **计划装炉时间排序**（第二优先级）：早装炉的任务优先
3. **任务编号排序**（第三优先级）：相同优先级和时间时，按任务编号升序

**示例**:
```
任务1: priority=high, plannedLoadingAt=2024-01-21 08:00
任务2: priority=emergency, plannedLoadingAt=2024-01-22 08:00
任务3: priority=high, plannedLoadingAt=2024-01-20 08:00

排序结果: 任务2 → 任务3 → 任务1
```
