## 功能概述

### 所有功能

模拟装炉方案（Simulate Loading Plan）是退火任务管理模块中的**预览功能**，用于在正式创建退火任务前，根据生产计划批次信息和炉容量参数，模拟输出建议的任务拆分方案。此接口不会在数据库中创建实际任务，仅用于预览和决策支持。

该功能是"基于计划批次生成任务"业务流程的前置步骤，帮助用户在正式生成任务前：
- 了解系统建议的任务拆分方式
- 评估每个任务的装载率和重量分配
- 调整任务数量并重新预览，直到获得满意的拆分方案
- 确保所有任务重量均在炉容范围（35-42吨）内

### 关键特性

- ✅ **智能拆分计算**：根据计划批次总重量和目标炉容量（默认40吨），自动计算最优任务数量，确保每个任务重量接近目标容量且不超出炉容范围
- ✅ **灵活调整支持**：支持用户手动指定任务数量（1-50个），系统重新计算每个任务的重量分配，实现人机协同决策
- ✅ **实时预览反馈**：提供任务预览列表，包含任务名称、计划重量、计划数量、装载率、是否在炉容范围内等关键信息
- ✅ **零副作用操作**：不在数据库中创建任何记录，不影响生产数据，可重复调用直到满意
- ✅ **精确重量分配**：使用高精度浮点计算（保留6位小数），最后一个任务自动补齐余数，确保总重量精确匹配
- ✅ **完整上下文返回**：除任务预览外，还返回计划批次信息、炉容范围等上下文数据，便于前端展示和用户判断

### 使用前提

- ✅ **计划批次存在**：指定的 `planItemId` 必须在系统中存在且未被删除
- ✅ **计划批次状态合法**：计划批次状态必须为"草稿"或"待排程"，已生产或已取消的批次不能模拟
- ✅ **权限要求**：调用者必须拥有 `prod.annealing-task.view` 权限
- ✅ **重量数据有效**：计划批次的 `plannedWeight` 必须大于0

### 不适用场景

- ❌ **已生成过任务的计划批次**：如需调整已生成的任务，应通过任务管理接口操作，而非重新模拟
- ❌ **计划批次状态为"执行中"或"已完成"**：这些状态的批次不应再拆分任务
- ❌ **未关联产品的计划批次**：计划批次必须关联有效的产品信息

### 详细步骤说明

#### 步骤1: 接收预览请求
- 接收前端传入的计划批次ID（必填）
- 可选接收用户指定的任务数量
- 可选接收用户指定的目标炉容量（默认40吨）

#### 步骤2: 参数校验与默认值设置
- 校验 `planItemId` 不为空，否则抛出 400 错误
- 如果未提供 `targetCapacity`，设置为默认值 40 吨
- 如果提供了 `taskCount`，校验其范围（1-50）

#### 步骤3: 查询计划批次信息
- 根据 `planItemId` 从数据库查询计划批次
- 关联查询所属生产计划主表（`ProductionPlan`）
- 获取批次的 `plannedWeight`（计划重量）和 `plannedQuantity`（计划数量）
- 获取产品编码等信息
- 如果计划批次不存在，抛出 404 错误

#### 步骤4: 计算任务数量
**计算逻辑**：
```javascript
// 若用户指定任务数量，直接使用
if (taskCount && taskCount > 0) {
  finalTaskCount = taskCount;
} else {
  // 否则自动计算：向上取整（总重量 / 目标容量）
  suggestedTaskCount = Math.ceil(plannedWeight / targetCapacity);
  finalTaskCount = suggestedTaskCount;
}
```

**示例**：
- 总重量 120 吨，目标容量 40 吨 → 建议任务数 = 3
- 总重量 100 吨，目标容量 40 吨 → 建议任务数 = 3（向上取整）
- 总重量 41 吨，目标容量 40 吨 → 建议任务数 = 2

#### 步骤5: 分配每个任务重量
**分配策略**：
```javascript
// 平均分配
weightPerTask = 总重量 / 任务数量

// 前 N-1 个任务使用平均重量
for (i = 0; i < finalTaskCount - 1; i++) {
  taskWeight[i] = round(weightPerTask, 6);
}

// 最后一个任务补齐余数，确保总和精确匹配
taskWeight[N-1] = round(总重量 - weightPerTask * (N-1), 6);
```

**示例**：
- 总重量 120 吨，任务数 3
  - 任务1: 40.000000 吨
  - 任务2: 40.000000 吨
  - 任务3: 40.000000 吨

- 总重量 100 吨，任务数 3
  - 任务1: 33.333333 吨（平均分配）
  - 任务2: 33.333333 吨（平均分配）
  - 任务3: 33.333334 吨（补齐余数，确保总和 = 100）

#### 步骤6: 生成任务预览列表
为每个任务生成预览信息：
```javascript
{
  sequence: i + 1,                               // 任务序号
  taskName: `${planNumber}-${itemNumber}-${i+1}`,// 任务名称
  plannedWeight: taskWeight,                     // 计划重量（吨）
  plannedQuantity: taskQuantity,                 // 计划数量
  targetCapacity: 40,                            // 目标容量（吨）
  loadRate: (taskWeight / targetCapacity) * 100, // 装载率（%）
  withinRange: (35 <= taskWeight <= 42)          // 是否在炉容范围内
}
```

**关键字段说明**：
- `sequence`: 任务序号，从 1 开始递增
- `taskName`: 任务名称，格式为 `{计划编号}-{批次号}-{序号}`，例如 `PLAN-2024-001-001-1`
- `plannedWeight`: 该任务分配的计划重量（吨）
- `plannedQuantity`: 该任务分配的计划数量（如果批次有数量信息）
- `targetCapacity`: 参考的目标炉容量
- `loadRate`: 装载率 = (任务重量 / 目标容量) × 100，单位 %
- `withinRange`: 布尔值，标识该任务重量是否在合法炉容范围（35-42吨）内

#### 步骤7: 组装响应数据
返回完整的模拟结果：
```javascript
{
  suggestedTaskCount,    // 系统建议的任务数量
  finalTaskCount,        // 最终采用的任务数量
  plannedWeight,         // 计划批次总重量
  targetCapacity,        // 目标炉容量
  taskPreview: [...],    // 任务预览列表
  planItem: {...},       // 计划批次信息
  capacityInfo: {        // 炉容范围信息
    minCapacity: 35,
    maxCapacity: 42,
    targetCapacity: 40
  }
}
```

#### 步骤8: 返回模拟结果
- 将组装好的数据包装在统一响应格式中
- 返回 HTTP 200 状态码
- **重要**：整个过程不涉及数据库写入操作，不创建任何任务记录

## 接口文档

### 基本信息

**接口路径**: `POST /v1/prod/annealing-tasks/simulate`

**功能描述**: 根据生产计划批次ID和炉容量参数，模拟输出建议的退火任务拆分方案，供前端预览和决策。不会在数据库中创建实际任务，支持多次调用和参数调整。

**认证要求**: Bearer Token 认证，需要 `prod.annealing-task.view` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 请求参数

| 参数名         | 类型   | 必填 | 限制             | 描述                                     | 示例                                   |
| -------------- | ------ | ---- | ---------------- | ---------------------------------------- | -------------------------------------- |
| planItemId     | string | 是   | UUID v4 格式     | 生产计划批次ID                           | "554e4422-beac-48bd-a22b-43b38a3c212b" |
| taskCount      | number | 否   | 整数，1-50       | 指定生成任务数量，不填则自动计算         | 3                                      |
| targetCapacity | number | 否   | 浮点数，35-42 吨 | 目标炉容量（吨），默认40，用于计算装载率 | 40                                     |

**参数说明**：
- `planItemId`: 必须是系统中存在的有效计划批次UUID
- `taskCount`: 若提供，系统将按此数量拆分任务；若不提供，系统自动计算最优数量
- `targetCapacity`: 影响装载率计算和建议任务数，实际任务重量可能与此值有偏差

## 使用示例

### 场景1: 自动计算任务数量

**业务需求**: 生产计划批次总重量为 100 吨，希望系统自动计算最优任务数量

**分析**：
- 系统计算出建议任务数为 3（100 ÷ 40 = 2.5，向上取整为 3）
- 每个任务约 33.33 吨，均低于最小炉容 35 吨（`withinRange: false`）
- 用户可能需要调整为 2 个任务或 3 个任务并优化装载策略

---

### 场景2: 指定任务数量后重新预览

**业务需求**: 针对场景1的结果，用户认为3个任务重量偏小，希望尝试拆分为2个任务
**分析**：
- 系统按用户指定的 2 个任务拆分，每个任务 50 吨
- 每个任务重量超出最大炉容 42 吨（`withinRange: false`）
- 装载率 125% 表示超载，不可行
- 用户应继续调整或接受系统建议的 3 个任务

---

### 场景3: 调整目标容量参数

**业务需求**: 某个退火炉的目标装载量为 38 吨，希望基于此重新模拟

**分析**：
- 目标容量调整为 38 吨后，建议任务数仍为 3
- 装载率从 83.33% 提升到 87.72%
- 但任务重量仍低于最小炉容 35 吨
- 实际应用中，可能需要考虑其他因素（如工艺要求、炉型限制等）

---

### 场景4: 理想拆分方案（重量在炉容范围内）

## 常见问题

### Q1: 为什么有时候 `withinRange` 为 false？

**A**: `withinRange` 字段标识任务重量是否在炉容合法范围（35-42吨）内。当出现 false 时，可能有以下原因：

1. **计划批次总重量过小**：如 30 吨拆成 1 个任务，低于最小炉容 35 吨
2. **任务数量指定过多**：如 100 吨拆成 4 个任务，每个 25 吨，低于最小炉容
3. **任务数量指定过少**：如 100 吨拆成 2 个任务，每个 50 吨，超出最大炉容 42 吨

**处理建议**：
- 调整 `taskCount` 参数重新模拟
- 考虑与其他计划批次合并或拆分
- 接受系统建议的任务数量（`suggestedTaskCount`）

---

### Q2: `suggestedTaskCount` 和 `finalTaskCount` 有什么区别？

**A**:
- **suggestedTaskCount**: 系统根据 `Math.ceil(总重量 / 目标容量)` 自动计算的建议任务数
- **finalTaskCount**: 最终采用的任务数量
  - 如果用户提供了 `taskCount` 参数，则 `finalTaskCount = taskCount`
  - 如果用户未提供，则 `finalTaskCount = suggestedTaskCount`

**示例**：
```json
// 用户未指定taskCount
{
  "planItemId": "xxx",
  // 系统自动计算
}
// 响应：suggestedTaskCount = 3, finalTaskCount = 3

// 用户指定taskCount
{
  "planItemId": "xxx",
  "taskCount": 5
}
// 响应：suggestedTaskCount = 3, finalTaskCount = 5
```

---

### Q3: 为什么最后一个任务的重量和前面不同？

**A**: 这是为了确保所有任务的总重量精确匹配计划批次的总重量。

**计算逻辑**：
```javascript
// 前 N-1 个任务使用平均重量
weightPerTask = 总重量 / 任务数量

// 最后一个任务补齐余数
lastTaskWeight = 总重量 - (weightPerTask * (任务数量 - 1))
```

**示例**：
- 总重量 100 吨，任务数 3
- 平均分配：33.333333 吨 / 任务
- 前2个任务：33.333333 吨
- 第3个任务：100 - (33.333333 × 2) = 33.333334 吨
- 总和：33.333333 + 33.333333 + 33.333334 = 100.000000 吨（精确匹配）

---

### Q4: 可以对同一个计划批次多次调用此接口吗？

**A**: 可以，且推荐这样做。

此接口设计为**无副作用操作**，不会在数据库中创建任何记录，可以：
- 多次调用，尝试不同的 `taskCount` 和 `targetCapacity` 参数
- 对比不同方案的装载率和重量分配
- 找到最满意的方案后，再调用 `POST /v1/prod/annealing-tasks` 正式创建任务

**推荐工作流程**：
1. 第1次调用：不带参数，查看系统建议方案
2. 第2次调用：调整 `taskCount`，对比装载率
3. 第3次调用：调整 `targetCapacity`，优化分配
4. 确认最终方案
5. 调用创建任务接口（`POST /v1/prod/annealing-tasks`）正式生成任务

---

### Q5: 接口返回的任务名称规则是什么？

**A**: 任务名称由三部分组成：`{计划编号}-{批次号}-{任务序号}`

**格式说明**：
```
{planNumber}-{itemNumber}-{sequence}
```

**示例**：
- 计划编号：`PLAN-2024-005`
- 批次号：`002`
- 任务序号：`1`, `2`, `3`, ...
- 生成任务名称：
  - `PLAN-2024-005-002-1`
  - `PLAN-2024-005-002-2`
  - `PLAN-2024-005-002-3`

**注意**：
- 任务序号从 1 开始，不是从 0
- 正式创建任务时，系统会生成唯一的 `taskCode`（任务编码），格式不同于 `taskName`

---

### Q6: 如果计划批次已经生成过任务，还能模拟吗？

**A**: 可以，模拟接口不检查是否已生成过任务。

但**不建议**这样做，原因：
- 模拟预览的目的是在生成任务前辅助决策
- 如果已生成任务，应通过任务管理接口进行调整或删除重建
- 重复生成可能导致数据混乱和库存绑定冲突

**推荐做法**：
- 生成任务前：多次调用模拟接口，确定方案
- 生成任务后：通过任务详情接口查看实际任务
- 需要调整：先取消或删除已生成的任务，再重新模拟和生成

---

### Q7: `loadRate`（装载率）是如何计算的？

**A**: 装载率 = (任务重量 / 目标容量) × 100

**公式**：
```javascript
loadRate = (plannedWeight / targetCapacity) * 100
```

**示例**：
- 任务重量 40 吨，目标容量 40 吨 → 装载率 = 100%
- 任务重量 38 吨，目标容量 40 吨 → 装载率 = 95%
- 任务重量 50 吨，目标容量 40 吨 → 装载率 = 125%（超载）

**意义**：
- **100%**：理想装载，任务重量等于目标容量
- **< 100%**：未满载，炉容利用率不足
- **> 100%**：超载，可能超出炉容上限（需结合 `withinRange` 判断）

**注意**：
- 装载率 > 100% 不一定违规，只要任务重量 ≤ 42 吨（最大炉容）
- 装载率应结合 `withinRange` 字段综合判断

### 允许生成任务的计划批次状态

| 状态代码               | 状态名称 | 说明                       |
| ---------------------- | -------- | -------------------------- |
| `draft`                | 草稿     | 计划批次处于草稿状态       |
| `ready_for_scheduling` | 待排程   | 计划批次已准备好，等待排程 |

**不允许的状态**：
- `in_production`: 生产中（已生成任务，不应重复生成）
- `completed`: 已完成（生产已结束）
- `cancelled`: 已取消（不应再生成任务）

### 任务命名规范

**任务名称格式**：
```
{planNumber}-{itemNumber}-{sequence}
```

**字段说明**：
- `planNumber`: 生产计划编号，如 `PLAN-2024-005`
- `itemNumber`: 计划批次编号，如 `001`, `002`
- `sequence`: 任务序号，从 1 开始递增

**完整示例**：
```
PLAN-2024-005-001-1
PLAN-2024-005-001-2
PLAN-2024-005-001-3
```

**注意**：
- 任务序号用于区分同一批次拆分出的多个任务
- 正式创建任务时，系统会额外生成唯一的 `taskCode`（任务编码）

### 重量计算精度

| 计算项   | 精度    | 说明                         |
| -------- | ------- | ---------------------------- |
| 任务重量 | 6位小数 | 确保高精度分配，避免累积误差 |
| 装载率   | 2位小数 | 百分比展示，方便阅读         |
| 计划数量 | 6位小数 | 支持非整数产品数量           |
