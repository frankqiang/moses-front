# 退火任务管理业务流程说明

## 文档说明

本文档基于退火任务管理模块的实际实现，说明核心业务逻辑和数据流转规则，为前端开发提供业务理解基础。

## 核心概念

### 退火任务定义

**退火任务（AnnealingTask）**：退火炉生产过程的工作单元，从任务创建、物料准备、排程分配、装炉执行到出炉完成的完整管理流程，包含产品信息、工艺模板、排程信息、物料清单、执行进度等全生命周期数据。

### 任务来源

| 来源类型     | 代码值       | 定义                         | 特点                         | 触发方式       |
| ------------ | ------------ | ---------------------------- | ---------------------------- | -------------- |
| 计划拆分生成 | `plan-split` | 基于生产计划批次自动拆分生成 | 关联生产计划，自动计算分配   | 系统自动或手动 |
| 手工创建     | `manual`     | 调度员手工创建的独立退火任务 | 灵活性高，用于插单或特殊需求 | 手动创建       |

### 任务优先级

| 优先级 | 代码值      | 说明                 | 排程影响           |
| ------ | ----------- | -------------------- | ------------------ |
| 紧急   | `emergency` | 最高优先级，紧急订单 | 优先分配炉次和时间 |
| 高     | `high`      | 高优先级，重要订单   | 优先考虑           |
| 普通   | `normal`    | 正常优先级（默认）   | 按计划排程         |
| 低     | `low`       | 低优先级，可延后     | 可适当延后         |

### 物料类型

| 类型 | 代码值   | 说明         | 特点                 |
| ---- | -------- | ------------ | -------------------- |
| 料框 | `basket` | 铝箔卷料框   | 单位小，数量多       |
| 料垛 | `stack`  | 多个料框堆垛 | 单位大，便于批量管理 |

### 状态模型

#### 状态流转图

```
任务创建
   ↓
草稿 (draft) ───────────────────────┐
   ↓                                │
待排程 (pending-schedule) ←─────────┤
   ↓                 ↑              │
已排程 (scheduled) ──┘              │
   ↓                                │
待装炉 (waiting-loading)            │
   ↓                                │
装炉中 (loading) ────────────────┐  │
   ↓                 ↑           │  │
待执行 (waiting-execute)         │  │
   ↓                             │  │
执行中 (in-progress)             │  │
   ↓                             │  │
待出炉 (waiting-unload)          │  │
   ↓                             │  │
已完成 (completed)               │  │
                                 │  │
   ┌─────────────────────────────┘  │
   ↓                                │
已暂停 (paused) ─────────────────────┤
                                    │
已取消 (cancelled) ←─────────────────┘
异常终止 (terminated)
```

#### 状态定义

| 状态代码           | 状态名称 | 含义                   | 可执行操作                          |
| ------------------ | -------- | ---------------------- | ----------------------------------- |
| `draft`            | 草稿     | 任务已创建但未完成准备 | 绑定物料、更新信息、提交排程、取消  |
| `pending-schedule` | 待排程   | 任务已准备好，等待排程 | 排程分配、回退草稿、取消            |
| `scheduled`        | 已排程   | 已分配炉号和时间       | 开始装炉、重新排程、暂停、取消      |
| `waiting-loading`  | 待装炉   | 等待开始装炉           | 开始装炉、暂停、取消                |
| `loading`          | 装炉中   | 正在装炉               | 装炉完成、暂停、异常终止            |
| `waiting-execute`  | 待执行   | 装炉完成，等待PLC启动  | PLC启动执行、暂停、异常终止         |
| `in-progress`      | 执行中   | 退火炉正在执行工艺     | 执行完成（PLC反馈）、暂停、异常终止 |
| `waiting-unload`   | 待出炉   | 工艺完成，等待出炉     | 出炉完成、暂停、异常终止            |
| `completed`        | 已完成   | 任务执行完成           | 无（终态）                          |
| `paused`           | 已暂停   | 任务暂停               | 恢复到暂停前状态、取消、异常终止    |
| `cancelled`        | 已取消   | 任务取消               | 无（终态）                          |
| `terminated`       | 异常终止 | 任务异常结束           | 无（终态）                          |

### 状态转换约束

| 操作        | 允许的当前状态                                                | 目标状态           | 约束条件                          |
| ----------- | ------------------------------------------------------------- | ------------------ | --------------------------------- |
| 提交排程    | `draft`                                                       | `pending-schedule` | 已绑定物料且总重量在35-42吨范围内 |
| 回退草稿    | `pending-schedule`                                            | `draft`            | 尚未排程分配                      |
| 排程分配    | `pending-schedule`                                            | `scheduled`        | 排程系统分配炉号和时间            |
| 重新排程    | `scheduled`                                                   | `pending-schedule` | 管理权限                          |
| 开始装炉    | `scheduled`, `waiting-loading`                                | `loading`          | 到达计划装炉时间                  |
| 装炉完成    | `loading`                                                     | `waiting-execute`  | 确认所有物料已装炉                |
| PLC启动执行 | `waiting-execute`                                             | `in-progress`      | PLC反馈启动信号                   |
| 执行完成    | `in-progress`                                                 | `waiting-unload`   | PLC反馈工艺完成信号               |
| 出炉完成    | `waiting-unload`                                              | `completed`        | 确认所有物料已出炉                |
| 暂停任务    | 除终态外的所有状态                                            | `paused`           | 管理权限，记录暂停原因            |
| 恢复任务    | `paused`                                                      | 暂停前状态         | 管理权限                          |
| 取消任务    | 除 `completed`、`terminated` 外                               | `cancelled`        | 管理权限，记录取消原因            |
| 异常终止    | `loading`、`waiting-execute`、`in-progress`、`waiting-unload` | `terminated`       | 发生异常情况，记录终止原因        |

## 业务流程详解

### 1. 任务创建

#### 方式一：基于生产计划批次生成（推荐）

**前置条件**：
- 生产计划已创建并包含子批次
- 子批次状态为"待生产"或"生产中"
- 子批次已关联产品和工艺模板

**创建流程**：
1. **模拟装炉方案（可选）**
   - 输入：计划批次ID、目标任务数量（可选）、目标炉容量（可选，默认40吨）
   - 系统计算：根据批次总重量和目标炉容量，建议任务数量
   - 输出：任务预览列表（序号、任务名称、计划重量、装载率、是否在范围内）
   - 用途：验证拆分方案的合理性

2. **确认生成任务**
   - 输入：计划批次ID、任务数量、目标炉容量、优先级
   - 自动填充：
     - 任务编码：`AT-{日期}-{序号}`（如 AT-20240120-001）
     - 任务名称：`{计划编号}-{批次编号}-{任务序号}`
     - 产品信息：从计划批次复制（产品编码、名称、合金牌号）
     - 工艺模板：使用批次关联的工艺模板（状态必须为"生效"）
     - 计划重量：批次总重量 ÷ 任务数量
     - 关联关系：记录 planId、planItemId
   - 初始状态：`draft`（草稿）
   - 任务来源：`plan-split`

**示例**：
- 计划批次：PLAN-2024-001-001，总重量 120 吨
- 目标炉容量：40 吨
- 生成任务：3 个退火任务，每个 40 吨
  - AT-20240120-001：PLAN-2024-001-001-1，40 吨
  - AT-20240120-002：PLAN-2024-001-001-2，40 吨
  - AT-20240120-003：PLAN-2024-001-001-3，40 吨

#### 方式二：手工创建退火任务

**适用场景**：
- 插单生产，不依赖生产计划
- 特殊工艺需求
- 紧急订单

**创建流程**：
- **必填信息**：
  - 任务编码：自动生成或手动指定（需唯一）
  - 产品编码：必须关联有效的产品主数据
  - 计划重量：预计退火重量（吨）
  - 优先级：emergency/high/normal/low
- **可选信息**：
  - 任务名称：便于识别
  - 工艺模板ID：指定工艺模板（状态必须为"生效"）
  - 合金牌号：产品的合金牌号
  - 备注：任务说明
- **自动处理**：
  - 如未指定工艺模板，系统从产品关联的工艺模板中自动选择生效的模板
  - 如产品信息不完整，从产品主数据补全（产品名称、合金牌号）
- **初始状态**：`draft`（草稿）
- **任务来源**：`manual`

### 2. 物料绑定

**目的**：将待退火的料框/料垛关联到退火任务，明确实际装炉物料。

**前置条件**：
- 任务状态为 `draft` 或 `pending-schedule`
- 物料（料框/料垛）状态符合要求（如"待退火"）
- 物料未被其他任务绑定

**绑定流程**：
1. **选择物料**
   - 物料类型：basket（料框）或 stack（料垛）
   - 物料编码：唯一标识
   - 实际重量：物料的实际重量（必填）
   - 装炉顺序：可选，指定装炉顺序
   - 是否主料框：可选，标识主要物料

2. **系统校验**
   - 物料是否已被其他任务绑定（防止重复）
   - 物料状态是否符合要求
   - 绑定后总重量是否在炉容范围内（35-42吨）

3. **绑定完成**
   - 创建物料绑定记录
   - 更新任务实际重量
   - 记录操作日志

**重量约束**：
- **最小炉容**：35 吨
- **最大炉容**：42 吨
- **目标炉容**：40 吨
- **容差**：± 0.1 吨
- **校验规则**：绑定物料后，任务总重量必须在 35-42 吨范围内

**状态联动**：
- 如果任务状态为 `draft`，绑定物料后可提交到 `pending-schedule`
- 如果总重量不在范围内，系统会提示但允许继续绑定（需在提交排程前调整）

### 3. 任务排程

**目的**：为待排程任务分配退火炉号和生产时间，优化炉次利用率。

#### 3.1 获取待排程任务

**筛选条件**：
- 任务状态：`pending-schedule`
- 未锁定或锁定已超时
- 按优先级、计划重量排序

**返回信息**：
- 任务基本信息（编码、名称、产品、重量）
- 工艺参数（工艺模板、工艺时长）
- 关联信息（计划编号、批次编号）

#### 3.2 锁定任务用于排程

**目的**：防止排程过程中任务被其他操作修改。

**锁定逻辑**：
- 指定任务ID列表
- 记录锁定人、锁定时间
- 设置锁定超时时间（默认30分钟）
- 锁定期间任务不可被其他排程系统获取

#### 3.3 应用排程结果（排程回写）

**输入信息**：
- 任务ID
- 炉号：分配的退火炉编号
- 计划装炉时间：预计开始装炉时间
- 计划开始时间：预计退火开始时间
- 计划完成时间：预计退火完成时间
- 排程备注：可选

**处理逻辑**：
1. 验证任务状态为 `pending-schedule`
2. 验证炉号有效性
3. 验证时间逻辑（装炉时间 < 开始时间 < 完成时间）
4. 更新任务排程信息
5. 状态变更：`pending-schedule` → `scheduled`
6. 记录排程发布时间
7. 释放任务锁定

#### 3.4 释放任务排程锁定

**触发条件**：
- 排程完成
- 排程取消
- 锁定超时

**处理逻辑**：
- 清除锁定标记
- 清除锁定人和锁定时间

### 4. 任务执行

#### 4.1 装炉阶段

**状态流转**：`scheduled` → `waiting-loading` → `loading` → `waiting-execute`

**操作流程**：
1. **待装炉（waiting-loading）**
   - 到达计划装炉时间
   - 操作员准备开始装炉

2. **装炉中（loading）**
   - 记录实际装炉开始时间
   - 按装炉顺序将物料装入退火炉
   - 可实时更新装炉进度

3. **待执行（waiting-execute）**
   - 记录实际装炉完成时间
   - 所有物料已装炉
   - 等待PLC启动退火工艺

#### 4.2 执行阶段

**状态流转**：`waiting-execute` → `in-progress` → `waiting-unload`

**操作流程**：
1. **执行中（in-progress）**
   - PLC反馈启动信号
   - 记录执行开始时间
   - 实时同步PLC数据：
     - 当前温度
     - 目标温度
     - 当前阶段
     - 执行进度
     - 预计剩余时间

2. **待出炉（waiting-unload）**
   - PLC反馈工艺完成信号
   - 记录执行完成时间
   - 工艺执行完成，等待出炉

#### 4.3 出炉阶段

**状态流转**：`waiting-unload` → `completed`

**操作流程**：
1. 操作员开始出炉
2. 按顺序将物料从退火炉取出
3. 确认所有物料已出炉
4. 记录实际完成时间
5. 状态变更：`waiting-unload` → `completed`
6. 更新物料状态（如"待检验"）
7. 更新计划批次状态（如部分完成或全部完成）

### 5. 进度监控

**查询接口**：`GET /v1/prod/annealing-tasks/:taskId/progress`

**进度信息**：
- **整体进度**
  - 当前状态
  - 完成百分比
  - 预计剩余时间

- **装炉进度**
  - 已装物料数量
  - 总物料数量
  - 已装重量
  - 总计划重量

- **执行进度**
  - 当前工艺阶段
  - 当前温度 / 目标温度
  - 执行时长 / 计划时长
  - 预计剩余时间

- **出炉进度**
  - 已出炉物料数量
  - 总物料数量
  - 已出炉重量

- **时间信息**
  - 计划装炉时间 / 实际装炉时间
  - 计划开始时间 / 实际开始时间
  - 计划完成时间 / 预计完成时间

### 6. 任务调整

#### 任务暂停

**条件**：
- 任务状态为除 `completed`、`cancelled`、`terminated` 外的状态
- 需要管理权限（`prod.annealing-task.manage`）

**操作**：
- 必填：暂停原因
- 状态变更：当前状态 → `paused`
- 记录暂停前状态，用于恢复

**适用场景**：
- 设备故障需要维修
- 工艺参数需要调整
- 等待特殊物料

#### 任务恢复

**条件**：
- 任务状态为 `paused`
- 需要管理权限（`prod.annealing-task.manage`）

**操作**：
- 可选：恢复备注
- 状态变更：`paused` → 暂停前状态

#### 任务取消

**条件**：
- 任务状态为除 `completed`、`terminated` 外的状态
- 需要管理权限（`prod.annealing-task.manage`）

**操作**：
- 必填：取消原因
- 状态变更：当前状态 → `cancelled`
- 释放绑定的物料
- 更新计划批次状态（如取消部分任务）

**适用场景**：
- 订单取消
- 计划调整
- 产品变更

#### 异常终止

**条件**：
- 任务状态为 `loading`、`waiting-execute`、`in-progress`、`waiting-unload`
- 发生异常情况无法继续执行

**操作**：
- 必填：终止原因
- 状态变更：当前状态 → `terminated`
- 记录异常信息
- 释放炉次资源

**适用场景**：
- 设备严重故障
- 工艺执行异常
- 安全事故

## 数据约束规则

### 任务约束

| 字段         | 约束规则                                                   |
| ------------ | ---------------------------------------------------------- |
| 任务编码     | 唯一，建议格式：AT-YYYYMMDD-XXXX                           |
| 产品编码     | 必填，必须关联有效的产品主数据                             |
| 工艺模板     | 如提供，工艺模板状态必须为"生效"，最新版本状态必须为"生效" |
| 计划重量     | 必填，范围 0.1 - 1000 吨                                   |
| 实际重量     | 绑定物料后自动计算，范围 35 - 42 吨                        |
| 优先级       | emergency/high/normal/low，默认 normal                     |
| 任务来源     | plan-split（计划拆分）或 manual（手工创建）                |
| 计划装炉时间 | 排程时分配，必须晚于当前时间                               |
| 计划开始时间 | 排程时分配，必须晚于计划装炉时间                           |
| 计划完成时间 | 排程时分配，必须晚于计划开始时间                           |

### 重量约束

| 约束类型     | 数值     | 说明                         |
| ------------ | -------- | ---------------------------- |
| 最小炉容     | 35 吨    | 退火炉最小装载量             |
| 最大炉容     | 42 吨    | 退火炉最大装载量             |
| 目标炉容     | 40 吨    | 推荐装载量                   |
| 容差         | ± 0.1 吨 | 重量计算容差                 |
| 物料绑定校验 | 35-42 吨 | 绑定物料后总重量必须在范围内 |

### 时间记录规则

| 时间类型         | 记录方式   | 说明                              |
| ---------------- | ---------- | --------------------------------- |
| 创建时间         | 自动记录   | 任务创建时记录                    |
| 排程发布时间     | 自动记录   | 状态变为 `scheduled` 时记录       |
| 计划装炉时间     | 排程时指定 | 排程系统分配                      |
| 实际装炉开始时间 | 自动记录   | 状态变为 `loading` 时记录         |
| 实际装炉完成时间 | 自动记录   | 状态变为 `waiting-execute` 时记录 |
| 执行开始时间     | 自动记录   | 状态变为 `in-progress` 时记录     |
| 执行完成时间     | 自动记录   | 状态变为 `waiting-unload` 时记录  |
| 实际完成时间     | 自动记录   | 状态变为 `completed` 时记录       |

### 物料绑定规则

| 规则         | 说明                                          |
| ------------ | --------------------------------------------- |
| 绑定状态限制 | 只有 `draft` 和 `pending-schedule` 状态可绑定 |
| 重复绑定检查 | 物料不能同时绑定到多个任务                    |
| 重量自动计算 | 绑定后自动累加更新任务实际重量                |
| 装炉顺序     | 可指定装炉顺序，用于装炉操作指导              |
| 物料状态快照 | 记录绑定时物料的状态，用于追溯                |

### 状态联动规则

| 操作     | 任务状态变更                      | 物料状态变更             | 计划批次状态变更             |
| -------- | --------------------------------- | ------------------------ | ---------------------------- |
| 绑定物料 | 无（保持当前状态）                | 无（建议标记为"待退火"） | 无                           |
| 提交排程 | `draft` → `pending-schedule`      | 无                       | 无                           |
| 排程分配 | `pending-schedule` → `scheduled`  | 无                       | 无                           |
| 开始装炉 | `scheduled` → `loading`           | 建议标记为"装炉中"       | 无                           |
| 装炉完成 | `loading` → `waiting-execute`     | 无                       | 无                           |
| 开始执行 | `waiting-execute` → `in-progress` | 建议标记为"退火中"       | 标记为"生产中"               |
| 执行完成 | `in-progress` → `waiting-unload`  | 无                       | 无                           |
| 出炉完成 | `waiting-unload` → `completed`    | 建议标记为"待检验"       | 累计完成量，检查是否全部完成 |
| 取消任务 | 任意状态 → `cancelled`            | 释放，恢复原状态         | 减少进行中任务数             |

## 核心业务规则

1. **状态单向流转**：任务状态按预定义规则流转，`completed`、`cancelled`、`terminated` 为终态不可逆
2. **重量强约束**：绑定物料后总重量必须在 35-42 吨范围内才能提交排程
3. **工艺模板生效校验**：关联的工艺模板及其最新版本状态必须为"生效"
4. **物料独占绑定**：一个物料同一时间只能绑定到一个退火任务
5. **排程锁定机制**：排程过程中锁定任务，防止并发修改，锁定超时自动释放
6. **时间自动记录**：实际时间由系统在状态变更时自动记录，不可手动修改
7. **事务保护**：关键操作（绑定物料、状态变更、排程回写）使用数据库事务确保数据一致性
8. **状态校验**：所有操作前验证当前状态是否允许，不允许则返回明确错误信息
9. **操作日志记录**：所有关键操作记录日志，包含操作人、操作时间、操作IP、操作内容

## 典型业务场景

### 场景1：基于生产计划生成退火任务

1. 生产计划已创建，包含批次 PLAN-2024-001-001，总重量 120 吨
2. 调度员选择批次，模拟装炉方案
   - 输入：计划批次ID、目标炉容量 40 吨
   - 系统建议：生成 3 个任务，每个 40 吨
3. 调度员确认方案，系统生成 3 个退火任务
   - AT-20240120-001：PLAN-2024-001-001-1，40 吨，状态 `draft`
   - AT-20240120-002：PLAN-2024-001-001-2，40 吨，状态 `draft`
   - AT-20240120-003：PLAN-2024-001-001-3，40 吨，状态 `draft`
4. 调度员为每个任务绑定物料（料框/料垛）
   - AT-20240120-001 绑定 10 个料框，总重量 40.2 吨（在范围内）
5. 调度员提交任务到排程
   - 状态变更：`draft` → `pending-schedule`
6. 排程系统分配炉号和时间
   - AT-20240120-001：1号炉，2024-01-21 08:00 装炉
   - 状态变更：`pending-schedule` → `scheduled`
7. 按计划执行任务
   - 装炉 → 执行 → 出炉 → 完成
8. 系统更新计划批次进度
   - 批次 PLAN-2024-001-001：已完成 1/3

### 场景2：手工创建紧急插单任务

1. 紧急订单，需要快速安排退火
2. 调度员手工创建退火任务
   - 任务编码：AT-20240120-999
   - 产品编码：AF-1060-O-0.05（系统自动补全产品名称、合金牌号）
   - 计划重量：40 吨
   - 优先级：emergency（紧急）
   - 工艺模板：自动选择产品关联的生效工艺模板
   - 状态：`draft`
3. 调度员立即绑定物料
   - 绑定 8 个料垛，总重量 39.8 吨
4. 提交排程
   - 状态变更：`draft` → `pending-schedule`
5. 排程系统优先分配（因为优先级为 emergency）
   - 2号炉，今天 14:00 装炉
   - 状态变更：`pending-schedule` → `scheduled`
6. 执行任务，完成生产

### 场景3：任务执行过程监控

1. 任务 AT-20240120-001 已排程，炉号 1号炉
2. 到达装炉时间，操作员开始装炉
   - 状态变更：`scheduled` → `waiting-loading` → `loading`
   - 记录实际装炉开始时间：2024-01-21 08:05
3. 装炉完成
   - 状态变更：`loading` → `waiting-execute`
   - 记录实际装炉完成时间：2024-01-21 09:30
4. PLC启动退火工艺
   - 状态变更：`waiting-execute` → `in-progress`
   - 记录执行开始时间：2024-01-21 09:35
5. 实时监控进度
   - 查询接口返回：当前温度 450℃，目标温度 500℃，完成度 60%，预计剩余时间 3小时
6. PLC反馈工艺完成
   - 状态变更：`in-progress` → `waiting-unload`
   - 记录执行完成时间：2024-01-21 14:35
7. 操作员出炉
   - 状态变更：`waiting-unload` → `completed`
   - 记录实际完成时间：2024-01-21 15:00
8. 系统更新物料状态为"待检验"，更新计划批次进度

### 场景4：任务暂停和恢复

1. 任务 AT-20240120-002 正在执行中（`in-progress`）
2. 设备故障，需要紧急维修
3. 操作员暂停任务
   - 填写暂停原因："1号炉温控系统故障，需要维修"
   - 状态变更：`in-progress` → `paused`
   - 记录暂停前状态：`in-progress`
4. 维修完成，操作员恢复任务
   - 填写恢复备注："温控系统已修复，已测试正常"
   - 状态变更：`paused` → `in-progress`（恢复到暂停前状态）
5. 继续执行，直至完成

### 场景5：任务取消

1. 任务 AT-20240120-003 已排程（`scheduled`），等待装炉
2. 客户取消订单，需要取消任务
3. 调度员取消任务
   - 填写取消原因："客户订单取消，订单号 SO-2024-001"
   - 状态变更：`scheduled` → `cancelled`
   - 释放绑定的物料（物料状态恢复）
   - 释放炉次资源
4. 系统更新计划批次状态
   - 批次 PLAN-2024-001-001：任务数减少，标记部分取消

| 接口类型     | 接口路径                                          | 说明                                   |

| 模拟装炉方案 | `POST /v1/prod/annealing-tasks/simulate`          | 预览基于计划批次的拆分方案             |

### 常见错误码

| 错误码                | 说明                 | 处理建议                 |
| --------------------- | -------------------- | ------------------------ |
| `RESOURCE_NOT_FOUND`  | 资源不存在           | 检查任务ID、计划批次ID   |
| `INVALID_STATUS`      | 状态不允许操作       | 检查任务当前状态         |
| `PARAM_ERROR`         | 参数验证失败         | 检查请求参数             |
| `WEIGHT_OUT_OF_RANGE` | 重量超出炉容范围     | 调整绑定的物料数量       |
| `DUPLICATE_MATERIAL`  | 物料已被其他任务绑定 | 检查物料状态，解绑后重试 |
| `LOCK_TIMEOUT`        | 排程锁定超时         | 释放锁定后重试           |
