### 2. batchNumber（批次号）

| 属性         | 说明                                     |
| ------------ | ---------------------------------------- |
| **业务含义** | 物料所属的生产批次号，用于追溯和质量管理 |
| **数据类型** | string（最大100字符）                    |
| **是否必填** | 否                                       |
| **默认值**   | `null`                                   |
| **存储字段** | `annealing_task_materials.batch_number`  |

**数据来源**：
- **料框**: 查询料框详情接口 `GET /v1/inv/bins/:id`，获取 `batchNumber` 字段
- **料垛**: 查询料垛详情接口 `GET /v1/inv/stacks/:id`，获取 `batchNumber` 字段

**后端处理逻辑**：
- 存储于物料绑定记录，不参与业务校验
- 用于追溯退火任务中使用的原材料批次

**关于组垛批次号的业务规则**：

根据 `stacks` 表设计，料垛的 `batch_number` 字段定义为：
```
可选一致性要求，组垛时所有料框批次可相同也可不同
```

这意味着：
1. **允许不同批次料框组垛** - 系统不强制要求同批次
2. **料垛批次号可能为空** - 当料框批次混合时，料垛批次号设为 `null`
3. **料垛批次号可能记录主批次** - 当大部分料框为同一批次时，可记录主要批次号

**实际绑定时的处理**：
- 直接使用物料（料框或料垛）的当前 `batchNumber` 字段值即可
- 如果料垛批次号为空，表示该料垛包含混合批次的料框
- 后端不会对批次号进行额外校验或处理

### 4. warehouseLocationId（库位ID）

| 属性         | 说明                                             |
| ------------ | ------------------------------------------------ |
| **业务含义** | 物料所在库位的唯一标识（UUID）                   |
| **数据类型** | string（UUID v4格式）                            |
| **是否必填** | 否                                               |
| **默认值**   | `null`                                           |
| **存储字段** | `annealing_task_materials.warehouse_location_id` |

**数据来源**：
- **料框**: 查询料框详情接口 `GET /v1/inv/bins/:id`，获取 `currentLocationId` 字段
- **料垛**: 查询料垛详情接口 `GET /v1/inv/stacks/:id`，获取 `currentLocationId` 字段

**关联表结构**：
- 字段关联到 `storage_locations` 表的主键 `id`
- `storage_locations` 表存储库位的详细信息（编码、类型、坐标等）

**后端处理逻辑**：
- 记录物料绑定时的库位信息，便于追溯物料来源
- 不校验库位是否存在或是否可用
- 用于后续查询"某库位的物料被哪些退火任务使用"

**使用场景**：
- 追溯退火任务使用的物料来自哪个库位
- 分析库位使用效率和周转率
- 物流路径优化和历史记录

---

### 5. warehouseLocationCode（库位编码）

| 属性         | 说明                                               |
| ------------ | -------------------------------------------------- |
| **业务含义** | 库位的可读编码，便于人工识别和操作                 |
| **数据类型** | string（最大80字符）                               |
| **是否必填** | 否                                                 |
| **默认值**   | `null`                                             |
| **存储字段** | `annealing_task_materials.warehouse_location_code` |

**数据来源**：
- **料框**: 查询料框详情接口 `GET /v1/inv/bins/:id`，获取 `currentLocation.locationId` 字段
- **料垛**: 查询料垛详情接口，通过 `currentLocationId` 关联查询库位信息

**库位编码格式示例**：
- `DA-01-01-A` - 库区代码-行号-列号-层号
- `WH-A-01-001` - 仓库区域-区号-架号-位号

**后端处理逻辑**：
- 冗余存储库位编码，避免每次查询都需要关联 `storage_locations` 表
- 用于日志记录、报表展示等场景
- 不参与业务逻辑校验

**与 warehouseLocationId 的区别**：
- `warehouseLocationId`: UUID，用于系统内部关联和查询
- `warehouseLocationCode`: 可读编码，用于人工识别和报表展示

---

### 6. currentLocation（当前位置描述）

| 属性         | 说明                                           |
| ------------ | ---------------------------------------------- |
| **业务含义** | 物料当前位置的文字描述，用于非标准库位场景     |
| **数据类型** | string（自由文本）                             |
| **是否必填** | 否                                             |
| **默认值**   | `null`                                         |
| **存储字段** | 暂不存储（接口接受但未在数据库表中定义此字段） |

**使用场景**：
- 物料临时存放在非标准库位时的位置说明（如"车间1号线"、"临时堆放区"）
- 补充描述库位的具体位置信息
- 用于人工记录和备注

**数据来源**：
- 可从 `storage_locations` 表的 `location_type_name` 字段获取（如"地面堆垛区"）
- 或根据业务需要自定义文本描述

**后端处理逻辑**：
- ⚠️ **注意**: 当前 `annealing_task_materials` 表定义中不包含此字段
- 该参数可能用于日志记录或未来扩展
- 建议确认是否需要此参数或修改表结构支持该字段

---

### 7. statusSnapshot（物料状态快照）

| 属性         | 说明                                       |
| ------------ | ------------------------------------------ |
| **业务含义** | 记录物料绑定时的状态，用于历史追溯         |
| **数据类型** | string（最大60字符）                       |
| **是否必填** | 否                                         |
| **默认值**   | `"pending-annealing"`                      |
| **存储字段** | `annealing_task_materials.status_snapshot` |

**数据来源**：
- **料框**: 查询料框详情接口 `GET /v1/inv/bins/:id`，获取 `status` 字段
- **料垛**: 查询料垛详情接口 `GET /v1/inv/stacks/:id`，获取 `status` 字段

**后端处理逻辑**：
```javascript
statusSnapshot: material.statusSnapshot || 'pending-annealing'
```
- 如果未传值，默认使用 `"pending-annealing"`
- 仅作为历史快照记录，不影响物料的实际状态
- 用于追溯"物料绑定时处于什么状态"

**料框可能的状态值**（中文）：
- `空闲`、`待入库退火`、`待退火`、`待备料`、`待装炉`
- `装炉中`、`退火中`、`待出炉`、`已退火`
- `待检验`、`已检验合格`、`已检验不合格`
- `待出库`、`已出库`

**料垛可能的状态值**（中文）：
- `活动中` - 料垛正常使用中
- `已拆垛` - 料垛已解除

**使用场景**：
- 分析退火任务绑定的物料状态分布
- 追溯异常：发现某些物料绑定时状态不符合预期
- 数据审计和质量管理

## 参数获取流程

### 获取料框物料参数

**接口**: `GET /v1/inv/bins/:id`

**响应示例**（关键字段）：
```json
{
  "success": true,
  "data": {
    "id": "554e4422-beac-48bd-a22b-43b38a3c212b",
    "binCode": "LK-20250110-0001",
    "productCode": "AF-1060-O-0.05X500",
    "batchNumber": "BATCH-2025-001",
    "weight": 250.5,                    // ← 单位kg
    "status": "待退火",                  // ← statusSnapshot
    "currentLocationId": "323e4567-...", // ← warehouseLocationId
    "currentLocation": {
      "id": "323e4567-...",
      "locationId": "DA-01-01-A",       // ← warehouseLocationCode
      "locationType": "ground_stacking",
      "locationTypeName": "地面堆垛区"
    }
  }
}
```

**参数映射**：
- `expectedWeight` = `weight` / 1000（kg转吨）
- `batchNumber` = `batchNumber`
- `warehouseLocationId` = `currentLocationId`
- `warehouseLocationCode` = `currentLocation.locationId`
- `statusSnapshot` = `status`

## 业务规则说明

### 1. 批次号混合规则

**组垛业务规则**（`src/models/inv/stack.model.js`）：
```javascript
batchNumber: {
  comment: '批次号，可选一致性要求，组垛时所有料框批次可相同也可不同'
}
```

**实际业务场景**：
- ✅ **允许**: 不同批次号的料框组成一个料垛
- ✅ **允许**: 料垛的批次号为 `null`（表示混合批次）
- ✅ **允许**: 料垛的批次号记录主要批次号

**绑定退火任务时**：
- 直接使用物料（料框/料垛）的 `batchNumber` 字段值
- 不需要特殊处理或校验
- 如果为 `null`，表示该物料包含混合批次

---

### 2. 重量单位转换

**系统中的重量单位**：
- **料框/料垛存储**: `weight` / `total_weight` 字段使用 **kg（千克）**
- **退火任务**: `actual_weight` / `expected_weight` 使用 **吨（t）**

**转换公式**：
```
吨 = 千克 / 1000
```

**示例**：
- 料框重量: `250.5 kg` → 绑定时传递: `0.2505 吨`
- 料垛重量: `1500.0 kg` → 绑定时传递: `1.5 吨`

---

### 3. 库位信息获取

**当前系统架构**：
```
物料（料框/料垛）
  └─ currentLocationId (UUID)
       └─ storage_locations（库位表）
            ├─ locationId (库位编码，如 DA-01-01-A)
            ├─ locationType (库位类型)
            └─ storageAreaId (所属库区ID)
                 └─ storage_areas（库区表）
```

**数据获取方式**：
1. 查询物料详情获取 `currentLocationId`（UUID）
2. 查询物料详情的关联对象 `currentLocation` 获取 `locationId`（编码）
3. `warehouseId` 当前暂不使用，传 `null` 即可

---

### 4. 可选参数的默认值处理

**后端代码逻辑**（`src/services/modules/prod/annealingTask/annealingTask.material.service.js`）：

```javascript
{
  batchNumber: material.batchNumber || null,
  expectedWeight: material.expectedWeight || null,
  loadSequence: material.loadSequence || null,
  isPrimary: material.isPrimary || false,
  warehouseId: material.warehouseId || null,
  warehouseLocationId: material.warehouseLocationId || null,
  warehouseLocationCode: material.warehouseLocationCode || null,
  statusSnapshot: material.statusSnapshot || 'pending-annealing',
  weightSource: material.weightSource || 'manual',
  remarks: material.remarks || null,

```

**默认值总结**：
| 参数                  | 默认值                |
| --------------------- | --------------------- |
| expectedWeight        | `null`                |
| batchNumber           | `null`                |
| warehouseId           | `null`                |
| warehouseLocationId   | `null`                |
| warehouseLocationCode | `null`                |
| statusSnapshot        | `"pending-annealing"` |

## 常见问题解答

### Q1: 如果料框的 `currentLocationId` 为空怎么办？

**A**: 传递 `null` 或不传该参数。后端会存储为 `null`，表示物料位置未知。

---

### Q2: 料垛的批次号为空，是否影响绑定？

**A**: 不影响。料垛允许混合批次，批次号为 `null` 是合法的业务场景。

---

### Q3: `expectedWeight` 和 `actualWeight` 有什么区别？

**A**:
- `actualWeight`: 实际称重值，**必填**，用于计算任务总重量
- `expectedWeight`: 预期重量，**可选**，用于对比分析重量偏差

---

### Q4: `warehouseId` 必须填写吗？

**A**: 不必须。当前系统暂未实现独立的仓库管理，该字段可传 `null` 或不传。

---

### Q5: `statusSnapshot` 应该传物料的实时状态还是固定值？

**A**: 建议传物料的**实时状态**（从物料详情接口获取），这样可以追溯绑定时刻的物料状态。如果不传，后端会使用默认值 `"pending-annealing"`。

---

### Q6: `weightSource` 支持自定义值吗？

**A**: 是的，后端不对该字段进行枚举校验。但建议使用文档推荐的值（`manual`、`scale`、`plc`、`system`、`estimated`），便于后期数据统计和分析。

---

### Q7: 如果对接了电子秤，应该如何传递重量来源？

**A**: 设置 `weightSource: "scale"`，表示重量来自电子秤自动采集，提高数据可信度。
