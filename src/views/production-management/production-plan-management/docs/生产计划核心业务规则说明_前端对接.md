# 生产计划核心业务规则 - 前端对接说明

> **更新日期**: 2025-01-XX | **版本**: v1.0

## 📋 三个核心问题

1. **子批次状态** - 是否需要提供状态变更功能？
2. **工艺模板** - 拆分/调整操作时是否必填？
3. **设备分配** - assignedEquipmentId 字段的作用？

---

## 问题1：子批次状态管理

### 结论

**子批次状态由系统自动管理，前端只负责展示，无需提供状态修改功能。**

### 状态流转

```
拆分创建 → READY_FOR_SCHEDULING (固定)
         ↓ (排程完成)
         SCHEDULED
         ↓ (任务开始)
         IN_PROGRESS
         ↓ (任务完成)
         COMPLETED
```

### 前端要做的

- ✅ 展示状态（只读）
- ✅ 状态图标/颜色区分
- ❌ 不需要状态编辑下拉框
- ❌ 不需要状态变更按钮
---

## 问题2：工艺模板配置

### 结论

**工艺模板在所有操作中都是可选参数，不填会自动继承主计划配置。**

### 自动继承规则

```
用户指定的工艺模板
  ↓ (未指定)
主计划的工艺模板
  ↓ (未指定)
产品的默认工艺模板
  ↓ (都没有)
null
```

### 各操作的必填性

| 操作     | 是否必填 | 不填时的行为     |
| -------- | -------- | ---------------- |
| 创建计划 | ⭕ 可选   | 从产品主数据获取 |
| 拆分计划 | ⭕ 可选   | 继承主计划配置   |
| 调整计划 | ⭕ 可选   | 保持原有配置     |
| 合并计划 | ⭕ 可选   | 使用目标计划配置 |

### 前端建议

- **常规场景**（95%）：不填工艺模板，使用默认继承
- **差异化场景**：为每个子批次单独指定不同工艺模板

---

## 问题3：设备分配字段

### 结论

**`assignedEquipmentId` 是可选的数据记录字段，目前不影响实际设备分配，真正的设备由排程系统决定。**

### 字段说明

| 层级     | 字段名                 | 含义             | 作用           |
| -------- | ---------------------- | ---------------- | -------------- |
| 主计划   | `preferredEquipmentId` | 首选设备（建议） | 数据记录       |
| 子批次   | `assignedEquipmentId`  | 分配设备（指定） | 数据记录       |
| 退火任务 | `assignedFurnaceId`    | 实际使用设备     | ✅ 排程系统分配 |

### 实际流程

```
拆分计划（可选填 assignedEquipmentId）
  ↓
生成退火任务（不使用该字段）
  ↓
排程系统自动分配 ⭐ （写入 assignedFurnaceId）
  ↓
任务执行（使用排程结果）
```

### 前端建议

- **UI 设计**： 默认不展示
- **使用建议**：95%场景不填，让排程系统自动分配
