## 功能概述

### 所有功能

提交生产计划审批（Submit Production Plan Approval）是生产计划管理模块中的关键操作接口，用于提交计划状态变更的审批请求，以支持计划发布和取消等重要操作的审批流程管理。该接口会创建审批请求并将计划状态转为待审批状态，确保关键操作经过授权审批后才能生效。

### 关键特性

- ✅ **状态变更审批**：支持提交发布(RELEASED)和取消(CANCELLED)两种状态变更的审批请求
- ✅ **自动状态转换**：提交审批后自动将计划状态转为待审批(PENDING_APPROVAL)状态
- ✅ **审批记录创建**：自动创建审批请求记录，包含完整的计划快照和审批信息
- ✅ **权限灵活控制**：支持指定审批所需的权限列表，实现精细化的审批权限管理
- ✅ **变更追踪记录**：完整记录审批提交的变更日志，包括操作人、目标状态等信息
- ✅ **事务安全保障**：所有操作在数据库事务中执行，确保数据一致性和可回滚性

---

### 使用前提

- ✅ **认证要求**：需要提供有效的 JWT Token 进行身份认证
- ✅ **权限要求**：用户必须具有 `prod.production-plan.manage` 权限
- ✅ **计划存在性**：请求的计划ID必须存在且未被删除
- ✅ **状态转移合法性**：目标状态必须是当前状态的有效后继状态
- ✅ **参数完整性**：必须提供有效的目标状态（RELEASED 或 CANCELLED）

### 不适用场景

- ❌ **不需审批的状态变更**：如需直接变更状态而不经过审批，应使用 `PATCH /v1/prod/plans/:planId/status` 接口
- ❌ **查询审批记录**：如需查询已提交的审批记录，应使用 `GET /v1/prod/plans/:planId/approval/requests` 接口
- ❌ **审批决策操作**：如需批准或驳回审批，应使用审批中心的相关接口
- ❌ **其他状态变更**：除发布和取消外的其他状态变更不需要通过此接口提交审批

### 详细步骤说明

#### 步骤1: 接收审批提交请求
- 接收客户端的 POST 请求，路径为 `/v1/prod/plans/:planId/approval/submit`
- 提取路径参数中的 `planId` 和请求体中的审批信息

#### 步骤2: JWT 认证和权限检查
- 验证请求中的 JWT Token 是否有效
- 从 Token 中提取用户信息（用户ID、用户名、权限列表等）
- 检查用户是否拥有 `prod.production-plan.manage` 权限

#### 步骤3: 请求参数验证
- 验证 planId 是否为有效的 UUID v4 格式
- 使用 Joi 验证规则验证请求体参数
- 确保目标状态在允许的值列表中（RELEASED 或 CANCELLED）
- 验证其他可选参数的格式和长度限制

#### 步骤4: 目标状态合法性检查
- 将目标状态转换为大写格式进行标准化处理
- 验证目标状态是否为 RELEASED 或 CANCELLED
- 如果是其他状态，返回错误提示只能提交这两种状态的审批

#### 步骤5: 开启数据库事务
- 创建一个数据库事务，确保后续所有操作的原子性
- 事务失败时进行回滚，成功时进行提交

#### 步骤6: 查询计划数据并加锁
- 根据 planId 查询生产计划主表记录
- 对查询结果加锁（FOR UPDATE），防止并发修改
- 如计划不存在，返回 404 错误

#### 步骤7: 状态转移合法性检查
- 获取计划当前状态
- 检查目标状态是否为当前状态的有效后继状态
- 参考状态转移规则表，如转移非法则抛出业务异常

#### 步骤8: 获取计划完整快照
- 查询计划的所有子计划项（包含锁定）
- 获取计划的变更日志历史
- 将所有信息格式化为完整的计划快照
- 快照将作为审批元数据保存，用于审批回调时的状态恢复

#### 步骤9: 构建审批请求载荷
- 设置资源类型为 PRODUCTION_PLAN
- 设置资源ID为计划ID
- 设置请求的动作为目标状态（RELEASED 或 CANCELLED）
- 设置请求人ID为当前操作用户
- 处理备注信息（取消操作时优先使用取消原因）
- 在元数据中保存计划快照、目标状态、前置状态等信息
- 设置审批所需的权限列表（如果提供）

#### 步骤10: 调用审批中心服务
- 调用 `approvalCenterService.submitApproval` 创建审批请求
- 传入构建好的审批载荷和操作上下文
- 使用当前事务确保审批记录与计划状态更新在同一事务中
- 获取创建的审批请求信息（包含审批ID、状态等）

#### 步骤11: 更新计划状态为待审批
- 构建状态更新载荷，将状态设为 PENDING_APPROVAL
- 更新操作人为当前用户
- 如果提供了备注，更新计划备注信息
- 执行计划主表的状态更新操作

#### 步骤12: 创建变更日志
- 记录"状态更新请求"类型的变更日志
- 记录原始计划快照和更新后的快照
- 在变更上下文中记录：
  - 原始状态和目标状态
  - 审批请求ID
  - 操作人信息（ID、姓名、IP地址）
  - 请求追踪ID
- 保存变更日志记录

#### 步骤13: 提交事务
- 所有操作成功后提交事务
- 确保计划状态、审批请求、变更日志同时生效
- 如任何步骤失败，自动回滚所有变更

#### 步骤14: 返回审批提交结果
- 重新查询更新后的计划数据（包含关联信息）
- 组装响应数据，包括：
  - 更新后的计划信息（状态为 PENDING_APPROVAL）
  - 审批请求信息（状态为 PENDING）
  - 目标状态和当前状态
  - 提示消息
- 返回 HTTP 200 OK 响应

## 接口文档

### 基本信息

**接口路径**: `POST /v1/prod/plans/:planId/approval/submit`

**功能描述**: 提交生产计划状态变更的审批请求，支持发布和取消两种操作的审批流程

**认证要求**: Bearer Token 认证，需要 `prod.production-plan.manage` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 路径参数

| 参数名 | 类型   | 必填 | 限制         | 描述             | 示例                                   |
| ------ | ------ | ---- | ------------ | ---------------- | -------------------------------------- |
| planId | string | 是   | UUID v4 格式 | 生产计划唯一标识 | "123e4567-e89b-12d3-a456-426614174000" |

### 请求参数

| 参数名              | 类型   | 必填 | 限制                        | 描述                   | 示例                   |
| ------------------- | ------ | ---- | --------------------------- | ---------------------- | ---------------------- |
| targetStatus        | string | 是   | RELEASED 或 CANCELLED       | 目标计划状态           | "RELEASED"             |
| remarks             | string | 否   | 最多500字符                 | 审批备注信息           | "计划已确认，申请发布" |
| requiredPermissions | array  | 否   | 字符串数组，单项最多100字符 | 审批所需的权限代码列表 | ["prod.plan.release"]  |

### 请求示例

#### cURL 命令

```bash
# 示例1: 提交发布审批
curl -X POST http://localhost:3000/v1/prod/plans/123e4567-e89b-12d3-a456-426614174000/approval/submit \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "targetStatus": "RELEASED",
    "remarks": "计划已评估确认，申请发布执行"
  }'

# 示例2: 提交取消审批（带权限要求）
curl -X POST http://localhost:3000/v1/prod/plans/123e4567-e89b-12d3-a456-426614174000/approval/submit \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "targetStatus": "CANCELLED",
    "remarks": "客户订单取消，申请取消生产计划",
    "requiredPermissions": ["prod.production-plan.cancel"]
  }'
```

#### JSON 请求体

```json
{
  "targetStatus": "RELEASED",
  "remarks": "计划已评估确认，申请发布执行",
  "requiredPermissions": ["prod.plan.release", "prod.plan.manage"]
}
```

### 错误响应

| HTTP状态码 | 错误码                                    | 错误消息           | 说明                                  | 处理建议               |
| ---------- | ----------------------------------------- | ------------------ | ------------------------------------- | ---------------------- |
| 400        | PRODUCTION_PLAN_STATUS_INVALID            | 目标计划状态不合法 | 提供的目标状态不是RELEASED或CANCELLED | 检查状态值是否正确     |
| 400        | PRODUCTION_PLAN_STATUS_TRANSITION_INVALID | 状态转移不合法     | 当前状态无法转移到目标状态            | 参考附录的状态转移规则 |
| 400        | REQUIRED_FIELD_MISSING                    | 缺少必需字段       | 缺少目标状态等必填参数                | 检查请求体是否完整     |
| 401        | UNAUTHORIZED                              | 未授权             | Token无效或已过期                     | 重新登录获取新Token    |
| 403        | FORBIDDEN                                 | 无权限             | 用户无权限执行该操作                  | 联系管理员授权         |
| 404        | PRODUCTION_PLAN_NOT_FOUND                 | 生产计划不存在     | 指定ID的计划不存在                    | 检查计划ID是否正确     |
| 500        | INTERNAL_ERROR                            | 服务器内部错误     | 系统异常                              | 联系技术支持           |
| 500        | PRODUCTION_PLAN_TRANSACTION_FAILED        | 事务处理失败       | 数据库操作失败                        | 稍后重试               |

## 常见问题

### Q1: 为什么只能提交发布和取消两种状态的审批？

**A**: 根据业务规则，只有发布(RELEASED)和取消(CANCELLED)这两种操作对生产计划影响重大，需要经过审批流程。其他状态变更可以通过 `PATCH /v1/prod/plans/:planId/status` 接口直接更新，无需审批。

### Q2: 提交审批后计划状态会变成什么？

**A**: 提交审批后，计划状态会自动转为 PENDING_APPROVAL（待审批）。审批通过后，系统会自动将状态更新为目标状态；审批驳回后，状态会恢复到提交审批前的状态。

### Q3: requiredPermissions 参数有什么作用？

**A**: `requiredPermissions` 用于指定审批人必须具备的权限列表。审批中心会根据这些权限筛选符合条件的审批人。如果不指定，则按照默认的审批流程分配审批人。

### Q4: 如果审批被驳回，计划状态会怎样？

**A**: 审批被驳回后，计划状态会自动恢复到提交审批前的状态（例如从 PENDING_APPROVAL 恢复到 CONFIRMED）。系统会记录完整的变更日志，包括驳回原因和审批人信息。

### Q5: 可以取消已提交的审批吗？

**A**: 可以。在审批尚未处理时，可以通过审批中心的撤销功能取消审批请求。撤销后，计划状态会恢复到提交审批前的状态。

### Q6: 审批通过后会自动更新状态吗？

**A**: 是的。审批通过后，系统会自动触发状态更新流程，将计划状态从 PENDING_APPROVAL 更新为目标状态（RELEASED 或 CANCELLED），并级联更新子计划项的状态，同步进度信息。

### Q7: 提交审批时的备注和审批人的审批意见有什么区别？

**A**: 提交审批时的备注（remarks）是请求人提供的申请理由，会显示在审批请求中。审批人的审批意见是审批人在处理审批时填写的，两者都会被记录在审批记录和变更日志中。

### Q8: 如何查看审批的处理进度？

**A**: 可以使用 `GET /v1/prod/plans/:planId/approval/requests` 接口查询该计划的所有审批记录，包括审批状态、审批人、处理时间等信息。也可以通过审批中心的接口获取更详细的审批流程信息。

## 附录

### 可提交审批的状态

本接口只支持以下两种目标状态的审批提交：

| 状态代码  | 中文名称 | 说明                     | 审批原因                   |
| --------- | -------- | ------------------------ | -------------------------- |
| RELEASED  | 已发布   | 计划已发布，可以开始执行 | 发布操作影响重大，需审批   |
| CANCELLED | 已取消   | 计划已取消，不再执行     | 取消操作不可逆，需审批确认 |

### 状态转移前提条件

提交审批前，计划的当前状态必须允许转移到目标状态。参考以下转移规则：

#### 可发布（RELEASED）的前置状态

- CONFIRMED（已确认）
- PARTIALLY_RELEASED（部分发布）
- PENDING_APPROVAL（待审批，审批驳回后）

#### 可取消（CANCELLED）的前置状态

- RECEIVED（已接收）
- CONFIRMED（已确认）
- PENDING_APPROVAL（待审批）
- PARTIALLY_RELEASED（部分发布）
- RELEASED（已发布）
- IN_PROGRESS（执行中）

**注意**: COMPLETED（已完成）和 CANCELLED（已取消）状态是终态，无法再转移到其他状态。

### 审批状态说明

| 审批状态  | 中文名称 | 说明                   |
| --------- | -------- | ---------------------- |
| PENDING   | 待审批   | 审批请求已创建，待处理 |
| APPROVED  | 已批准   | 审批已通过             |
| REJECTED  | 已驳回   | 审批被驳回             |
| CANCELLED | 已取消   | 审批请求已撤销         |
| EXPIRED   | 已过期   | 审批请求已过期         |

### 审批流程说明

```
提交审批
   │
   ▼
创建审批请求
(状态: PENDING)
   │
   ▼
计划状态 → PENDING_APPROVAL
   │
   ├──→ 审批通过 ────→ 计划状态 → 目标状态 (RELEASED/CANCELLED)
   │
   ├──→ 审批驳回 ────→ 计划状态 → 恢复到提交前状态
   │
   └──→ 审批撤销 ────→ 计划状态 → 恢复到提交前状态
```

### 审批元数据说明

审批请求的 metadata 字段包含以下重要信息：

| 字段名         | 说明                       | 用途                   |
| -------------- | -------------------------- | ---------------------- |
| planSnapshot   | 计划快照                   | 审批驳回时恢复状态使用 |
| targetStatus   | 目标状态                   | 记录请求的目标状态     |
| previousStatus | 前置状态                   | 审批驳回时恢复到此状态 |
| cancelReason   | 取消原因（仅取消操作时有） | 记录取消的具体原因     |

这些元数据确保审批流程的完整性和可追溯性。
