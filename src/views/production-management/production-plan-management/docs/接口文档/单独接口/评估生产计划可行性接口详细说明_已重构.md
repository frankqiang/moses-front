## 功能概述

### 所有功能

评估生产计划可行性（Production Plan Feasibility Evaluation）是生产计划管理模块中的核心分析功能之一，用于根据设备负荷率、炉次容量、工艺时长等关键生产参数，自动计算生产计划的执行可行性，以支持生产排程决策、产能预测和交期评估的业务场景。该功能通过智能算法评估计划的执行风险，为管理人员提供科学的生产决策依据。

### 关键特性

- ✅ **智能可行性分析**：基于工艺模板、设备容量和负荷率，自动计算所需炉次数、预计工时和完成时间
- ✅ **交期风险预警**：对比计划交期与预计完成时间，提前识别交期延误风险
- ✅ **产能充足性评估**：评估当前产能配置是否满足计划重量需求，识别产能不足风险
- ✅ **详细排程计划**：生成包含每个炉次开始/结束时间、重量分配的详细排程表
- ✅ **灵活参数配置**：支持自定义设备负荷率、炉次容量、班次时长等关键参数
- ✅ **完整风险提示**：提供多维度风险分析和优化建议，辅助决策

---

### 使用前提

- ✅ **计划状态要求**：生产计划必须存在于系统中，且包含有效的子计划项（ProductionPlanItem）
- ✅ **权限要求**：需要 `prod.production-plan.view` 权限
- ✅ **工艺模板要求**：计划必须关联有效的工艺模板，且模板包含温度段时长配置
- ✅ **数据完整性要求**：计划必须包含有效的重量数据（plannedWeight > 0）

### 不适用场景

- ❌ **未关联工艺模板的计划**：无法获取工艺时长参数，无法进行可行性评估
- ❌ **缺少子计划项的计划**：无法获取分批重量数据，无法进行排程计算
- ❌ **工艺模板配置不完整**：温度段时长缺失或为0，无法计算工艺周期时间

### 详细步骤说明

#### 步骤1: 接收评估请求
- 从路径参数中提取生产计划ID（planId）
- 从查询参数中提取可选的评估参数：
  - `loadRate`：设备负荷率（默认1.0）
  - `furnaceCapacity`：炉次容量（默认40吨）
  - `shiftDurationHours`：班次时长（默认8小时）
- 提取操作上下文信息（操作人、IP、请求ID）

#### 步骤2: 查询生产计划
- 通过 `ProductionPlan.findByPk()` 查询计划主记录
- 预加载子计划项（ProductionPlanItem），按sequence排序
- 如果主查询未加载items，则单独查询子计划项列表

#### 步骤3: 数据有效性校验
- **计划存在性校验**：
  - 如果计划不存在，抛出404错误（PRODUCTION_PLAN_NOT_FOUND）
- **子计划项校验**：
  - 如果没有子计划项，抛出400错误："生产计划缺少可用于评估的子计划"
- **重量数据校验**：
  - 计算所有子计划项的总重量
  - 如果总重量≤0，抛出400错误："生产计划缺少有效重量，无法评估"

#### 步骤4: 获取工艺模板
- **解析模板ID**：
  - 调用 `resolvePlanTemplateId(plan, items)` 从计划或子计划项中解析工艺模板ID
  - 如果未找到模板ID，抛出400错误（PRODUCTION_PLAN_PROCESS_TEMPLATE_INVALID）
- **验证模板有效性**：
  - 调用 `ensureProcessTemplateValid(templateId)` 验证模板状态
  - 获取模板的最新版本（version）
- **计算工艺时长**：
  - 调用 `sumSegmentDurationMinutes(version)` 累加所有温度段时长
  - 如果总时长≤0，抛出400错误："工艺模板缺少有效温度段时长，无法评估"

#### 步骤5: 参数标准化处理
使用 `parsePositiveNumberOrDefault()` 函数标准化参数：
- **furnaceCapacity**：炉次容量（吨），默认40吨
- **loadRate**：设备负荷率，默认1.0
- **shiftDurationHours**：班次时长（小时），默认8小时

#### 步骤6: 可行性计算
执行核心可行性计算：
- **工艺周期时间**：`cycleTimeHours = totalSegmentMinutes / 60`
- **单炉容量**：`capacityPerBatch = furnaceCapacity * loadRate`
- **所需炉次数**：`estimatedBatchCount = Math.ceil(totalPlannedWeight / capacityPerBatch)`
- **单炉日历小时**：`calendarHoursPerBatch = (cycleTimeHours / shiftDurationHours) * 24`
- **总日历小时**：`totalCalendarHours = estimatedBatchCount * calendarHoursPerBatch`

#### 步骤7: 生成排程表
调用 `buildFeasibilitySchedule()` 生成详细排程：
- 遍历每个炉次（1 到 estimatedBatchCount）
- 为每个炉次分配：
  - **开始时间**：基于上一炉次结束时间
  - **结束时间**：开始时间 + 单炉日历小时
  - **计划重量**：min(单炉容量, 剩余重量)
  - **容量利用率**：(实际重量 / 单炉容量) * 100%
- 返回完整的炉次排程数组

#### 步骤8: 风险评估
调用 `evaluateFeasibilityRisk()` 进行多维度风险分析：

**交期风险检测**：
- 如果预计完成时间 > 计划交期
- 添加风险提示：`delivery-delay`

**产能充足性检测**：
- 如果总重量 > (单炉容量 * 炉次数)
- 添加风险提示：`capacity-insufficient`

**配置有效性检测**：
- 如果单炉日历小时 ≤ 0
- 添加风险提示：`invalid-cycle-time`

#### 步骤9: 记录评估日志
- 如果存在风险（warnings.length > 0）：
  - 使用 `logger.warn()` 记录警告日志
  - 调用 `createChangeLog()` 创建变更日志：
    - 类型：PROGRESS_SYNC
    - 描述：计划可行性评估预警
    - 内容：风险列表和评估参数
- 如果无风险：
  - 使用 `logger.info()` 记录信息日志

#### 步骤10: 返回评估结果
调用 `buildFeasibilityResult()` 构建完整响应：
- 基础计划信息（planId、planNumber、productCode等）
- 需求和重量数据（demandQuantity、totalPlannedWeight）
- 评估计算结果（炉次数、工时、排程等）
- 风险提示和优化建议
- 使用 `roundTo()` 进行数值精度处理

## 接口文档

### 基本信息

**接口路径**: `GET /v1/prod/plans/:planId/feasibility`

**功能描述**: 根据设备负荷率、炉次容量、工艺时长等因素，评估生产计划的可行性，计算所需炉次数、预计工时、是否可按期交付等关键指标，为生产排程和决策提供数据支持。

**认证要求**: JWT Bearer Token，需要 `prod.production-plan.view` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 路径参数

| 参数名 | 类型   | 必填 | 限制              | 描述       | 示例                                   |
| ------ | ------ | ---- | ----------------- | ---------- | -------------------------------------- |
| planId | string | 是   | UUID v4格式字符串 | 生产计划ID | "7f3c6d8e-9a2b-4f1c-8e5d-6a9b0c1d2e3f" |

### 查询参数

| 参数名             | 类型   | 必填 | 限制                         | 描述                                   | 默认值 | 示例 |
| ------------------ | ------ | ---- | ---------------------------- | -------------------------------------- | ------ | ---- |
| loadRate           | number | 否   | 0-1.5之间的正数，最多3位小数 | 设备负荷率，影响单炉实际装载容量       | 1.0    | 1.2  |
| furnaceCapacity    | number | 否   | 正数，最多3位小数            | 炉次容量（吨），单炉次最大装载重量     | 40.0   | 45.0 |
| shiftDurationHours | number | 否   | 正数，最多2位小数            | 班次时长（小时），用于计算日历时间转换 | 8.0    | 10.0 |

**参数说明**：

- **loadRate（负荷率）**：
  - 范围：0.1-1.5
  - 表示设备的实际装载率
  - 1.0表示满负荷，1.2表示超负荷20%
  - 实际单炉容量 = furnaceCapacity × loadRate

- **furnaceCapacity（炉次容量）**：
  - 单位：吨
  - 表示单个炉次的标准装载容量
  - 默认40吨（基于实际生产设备配置）

- **shiftDurationHours（班次时长）**：
  - 单位：小时
  - 用于将工艺时长转换为日历时间
  - 默认8小时（标准工作班次）

## 常见问题

### Q1: 为什么评估结果显示"交期延误风险"？

**原因**：
- 基于当前参数计算的预计完成时间晚于计划交期
- 可能是因为：
  1. 计划重量过大，超出当前产能
  2. 工艺周期时间较长
  3. 设备负荷率设置保守

**解决方案**：
1. **提高负荷率**：适当提高loadRate参数（如从1.0提高到1.2）
2. **使用大容量设备**：增加furnaceCapacity参数
3. **延长班次时长**：增加shiftDurationHours参数
4. **拆分计划**：将大计划拆分为多个小计划并行生产
5. **调整交期**：与客户协商延长交期

### Q2: 为什么会出现"产能不足"警告？

**原因**：
- 计划总重量 > (单炉容量 × 炉次数)
- 说明即使所有炉次满载，也无法完成计划重量

**典型场景**：
```
计划总重量：1000吨
单炉容量：40吨 × 1.0（负荷率）= 40吨
预估炉次数：25炉次
总容量：25 × 40 = 1000吨
```

如果最后一炉未满载，可能导致容量不足。

**解决方案**：
1. 提高负荷率（loadRate > 1.0）
2. 使用更大容量设备
3. 增加炉次数（调整子计划项配置）

### Q3: 评估参数应该如何选择？

**参数选择指南**：

**loadRate（负荷率）**：
- **0.8-0.9**：保守设置，适用于高质量要求产品
- **1.0**：标准设置，常规生产场景
- **1.1-1.2**：积极设置，紧急订单或产能优化
- **1.3-1.5**：极限设置，短期应急使用

**furnaceCapacity（炉次容量）**：
- 根据实际设备容量设置
- 常见值：30吨、40吨、50吨
- 建议与设备管理模块中的设备容量保持一致

**shiftDurationHours（班次时长）**：
- **8小时**：标准单班制
- **10-12小时**：延长班制
- **16小时**：双班制
- **24小时**：三班倒连续生产

### Q4: 为什么排程表中最后一炉的容量利用率很低？

**原因**：
- 计划总重量无法被单炉容量整除
- 最后一炉装载剩余重量

**示例**：
```
计划总重量：980吨
单炉容量：40吨
前24炉：24 × 40 = 960吨
最后一炉：980 - 960 = 20吨
容量利用率：20 / 40 = 50%
```

**优化建议**：
1. **调整计划重量**：使总重量更接近单炉容量的整数倍
2. **合并计划**：将多个小计划合并，提高整体利用率
3. **混合装载**：在最后一炉中混合装载其他计划的产品

### Q5: 评估结果中的时间是基于什么计算的？

**时间计算逻辑**：

1. **工艺周期时间**（cycleTimeHours）：
   - 来源：工艺模板的所有温度段时长之和
   - 单位：小时
   - 示例：如果温度段总时长750分钟，则工艺周期时间 = 750 / 60 = 12.5小时

2. **单炉日历小时**（calendarHoursPerBatch）：
   - 公式：(工艺周期时间 / 班次时长) × 24
   - 示例：(12.5 / 8) × 24 = 37.5小时
   - 含义：考虑班次安排后，单炉占用的日历时间

3. **总日历小时**（totalCalendarHours）：
   - 公式：炉次数 × 单炉日历小时
   - 示例：25 × 37.5 = 937.5小时 ≈ 39天

4. **排程时间**：
   - 第一炉从评估时刻开始
   - 每炉结束时间 = 开始时间 + 单炉日历小时
   - 连续排程，无间隔时间

### Q6: 如何理解"warnings"中的风险提示？

**风险类型说明**：

**1. delivery-delay（交期延误）**：
```json
{
  "type": "delivery-delay",
  "message": "预计完成时间晚于计划交期，存在交期风险",
  "expectedCompletion": "2025-01-15T00:00:00.000Z",
  "plannedDeliveryDate": "2024-12-31T23:59:59.000Z"
}
```
- **含义**：预计完成时间 > 计划交期
- **影响**：可能无法按时交付
- **处理**：优化参数或调整交期

**2. capacity-insufficient（产能不足）**：
```json
{
  "type": "capacity-insufficient",
  "message": "基于当前装载率估算的总容量不足以完成计划重量",
  "totalWeight": 1000.0,
  "estimatedCapacity": 960.0
}
```
- **含义**：总产能 < 计划重量
- **影响**：无法完成全部计划
- **处理**：提高负荷率或增加炉次

**3. invalid-cycle-time（配置无效）**：
```json
{
  "type": "invalid-cycle-time",
  "message": "评估周期时长配置无效，请检查工艺模板段设置"
}
```
- **含义**：工艺模板配置错误
- **影响**：无法准确评估
- **处理**：检查并修复工艺模板

### Q7: 评估功能会修改生产计划数据吗？

**答案**：不会修改核心业务数据，但会记录评估日志

**具体行为**：
- ✅ **不修改**：计划状态、重量、交期等业务数据
- ✅ **不修改**：子计划项配置
- ✅ **不修改**：工艺模板数据
- ⚠️ **会记录**：如果存在风险，会创建变更日志（PROGRESS_SYNC类型）
- ⚠️ **会记录**：评估操作的INFO或WARN级别日志

### 核心计算公式

#### 1. 单炉实际容量
```
capacityPerBatch = furnaceCapacity × loadRate
```

#### 2. 所需炉次数
```
estimatedBatchCount = Math.ceil(totalPlannedWeight / capacityPerBatch)
```

#### 3. 工艺周期时间
```
cycleTimeHours = sumOfAllSegmentDurations(minutes) / 60
```

#### 4. 单炉日历小时
```
calendarHoursPerBatch = (cycleTimeHours / shiftDurationHours) × HOURS_PER_DAY
```

#### 5. 总日历小时
```
totalCalendarHours = estimatedBatchCount × calendarHoursPerBatch
```

#### 6. 容量利用率
```
utilizationRate = (actualWeight / capacityPerBatch) × 100%
```
