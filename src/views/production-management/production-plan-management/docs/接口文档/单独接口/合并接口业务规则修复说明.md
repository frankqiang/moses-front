# 合并生产计划接口业务规则修复说明

## 修复日期
2025-10-20

## 问题描述

### 原始问题
用户在使用合并生产计划接口时遇到以下情况：
- 计划已有两个批次
- 用户尝试将其中一个批次"合并"到该计划自己
- 系统返回数据库错误：`FOR UPDATE 不能用于外连接中的空值一边`

### 发现的两个问题

#### 问题1：PostgreSQL 数据库锁定错误（技术问题）
**错误原因**：查询源计划时同时使用了外连接（LEFT JOIN）和行锁（FOR UPDATE），PostgreSQL 不允许这种组合

**修复方案**：优化查询逻辑，移除外连接，只锁定主表

**修复文件**：`src/services/modules/prod/productionPlan/productionPlan.operation.service.js`

#### 问题2：业务逻辑漏洞（更重要）
**问题本质**：原代码允许"自己合并自己"的无效操作

**业务规则澄清**：
- ❌ **错误理解**：可以将计划A的批次合并到计划A自己
- ✅ **正确理解**：必须将其他计划的批次合并到目标计划

**修复方案**：增加校验，要求至少有一个来自其他计划的批次

**修复文件**：`src/services/modules/prod/productionPlan/productionPlan.operation.service.js`

## 修复内容总览

### 1. 技术修复：数据库锁定问题
- 移除了查询中的外连接关联
- 保留主表的行锁以确保事务安全
- 源计划在后续 UPDATE 时自动锁定

### 2. 业务逻辑修复：防止自合并
- 新增批次来源校验：必须至少有一个来自其他计划的批次
- 如果所有批次都属于目标计划自己，返回明确的业务错误
- 错误信息：`合并操作必须选择其他计划的批次，不能将计划自己的批次合并到自己`

### 3. 测试用例补充
- 新增单元测试验证"自合并"操作会被正确拒绝
- 测试结果：✅ 全部通过

### 4. 文档更新
更新了接口文档 `合并生产计划接口详细说明_已重构.md`，包括：
- 关键特性：新增"防止自合并"说明
- 使用前提：强调必须选择其他计划的批次
- 不适用场景：明确不允许自合并
- 错误响应：新增自合并错误示例
