## 功能概述

### 所有功能

更新生产计划状态（Update Production Plan Status）是生产计划管理模块中的核心操作接口，用于改变生产计划的执行状态，以支持计划生命周期管理、审批流程、状态转移和进度同步的业务场景。该接口支持直接状态转移和审批流程两种模式，并自动处理子计划级联更新和进度同步。

### 关键特性

- ✅ **灵活的状态转移**：支持8种计划状态之间的有效转移，按照业务规则验证状态转移合法性
- ✅ **审批流程支持**：对发布和取消操作需要审批，确保重要操作的可控性和可追溯性
- ✅ **级联状态更新**：更新计划状态时自动级联更新所有子计划项的相应状态
- ✅ **进度自动同步**：状态变更后自动重新计算并同步计划进度百分比
- ✅ **权限精细化控制**：取消操作需要特定权限 `prod.production-plan.cancel`，确保操作安全
- ✅ **完整变更追踪**：所有状态变更都记录详细的变更日志，包括操作人、操作时间、变更原因等

---

### 使用前提

- ✅ **认证要求**：需要提供有效的 JWT Token 进行身份认证
- ✅ **权限要求**：用户必须具有 `prod.production-plan.cancel` 权限（针对取消操作）
- ✅ **计划存在性**：请求的计划ID必须存在且未被删除
- ✅ **状态转移合法性**：目标状态必须是当前状态的有效后继状态
- ✅ **参数完整性**：必须提供有效的目标状态

### 不适用场景

- ❌ **批量状态更新**：如需批量更新多个计划的状态，应使用批量操作接口
- ❌ **查询状态转移规则**：如需了解状态转移规则，应查阅系统文档或使用查询接口
- ❌ **获取历史状态变更**：如需查询计划的历史状态变更，应使用 `GET /v1/prod/plans/:planId/audit-logs` 接口
- ❌ **仅更新备注信息**：如只需更新计划备注而不改变状态，应使用 `PATCH /v1/prod/plans/:planId` 接口

### 详细步骤说明

#### 步骤1: 接收状态更新请求
- 接收客户端的 PATCH 请求，路径为 `/v1/prod/plans/:planId/status`
- 提取路径参数中的 `planId` 和请求体中的状态信息

#### 步骤2: JWT 认证和权限检查
- 验证请求中的 JWT Token 是否有效
- 从 Token 中提取用户信息（用户ID、权限列表等）
- 如目标状态为 CANCELLED，检查用户是否拥有 `prod.production-plan.cancel` 权限

#### 步骤3: 请求参数验证
- 验证 planId 是否为有效的 UUID v4 格式
- 使用 Joi 验证规则验证请求体参数的完整性和格式正确性
- 确保必填字段（targetStatus）存在且非空

#### 步骤4: 目标状态合法性验证
- 将目标状态转换为大写格式进行标准化处理
- 检查目标状态是否在允许的状态值列表中
- 对取消操作进行额外的权限检查

#### 步骤5: 开启数据库事务
- 创建一个数据库事务，确保后续所有操作的原子性
- 事务失败时进行回滚，成功时进行提交

#### 步骤6: 查询计划数据并加锁
- 根据 planId 查询生产计划主表记录
- 对查询结果加锁（FOR UPDATE），支持并发控制
- 如计划不存在，返回 404 错误

#### 步骤7: 状态转移合法性检查
- 获取计划当前状态
- 检查目标状态是否为当前状态的有效后继状态
- 如转移非法，抛出业务异常

#### 步骤8: 判断是否需要审批流程
- 检查目标状态是否在需审批状态列表中（RELEASED, CANCELLED）
- 检查审批上下文是否标记为已批准
- 根据条件分支进入不同的处理流程

#### 步骤8a: 审批流程（当需要审批且未批准）
- 获取计划快照作为原始数据
- 构建审批请求，包括资源信息、操作人、备注等
- 调用审批服务创建审批请求
- 将计划状态转为 PENDING_APPROVAL（待审批）
- 记录"状态更新请求"变更日志

#### 步骤8b: 直接更新流程（无需审批或已批准）
- 构建状态更新载荷，包括新状态、时间戳等信息
- 根据取消原因或备注信息补充载荷内容
- 更新计划主表中的状态字段
- 继续执行步骤9

#### 步骤9: 级联更新子计划项状态
- 查询该计划下所有子计划项
- 为每个子项确定对应的目标状态（根据计划状态转移规则）
- 验证子项从当前状态到目标状态的转移合法性
- 批量更新所有子项状态（并行操作）

#### 步骤10: 同步计划执行进度
- 获取所有子计划项的最新状态
- 根据子项的完成度、权重等参数计算计划总体进度百分比
- 更新计划的进度百分比字段

#### 步骤11: 创建变更日志
- 记录"状态更新"变更日志，包括：
  - 原始状态和新状态
  - 操作人信息（用户ID、用户名、IP地址）
  - 子项更新详情
  - 进度同步信息
  - 请求ID用于追踪

#### 步骤12: 提交事务
- 所有操作成功后提交事务，确保数据一致性
- 如任何步骤失败，自动回滚所有变更

#### 步骤13: 返回更新结果
- 重新查询更新后的计划数据
- 组装响应数据，包括更新后的计划信息、进度信息、子项更新列表等
- 返回 HTTP 200 OK 响应

## 接口文档

### 基本信息

**接口路径**: `PATCH /v1/prod/plans/:planId/status`

**功能描述**: 更新生产计划的执行状态，支持直接状态转移和审批流程两种模式，自动处理子计划级联更新和进度同步

**认证要求**: Bearer Token 认证，取消操作需要 `prod.production-plan.cancel` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 路径参数

| 参数名 | 类型   | 必填 | 限制         | 描述             | 示例                                   |
| ------ | ------ | ---- | ------------ | ---------------- | -------------------------------------- |
| planId | string | 是   | UUID v4 格式 | 生产计划唯一标识 | "123e4567-e89b-12d3-a456-426614174000" |

### 请求参数

| 参数名            | 类型   | 必填 | 限制                                                      | 描述                     | 示例                       |
| ----------------- | ------ | ---- | --------------------------------------------------------- | ------------------------ | -------------------------- |
| targetStatus      | string | 是   | 有效的计划状态值（不允许 `PENDING_APPROVAL`，由系统设置） | 目标计划状态             | "RELEASED"                 |
| approvalContext   | object | 否   | 审批上下文对象                                            | 审批批准信息             | 见下方结构说明             |
| changeDescription | string | 否   | 最多500字符                                               | 变更的描述信息           | "根据客户需求调整计划状态" |
| cancelReason      | string | 否   | 最多200字符                                               | 取消原因（仅取消时需要） | "客户订单取消"             |
| remarks           | string | 否   | 最多500字符                                               | 备注信息                 | "已与客户沟通确认"         |

> ⚠️ **重要说明**：`targetStatus` 不允许传递 `PENDING_APPROVAL`，该状态是系统内部状态，只能由审批流程自动设置。如果传递会返回 `400 Bad Request` 错误，提示"目标状态不合法，PENDING_APPROVAL 状态由系统自动设置，不允许用户直接请求"。

### approvalContext 结构

| 参数名          | 类型    | 必填 | 描述               | 示例       |
| --------------- | ------- | ---- | ------------------ | ---------- |
| approved        | boolean | 否   | 审批状态（已批准） | true       |
| approvalUserId  | string  | 否   | 审批人用户ID       | UUID       |
| approvalRemarks | string  | 否   | 审批人的审批意见   | "批准通过" |

### 请求示例

#### cURL 命令

```bash
# 示例1: 发布计划（需要审批）
curl -X PATCH http://localhost:3000/v1/prod/plans/123e4567-e89b-12d3-a456-426614174000/status \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "targetStatus": "RELEASED",
    "remarks": "计划已确认，现在发布执行"
  }'

# 示例2: 取消计划（需要审批和权限）

  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "targetStatus": "CANCELLED",
    "cancelReason": "客户订单取消",
    "remarks": "已与客户确认"
  }'

# 示例3: 直接状态转移（不需要审批）
curl -X PATCH http://localhost:3000/v1/prod/plans/123e4567-e89b-12d3-a456-426614174000/status \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "targetStatus": "CONFIRMED"
  }'
```

## 常见问题

### Q1: 为什么不能直接传递 `targetStatus: "PENDING_APPROVAL"`？（🆕 新增）

**A**: `PENDING_APPROVAL`（待审批）是系统内部状态，只能由审批流程自动设置，用户不允许直接请求该状态。这是为了保证审批流程的完整性和安全性。

**正确做法**：
- ✅ 想要发布计划：传递 `targetStatus: "RELEASED"`，系统会自动进入审批流程并设置为 `PENDING_APPROVAL`
- ✅ 想要取消计划：传递 `targetStatus: "CANCELLED"`，系统会自动进入审批流程并设置为 `PENDING_APPROVAL`
- ✅ 或者使用专门的审批提交接口：`POST /v1/prod/plans/:planId/approval/submit`

**错误做法**：
- ❌ 直接传递 `targetStatus: "PENDING_APPROVAL"` 会返回 `400 Bad Request` 错误

### Q2: 状态转移时发生了"状态转移不合法"错误，如何解决？

**A**: 这通常是因为您尝试转移到的状态不是当前状态的有效后继状态。请参考附录中的"状态转移规则"表，确认所需的目标状态是否为合法的转移目标。如确实需要该转移，考虑通过中间状态进行多步转移。

### Q3: 为什么发布和取消操作需要审批流程？

**A**: 发布和取消是计划生命周期中的重要操作，需要经过授权人审核后才能生效。这样设计是为了确保操作的可控性、可追溯性和组织的管理合规。审批流程由审批中心模块管理。

### Q4: 级联更新是什么意思？

**A**: 当计划状态发生变更时，系统会自动根据对应的转移规则更新该计划下所有子计划项的状态。例如，计划从 CONFIRMED 转为 RELEASED 时，状态下的子项会从 DRAFT 转为 READY_FOR_SCHEDULING。

### Q5: 为什么需要提供 cancelReason（取消原因）？

**A**: 取消原因用于记录计划取消的业务理由，这对于后续的问题追踪、数据分析和审计非常重要。系统会将该信息保存到变更日志中。

### Q6: 如何查看状态变更的历史记录？

**A**: 您可以使用 `GET /v1/prod/plans/:planId/audit-logs` 接口查询计划的所有变更历史记录，包括状态变更、操作人、操作时间等信息。

### Q7: 进度百分比是如何计算的？

**A**: 进度百分比基于子计划项的完成情况计算。系统会统计已完成的子项权重占总权重的比例。计划状态变更时会自动重新计算并更新该值。

### Q8: 并发情况下是否会出现数据不一致？

**A**: 不会。系统使用数据库事务和行级锁确保并发操作的安全性。每个状态更新操作都在事务内进行，如果操作失败会自动回滚所有变更。

### Q9: 是否可以跳过中间状态直接转移？

**A**: 不可以。系统严格按照定义的状态转移规则进行转移。每个状态只能转移到指定的后继状态。如需进行多步转移，请分别调用本接口多次。

### 生产计划状态清单

> **⚠️ 状态转换规则已更新**：为确保业务流程合理性，状态转换规则已收紧，不再允许不合理的回退和跳跃操作。

| 状态代码           | 中文名称 | 说明                             | 可转移到的状态                          | 变更说明                                   |
| ------------------ | -------- | -------------------------------- | --------------------------------------- | ------------------------------------------ |

| PARTIALLY_RELEASED | 部分发布 | 计划仅部分发布，其余待继续发布   | RELEASED, IN_PROGRESS, PENDING_APPROVAL | ❌ 移除：不可直接 CANCELLED                 |

**关键变更总结**：
- ✅ **更严格的审批控制**：已发布和执行中的计划取消必须通过审批流程，不能直接取消
- ✅ **禁止不合理回退**：待审批状态不能回退到已接收状态
- ✅ **强制审批流程**：确认后的计划要发布或取消必须通过审批，不能直接操作
- ✅ **保护业务流程**：每个状态转换都必须符合业务逻辑，防止跳跃式转换
