## 功能概述

### 所有功能

获取生产计划进度报表（Production Plan Progress Report）是生产计划管理模块中的核心查询接口之一，用于获取生产计划的执行进度统计数据，支持多维度筛选和多种导出格式，以满足生产进度监控、数据分析和报表导出的业务场景。

该接口提供了完整的生产计划进度快照，包括计划整体的完成百分比以及计划项的详细状态分布，帮助管理者实时掌握生产执行情况。

### 关键特性

- ✅ **多维度筛选**：支持按来源、状态、优先级、产品编码、计划编号、外部订单号、交期范围、创建时间范围等多种条件组合查询
- ✅ **实时进度计算**：自动计算计划的当前完成百分比，基于计划项的重量加权平均，排除已取消项
- ✅ **进度明细分解**：提供计划项的详细状态统计，包括总数、已完成、执行中、活动中、已取消等维度
- ✅ **多格式导出**：支持 JSON 和 CSV 两种数据格式，满足在线查看和数据导出的不同需求
- ✅ **灵活分页**：支持自定义分页大小（1-5000条）和偏移量，优化大数据量查询性能
- ✅ **自定义排序**：支持多字段组合排序，默认按计划交期升序和创建时间降序排列

---

### 使用前提

- ✅ **权限要求**：用户必须具有 `prod.production-plan.view` 权限
- ✅ **认证要求**：需要有效的 JWT 访问令牌
- ✅ **数据要求**：系统中存在生产计划数据（计划可处于任何状态）
- ✅ **格式要求**：CSV 导出时建议指定 fileName 参数以便识别文件

### 不适用场景

- ❌ **实时进度更新**：此接口为查询接口，不会触发进度的重新计算或同步，如需更新进度请使用进度同步接口
- ❌ **详细工序进度**：仅提供计划项级别的状态统计，不包含具体工序的执行明细，工序详情请查询计划详情接口
- ❌ **历史进度趋势**：仅返回当前时刻的进度快照，不包含历史进度变化趋势数据

### 详细步骤说明

#### 步骤1: 接收查询请求
- 从 query 参数中提取筛选条件（source、status、planPriority 等）
- 获取分页参数（offset、limit）
- 确定导出格式（format: json/csv）
- 接收自定义排序规则（sortBy）

#### 步骤2: 参数验证
- 使用 Joi 验证器校验所有查询参数
- 验证日期范围合法性（结束时间必须晚于开始时间）
- 限制分页大小（1-5000条）
- 验证格式参数有效性（json/csv）

#### 步骤3: 权限校验
- 验证 JWT Token 有效性
- 检查用户是否具有 `prod.production-plan.view` 权限
- 权限不足时返回 403 错误

#### 步骤4: 构建查询条件
- 将筛选参数转换为 Sequelize WHERE 条件
- 解析排序规则字符串（格式：`field:asc,field2:desc`）
- 处理分页参数（offset、limit）
- 设置默认排序：计划交期升序 + 创建时间降序

#### 步骤5: 查询计划数据
- 执行 `findAndCountAll` 查询
- 自动关联 `ProductionPlanItem`（计划项）
- 应用所有筛选条件和排序规则
- 返回符合条件的计划数据和总数

#### 步骤6: 计算进度快照
- **状态统计**：遍历计划项，按状态分类计数和汇总重量
- **活动项识别**：排除已取消项，计算活动项数量和重量
- **进度计算**：完成重量 / 活动重量 × 100%
- **特殊处理**：全部取消时进度为100%，无活动项时进度为0%
- **精度控制**：进度百分比保留2位小数，重量保留3位小数

#### 步骤7: 格式化输出
- **JSON 格式**：
  - 返回结构化数据，包含 columns（列定义）和 rows（数据行）
  - 每行包含：planNumber、status、plannedDeliveryDate、currentProgressPercentage、进度明细
- **CSV 格式**：
  - 转换为 CSV 文本内容
  - 设置响应头（Content-Type、Content-Disposition）
  - 使用自定义文件名或默认时间戳命名

#### 步骤8: 返回结果
- **JSON 响应**：使用 `sendSuccess` 统一响应格式，包含 data 和 meta
- **CSV 下载**：直接发送 CSV 文本，触发浏览器下载
- 记录操作日志（操作人、请求ID）

## 接口文档

### 基本信息

**接口路径**: `GET /v1/prod/plans/progress-report`

**功能描述**: 获取生产计划进度报表，支持多维度筛选和JSON/CSV格式导出，用于生产进度监控和数据分析。

**认证要求**: Bearer Token 认证，需要 `prod.production-plan.view` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 查询参数

| 参数名                   | 类型   | 必填 | 限制                          | 描述                                                   | 默认值   | 示例                           |
| ------------------------ | ------ | ---- | ----------------------------- | ------------------------------------------------------ | -------- | ------------------------------ |
| source                   | string | 否   | `ERP` 或 `MANUAL`             | 计划来源筛选                                           | null     | `ERP`                          |
| status                   | string | 否   | 见附录"计划状态枚举"          | 计划状态筛选                                           | null     | `IN_PROGRESS`                  |
| planPriority             | string | 否   | `LOW/NORMAL/HIGH/URGENT`      | 计划优先级筛选                                         | null     | `HIGH`                         |
| productCode              | string | 否   | 最大50字符                    | 产品编码模糊匹配                                       | null     | `AF-1060-O-0.05x1000`          |
| planNumber               | string | 否   | 最大100字符                   | 计划编号模糊匹配                                       | null     | `PL-2024-001`                  |
| externalOrderNumber      | string | 否   | 最大100字符                   | 外部订单号模糊匹配                                     | null     | `ERP-ORDER-2024-001`           |
| search                   | string | 否   | 最大100字符                   | 全局搜索（计划编号、产品编码、订单号）                 | null     | `1060`                         |
| plannedDeliveryDateStart | string | 否   | ISO 8601 日期格式             | 计划交期开始时间（含）                                 | null     | `2024-01-01`                   |
| plannedDeliveryDateEnd   | string | 否   | ISO 8601，需晚于开始时间      | 计划交期结束时间（含）                                 | null     | `2024-12-31`                   |
| createdAtStart           | string | 否   | ISO 8601 日期格式             | 创建时间开始（含）                                     | null     | `2024-01-01T00:00:00Z`         |
| createdAtEnd             | string | 否   | ISO 8601，需晚于开始时间      | 创建时间结束（含）                                     | null     | `2024-12-31T23:59:59Z`         |
| format                   | string | 否   | `json` 或 `csv`               | 导出格式                                               | `json`   | `csv`                          |
| fileName                 | string | 否   | 最大200字符                   | CSV 导出时的文件名（不含扩展名）                       | 自动     | `production-progress-20240121` |
| offset                   | number | 否   | 整数，≥0                      | 分页偏移量                                             | 0        | `0`                            |
| limit                    | number | 否   | 整数，1-5000                  | 每页数量                                               | 1000     | `100`                          |
| sortBy                   | string | 否   | 格式：`field:asc,field2:desc` | 排序规则，多字段用逗号分隔，方向用冒号指定（asc/desc） | 默认排序 | `plannedDeliveryDate:asc`      |

## 使用示例

### 场景1: 获取紧急计划的进度概览

**业务需求**: 生产经理需要快速查看所有高优先级和紧急计划的执行进度，以便识别潜在延期风险。

```bash
# 查询高优先级和紧急计划，按交期升序排列
curl -X GET "http://localhost:3000/v1/prod/plans/progress-report?planPriority=HIGH&status=IN_PROGRESS&sortBy=plannedDeliveryDate:asc&limit=50" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

**预期结果**: 返回前50条高优先级执行中的计划，按交期从近到远排序，可快速识别临近交期的计划进度。

### 场景2: 导出月度进度报表（CSV格式）

**业务需求**: 财务部门需要导出本月所有生产计划的进度数据，用于月度生产绩效分析。

```bash
# 导出2024年1月的所有计划进度
curl -X GET "http://localhost:3000/v1/prod/plans/progress-report?plannedDeliveryDateStart=2024-01-01&plannedDeliveryDateEnd=2024-01-31&format=csv&fileName=progress-january-2024&limit=5000" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -o progress-january-2024.csv
```

**预期结果**: 下载一个名为 `progress-january-2024.csv` 的文件，包含1月所有计划的进度数据。

### 场景3: 监控特定产品系列的生产进度

**业务需求**: 销售团队需要追踪某个客户订单（AF-1060系列产品）的所有相关计划执行情况。

```bash
# 按产品编码筛选并获取详细进度
curl -X GET "http://localhost:3000/v1/prod/plans/progress-report?productCode=AF-1060&status=IN_PROGRESS&format=json&limit=100" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

**预期结果**: 返回所有包含 "AF-1060" 的执行中计划，展示每个计划的完成百分比和明细统计。

### 场景4: 分析ERP同步计划的执行效率

**业务需求**: 生产总监需要对比ERP自动同步的计划与手工创建计划的执行效率差异。

```bash
# 查询ERP来源的计划进度
curl -X GET "http://localhost:3000/v1/prod/plans/progress-report?source=ERP&createdAtStart=2024-01-01&createdAtEnd=2024-01-31&sortBy=currentProgressPercentage:desc&limit=200" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

**预期结果**: 返回1月份ERP同步的计划，按进度百分比降序排列，可统计平均完成度和执行效率。

### 场景5: 大批量数据分页查询

**业务需求**: 系统管理员需要提取所有历史计划数据进行数据分析，使用分页方式避免超时。

```bash
# 第一页（0-1000条）
curl -X GET "http://localhost:3000/v1/prod/plans/progress-report?offset=0&limit=1000&format=json" \
```

## 常见问题

### Q1: 为什么进度百分比与预期不符？

**A**: 进度百分比的计算基于以下逻辑：
- **计算公式**: `(已完成项重量总和 / 活动项重量总和) × 100%`
- **活动项定义**: 排除状态为 `CANCELLED` 的计划项
- **特殊情况**:
  - 全部取消时，进度显示 100%（无需执行）
  - 无活动项时，进度显示 0%
- **精度**: 重量保留3位小数，百分比保留2位小数

如果发现进度异常，请检查：
1. 计划项的 `plannedWeight` 是否正确设置
2. 是否有计划项被意外取消
3. 是否需要先执行进度同步接口

### Q2: CSV 导出的文件乱码如何解决？

**A**: CSV 文件使用 UTF-8 编码，部分编辑器可能无法正确识别：
- **Excel 打开**:
  1. 数据 → 导入文本/CSV
  2. 选择文件编码为 UTF-8
  3. 分隔符选择逗号
- **记事本/VSCode**: 默认支持 UTF-8，可正常查看
- **建议**: 使用 `fileName` 参数指定有意义的文件名

### Q3: 如何实现全局搜索？

**A**: 使用 `search` 参数实现跨字段模糊匹配：
```bash
# 搜索包含 "1060" 的计划（匹配计划编号、产品编码、外部订单号）
GET /v1/prod/plans/progress-report?search=1060
```

**注意**: `search` 与其他筛选参数可组合使用（AND关系）。

### Q4: 查询结果为空但确实存在数据？

**A**: 请检查以下几点：
1. **权限问题**: 确认用户具有 `prod.production-plan.view` 权限
2. **筛选条件过严**: 尝试减少筛选条件或放宽日期范围
3. **状态不匹配**: 检查 `status` 参数是否与实际计划状态一致
4. **大小写敏感**: 枚举值必须使用大写（如 `IN_PROGRESS` 而非 `in_progress`）

### Q5: 最大可查询多少条记录？

**A**:
- **单次查询限制**: 最大 5000 条（`limit` 参数上限）
- **推荐值**: 1000 条以内，保证响应速度
- **大数据量处理**:
  - JSON 格式：使用分页多次查询
  - CSV 格式：单次导出最多 5000 条
- **性能优化**: 添加筛选条件缩小结果集

### Q6: 如何按多个字段排序？

**A**: 使用 `sortBy` 参数，多个字段用逗号分隔：
```bash
# 先按交期升序，再按优先级降序，最后按进度降序
GET /v1/prod/plans/progress-report?sortBy=plannedDeliveryDate:asc,planPriority:desc,currentProgressPercentage:desc
```

**可排序字段**: 所有 columns 中的字段，以及模型中的其他属性。

### Q7: 进度明细中的各项数量含义？

**A**:
- **totalItems**: 计划包含的所有计划项（含已取消）
- **activeItems**: 活动项 = totalItems - cancelledItems
- **completedItems**: 状态为 `COMPLETED` 的计划项数量
- **inProgressItems**: 状态为 `IN_PROGRESS` 的计划项数量
- **cancelledItems**: 状态为 `CANCELLED` 的计划项数量

**注意**: 进度百分比仅基于 activeItems 计算，已取消项不影响进度。
