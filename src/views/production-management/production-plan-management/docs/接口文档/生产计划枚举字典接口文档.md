# Moses API 生产计划枚举字典接口文档

## 概述

本文档详细说明了 Moses API 生产计划模块的枚举字典接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。**本文档严格基于实际代码实现编写**，确保前端开发人员能够准确对接。

### API 基础信息

- **基础 URL**: `http://localhost:3000/v1` (开发环境)
- **API 版本**: v1
- **认证方式**: JWT Bearer Token
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### Swagger 文档

项目已集成 Swagger 文档，可通过以下地址访问：

- **开发环境**: http://localhost:3000/v1/docs
- **在线文档**: 提供完整的 API 接口说明、参数定义和示例

### 权限约定

- `prod.production-plan.view`：查看生产计划及相关枚举字典的权限
- `prod.production-plan.manage`：管理生产计划的权限（字典接口无需此权限）

## 统一响应格式

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2025-10-16T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）"
    }
  },
  "meta": {
    "timestamp": "2025-10-16T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

```
Authorization: Bearer <access_token>
```

### 2. 获取特定类型枚举字典

**接口路径**: `GET /v1/prod/plans/dictionaries/:type`

**功能描述**: 返回指定类型的枚举字典。如果只需要某一种枚举类型（如只需要生产计划状态），可以使用此接口减少数据传输量。接口会根据type参数返回对应的枚举值到中文标签的映射。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**路径参数**:

| 参数名 | 类型   | 必填 | 限制               | 描述                                   | 示例         |
| ------ | ------ | ---- | ------------------ | -------------------------------------- | ------------ |
| type   | string | 是   | 见下方"可选值"列表 | 字典类型标识，用于指定要获取的枚举类型 | planStatuses |

**type 参数可选值**:

| 值                       | 说明             | 枚举数量 |
| ------------------------ | ---------------- | -------- |
| planStatuses             | 生产计划状态     | 8        |
| planItemStatuses         | 子批次状态       | 7        |
| planPriorities           | 计划优先级       | 4        |
| planSources              | 计划来源         | 2        |
| processTemplateLinkTypes | 工艺模板关联类型 | 3        |
| equipmentLinkTypes       | 设备关联类型     | 3        |
| changeTypes              | 变更类型         | 9        |
| operationSources         | 操作来源         | 3        |
| approvalStatuses         | 审批状态         | 6        |

**查询参数**: 无

**请求参数**: 无

**请求示例**:

```bash
curl -X GET http://localhost:3000/v1/prod/plans/dictionaries/planStatuses \
```

## 错误码说明

### 生产计划字典相关错误码

| 错误码               | HTTP 状态码 | 错误消息       | 说明                   | 处理建议             |
| -------------------- | ----------- | -------------- | ---------------------- | -------------------- |
| DICTIONARY_NOT_FOUND | 404         | 字典类型不存在 | 请求的字典类型标识无效 | 检查type参数是否正确 |

### 通用错误码

| 错误码         | HTTP 状态码 | 错误消息                | 说明                         | 处理建议               |
| -------------- | ----------- | ----------------------- | ---------------------------- | ---------------------- |
| UNAUTHORIZED   | 401         | 未授权，Token无效或过期 | 未提供认证Token或Token已失效 | 重新登录获取有效Token  |
| FORBIDDEN      | 403         | 无权限执行此操作        | 当前用户没有该操作的权限     | 联系管理员分配相应权限 |
| INTERNAL_ERROR | 500         | 服务器内部错误          | 服务器处理请求时发生异常     | 联系技术支持           |

### 错误处理最佳实践

1. **统一错误处理**: 建议根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理
   - `AUTH_`: 认证相关错误，可能需要重新登录或刷新令牌
   - `DICTIONARY_`: 字典相关错误，需要检查参数有效性

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需客户端硬编码错误消息

## 数据模型

### 枚举字典数据结构

枚举字典采用简洁的键值对格式，其中键为枚举CODE（大写英文，下划线分隔），值为对应的中文标签。

**通用结构**:

```json
{
  "{枚举类型}": {
    "{CODE1}": "{中文标签1}",
    "{CODE2}": "{中文标签2}"
  }
}
```

**设计说明**:
- 枚举CODE用于数据库存储和业务逻辑判断
- 中文标签用于用户界面显示
- 采用扁平结构，避免嵌套复杂度

### 枚举类型详细定义

#### 1. 生产计划状态 (planStatuses)

**数据结构**:
```json
{
  "RECEIVED": "已接收",
  "CONFIRMED": "已确认",
  "PENDING_APPROVAL": "待审批",
  "PARTIALLY_RELEASED": "部分发布",
  "RELEASED": "已发布",
  "IN_PROGRESS": "执行中",
  "COMPLETED": "已完成",
  "CANCELLED": "已取消"
}
```

**字段说明**:

| 枚举CODE           | 中文标签 | 说明                 | 状态转换说明                               |
| ------------------ | -------- | -------------------- | ------------------------------------------ |
| RECEIVED           | 已接收   | 从ERP接收的初始状态  | 可转换为：已确认、待审批、已取消           |
| CONFIRMED          | 已确认   | 计划已确认，可以排程 | 可转换为：部分发布、已发布、待审批、已取消 |
| PENDING_APPROVAL   | 待审批   | 等待审批             | 可转换为：已发布、已取消、已确认等         |
| PARTIALLY_RELEASED | 部分发布 | 部分子批次已发布     | 可转换为：已发布、执行中、待审批、已取消   |
| RELEASED           | 已发布   | 全部子批次已发布     | 可转换为：执行中、待审批、已取消           |
| IN_PROGRESS        | 执行中   | 计划正在执行         | 可转换为：已完成、待审批、已取消           |
| COMPLETED          | 已完成   | 计划已完成           | 终态，不可再转换                           |
| CANCELLED          | 已取消   | 计划已取消           | 终态，不可再转换                           |

#### 2. 子批次状态 (planItemStatuses)

**数据结构**:
```json
{
  "DRAFT": "草稿",
  "READY_FOR_SCHEDULING": "待排程",
  "SCHEDULED": "已排程",
  "RELEASED": "已发布",
  "IN_PROGRESS": "执行中",
  "COMPLETED": "已完成",
  "CANCELLED": "已取消"
}
```

**字段说明**:

| 枚举CODE             | 中文标签 | 说明           | 业务场景                 |
| -------------------- | -------- | -------------- | ------------------------ |
| DRAFT                | 草稿     | 初始状态       | 子批次创建后的初始状态   |
| READY_FOR_SCHEDULING | 待排程   | 等待排程分配   | 计划确认后，等待系统排程 |
| SCHEDULED            | 已排程   | 已分配排程计划 | 排程算法分配完成         |
| RELEASED             | 已发布   | 已发布到生产线 | 发布后可开始生产         |
| IN_PROGRESS          | 执行中   | 正在执行       | 生产执行过程中           |
| COMPLETED            | 已完成   | 已完成         | 生产完成                 |
| CANCELLED            | 已取消   | 已取消         | 计划取消或调整           |

**数据结构**:

### 字段说明

**日期时间格式**:
- 所有日期时间字段均使用 ISO 8601 格式：`YYYY-MM-DDTHH:mm:ss.sssZ`
- 示例：`"2025-10-16T10:30:00.000Z"`

**枚举CODE命名规范**:
- 全部大写英文字母
- 多个单词使用下划线 `_` 分隔
- 具有自解释性
- 示例：`PENDING_APPROVAL`、`READY_FOR_SCHEDULING`、`STATUS_UPDATE_REQUESTED`

**中文标签规范**:
- 简洁明确，通常2-6个汉字
- 使用用户容易理解的业务术语
- 保持系统内一致性

## 安全说明

### 认证机制

所有枚举字典接口需要通过JWT Token认证，Token需在请求头中提供：

```
Authorization: Bearer {token}
```

Token获取方式请参考登录模块文档。

### 安全特性

1. **JWT Token验证**: 每次请求都会验证Token的有效性和过期时间
2. **权限控制**: 需要 `prod.production-plan.view` 权限
3. **数据只读**: 枚举字典接口仅提供查询功能，不支持修改
4. **速率限制**: 遵循系统统一的API访问速率限制

### 使用建议

1. **缓存策略**: 枚举数据变化频率低，建议客户端实现缓存机制
2. **批量获取**: 优先使用"获取所有枚举字典"接口，减少请求次数
3. **错误处理**: 实现降级方案，当接口不可用时使用本地默认值
4. **安全传输**: 生产环境必须使用HTTPS协议
5. **状态流转控制**: 生产计划包含复杂的状态转换逻辑，严格按照状态转换规则进行操作
