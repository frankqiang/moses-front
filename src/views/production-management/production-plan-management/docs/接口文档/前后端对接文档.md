## 🎯 核心概念

### 1. 审批流程机制

#### 需要审批的状态
- **RELEASED** (下达生产计划)
- **CANCELLED** (取消生产计划)

#### 审批流程说明
```
用户操作 → 系统检测状态 → 创建审批请求 → 状态变为PENDING_APPROVAL → 等待审批 → 审批通过 → 状态变为目标状态
```

#### 不需要审批的状态
- RECEIVED (接收)
- CONFIRMED (确认)
- PARTIALLY_RELEASED (部分下达)
- IN_PROGRESS (进行中)
- COMPLETED (已完成)

### 2. 状态流转图

```
┌─────────────┐
│   RECEIVED  │ 接收（从ERP导入）
└──────┬──────┘
       │ 无需审批
       ▼
┌─────────────┐
│  CONFIRMED  │ 确认
└──────┬──────┘
       │ 需要审批
       ▼
┌──────────────────┐     审批通过      ┌─────────────┐
│ PENDING_APPROVAL ├──────────────────►│  RELEASED   │ 下达
└──────────────────┘                   └──────┬──────┘
                                              │
                                              ▼
                                       ┌─────────────┐
                                       │ IN_PROGRESS │ 进行中
                                       └──────┬──────┘
                                              │
                                              ▼
                                       ┌─────────────┐
                                       │  COMPLETED  │ 完成
                                       └─────────────┘

任何状态 ─需要审批─► PENDING_APPROVAL ─审批通过─► CANCELLED (取消)
```

### 2. 更新生产计划状态（重点）

**接口**: `PATCH /v1/prod/plans/:planId/status`

#### 场景1: 确认计划（无需审批）

**请求**:
```typescript
const confirmPlan = async (planId: string) => {
  const response = await api.patch(`/v1/prod/plans/${planId}/status`, {
    targetStatus: 'CONFIRMED',
    changeDescription: '确认生产计划'
  });

  // 响应数据结构
  const { plan, progress, itemUpdates } = response.data.data;

  // ✅ 直接更新成功，刷新列表
  message.success('生产计划已确认');
  refreshPlanList();
};
```

#### 场景2: 取消计划（需要审批）⭐

**请求**:
```typescript
const cancelPlan = async (planId: string, cancelReason: string, remarks?: string) => {
  const response = await api.patch(`/v1/prod/plans/${planId}/status`, {
    targetStatus: 'CANCELLED',
    cancelReason: cancelReason,        // ⚠️ 必填，会传递到审批请求
    changeDescription: '取消生产计划',
    remarks: remarks                    // 可选，额外备注
  });

  const { plan, approval, targetStatus, status } = response.data.data;

  // 检查是否需要审批
  if (status === 'PENDING_APPROVAL' && approval) {
    // ✅ 已提交审批，显示审批ID
    message.info(`取消申请已提交，等待审批（审批ID: ${approval.id}）`);

    // 保存审批ID，用于后续查询
    localStorage.setItem(`approval_${planId}`, approval.id);

    // 跳转到审批中心或待审批列表
    router.push(`/approval-center?approvalId=${approval.id}`);
  }
};
```

**重要说明**:
- ✅ `cancelReason` 会自动传递到审批请求的 `remarks` 字段
- ✅ 如果同时提供 `remarks`，会合并为：`"${cancelReason}（备注：${remarks}）"`
- ✅ 审批人可以在审批记录中看到完整的取消原因

#### 场景3: 下达计划（需要审批）

```typescript
const releasePlan = async (planId: string, remarks?: string) => {
```

### 4. 审批操作

**通过审批**: `POST /v1/approval-center/requests/:approvalId/approve`

```typescript
const approveRequest = async (approvalId: string, decisionRemarks?: string) => {
  const response = await api.post(
    `/v1/approval-center/requests/${approvalId}/approve`,
    {
      decisionRemarks: decisionRemarks || '审批通过',
      requiredPermissions: ['prod.production-plan.approval']
    }
  );

  message.success('审批已通过');

  // ✅ 审批通过后，生产计划状态会自动更新为目标状态
  // 需要刷新计划列表
  refreshPlanList();
};
```

**驳回审批**: `POST /v1/approval-center/requests/:approvalId/reject`

```typescript
const rejectRequest = async (approvalId: string, decisionRemarks: string) => {
  // ⚠️ decisionRemarks 必填
  if (!decisionRemarks) {
    message.error('驳回时必须填写审批意见');
    return;
  }

  const response = await api.post(
    `/v1/approval-center/requests/${approvalId}/reject`,
    {
      decisionRemarks: decisionRemarks,
      requiredPermissions: ['prod.production-plan.approval']
    }
  );

  message.warning('审批已驳回');

  // ✅ 审批驳回后，生产计划状态会恢复到之前的状态
  refreshPlanList();
};
```

## 🆘 常见问题

### Q1: 为什么取消计划后状态是 PENDING_APPROVAL 而不是 CANCELLED？

A: 取消和下达操作需要审批。提交后，计划状态会先变为 `PENDING_APPROVAL`，审批通过后才会变为 `CANCELLED`。

### Q2: `cancelReason` 和 `remarks` 有什么区别？

A:
- `cancelReason`: 取消的主要原因，会传递给审批人（必填）
- `remarks`: 额外的备注说明（可选）
- 两者会合并到审批请求的 `remarks` 字段

### Q3: 如何判断一个计划是否在审批中？

A: 检查 `plan.status === 'PENDING_APPROVAL'`，并且可以调用审批记录接口查询具体的审批详情。

### Q4: 审批通过后需要手动刷新计划列表吗？

A: 是的，审批操作不会主动推送状态更新。建议审批成功后调用计划列表接口刷新数据。或者可以考虑使用WebSocket实现实时推送。

### Q5: 用户权限不足时应该如何处理？

A: 统一在拦截器中处理，显示友好的错误提示，并引导用户联系管理员分配权限。
