### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {

  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }

```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

## 生产计划业务流程说明

### 业务流程概述

```
步骤1：创建或导入生产计划
   ↓
步骤2：确认计划 → 拆分为子批次（可选）
   ↓
步骤3：调整计划数量/交期（可选）
   ↓
步骤4：提交审批 → 审批通过/驳回
   ↓
步骤5：下达计划 → 生成退火任务
   ↓
步骤6：监控进度 → 同步完成状态
   ↓
步骤7：查看报表和审计日志
```

### 流程说明

- **步骤1**：通过手工创建或ERP导入生成生产计划，计划初始状态为 `RECEIVED`（已接收）
- **步骤2**：确认计划后状态变为 `CONFIRMED`（已确认），可以进行拆分操作
- **步骤3**：根据实际情况调整计划数量、交期或优先级
- **步骤4**：关键状态变更（如下达、取消）需要提交审批流程
- **步骤5**：审批通过后计划状态变为 `RELEASED`（已下达），系统自动生成退火任务
- **步骤6**：计划执行过程中实时同步进度，状态变为 `IN_PROGRESS`（执行中）直至 `COMPLETED`（已完成）
- **步骤7**：通过报表和审计日志接口查看计划执行情况和变更历史

### 4. 拆分生产计划

**接口路径**: `POST /v1/prod/plans/:planId/split`

**功能描述**: 将生产计划拆分为多个子批次。拆分后的子批次总重量必须与主计划需求数量一致（允许0.5的误差）。拆分操作会记录审计日志。仅已确认或待排程状态的计划可以拆分。

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

| 参数名 | 类型   | 必填 | 限制    | 描述       | 示例                                   |

**请求参数**:

| 参数名            | 类型   | 必填 | 限制                   | 描述                            | 示例               |

### 6. 调整生产计划

**接口路径**: `PATCH /v1/prod/plans/:planId`

**功能描述**: 调整生产计划的需求数量、交期、优先级等信息。支持同时调整主计划和子批次。调整操作会记录审计日志。

**认证要求**: 需要 Bearer Token，需要 `prod.production-plan.adjust` 权限

```

Content-Type: application/json
```

| 参数名              | 类型   | 必填 | 限制                            | 描述                       | 示例                       |
| ------------------- | ------ | ---- | ------------------------------- | -------------------------- | -------------------------- |

### 7. 更新生产计划状态

**接口路径**: `PATCH /v1/prod/plans/:planId/status`

**功能描述**: 更新生产计划的状态。关键状态变更（如下达RELEASED、取消CANCELLED）需要提交审批流程。状态流转必须符合预定义的状态转换规则。

**审批流程说明**:
- **需要审批的状态**: `RELEASED`（下达）、`CANCELLED`（取消）
- **审批触发**: 当目标状态为上述状态时，系统自动创建审批请求
- **状态变更**: 计划状态先变为 `PENDING_APPROVAL`（待审批），审批通过后才变更为目标状态
- **取消原因传递**: 当 `targetStatus` 为 `CANCELLED` 时，`cancelReason` 参数会自动传递到审批请求的 `remarks` 字段，审批人可以看到取消原因
- **审批响应**: 返回数据中会包含 `approval` 对象，包含审批请求ID和状态

**认证要求**: 需要 Bearer Token，需要 `prod.production-plan.cancel` 权限（取消操作）

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**路径参数**:

| 参数名 | 类型   | 必填 | 限制    | 描述       | 示例                                   |
| ------ | ------ | ---- | ------- | ---------- | -------------------------------------- |
| planId | string | 是   | UUID v4 | 生产计划ID | "7f3c6d8e-9a2b-4f1c-8e5d-6a9b0c1d2e3f" |

**请求参数**:

| 参数名            | 类型   | 必填 | 限制                                                                                                         | 描述                            | 示例           |

| approvalContext   | object | 否   | 审批上下文信息                                                                                               | 审批相关信息                    | 见下方结构     |

**功能描述**: 提交生产计划状态变更的审批请求。用于关键状态变更（如下达RELEASED、取消CANCELLED）的审批流程。审批请求会发送到审批中心，由具有相应权限的用户进行审批。

**认证要求**: 需要 Bearer Token，需要 `prod.production-plan.manage` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**路径参数**:

| 参数名 | 类型   | 必填 | 限制    | 描述       | 示例                                   |
| ------ | ------ | ---- | ------- | ---------- | -------------------------------------- |
| planId | string | 是   | UUID v4 | 生产计划ID | "7f3c6d8e-9a2b-4f1c-8e5d-6a9b0c1d2e3f" |

**请求参数**:

| 参数名              | 类型   | 必填 | 限制                      | 描述           | 示例                              |
| ------------------- | ------ | ---- | ------------------------- | -------------- | --------------------------------- |
| targetStatus        | string | 是   | 枚举: RELEASED, CANCELLED | 目标状态       | "RELEASED"                        |
| remarks             | string | 否   | 最大500字符               | 审批说明       | "申请下达生产计划"                |
| requiredPermissions | array  | 否   | 权限代码数组              | 要求的审批权限 | ["prod.production-plan.approval"] |

**请求示例**:

```bash
curl -X POST http://localhost:3000/v1/prod/plans/7f3c6d8e-9a2b-4f1c-8e5d-6a9b0c1d2e3f/approval/submit \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "targetStatus": "RELEASED",
    "remarks": "申请下达生产计划",
    "requiredPermissions": ["prod.production-plan.approval"]
  }'
```


| 错误码                 | HTTP 状态码 | 错误消息                | 说明                         | 处理建议                         |
| ---------------------- | ----------- | ----------------------- | ---------------------------- | -------------------------------- |
| VALIDATION_ERROR       | 400         | 请求参数验证失败        | 请求参数不符合验证规则       | 检查请求参数的格式、类型和必填项 |
| UNAUTHORIZED           | 401         | 未授权，Token无效或过期 | 未提供认证Token或Token已失效 | 重新登录获取有效的访问令牌       |

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理
   - `PRODUCTION_PLAN_*`: 生产计划相关错误，需要检查计划数据和状态
   - `VALIDATION_ERROR`: 验证错误，需要检查输入参数
   - `UNAUTHORIZED/FORBIDDEN`: 认证和授权错误，需要检查用户权限
   - `*_FAILED`: 操作失败错误，可能需要重试或联系技术支持

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息

4. **重试机制**: 对于包含 `retryAfter` 字段的错误，应按照指定时间后重试

5. **日志记录**: 使用 `traceId` 或 `requestId` 进行错误追踪和问题排查

## 安全说明

### 认证机制

本模块所有接口均需要进行JWT Bearer Token认证。Token在用户登录时由认证模块颁发，有效期为配置的过期时间。

**认证流程**:
1. 用户通过登录接口获取访问令牌（access token）
2. 在每个API请求的Authorization头中携带Bearer Token
3. 服务器验证Token的有效性和权限
4. Token过期后需要重新登录或使用刷新令牌

### 权限控制

生产计划管理模块采用基于权限的访问控制（PBAC），不同操作需要不同的权限：

**查询和查看权限**:
- `prod.production-plan.view`: 查看生产计划列表、详情、审计日志、进度报表、导出数据

**管理权限**:
- `prod.production-plan.manage`: 创建计划、导入计划、提交审批

**操作权限**:
- `prod.production-plan.split`: 拆分生产计划
- `prod.production-plan.merge`: 合并生产计划
- `prod.production-plan.adjust`: 调整生产计划数量、交期等
- `prod.production-plan.cancel`: 取消生产计划（需要审批）

**审批权限**:
- `prod.production-plan.approval`: 审批生产计划状态变更请求

### 数据安全

1. **敏感数据保护**:
   - 密码和敏感信息在传输和存储时加密
   - 审计日志记录所有关键操作，包含操作人、时间、IP地址

2. **SQL注入防护**:
   - 使用Sequelize ORM进行数据库操作
   - 所有用户输入进行参数化查询

3. **XSS防护**:
   - 对用户输入进行验证和转义
   - 响应头设置Content-Type: application/json

4. **CSRF防护**:
   - API采用JWT认证，不依赖Cookie
   - 支持跨域资源共享（CORS）配置

### 数据访问控制

1. **行级权限**: 用户只能访问其权限范围内的生产计划数据
2. **字段级过滤**: 敏感字段（如erpSyncFingerprint、remarks）不在响应中返回
3. **审计追踪**: 所有数据变更操作记录审计日志，包含操作人、时间、变更内容

### 使用建议

1. **Token管理**:
   - 妥善保管访问令牌，不要在日志或URL中暴露
   - Token过期后及时刷新
   - 退出登录时清除本地存储的Token

2. **权限申请**:
   - 根据实际业务需要申请最小必要权限
   - 定期审查和回收不再需要的权限

3. **安全最佳实践**:
   - 使用HTTPS协议进行数据传输
   - 实施API访问频率限制，防止滥用
   - 定期更新依赖包，修复安全漏洞
