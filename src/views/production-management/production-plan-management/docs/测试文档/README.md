## 测试执行流程

### 1. 测试准备
1. 检查测试环境是否就绪
2. 准备测试数据
3. 确认后端接口可用
4. 准备测试账号

### 2. 测试执行
1. 按照测试用例文档逐项执行
2. 记录测试结果（通过/失败/阻塞）
3. 截图保存失败场景
4. 填写缺陷报告

### 3. 缺陷跟踪
1. 使用缺陷管理系统记录问题
2. 分类：功能缺陷、UI问题、性能问题、建议优化
3. 优先级：P0-致命、P1-严重、P2-一般、P3-轻微
4. 跟踪修复状态

### 4. 回归测试
1. 修复后重新执行失败用例
2. 执行相关功能的回归测试
3. 验证修复效果

### 5. 测试报告
1. 汇总测试结果
2. 统计测试覆盖率
3. 统计缺陷分布
4. 输出测试报告

## 测试用例说明

### 用例编号规则
- **格式**：`模块-类型-序号`
- **示例**：`PLAN-FUNC-001`（生产计划-功能测试-001）

### 用例优先级
- **P0**：核心功能，必须通过
- **P1**：重要功能，高优先级
- **P2**：常规功能，中优先级
- **P3**：辅助功能，低优先级

### 用例状态
- **未执行**：尚未开始测试
- **执行中**：正在测试
- **通过**：测试通过
- **失败**：测试失败，已提缺陷
- **阻塞**：依赖未就绪，无法测试
- **跳过**：当前版本不测试

### 用例字段说明
- **用例编号**：唯一标识
- **用例标题**：简要说明测试内容
- **优先级**：P0/P1/P2/P3
- **前置条件**：执行测试前需要满足的条件
- **测试步骤**：详细的操作步骤
- **预期结果**：期望的系统行为
- **实际结果**：实际的系统行为（执行时填写）
- **测试状态**：通过/失败/阻塞/跳过
- **备注**：补充说明

## 关键测试点

### 1. 状态流转
- 验证所有合法的状态转换
- 验证非法状态转换被拒绝
- 验证冻结计划不能变更状态
- 验证终态（COMPLETED、CANCELLED）不能再变更

### 2. 审批流程
- 验证需要审批的状态变更自动创建审批
- 验证审批通过后状态正确更新
- 验证审批驳回后状态恢复
- 验证并发审批冲突检测

### 3. 数据验证
- 验证必填字段校验
- 验证数据格式校验
- 验证数据范围校验
- 验证业务规则校验

### 4. 用户体验
- 验证加载状态提示
- 验证操作成功/失败提示
- 验证防抖和防重复点击
- 验证页面缓存和状态恢复

### 5. 错误处理
- 验证网络错误提示
- 验证权限不足提示
- 验证数据不存在提示
- 验证并发冲突提示
