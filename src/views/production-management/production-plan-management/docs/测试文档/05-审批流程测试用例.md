# 05-审批流程测试用例

## 文档说明

本文档包含生产计划管理模块的审批流程测试用例，覆盖审批提交、审批处理、审批撤销等全流程场景。

---

## 1. 审批提交测试

### PLAN-APPROVAL-001：提交下达审批

**优先级**：P0

**前置条件**：
- 计划状态为CONFIRMED
- 用户具有"管理生产计划"权限

**测试步骤**：
1. 进入计划详情页
2. 点击"提交审批"按钮
3. 填写审批信息：
   - 目标状态：已发布
   - 申请说明：准备下达执行
4. 点击"提交"按钮

**预期结果**：
- 提交成功，提示"提交审批成功"
- 计划状态变更为"待审批"（PENDING_APPROVAL）
- 自动创建审批请求：
  - 资源类型：prod.production-plan
  - 资源ID：计划ID
  - 请求操作：RELEASED
  - 申请人：当前用户
  - 申请说明：准备下达执行
  - 审批状态：PENDING
- 记录申请时间

**测试数据**：
```json
{
  "targetStatus": "RELEASED",
  "requestDescription": "准备下达执行"
}
```

---

### PLAN-APPROVAL-002：提交取消审批

**优先级**：P0

**前置条件**：
- 计划状态为RELEASED或IN_PROGRESS
- 用户具有"取消生产计划"权限

**测试步骤**：
1. 点击计划的"取消"按钮
2. 输入取消原因："客户取消订单"
3. 点击"确定"按钮

**预期结果**：
- 提交成功，提示"提交取消审批成功"
- 计划状态变更为"待审批"
- 创建取消审批请求：
  - 请求操作：CANCELLED
  - 取消原因：客户取消订单
  - 审批状态：PENDING

**测试数据**：
```json
{
  "targetStatus": "CANCELLED",
  "cancelReason": "客户取消订单",
  "changeDescription": "取消生产计划"
}
```

### PLAN-APPROVAL-003：重复提交审批（冲突检测）

**优先级**：P1

**前置条件**：
- 计划状态为PENDING_APPROVAL
- 已存在待处理的审批请求

**测试步骤**：
1. 尝试再次点击"提交审批"按钮
2. 或通过API再次提交审批

**预期结果**：
- ❌ 提交失败
- 返回错误码：BIZ_030
- 错误信息："该资源存在待处理的审批请求，请等待审批完成或撤销后再试"
- 显示友好提示，引导用户查看现有审批或撤销

**测试数据**：无

### PLAN-APPROVAL-004：无权限提交审批

**优先级**：P1

**前置条件**：
- 计划状态为CONFIRMED
- 用户不具有"管理生产计划"权限

**优先级**：P1

**前置条件**：

## 2. 审批处理测试

### PLAN-APPROVAL-006：审批通过（下达审批）

**优先级**：P0

**前置条件**：
- 计划状态为PENDING_APPROVAL
- 存在待处理的下达审批请求
- 用户具有"审批生产计划"权限

**测试步骤**：
1. 进入计划详情页
2. 切换到"审批记录"Tab
3. 点击待审批记录的"审批"按钮
4. 选择"通过"
5. 输入审批意见："同意下达"
6. 点击"确定"按钮

**预期结果**：
- 审批成功，提示"审批成功"
- 审批状态变更为"已通过"（APPROVED）
- 计划状态自动变更为"已发布"（RELEASED）
- 记录审批人、审批时间、审批意见
- 记录计划下达时间（releasedAt）
- 子批次状态联动更新（如有）

**测试数据**：
```json
{
  "action": "approve",
  "approvalComment": "同意下达"
}
```

**前置条件**：

- 存在待处理的取消审批请求

**测试步骤**：
1. 在审批记录中点击"审批"按钮
2. 选择"通过"
3. 输入审批意见："同意取消"

**预期结果**：

- 审批状态变更为"已通过"

- 记录取消时间（cancelledAt）
- 记录取消原因
- 子批次联动取消（未完成的）

### PLAN-APPROVAL-008：审批驳回

**优先级**：P1

**前置条件**：
- 计划状态为PENDING_APPROVAL
- 存在待处理的审批请求
- 用户具有"审批生产计划"权限

**测试步骤**：
1. 点击待审批记录的"审批"按钮
2. 选择"驳回"
3. 输入驳回原因："交期不合理，需要重新评估"
4. 点击"确定"按钮

**预期结果**：
- 审批成功，提示"审批已驳回"
- 审批状态变更为"已驳回"（REJECTED）
- 计划状态恢复为审批前状态（通常是CONFIRMED）
- 记录驳回人、驳回时间、驳回原因
- 驳回原因必须填写

**测试数据**：
```json
{
  "action": "reject",
  "rejectionReason": "交期不合理，需要重新评估"
}
```

**优先级**：P1

**前置条件**：
- 计划状态为PENDING_APPROVAL
- 存在待处理的审批请求
- 当前用户是审批的申请人

**测试步骤**：
1. 进入计划详情页
2. 切换到"审批记录"Tab
3. 点击待审批记录的"撤销"按钮
4. 确认撤销操作

**预期结果**：
- 撤销成功，提示"审批已撤销"
- 审批状态变更为"已撤销"（WITHDRAWN）
- 计划状态恢复为审批前状态（通常是CONFIRMED）
- 记录撤销时间和撤销原因

**测试数据**：无
