# 生产计划管理业务流程说明

## 文档说明

本文档基于生产计划模块的实际实现，详细说明后端业务逻辑和数据流转规则，为前端开发提供准确的业务理解基础。

## 核心概念

### 主计划与子批次

- **主计划（ProductionPlan）**：对应一个客户订单或生产需求，包含产品信息、需求数量、交期等核心数据
- **子批次（ProductionPlanItem）**：主计划可拆分为多个子批次，每个子批次对应一次退火炉的装炉任务

### 状态模型

#### 主计划状态流转

```
RECEIVED（已接收）
    ↓
CONFIRMED（已确认）
    ↓
PENDING_APPROVAL（待审批）
    ↓
RELEASED（已发布）
    ↓
IN_PROGRESS（执行中）
    ↓
COMPLETED（已完成）
```

**并行状态**：`CANCELLED`（已取消）、`PARTIALLY_RELEASED`（部分发布）

#### 子批次状态流转

```
DRAFT（草稿）
    ↓
READY_FOR_SCHEDULING（待排程）
    ↓
SCHEDULED（已排程）
    ↓
RELEASED（已发布）
    ↓
IN_PROGRESS（执行中）
    ↓
COMPLETED（已完成）
```

**并行状态**：`CANCELLED`（已取消）

### 状态转换规则

#### 允许的状态转换

- **RECEIVED** → CONFIRMED、PENDING_APPROVAL、CANCELLED
- **CONFIRMED** → PARTIALLY_RELEASED、PENDING_APPROVAL、RELEASED、CANCELLED
- **PENDING_APPROVAL** → RELEASED、CANCELLED、CONFIRMED、RECEIVED、PARTIALLY_RELEASED、IN_PROGRESS
- **PARTIALLY_RELEASED** → RELEASED、IN_PROGRESS、PENDING_APPROVAL、CANCELLED
- **RELEASED** → IN_PROGRESS、PENDING_APPROVAL、CANCELLED
- **IN_PROGRESS** → COMPLETED、PENDING_APPROVAL、CANCELLED
- **COMPLETED** → 终态（不可转换）
- **CANCELLED** → 终态（不可转换）

#### 状态转换约束

- 状态转换必须符合预定义的转换规则，非法转换会被拒绝
- 从当前状态转换到同一状态时，系统会直接返回当前计划，不执行实际更新
- 冻结状态（isFrozen=true）的计划禁止执行任何状态变更操作

## 业务流程详解

### 1. 计划创建阶段

#### 1.1 手工创建

**触发方式**：用户通过界面手工录入

**必填信息**：
- 产品ID（必须是有效的铝箔产品）
- 需求数量和单位
- 计划交期（不得早于当前日期）

**可选信息**：
- 计划编号（未提供时系统自动生成）
- 客户信息（客户名称、客户编码）
- 优先级（默认NORMAL）
- 工艺模板（必须是"生效"状态）
- 特殊要求备注

**状态初始化**：RECEIVED

**子批次创建**：支持在创建主计划时同步创建子批次

#### 1.2 ERP导入

**触发方式**：从ERP系统批量同步订单

**去重策略**：根据外部订单号（externalOrderNumber）去重

**必填信息**：
- 外部订单号（ERP系统订单ID）
- 产品编码（自动关联产品主数据）
- 需求数量和单位
- 计划交期

**批次管理**：
- 记录同步批次号（erpSyncBatchNo）
- 记录导入时间戳
- 区分成功和失败记录

**数据校验**：
- 产品编码必须存在于产品主数据中
- 需求数量必须大于0
- 交期不得早于当前日期
- 工艺模板状态必须为"生效"

### 2. 计划确认阶段

#### 2.1 状态确认

**前置条件**：计划状态为RECEIVED

**操作内容**：
- 状态从RECEIVED转换为CONFIRMED
- 记录确认时间（confirmedAt）
- 记录变更日志

**业务含义**：生产调度人员确认该计划可以纳入排程

#### 2.2 计划拆分

**前置条件**：计划状态必须为CONFIRMED或PARTIALLY_RELEASED

**拆分规则**：
- 必须提供拆分方案（拆分数量列表）
- 拆分数量之和必须等于原计划数量（允许0.5吨的误差）
- 拆分后生成多个子批次，序号自动递增

**数据更新**：
- 主计划保持原状态
- 创建多个子批次记录，初始状态为DRAFT
- 记录拆分变更日志（changeType=SPLIT）

**业务场景**：根据退火炉容量将大订单拆分为多个批次

#### 2.3 计划合并

**前置条件**：
- 待合并的计划必须属于同一产品
- 所有计划状态必须相同且为CONFIRMED或PARTIALLY_RELEASED
- 所有计划不能处于冻结状态

**合并规则**：
- 保留第一个计划作为目标计划
- 将其他计划的需求数量累加到目标计划
- 取最早的交期作为合并后交期
- 优先级取最高级别

**数据更新**：
- 目标计划：更新数量、交期、优先级
- 源计划：状态变更为CANCELLED，记录取消原因（"已合并到计划XXX"）
- 记录合并变更日志（changeType=MERGE）

**业务场景**：多个小订单合并为一个批次以提高退火炉装载率

#### 2.4 计划调整

**前置条件**：计划状态为CONFIRMED或PARTIALLY_RELEASED

**可调整内容**：
- 需求数量
- 计划交期
- 优先级
- 特殊要求

**数据校验**：
- 需求数量必须大于0
- 交期不得早于当前日期

**数据更新**：
- 更新指定字段的值
- 记录调整变更日志（changeType=ADJUST）

### 3. 审批流程

#### 3.1 触发审批的状态

- **RELEASED（已发布）**：计划下达执行
- **CANCELLED（已取消）**：取消计划

#### 3.2 审批流程

**自动触发**：
- 当状态更新接口的目标状态为RELEASED或CANCELLED时
- 系统自动创建审批请求
- 计划状态变更为PENDING_APPROVAL

**审批请求内容**：
- 资源类型：prod.production-plan
- 资源ID：计划ID
- 请求操作：目标状态（RELEASED/CANCELLED）
- 申请人信息
- 申请说明（changeDescription）
- 取消原因（cancelReason，仅CANCELLED状态）

**审批结果处理**：
- **审批通过**：计划状态更新为目标状态，记录审批时间和审批人
- **审批驳回**：计划状态恢复为CONFIRMED，记录驳回原因
- **审批撤销**：计划状态恢复为CONFIRMED

#### 3.3 并发审批控制

**冲突检测**：同一计划同时只能有一个待审批请求

**冲突处理**：
- 检测到冲突时返回错误码BIZ_030
- 错误信息："该资源存在待处理的审批请求"

**建议操作**：等待当前审批完成或撤销后重新提交

### 4. 计划下达阶段

#### 4.1 状态下达

**前置条件**：
- 计划状态为CONFIRMED或PARTIALLY_RELEASED
- 审批流程已通过（如需审批）

**状态变更**：CONFIRMED/PARTIALLY_RELEASED → RELEASED

**自动触发**：
- 子批次状态同步更新
- 记录下达时间（releasedAt）

**业务含义**：计划正式生效，可以开始排程和执行

#### 4.2 子批次状态联动

**联动规则**：
- 主计划状态为RELEASED时，所有DRAFT或READY_FOR_SCHEDULING状态的子批次自动变更为RELEASED
- 主计划状态为CANCELLED时，所有未完成的子批次自动变更为CANCELLED

**状态优先级**：按完成度递增（DRAFT < READY_FOR_SCHEDULING < SCHEDULED < RELEASED < IN_PROGRESS < COMPLETED）

**主计划状态推导**：根据子批次状态自动计算主计划的最合适状态

### 5. 计划执行阶段

#### 5.1 进度同步

**触发方式**：
- 退火任务状态更新时自动触发
- 手动调用进度同步接口

**计算逻辑**：
- 统计所有子批次的已完成重量和总重量
- 计算完成百分比：(已完成重量 / 总重量) * 100

**状态自动更新**：
- 任意子批次开始执行 → 主计划状态变为IN_PROGRESS
- 所有子批次完成 → 主计划状态变为COMPLETED

**进度数据**：
- 总子批次数量
- 活跃子批次数量（未取消）
- 已完成子批次数量
- 总重量、活跃重量、已完成重量

#### 5.2 状态流转约束

**冻结检查**：计划冻结时禁止所有状态变更

**状态合法性检查**：
- 验证目标状态是否在允许的转换列表中
- 验证是否需要审批
- 验证是否有权限执行操作

**并发控制**：使用数据库事务确保状态变更的原子性

### 6. 计划取消

#### 6.1 取消条件

**可取消状态**：RECEIVED、CONFIRMED、PENDING_APPROVAL、PARTIALLY_RELEASED、RELEASED、IN_PROGRESS

**不可取消状态**：COMPLETED（已完成）、CANCELLED（已取消）

#### 6.2 取消流程

**审批要求**：取消操作必须经过审批

**必填信息**：取消原因（cancelReason）

**数据更新**：
- 计划状态变更为CANCELLED
- 记录取消时间（cancelledAt）
- 记录取消原因
- 所有未完成的子批次状态变更为CANCELLED

**变更日志**：记录取消操作的变更日志（changeType=STATUS_UPDATE）

## 数据约束规则

### 主计划约束

- **计划编号**：系统自动生成，格式为"PLAN-YYYYMMDD-序号"，也可用户指定
- **需求数量**：必须大于0，支持3位小数
- **计划交期**：必须晚于当前时间
- **产品关联**：产品必须存在且状态有效
- **工艺模板关联**：工艺模板及其最新版本状态必须为"生效"
- **优先级**：LOW（低）、NORMAL（正常）、HIGH（高）、URGENT（紧急）
- **来源**：ERP（ERP系统）、MANUAL（手工创建）

### 子批次约束

- **子计划编号**：拆分时系统自动生成，格式为"主计划编号-序号"
- **拆分序号**：从1开始递增
- **预计重量**：必须大于0
- **预计数量**：可选，表示卷数或件数
- **工艺模板**：可继承主计划的工艺模板，也可单独指定

### 变更日志规则

**记录的变更类型**：
- SPLIT：拆分操作
- MERGE：合并操作
- ADJUST：调整操作
- STATUS_UPDATE：状态更新
- PROGRESS_SYNC：进度同步

**日志内容**：
- 变更前后的数据快照
- 操作人信息
- 操作时间
- 变更描述
- 关联的审批请求（如有）

## 业务规则总结

### 关键业务逻辑

1. **状态单向流转**：生产计划状态按照预定义规则单向流转，不允许回退（审批驳回除外）
2. **审批前置**：RELEASED和CANCELLED状态变更必须先经过审批
3. **子批次联动**：主计划状态变更时，子批次状态自动联动更新
4. **进度自动计算**：主计划进度基于子批次进度自动计算，无需手动维护
5. **冻结保护**：计划冻结后禁止任何变更操作
6. **并发控制**：使用数据库事务和乐观锁防止并发冲突

### 数据一致性保证

1. **事务保护**：拆分、合并、状态变更等关键操作使用数据库事务
2. **约束校验**：数据库层面和业务层面双重校验
3. **变更追溯**：所有变更操作记录详细的变更日志
4. **审计完整**：保留完整的操作人、操作时间、变更内容

### 容错机制

1. **状态幂等**：相同状态转换请求返回当前状态，不报错
2. **数据校验**：参数校验失败返回明确的错误码和错误信息
3. **冲突检测**：并发操作冲突时返回冲突提示，引导用户重试
4. **回滚保护**：事务失败时自动回滚，保证数据一致性

## 与其他模块的集成

### 产品主数据模块

- **依赖关系**：生产计划必须关联有效的铝箔产品
- **数据同步**：创建计划时自动读取产品编码、产品名称等信息

### 工艺模板模块

- **依赖关系**：生产计划可关联工艺模板
- **状态验证**：工艺模板及其最新版本必须为"生效"状态
- **快照机制**：关联时保存工艺参数快照，后续工艺模板变更不影响已有计划

### 退火任务模块

- **触发关系**：生产计划下达后，系统根据子批次自动生成退火任务
- **进度同步**：退火任务进度更新时，反向更新生产计划进度

### 审批中心模块

- **集成方式**：通过统一的审批中心接口提交和查询审批请求
- **资源标识**：使用"prod.production-plan"作为资源类型标识
- **状态联动**：审批结果自动触发生产计划状态变更

## 典型业务场景

### 场景1：手工创建订单并下达

1. 用户创建生产计划，选择产品和工艺模板，状态为RECEIVED
2. 用户确认计划，状态变更为CONFIRMED
3. 用户提交下达申请，状态变更为PENDING_APPROVAL，创建审批请求
4. 审批人审批通过，状态变更为RELEASED
5. 系统自动生成退火任务，计划进入执行阶段

### 场景2：ERP订单批量导入

1. 系统从ERP同步订单数据，批量创建生产计划
2. 根据外部订单号去重，避免重复导入
3. 自动关联产品主数据，填充产品信息
4. 导入成功的计划状态为RECEIVED，失败的返回错误详情
5. 用户确认导入结果，进行后续排程

### 场景3：大订单拆分排程

1. 用户创建一个1000吨的大订单，状态为RECEIVED
2. 用户确认计划，状态变更为CONFIRMED
3. 用户根据退火炉容量拆分为5个200吨的子批次
4. 用户提交下达申请，审批通过后状态变更为RELEASED
5. 系统为每个子批次生成退火任务，分批执行

### 场景4：紧急订单取消

1. 用户创建订单并已下达，状态为RELEASED
2. 客户通知取消订单，用户申请取消
3. 系统创建取消审批请求，计划状态变更为PENDING_APPROVAL
4. 审批人审批通过，计划状态变更为CANCELLED
5. 所有关联的子批次和退火任务自动取消

### 场景5：多订单合并执行

1. 用户创建3个小订单（各300吨），状态均为CONFIRMED
2. 用户选择3个计划进行合并，合并为1个900吨的计划
3. 保留第一个计划，其他计划状态变更为CANCELLED
4. 目标计划继续后续的排程和下达流程

## 接口使用建议

### 查询接口

- **分页查询**：使用`/v1/prod/plans`接口，支持多种筛选条件
- **详情查询**：使用`/v1/prod/plans/:planId`接口，返回完整的计划信息和子批次列表
- **格式选择**：查询接口支持table和gantt两种输出格式，按需选择

### 操作接口

- **创建操作**：使用POST `/v1/prod/plans`接口，可选择同时创建子批次
- **拆分操作**：使用POST `/v1/prod/plans/:planId/split`接口，提供拆分方案
- **合并操作**：使用POST `/v1/prod/plans/merge`接口，提供待合并的计划ID列表
- **调整操作**：使用PATCH `/v1/prod/plans/:planId/adjust`接口，更新数量、交期等
- **状态更新**：使用PATCH `/v1/prod/plans/:planId/status`接口，统一管理状态流转

### 审批接口

- **提交审批**：使用POST `/v1/prod/plans/:planId/approval/submit`接口
- **查询审批**：使用GET `/v1/prod/plans/:planId/approval/requests`接口
- **自动审批**：状态更新接口在必要时自动触发审批流程

### 导出接口

- **计划导出**：使用GET `/v1/prod/plans/export`接口，支持Excel和CSV格式
- **进度报表**：使用GET `/v1/prod/plans/progress-report`接口，导出进度数据
- **审计日志**：使用GET `/v1/prod/plans/:planId/audit-logs`接口，查看变更历史
