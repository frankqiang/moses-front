# 创建排程方案接口详细说明

> **接口说明**：创建排程方案接口用于根据筛选条件创建排程方案并运行排程算法，生成退火炉排程结果。

---

## 🔔 最新更新（2025-10-24）

### ✨ 响应结构优化（2025-10-24）

#### 新增字段
- ✅ **`statusLabel`**: 方案状态中文名称（如"已生成"、"计算中"），无需前端映射
- ✅ **`algorithmTypeLabel`**: 算法类型中文名称（如"规则算法"），无需前端映射
- ✅ **`taskCount`**: 成功排程的任务总数，方便统计
- ✅ **`conflictCount`**: 检测到的冲突总数，方便统计

#### 结构调整
- ✅ **`items[].task`**: 排程结果项新增嵌套的任务详情对象，包含：
  - `task.id`: 任务ID
  - `task.taskCode`: 任务编号
  - `task.productCode`: 产品编码
  - `task.plannedWeight`: 计划重量（吨）
  - `task.alloyGrade`: 合金牌号

#### 字段名修正
- ✅ `planNumber` → `planCode`（统一命名规范）
- ✅ `plannedLoadTime` → `plannedLoadingAt`（统一时间字段命名）
- ✅ `plannedUnloadTime` → `plannedUnloadingAt`（统一时间字段命名）
- ✅ `algorithmExecutionTimeMs` → `computationDurationSeconds`（单位更清晰）

#### 升级影响
- 前端可直接使用 `statusLabel` 和 `algorithmTypeLabel`，减少枚举映射代码
- 前端通过 `items[].task.productCode` 直接获取产品信息，无需额外查询
- 旧字段名仍兼容，建议逐步迁移到新字段名

---

### ⚠️ 重要变更：参数优化

#### 新增参数（推荐使用）✅
- **`taskFilters.deliveryDateFrom`**: 按交货日期起筛选任务
- **`taskFilters.deliveryDateTo`**: 按交货日期止筛选任务
- **`taskFilters.planId`**: 按生产计划ID筛选（单个）
- **`taskFilters.planIds`**: 按生产计划ID列表筛选（多个）
- **`taskFilters.mixingGroupCode`**: 按混炉分组编码筛选
- **`taskFilters.includeScheduleLocked`**: 是否包含已锁定的任务

#### 废弃参数（不推荐，但仍兼容）❌
- **`taskFilters.plannedLoadingFrom`**: 已废弃，请使用 `deliveryDateFrom` 代替
- **`taskFilters.plannedLoadingTo`**: 已废弃，请使用 `deliveryDateTo` 代替

#### 变更原因
待排程任务的 `plannedLoadingAt`（计划装炉时间）字段为 NULL，使用时间范围筛选会导致找不到任何待排程任务。应该使用**交货期**（生产计划的 `plannedDeliveryDate`）来筛选需要优先排程的任务。

#### 迁移示例
```javascript
// ❌ 旧方式（已废弃）
{
  "taskFilters": {
    "plannedLoadingFrom": "2025-10-20T00:00:00.000Z",
    "plannedLoadingTo": "2025-10-27T00:00:00.000Z"
  }
}

// ✅ 新方式（推荐）
{
  "taskFilters": {
    "deliveryDateFrom": "2025-10-20T00:00:00.000Z",
    "deliveryDateTo": "2025-10-27T00:00:00.000Z"
  }
}
```

#### 兼容性说明
- 旧参数仍可使用，但会在服务器日志中输出废弃警告
- 建议尽快迁移到新参数，旧参数将在未来版本中移除
- 详细说明请查看 [taskFilters 结构](#taskfilters-结构)

## 功能概述

### 所有功能

创建排程方案（Create Schedule Plan）是退火炉排程管理模块中的核心功能之一，用于根据指定的时间范围和筛选条件创建排程方案并运行排程算法，以支持生产计划执行和设备资源优化的业务场景。

该接口综合考虑炉子容量（约40T）、工艺兼容性、物料可用性、设备维护等多维约束，通过选择的排程算法优化炉子利用率和装载率，生成详细的排程结果和冲突检测报告。

### 关键特性

- ✅ **多算法支持**：支持基于规则的启发式算法、约束规划算法、模拟退火算法、遗传算法等多种排程算法
- ✅ **智能冲突检测**：自动检测时间冲突、容量超限、工艺不兼容、物料未就绪、维护冲突等问题
- ✅ **灵活筛选条件**：支持按产品编码、合金牌号、优先级、时间范围、重量等条件筛选待排程任务
- ✅ **优化目标配置**：可自定义交期达成权重、炉子利用率权重、装载率权重、节能权重等优化目标
- ✅ **约束规则定制**：支持自定义容量范围、混炉规则等约束条件
- ✅ **实时性能监控**：提供算法执行时间、利用率、装载率、交期达成率等性能指标

---

### 使用前提

- ✅ 用户已登录并具备 `prod.scheduling.create` 权限
- ✅ 系统中存在状态为"待排程"的退火任务
- ✅ 设备管理模块中已配置退火炉基础信息和能力参数
- ✅ 排程时间范围内的任务数据完整且符合业务规则

### 不适用场景

- ❌ 排程时间范围内无待排程任务时不建议创建空方案
- ❌ 系统正在执行其他排程算法时应避免并发创建

### 详细步骤说明

#### 步骤1: 验证请求参数
- 验证时间范围有效性（开始时间必须早于结束时间）
- 验证算法类型是否为支持的枚举值
- 验证优化目标权重总和不超过1.0
- 验证约束规则配置的合理性

#### 步骤2: 获取待排程任务
- 查询数据库中状态为"待排程"的退火任务
- 排除已被其他排程方案锁定的任务
- 获取任务关联的产品信息、工艺参数、物料状态等

#### 步骤3: 应用筛选条件
- 根据taskFilters参数过滤任务列表
- 支持按产品编码、合金牌号、优先级、时间范围、重量等条件筛选
- 确保筛选后的任务符合排程时间窗口

#### 步骤4: 创建排程方案
- 生成唯一的排程方案ID和编号
- 设置方案状态为"computing"（运算中）
- 记录创建时间、创建人、算法类型等基础信息

#### 步骤5: 运行排程算法
- 根据algorithmType参数选择对应的排程算法
- 传入优化目标权重和约束规则配置
- 算法综合考虑炉子容量、工艺兼容性、物料可用性等约束
- 生成排程结果包括炉号分配、计划装炉/出炉时间等

#### 步骤6: 执行冲突检测
- 检测时间冲突：同一炉子的时间重叠
- 检测容量超限：任务总重量超出炉子容量
- 检测工艺不兼容：违反混炉规则的任务组合
- 检测物料未就绪：物料到达时间晚于计划装炉时间
- 检测维护冲突：与设备维护计划时间冲突

#### 步骤7: 保存排程结果
- 将算法生成的排程结果保存到数据库
- 更新方案状态为"generated"（已生成）
- 记录性能指标：利用率、装载率、交期达成率、算法执行时间

#### 步骤8: 返回方案详情
- 返回完整的排程方案信息
- 包含排程结果列表、冲突检测结果、性能指标等
- 记录操作日志供后续审计

## 接口文档

### 基本信息

**接口路径**: `POST /v1/prod/schedule-plans`

**功能描述**: 根据筛选条件创建排程方案并运行排程算法。系统将获取符合条件的待排程任务，根据选择的算法和配置生成排程结果，并自动执行冲突检测。

**认证要求**: Bearer Token认证，需要 `prod.scheduling.create` 权限

### 重要说明

#### 1. 筛选逻辑
- **taskFilters 用于筛选待排程任务**（status = 'pending-schedule'）
- 待排程任务的 `plannedLoadingAt` 字段为空（NULL），由排程算法自动计算
- 排程算法会根据**炉子可用性**、**任务优先级**、**交货期**等因素计算最优装炉时间

#### 2. 时间参数说明
| 参数              | 作用对象 | 含义                       | 示例                       |
| ----------------- | -------- | -------------------------- | -------------------------- |
| scheduleStartTime | 排程窗口 | 排程算法计算的时间范围起点 | "2025-10-20T00:00:00.000Z" |
| scheduleEndTime   | 排程窗口 | 排程算法计算的时间范围终点 | "2025-10-27T23:59:59.999Z" |
| deliveryDateFrom  | 任务筛选 | 筛选交货期 >= 此时间的任务 | "2025-10-20"               |
| deliveryDateTo    | 任务筛选 | 筛选交货期 <= 此时间的任务 | "2025-10-27"               |

#### 3. 废弃参数说明
- `plannedLoadingFrom` 和 `plannedLoadingTo` 已废弃
- **废弃原因**：待排程任务的 `plannedLoadingAt` 字段为 NULL，使用这两个参数筛选会导致找不到任何待排程任务
- **替代方案**：使用 `deliveryDateFrom` 和 `deliveryDateTo` 按生产计划的交货期筛选任务
- **兼容性**：这两个参数暂时保留，但会在日志中输出废弃警告，建议尽快迁移到新参数

## 常见问题

### Q1: 创建排程方案时提示"无待排程任务"？

**A**: 检查以下几个方面：
- 确认指定时间范围内确实存在状态为"待排程"的退火任务
- 检查taskFilters筛选条件是否过于严格，导致过滤掉了所有任务
- 确认任务没有被其他排程方案锁定
- 联系生产计划人员确认是否有新任务需要创建

### Q2: 优化目标权重应如何设置？

**A**: 根据不同生产模式调整：
- **订单生产模式**：提高meetDeadlineWeight（0.5-0.6）
- **库存生产模式**：提高utilizationWeight和loadRateWeight（各0.3-0.4）
- **节能模式**：适当提高energySavingWeight（0.15-0.2）
- **平衡模式**：使用默认配置（0.4, 0.3, 0.2, 0.1）

### Q3: 不同排程算法的选择标准？

**A**:
- **rule-based**：日常使用，任务数<100，执行快速稳定
- **constraint-programming**：复杂约束场景，需要精确最优解
- **simulated-annealing**：大规模排程，任务数>200
- **genetic-algorithm**：研究和特殊优化需求

### Q4: 算法执行时间过长怎么办？

**A**:
- 缩短排程时间范围（如从月度改为周度）
- 使用更高效的rule-based算法
- 增加筛选条件减少待排程任务数量
- 如必须使用复杂算法，可考虑异步处理

### Q5: 如何处理创建后发现的冲突？

**A**:
- 使用 `GET /v1/prod/schedule-plans/:id/conflicts` 查看详细冲突信息
- 对于CRITICAL级别冲突，必须通过手动调整接口解决
- 对于HIGH/MEDIUM级别冲突，可以选择强制发布或手动调整
- 参考冲突解决建议进行操作
