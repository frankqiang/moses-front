## 🔔 最新更新（2025-10-24）

### ✨ 响应结构优化

#### 新增字段
- ✅ **`plan.statusLabel`**: 方案状态中文名称（如"已生成"、"已发布"），无需前端映射
- ✅ **`plan.algorithmTypeLabel`**: 算法类型中文名称（如"规则算法"），无需前端映射

#### 结构调整
- ✅ **`items[].task`**: 任务详情对象字段简化，只保留核心字段：
  - `task.id`: 任务ID
  - `task.taskCode`: 任务编号
  - `task.productCode`: 产品编码
  - `task.plannedWeight`: 计划重量（吨）
  - `task.alloyGrade`: 合金牌号
- ❌ 移除冗余字段：`customerName`、`urgencyLevel`、`plannedQuantity`、`actualWeight`

#### 升级影响
- 前端可直接使用 `statusLabel` 和 `algorithmTypeLabel`，减少枚举映射代码
- 任务详情更聚焦，减少不必要的数据传输
- 产品和客户信息可通过任务详情接口单独查询

## 功能概述

### 所有功能

获取排程方案详情（Get Schedule Plan Detail）是退火排程管理模块中的核心查询接口之一，用于获取指定排程方案的完整详细信息，以支持排程方案查看、调整、分析决策的业务场景。

### 关键特性

- ✅ **完整信息展示**：返回排程方案的基本信息、算法参数、评分结果、状态信息等全部详情
- ✅ **排程结果查看**：提供方案中所有排程结果项的详细信息，包含任务、炉号、时间安排等
- ✅ **冲突检测结果**：展示排程过程中检测到的所有冲突信息及其严重程度
- ✅ **操作日志跟踪**：提供方案的完整操作历史记录，支持审计追溯
- ✅ **关联数据加载**：包含创建人、更新人等用户信息，以及关联的退火任务详情
- ✅ **状态实时展示**：准确反映方案当前状态和各阶段时间节点

---

### 使用前提

- ✅ 用户已通过身份认证并具备有效的访问令牌
- ✅ 用户拥有 `prod.scheduling.view` 权限
- ✅ 提供的排程方案ID必须存在且有效
- ✅ 排程方案未被删除（软删除状态下不可访问）

### 不适用场景

- ❌ 批量查询多个排程方案（应使用排程方案列表接口）
- ❌ 仅需要基本信息而不需要详细数据的轻量级查询场景

### 详细步骤说明

#### 步骤1: 接收请求参数
- 从路径参数中提取排程方案ID
- 验证ID格式是否为有效的UUID
- 检查用户认证状态和访问权限

#### 步骤2: 参数验证校验
- 校验用户是否具备 `prod.scheduling.view` 权限
- 验证排程方案ID格式是否符合UUID规范
- 确认请求头中包含有效的认证令牌

#### 步骤3: 查询排程方案基本信息
- 根据ID查询排程方案主表数据
- 检查方案是否存在且未被删除
- 获取方案编号、名称、状态、时间范围等基础信息

#### 步骤4: 关联查询排程结果项列表
- 查询该方案下所有的排程结果项
- 包含任务ID、炉号、计划时间、持续时长等
- 按序号或时间排序返回有序列表

#### 步骤5: 关联查询冲突检测结果
- 查询方案相关的所有冲突记录
- 按严重程度分类展示冲突信息
- 提供冲突描述和解决建议

#### 步骤6: 关联查询操作日志记录
- 获取方案的操作历史记录
- 包含创建、调整、发布、取消等操作
- 按时间倒序返回最近的操作记录

#### 步骤7: 关联查询用户信息数据
- 查询创建人、更新人等用户基本信息
- 提供用户姓名、角色等展示数据
- 确保敏感信息不被泄露

#### 步骤8: 组装响应数据并返回结果
- 将所有查询结果组装成统一的数据结构
- 对敏感字段进行过滤处理
- 返回符合API规范的JSON响应

## 接口文档

### 基本信息

**接口路径**: `GET /v1/prod/schedule-plans/:id`

**功能描述**: 获取指定排程方案的详细信息，包含排程结果、冲突记录、操作日志等完整数据

**认证要求**: Bearer Token认证，需要 `prod.scheduling.view` 权限

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json

  "error": {
    "code": "ERROR_CODE",

    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号


**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

## 常见问题

### Q1: 为什么获取不到排程方案详情？

**A1**: 可能的原因包括：
- 排程方案ID不存在或格式错误
- 方案已被删除（软删除）
- 用户没有查看权限
- 认证令牌已过期

建议检查ID格式、确认权限配置、更新访问令牌。

### Q2: 响应数据量很大，如何优化加载性能？

**A2**: 该接口返回完整详情，数据量较大是正常的。优化建议：
- 仅在需要详细信息时调用该接口
- 考虑使用分页加载操作日志
- 前端实现数据缓存机制
- 必要时可联系后端团队提供轻量级查询接口

### Q3: 排程结果项的关联任务信息不完整怎么办？

**A3**: 如果任务详情不足，可能是：
- 关联的退火任务被删除或状态异常
- 数据库关联关系存在问题
- 权限限制导致部分字段被过滤

建议检查任务状态，必要时联系技术支持。

### Q4: 冲突检测结果如何理解和处理？

**A4**: 冲突检测结果说明：
- `severity` 为 `critical` 的冲突必须处理才能发布
- `high` 和 `medium` 级别的冲突建议处理
- `low` 级别的冲突可以接受
- 查看 `resolutionSuggestion` 获取处理建议

### Q5: 操作日志记录不全或缺失？

**A5**: 操作日志默认返回最近的记录，如需完整历史：
- 检查日志记录的时间范围
- 确认操作是否正确触发了日志记录
- 部分旧版本操作可能没有完整日志
- 可通过审计模块查询更详细的历史记录
