## 功能概述

### 所有功能

取消排程方案（Cancel Schedule Plan）是退火炉排程管理模块中的重要操作之一，用于取消未发布或正在计算的排程方案，并释放关联的退火任务锁定状态，以支持排程方案的灵活调整和管理的业务场景。

当排程方案因业务变更、设备调整、任务优先级变更等原因不再需要时，可以通过此接口取消方案，使关联的退火任务重新回到待排程状态，供其他排程方案使用。

### 关键特性

- ✅ **状态智能校验**：自动校验排程方案状态，只有草稿、计算中、已生成的方案可以取消，已发布的方案不允许取消
- ✅ **任务锁定释放**：自动释放排程方案关联的所有退火任务的锁定状态，使任务重新可用
- ✅ **原因记录追溯**：强制要求填写取消原因，完整记录取消操作的上下文信息，支持后续追溯
- ✅ **操作日志完整**：自动记录取消操作的完整日志，包括操作人、操作时间、取消原因等信息
- ✅ **事务安全保障**：使用数据库事务确保取消操作的原子性，避免数据不一致
- ✅ **幂等性保护**：已取消的方案不能重复取消，避免误操作

---

### 使用前提

- ✅ 排程方案必须存在且未被删除
- ✅ 操作人必须具备 `prod.scheduling.cancel` 权限
- ✅ 排程方案状态必须为 `draft`、`computing` 或 `generated` 之一
- ✅ 必须提供明确的取消原因说明

### 不适用场景

- ❌ 已发布（published）的排程方案不能直接取消，需要通过其他方式处理（如创建新的排程方案覆盖）
- ❌ 已取消（cancelled）的排程方案不能重复取消
- ❌ 不适用于需要回退退火任务排程信息的场景（取消操作不会回退已发布方案对任务的影响）

### 详细步骤说明

#### 步骤1: 接收取消请求

**功能说明**：
- 接收客户端传入的排程方案ID（路径参数）和取消原因（请求体）
- 提取操作人信息（从认证令牌中获取）

**数据来源**：
- `planId`：URL路径参数
- `reason`：请求体JSON字段
- `operatorInfo`：从JWT令牌解析得到，包含 userId、userName、userRole、ipAddress

#### 步骤2: 参数校验

**校验规则**：
- `planId` 不能为空，必须为有效的UUID格式
- `reason` 不能为空，最大长度500字符
- `operatorInfo.userId` 不能为空

**校验失败处理**：
- 抛出 `400 Bad Request` 错误
- 错误码：`PARAM_ERROR`
- 错误消息：具体指明哪个参数校验失败

#### 步骤3: 开启数据库事务

**事务目的**：
- 确保取消操作的原子性（要么全部成功，要么全部回滚）
- 避免并发操作导致的数据不一致
- 使用行级锁防止并发修改

**事务范围**：
- 排程方案状态更新
- 任务锁定状态释放
- 变更日志记录

#### 步骤4: 查询排程方案

**查询条件**：
- 根据 `planId` 查询排程方案
- 关联查询 `items`（排程结果项）
- 使用 `transaction.LOCK.UPDATE` 添加行级锁

**返回数据**：
- 排程方案完整信息
- 包含关联的排程结果项列表

#### 步骤5: 方案存在性校验

**校验逻辑**：
- 检查查询结果是否为空
- 如果方案不存在，抛出 `404 Not Found` 错误

**错误处理**：
- 错误码：`RESOURCE_NOT_FOUND`
- 错误消息：`排程方案不存在`
- 错误详情：包含 `planId`

#### 步骤6: 方案状态校验

**校验规则**：

1. **禁止取消已发布的方案**：
   - 条件：`plan.status === 'published'`
   - 原因：已发布的方案已经同步到退火任务，不能简单取消
   - 错误码：`INVALID_STATUS`
   - 错误消息：`已发布的排程方案不允许取消`

2. **禁止重复取消**：
   - 条件：`plan.status === 'cancelled'`
   - 原因：方案已经被取消，避免重复操作
   - 错误码：`INVALID_STATUS`
   - 错误消息：`排程方案已被取消`

3. **允许取消的状态**：
   - `draft`（草稿）
   - `computing`（计算中）
   - `generated`（已生成）

**日志记录**：
- 记录开始取消操作的日志
- 包含方案ID、方案编号、关联任务数量、操作人信息

#### 步骤7: 释放任务锁定

**释放逻辑**：

1. **收集任务ID列表**：
   - 从 `plan.items` 中提取所有 `taskId`
   - 构建任务ID数组

2. **调用解锁服务**：
   - 调用 `annealingTaskSchedulingService.unlockTasksForScheduling()`
   - 传递任务ID列表和操作人信息
   - 在当前事务中执行

3. **异常处理**：
   - 如果解锁失败，记录错误日志
   - **不阻断取消流程**（继续执行后续步骤）
   - 原因：方案取消的优先级高于任务解锁

**日志输出**：
- 成功：`释放任务锁定成功: taskCount=${taskIds.length}`
- 失败：`释放任务锁定失败: ${error.message}`

#### 步骤8: 更新方案状态

**更新字段**：
- `status`：设置为 `cancelled`
- `cancelledAt`：当前时间戳
- `cancelReason`：取消原因（去除首尾空格）
- `statusUpdatedAt`：当前时间戳
- `updatedBy`：操作人ID

**数据完整性**：
- 使用 `plan.update()` 方法确保触发模型钩子
- 在事务中执行，保证原子性

#### 步骤9: 记录变更日志

**日志内容**：
- `schedulePlanId`：排程方案ID
- `action`：`plan-cancelled`（取消方案）
- `operatorId`：操作人ID
- `operatorName`：操作人姓名
- `operatorRole`：操作人角色
- `targetType`：`plan`（目标类型为方案）
- `targetId`：排程方案ID
- `oldValue`：原状态信息 `{ status: <原状态> }`
- `newValue`：新状态信息 `{ status: 'cancelled', cancelledAt, cancelReason }`
- `changeDescription`：`取消排程方案: ${planCode}`
- `remarks`：取消原因
- `operationContext`：包含 IP 地址和释放的任务数量

**日志用途**：
- 审计追溯
- 问题排查
- 操作历史查询

#### 步骤10: 提交事务

**提交时机**：
- 所有数据库操作成功完成后
- 变更日志记录成功后

**失败回滚**：
- 任何步骤失败时，事务自动回滚
- 所有数据变更撤销
- 抛出原始错误

#### 步骤11: 重新查询完整数据

**查询目的**：
- 确保返回最新的数据
- 包含关联数据（items、conflicts、changeLogs）

**关联查询**：
- `items`：排程结果项列表
- `conflicts`：冲突记录列表
- `changeLogs`：最近10条变更日志（按时间倒序）

**返回数据**：
- 转换为 JSON 对象返回给客户端

## 接口文档

### 基本信息

**接口路径**: `POST /v1/prod/schedule-plans/:id/cancel`

**功能描述**: 取消排程方案并释放关联的退火任务锁定。支持取消草稿、计算中、已生成状态的方案，已发布的方案不允许取消。取消操作将自动释放所有关联任务的锁定状态，使其可以被其他排程方案使用。

**认证要求**: Bearer Token，需要 `prod.scheduling.cancel` 权限

## 使用示例

### 场景1: 设备故障需要取消排程

**业务需求**：TH-01炉突发故障，需要取消已生成但未发布的排程方案，重新编排到其他炉子。

**操作步骤**：
1. 通过排程列表查询到待取消的方案ID
2. 确认方案状态为 `generated`（已生成）
3. 调用取消接口，提供设备故障原因
4. 系统自动释放关联的25个退火任务
5. 任务重新变为待排程状态，可以被新方案使用

**业务价值**：
- 快速响应设备异常情况
- 避免任务被错误的方案锁定
- 完整记录故障原因，便于后续分析

### 场景2: 排程算法配置错误需要重新生成

**业务需求**：发现排程方案使用的约束规则配置有误（如炉子容量参数设置错误），导致生成的方案不合理，需要取消后重新配置并生成。

**操作步骤**：
1. 查看排程方案详情，发现装载率异常（如只有50%）
2. 确认是因为约束规则中炉子容量参数设置过小
3. 取消当前方案
4. 修正约束规则配置
5. 重新创建排程方案

**业务价值**：
- 确保排程方案的准确性
- 支持配置调优和试错
- 记录配置变更历史

### 场景3: 生产计划调整，降低优先级

**业务需求**：收到上游通知，本批次订单交期延后，不需要立即排程，取消当前排程方案，优先处理更紧急的订单。

**操作步骤**：
1. 接收到生产计划调整通知
2. 查询当前正在进行的排程方案
3. 取消低优先级批次的排程方案
4. 释放的任务留待后续重新排程
5. 创建新的排程方案处理高优先级订单

**业务价值**：
- 灵活应对生产计划变化
- 支持优先级动态调整
- 记录计划调整决策依据

### 场景4: 算法计算中途发现问题需要中止

**业务需求**：创建排程方案后，算法正在计算中（status=computing），发现筛选条件设置有误（如时间范围错误），需要立即中止并取消方案。

## 常见问题

### Q1: 已发布的排程方案能取消吗？

**答**：不能。已发布（status=published）的排程方案已经同步到退火任务，任务状态已经更新为"已排程"，不能通过简单取消来回退。

**处理方式**：
- 如果需要调整已发布的方案，应该创建新的排程方案覆盖旧的排程信息
- 或者通过退火任务管理接口单独调整具体任务的排程信息
- 或者联系管理员评估是否需要手动回退数据

### Q2: 取消方案后，关联的退火任务会怎样？

**答**：取消方案后，系统会自动释放关联任务的锁定状态，使其重新变为"待排程"状态。

**具体效果**：
- 任务的 `schedulePlanId` 字段清空
- 任务的 `plannedFurnaceCode`、`plannedLoadingAt` 等排程信息清空
- 任务状态保持为 `pending-schedule`（待排程）
- 任务可以被其他新的排程方案使用

**注意事项**：
- 解锁失败不会阻断取消操作（会记录日志）
- 已发布方案取消后不会自动回退任务信息

### Q3: 取消原因必须填写吗？

**答**：是的，取消原因（reason）是必填字段。

**原因**：
- 便于后续审计和追溯
- 帮助分析排程方案取消的主要原因
- 支持问题排查和流程优化
- 记录在变更日志中，可供团队查询

**建议**：
- 提供明确、具体的取消原因
- 长度控制在1-500字符
- 避免使用过于简单的理由（如"取消"、"不要了"）

### Q4: 取消方案后能恢复吗？

**答**：不能直接恢复。取消是不可逆操作。

**替代方案**：
- 如果需要类似的排程方案，可以使用相同的配置参数重新创建
- 变更日志中保存了方案的原始配置信息，可以参考历史记录
- 建议在取消前确认是否真的需要取消

**最佳实践**：
- 在取消前通过排程详情接口查看方案信息
- 确认方案状态和关联任务数量
- 评估取消的影响范围

### Q5: 取消操作失败了怎么办？

**答**：取消操作使用数据库事务保证原子性，失败时会自动回滚。

**常见失败原因**：
1. 方案已被删除（404错误）
2. 方案状态不允许取消（400错误，如已发布）
3. 数据库连接异常（500错误）
4. 并发操作冲突（500错误）

**处理建议**：
- 检查错误码和错误消息，确定具体原因
- 如果是状态问题，确认方案当前状态
- 如果是系统错误，记录requestId并联系技术支持
- 稍后重试操作

### Q6: 取消操作会影响其他排程方案吗？

**答**：不会。取消操作只影响当前指定的排程方案及其关联的任务。

**隔离保障**：
- 使用行级锁确保并发安全
- 事务保证操作的原子性
- 不会影响其他方案的状态和数据
- 释放的任务可以被其他方案使用

### Q7: 草稿状态的方案能取消吗？

**答**：可以。草稿状态（status=draft）的方案可以随时取消。

**适用场景**：
- 创建方案后发现参数设置错误
- 暂时不需要该方案
- 需要重新规划排程策略

**注意**：草稿状态的方案通常还没有关联任务，取消操作主要是更新方案状态。

### Q8: 取消方案时任务解锁失败会怎样？

**答**：任务解锁失败不会阻断取消操作的完成。

**处理逻辑**：
- 系统会记录解锁失败的错误日志
- 方案状态仍然会更新为已取消
- 变更日志仍然会被记录
- 事务仍然会提交

**原因**：
- 方案取消的优先级高于任务解锁
- 避免因任务问题导致方案无法取消
- 任务锁定状态可以后续手动处理

**后续处理**：
- 运维人员可通过日志排查解锁失败原因
- 必要时手动调整任务状态
- 通常情况下任务会在超时后自动解锁

### Q9: 如何查询被取消的排程方案？

**答**：通过排程方案列表接口，使用状态筛选参数。

**查询方式**：
```bash
GET /v1/prod/schedule-plans?status=cancelled&sortBy=cancelledAt:desc
```

**返回信息**：
- 包含取消时间（cancelledAt）
- 包含取消原因（cancelReason）
- 包含完整的方案配置和结果
- 可以查看变更日志了解取消操作详情

### Q10: 取消方案需要什么权限？

**答**：需要 `prod.scheduling.cancel` 权限。

**权限说明**：
- 权限码：`prod.scheduling.cancel`
- 权限名称：取消排程方案
- 所属模块：生产模块 - 排程管理

**角色建议**：
- 生产调度员：建议授予此权限
- 排程专员：建议授予此权限
- 车间主任：建议授予此权限
- 普通操作工：不建议授予

**权限申请**：
- 联系系统管理员
- 说明业务需求和使用场景
- 通过审批后由管理员授权

### 排程方案状态枚举

| 状态码    | 中文名称 | 说明                                 | 可否取消 |
| --------- | -------- | ------------------------------------ | -------- |
| draft     | 草稿     | 方案已创建但未开始计算               | ✅ 可以   |
| computing | 计算中   | 排程算法正在运行                     | ✅ 可以   |
| generated | 已生成   | 排程算法已完成，方案已生成，待发布   | ✅ 可以   |
| published | 已发布   | 方案已发布，排程信息已同步到退火任务 | ❌ 不可以 |
| cancelled | 已取消   | 方案已被取消，关联任务已解锁         | ❌ 不可以 |

### 状态转换图

```
draft（草稿）
    ↓ 运行算法
computing（计算中）
    ↓ 算法完成
generated（已生成）
    ↓ 发布
published（已发布）

draft/computing/generated → cancelled（已取消）
❌ published → cancelled（禁止）
❌ cancelled → cancelled（禁止重复取消）
```
