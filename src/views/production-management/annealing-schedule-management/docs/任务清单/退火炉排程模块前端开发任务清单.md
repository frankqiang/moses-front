# 退火炉排程模块前端开发任务清单

## 项目概述

退火炉排程模块是生产执行系统的核心调度引擎,负责将待执行的退火任务合理分配到各个退火炉,制定详细的炉次排程计划。本模块需要综合考虑炉子容量(约40T)、工艺兼容性、物料可用性、设备维护等多维约束,通过智能排程算法优化炉子利用率和装载率,并提供可视化的甘特图展示,支持手动调整与冲突检测。模块与退火任务管理、设备管理、物流任务生成等模块紧密协同,确保排程结果能够指导实际生产执行。

- 实现多条件筛选功能，支持按方案状态、算法类型、排程开始时间范围(scheduleStartTimeFrom至scheduleStartTimeTo)、创建时间范围(createdAtStart至createdAtEnd)、创建人ID筛选

- 列表每行提供操作按钮：查看详情、查看甘特图、发布（仅generated状态）、取消（仅draft/generated状态）
- 实现批量操作功能，支持批量取消已选中的草稿或已生成状态方案
- 实现列表自动刷新功能，当检测到方案状态为"运算中"时，每3秒自动刷新列表获取最新状态
- 实现权限控制：查看列表需要`prod.scheduling.view`权限，发布和取消按钮需要对应权限
- 处理接口错误响应，针对不同错误码（SPM_001方案不存在、SPM_005查询失败等）显示对应的用户友好提示
- 实现操作按钮的权限显示，无对应权限时隐藏或禁用操作按钮

- 第一步：基本信息配置，包含排程时间范围(scheduleStartTime必填、scheduleEndTime必填)、方案名称(planName可选，最大200字符)、算法类型(algorithmType必选)、备注(remarks可选，最大1000字符)
- 排程时间范围使用日期时间范围选择器，结束时间必须晚于开始时间，建议默认值为当前时间的未来7天
- 算法类型使用单选或下拉选择，选项包括：基于规则的启发式算法(推荐⭐⭐⭐⭐⭐)、约束规划算法、模拟退火算法、遗传算法
- 每个算法类型提供详细说明：特点、适用场景、推荐度，帮助用户选择合适的算法

- 任务筛选条件均为可选，不填写表示不限制该条件
- 优先级列表支持多选勾选框或标签输入，选项包括：低(low)、中(medium)、高(high)、紧急(emergency)
- 重量范围输入支持数值输入框，带单位标识"吨"，校验范围0.01-100
- 提供"预览待排程任务"按钮，根据当前筛选条件调用 `GET /v1/prod/annealing-tasks/scheduling/pending` 接口查询符合条件的待排程任务数量和列表摘要
- 预览功能将taskFilters中的参数（productCode、alloyGrade、priorities、minWeight、maxWeight等）作为query参数传递给接口
- 预览结果展示：任务总数、任务列表（显示任务编号、产品编码、重量、优先级等关键信息）、总重量统计
- 第三步：优化目标配置(optimizationGoals对象)，包含交期达成权重(meetDeadlineWeight)、炉子利用率权重(utilizationWeight)、装载率权重(loadRateWeight)、节能权重(energySavingWeight)

- 提供预设配置模板：交期敏感型(0.5/0.2/0.2/0.1)、效率优先型(0.2/0.4/0.3/0.1)、平衡型(0.4/0.3/0.2/0.1)，用户可快速选择
- 实时显示权重总和及剩余可分配权重，超过1.0时显示错误提示
- 第四步：约束规则配置(constraintRules对象)，包含最小容量(minCapacity，单位吨，默认35)、最大容量(maxCapacity，单位吨，默认42)、是否允许混炉(allowMixing，布尔值，默认true)、~~混炉规则(mixingRules对象，自定义)~~【已取消，P0阶段暂不实现】

- 排程方案详情能够完整展示方案信息、排程结果、冲突记录、操作日志
- 排程甘特图能够可视化展示排程结果，支持交互查看
- 调度员可以手动调整排程结果，实时检测冲突
- 调度员可以发布排程方案，同步更新退火任务状态
- 调度员可以取消排程方案，释放任务锁定
- 所有操作有权限控制，有错误提示

### 🟡 **第二阶段：重要功能（后续优化）**

**目标：** 提升排程配置效率和用户体验，减少重复操作成本

**时间要求：** 第一阶段完成后1-2周内

1. **TASK007** - 排程配置管理功能（P1 重要功能）
2. **TASK001-TASK006的P1验收标准** - 导出、批量操作、配置模板、历史记录等优化功能

### 🟢 **第三阶段：优化功能（可暂缓实施）**

**目标：** 提供更丰富的交互和智能化辅助，提升排程质量和决策效率

**时间要求：** 可根据项目时间和资源情况决定是否实施

1. **任务块拖拽调整** - 在甘特图上直接拖拽任务块调整时间和炉号
2. **方案对比功能** - 对比多个排程方案的关键指标和差异
3. **智能冲突修复** - 自动建议和执行冲突解决方案
4. **排程优化建议** - 基于历史数据分析，提供排程参数优化建议
5. **移动端支持** - 提供移动端查看排程甘特图和审批发布的功能

**⚠️ 重要提醒：** 第三阶段功能可以完全暂缓，不会影响系统的基本运行和主要业务流程。即使没有拖拽调整和智能建议，用户仍然可以通过手动调整对话框修改排程结果。

## 🎯 紧急开发模式总结

### ✅ **当前阶段必须完成（P0）：**

- 权限配置与菜单集成
- 排程方案列表的基本展示、搜索、筛选、状态管理功能
- 创建排程方案的配置表单和算法执行功能
- 排程方案详情的完整展示（方案信息、排程结果、冲突记录、操作日志）
- 排程甘特图的可视化展示和交互查看功能
- 手动调整排程结果的表单输入和实时冲突检测功能
- 发布和取消排程方案的确认对话框和执行功能
- 统一的错误处理和用户提示
- 与后端接口的完整对接

### ⏳ **可以简化实现的功能：**

- 批量操作 → 暂缓实现，第一阶段仅支持单个操作
- 导出功能 → 暂缓实现，可通过后端直接导出或手动截图替代
- 配置模板保存 → 暂缓实现，用户可手动记录常用配置
- 调整历史记录 → 暂缓实现，第一阶段仅在操作日志中记录
- 方案对比 → 暂缓实现，用户可打开多个页面手动对比

### ❌ **可以完全暂缓的功能：**

- TASK007排程配置管理功能（可手动填写配置替代）
- 任务块拖拽调整（可用手动调整对话框替代）
- 方案对比功能（可打开多个页面手动对比）
- 智能冲突修复（可手动调整替代）
- 排程优化建议（可依靠经验替代）
- 移动端支持（可使用PC端替代）
- 所有P1和P2验收标准的功能

### 🚀 **开发建议：**

1. **优先实现核心流程：** 确保创建-查看-调整-发布的完整流程能够顺利走通
2. **精简UI交互：** 第一阶段可使用简单的表单和列表，不追求复杂的交互效果和动画
3. **充分利用后端能力：** 后端已实现完整的排程算法、约束校验、冲突检测，前端重点在于数据展示和用户交互
4. **分步骤测试：** 每完成一个页面立即测试，确保基础功能稳定后再继续
5. **关注甘特图性能：** 甘特图是复杂的可视化组件，建议使用成熟的第三方库，避免自己实现
6. **重视冲突检测反馈：** 冲突检测是排程系统的核心功能，需要清晰直观地展示冲突信息和解决建议
7. **预留扩展接口：** 考虑未来可能的功能扩展，如任务块拖拽、方案对比等，设计时预留扩展点

**预期效果：** 完成P0阶段后，系统具备完整的排程方案管理能力，调度员可以高效地创建排程方案、查看排程结果、手动调整冲突、发布排程计划，为退火任务的执行提供明确的炉次分配和时间安排。虽然缺少配置模板和智能建议等高级功能，但不影响系统的核心价值交付。
