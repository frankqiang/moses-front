## 🎯 1. 业务背景与目标

### 1.1 模块定位

退火炉排程模块是Moses生产执行系统(MES)的核心调度引擎，负责将待执行的退火任务合理分配到各个退火炉，制定详细的炉次排程计划。

### 1.2 业务价值

**解决的核心问题：**
- **人工排程效率低**：传统依赖调度员经验进行手工排程，耗时且容易出错
- **炉子利用率不高**：缺乏科学的装载规划，炉子经常出现空载或低载运行
- **冲突频繁发生**：时间冲突、容量超限、工艺不兼容等问题影响生产连续性
- **交期难以保证**：缺乏整体优化，紧急任务插单困难

**预期目标：**
- **炉子利用率** ≥ 85%
- **装载率** ≥ 90%
- **交期达成率** ≥ 95%
- **排程冲突率** ≤ 5%

### 1.3 业务范围

**包含功能：**
- 排程方案创建与算法执行
- 排程结果查看与甘特图可视化
- 手动调整与实时冲突检测
- 排程方案发布与任务同步
- 排程历史与操作日志管理

**不包含功能：**
- 退火任务的创建（由任务管理模块负责）
- 炉子设备的维护管理（由设备管理模块负责）
- 具体的工艺参数控制（由执行监控模块负责）

## 🧩 2. 核心概念解释

### 2.1 基础概念

#### **排程方案 (Schedule Plan)**
- **定义**: 一个完整的炉次分配计划，包含特定时间范围内所有待排程任务的炉次安排
- **生命周期**: 草稿 → 运算中 → 已生成 → 已发布 → (已取消)
- **核心属性**: 方案编号、时间范围、算法类型、优化目标、约束规则
- **业务价值**: 为生产执行提供明确的炉次计划和时间安排

#### **排程结果项 (Schedule Plan Item)**
- **定义**: 排程方案中的单个任务分配记录，描述具体任务在具体炉子的具体时间安排
- **包含信息**: 任务ID、炉号、计划装炉时间、计划出炉时间、预计时长、是否混炉
- **业务意义**: 指导生产执行人员按照什么顺序、在什么时间、使用哪个炉子执行哪个任务

#### **炉次 (Furnace Batch)**
- **定义**: 一次退火操作，可能包含一个或多个兼容的任务（混炉）
- **容量约束**: 单炉最小35吨，最大42吨（可配置）
- **时间约束**: 包含装炉、升温、保温、降温、出炉等完整过程

#### **混炉 (Mixed Loading)**
- **定义**: 将多个工艺兼容的任务合并到同一炉次执行
- **兼容条件**:
  - 相同产品编码：完全兼容 ✅
  - 相同合金牌号 + 相近温度范围（±20°C）：兼容 ✅
  - 不同合金牌号：不兼容 ❌
- **业务价值**: 提高炉子装载率，降低单位能耗

### 2.2 状态概念

#### **方案状态**
- **draft (草稿)**: 刚创建，尚未运行排程算法
- **computing (运算中)**: 正在执行排程算法，请等待
- **generated (已生成)**: 算法执行完成，可查看结果、手动调整、发布
- **published (已发布)**: 已发布给生产执行，任务状态已同步更新
- **cancelled (已取消)**: 方案已取消，不再使用

#### **冲突严重程度**
- **critical (致命)**: 绝对不允许发布，必须解决（如时间冲突、容量超限）
- **high (高)**: 强烈建议解决，可强制发布（如工艺不兼容）
- **medium (中)**: 建议解决，可直接发布（如物料未就绪）
- **low (低)**: 提示性信息，不影响发布

## ⚙️ 4. 业务规则与约束

### 4.1 硬性约束（必须满足）

#### **炉子容量约束**
- **规则**: 分配到同一炉次的任务总重量必须在35-42吨范围内
- **检查时机**: 算法运行时、手动调整时
- **违反后果**: 产生"容量超限"致命冲突，无法发布

#### **时间冲突约束**
- **规则**: 同一炉子不能在同一时间段执行多个任务
- **检查时机**: 算法运行时、手动调整时
- **违反后果**: 产生"时间冲突"致命冲突，无法发布

#### **设备维护约束**
- **规则**: 不能将任务排在设备计划维护时间段内
- **数据来源**: 设备管理模块的维护计划
- **违反后果**: 产生"维护冲突"致命冲突，无法发布

### 4.2 软性约束（优化目标）

#### **工艺兼容性约束**
- **规则**: 只有工艺兼容的任务才建议合并到同一炉次
- **兼容规则**: 相同产品 > 相同合金牌号 > 相近温度
- **违反后果**: 产生"工艺不兼容"高级冲突，可强制发布

#### **物料可用性约束**
- **规则**: 排程时间应考虑物料到达时间和准备时间
- **违反后果**: 产生"物料未就绪"中级冲突，可正常发布

#### **交期达成约束**
- **规则**: 任务完成时间尽量不超过客户要求的交期
- **处理方式**: 通过优化目标权重平衡，不产生冲突

## 🤖 5. 排程算法说明

### 5.1 算法类型对比

| 算法类型                 | 执行时间 | 适用场景               | 优缺点                       | 推荐度 |
| ------------------------ | -------- | ---------------------- | ---------------------------- | ------ |
| **基于规则的启发式算法** | < 2秒    | 日常排程、任务数<100   | 快速、稳定、可解释性强       | ⭐⭐⭐⭐⭐  |
| **约束规划算法**         | 2-10秒   | 复杂约束场景           | 精确、保证最优解，但耗时较长 | ⭐⭐⭐⭐   |
| **模拟退火算法**         | 3-15秒   | 大规模排程、任务数>200 | 全局优化、避免局部最优       | ⭐⭐⭐    |
| **遗传算法**             | 5-20秒   | 科研优化               | 多目标优化，但稳定性较差     | ⭐⭐     |

### 5.2 推荐算法选择策略

**日常生产排程**：推荐使用"基于规则的启发式算法"
- 执行速度快（<2秒）
- 结果稳定可靠
- 可解释性强，便于理解调整

**复杂约束场景**：使用"约束规划算法"
- 能精确满足多重约束
- 保证找到可行解
- 适合高价值订单排程

### 5.3 算法执行过程

```
1. 数据准备
   ├── 获取待排程任务列表
   ├── 获取可用炉子列表
   ├── 获取设备维护计划
   └── 加载约束规则配置

2. 约束校验
   ├── 检查任务基础数据完整性
   ├── 验证炉子能力匹配
   └── 确认时间范围合理性

3. 排程计算
   ├── 按优先级排序任务
   ├── 应用混炉规则合并兼容任务
   ├── 分配炉子和时间段
   └── 优化目标函数

4. 冲突检测
   ├── 时间冲突检测
   ├── 容量超限检测
   ├── 工艺兼容性检测
   └── 其他约束检测

5. 结果生成
   ├── 生成排程结果项列表
   ├── 计算关键指标
   ├── 标记冲突任务
   └── 记录执行日志
```

## 📈 6. 关键指标说明

### 6.1 核心KPI定义

#### **炉子利用率 (Utilization Rate)**
- **计算公式**: 实际使用时间 / 可用时间 × 100%
- **业务含义**: 炉子的繁忙程度，反映设备效率
- **目标值**: ≥ 85%
- **影响因素**: 任务数量、排程紧密度、维护时间

#### **装载率 (Load Rate)**
- **计算公式**: 实际装载重量 / 最大容量 × 100%
- **业务含义**: 每炉次的装载饱满程度，反映资源利用
- **目标值**: ≥ 90%
- **影响因素**: 混炉策略、任务重量分布

#### **交期达成率 (Delivery Achievement Rate)**
- **计算公式**: 按时完成任务数 / 总任务数 × 100%
- **业务含义**: 是否满足客户交期要求
- **目标值**: ≥ 95%
- **影响因素**: 优化目标权重、紧急插单

### 6.2 优化目标权重配置

#### **预设配置模板**

**交期敏感型（订单生产）**：
```json
{
  "meetDeadlineWeight": 0.5,    // 优先保证交期
  "utilizationWeight": 0.2,     // 兼顾设备效率
  "loadRateWeight": 0.2,        // 兼顾装载效率
  "energySavingWeight": 0.1     // 适当考虑节能
}
```

**效率优先型（库存生产）**：
```json
{
  "meetDeadlineWeight": 0.2,    // 交期要求较宽松
  "utilizationWeight": 0.4,     // 优先提升设备利用率
  "loadRateWeight": 0.3,        // 优先提升装载率
  "energySavingWeight": 0.1     // 适当考虑节能
}
```

**平衡型（常规生产）**：
```json
{
  "meetDeadlineWeight": 0.4,    // 平衡各项目标
  "utilizationWeight": 0.3,
  "loadRateWeight": 0.2,
  "energySavingWeight": 0.1
}
```

## 🎬 7. 典型业务场景示例

### 7.1 场景一：正常周排程

**业务背景**: 调度员每周一创建本周排程方案

**操作步骤**:
```
1. 调度员登录系统，进入排程管理模块
2. 点击"创建排程方案"按钮
3. 配置排程参数：
   - 时间范围：本周一至周日
   - 算法类型：基于规则的启发式算法
   - 优化目标：交期敏感型
   - 任务筛选：优先级为"high"和"emergency"
4. 点击"运行算法"（2秒完成）
5. 查看排程结果：
   - 利用率：87%
   - 装载率：91%
   - 交期达成率：96%
   - 冲突数量：0
6. 查看甘特图确认排程合理性
7. 点击"发布方案"
8. 系统同步更新25个退火任务的排程信息
```

**预期结果**: 本周生产有序进行，各炉子按计划执行

### 7.2 场景二：有冲突需要调整

**业务背景**: 算法生成结果后发现冲突需要手动调整

**操作步骤**:
```
1. 算法运行完成，系统显示："生成排程方案成功，但检测到3个冲突"
2. 调度员点击"查看冲突"查看详情：
   - 冲突1：TH-01炉子时间重叠（致命冲突）
   - 冲突2：工艺不兼容混炉（高级冲突）
   - 冲突3：物料预计延迟到达（中级冲突）
3. 针对致命冲突进行手动调整：
   - 选择重叠任务之一
   - 点击"手动调整"
   - 修改装炉时间延后2小时
   - 系统实时检测：冲突已解决
4. 针对高级冲突：
   - 选择不兼容的任务
   - 更换到其他炉子
   - 或者选择取消混炉，单独排程
5. 中级冲突可选择忽略或调整
6. 所有致命冲突解决后，发布方案
```

**预期结果**: 冲突得到妥善解决，排程方案可正常执行

### 7.3 场景三：紧急插单处理

**业务背景**: 已发布排程执行中，接到紧急订单需要插单

**操作步骤**:
```
1. 接到紧急订单，生成紧急退火任务
2. 查看当前已发布的排程方案
3. 评估插单影响：
   - 是否有空余炉子时间
   - 是否需要调整现有安排
4. 选择处理方式：
   方式一：小幅调整现有排程
   - 手动调整部分任务时间
   - 为紧急任务腾出空间

   方式二：取消重新排程
   - 取消当前排程方案
   - 创建新排程方案，包含紧急任务
   - 设置紧急任务优先级为"emergency"
5. 重新发布新的排程方案
6. 通知生产执行人员按新排程执行
```

**预期结果**: 紧急任务得到及时安排，对现有生产影响最小

### 7.4 场景四：设备故障应急调整

**业务背景**: TH-01炉子突发故障，需要紧急调整排程

**操作步骤**:
```
1. 接到设备故障通知：TH-01炉子故障，预计维修4小时
2. 查看受影响的排程：
   - 当前正在执行的任务：继续完成
   - 后续4个待执行任务：需要调整
3. 紧急调整策略：
   - 任务1：转移到TH-02炉子，延后1小时
   - 任务2：转移到TH-03炉子，无延后
   - 任务3：与任务4合并混炉，转移到TH-02
   - 任务4：与任务3合并混炉
4. 逐个进行手动调整，实时检查冲突
5. 确认无致命冲突后，发布调整后的方案
6. 通知相关人员按新安排执行
```

**预期结果**: 设备故障对生产影响最小化，生产连续性得到保证

## 🔗 8. 与其他模块的关系

### 8.1 上游依赖关系

#### **退火任务管理模块**
- **依赖内容**: 待排程的退火任务数据
- **接口调用**: `GET /v1/prod/annealing-tasks/scheduling/pending`
- **关键字段**: 任务ID、产品编码、重量、优先级、计划装炉时间、工艺要求
- **业务影响**: 排程算法的输入数据来源，任务数据质量直接影响排程效果

#### **设备管理模块**
- **依赖内容**: 炉子信息和维护计划
- **接口调用**: `GET /v1/mdm/equipment/furnaces`, `GET /v1/mdm/maintenance-plans`
- **关键字段**: 炉号、容量、当前状态、维护时间段
- **业务影响**: 决定可用资源和约束条件

### 8.2 下游影响关系

#### **退火任务管理模块**
- **影响内容**: 任务的排程信息更新
- **触发时机**: 排程方案发布时
- **更新字段**: `scheduledFurnaceCode`, `scheduledLoadTime`, `scheduledUnloadTime`
- **业务价值**: 为任务执行提供明确的炉次安排

#### **物流任务生成模块**
- **影响内容**: 自动生成上料/下料物流任务
- **触发时机**: 排程方案发布后
- **生成内容**: 料框搬运任务、时间计划、路径规划
- **业务价值**: 实现排程与物流的自动协同

#### **生产执行模块**
- **影响内容**: 提供生产执行依据
- **数据来源**: 已发布的排程方案和甘特图数据
- **使用方式**: 执行人员按排程时间和炉次安排生产
- **业务价值**: 指导现场作业，确保计划执行

## ❓ 9. 常见问题FAQ

### 9.1 算法相关问题

**Q: 为什么算法执行时间有时很长？**

A: 算法执行时间主要受以下因素影响：
- **任务数量**: 超过100个任务时执行时间显著增加
- **算法类型**: 约束规划算法比规则算法耗时更长
- **约束复杂度**: 混炉规则越复杂，计算越耗时
- **解决方案**:
  - 日常排程使用"基于规则算法"（<2秒）
  - 复杂场景才使用"约束规划算法"
  - 分批排程，避免单次处理过多任务

**Q: 什么情况下应该选择哪种算法？**

A: 算法选择建议：
- **日常周排程** → 基于规则算法（快速稳定）
- **复杂约束场景** → 约束规划算法（精确求解）
- **大规模排程** → 模拟退火算法（全局优化）
- **科研分析** → 遗传算法（多目标优化）

### 9.2 冲突处理问题

**Q: 冲突检测是实时的吗？**

A: 冲突检测机制：
- **算法运行后**: 自动进行全面冲突检测
- **手动调整时**: 实时检测调整是否产生新冲突
- **发布前检查**: 再次验证是否存在致命冲突
- **检测速度**: 通常在1秒内完成

**Q: 什么是致命冲突？为什么不能发布？**

A: 致命冲突类型及原因：
- **时间冲突**: 同一炉子时间重叠，物理上不可行
- **容量超限**: 超出炉子最大容量，安全风险
- **维护冲突**: 设备维护期间不能使用
- **必须解决**: 这些冲突会导致生产无法执行或安全风险

### 9.3 操作流程问题

**Q: 发布后还能修改排程吗？**

A: 发布后的限制：
- **已发布方案**: 不能再次编辑或调整
- **任务状态**: 已同步到任务管理模块
- **修改方式**:
  - 取消当前方案（不影响已开始任务）
  - 创建新的排程方案
  - 重新发布新方案

**Q: 取消已发布的方案会影响已开始的任务吗？**

A: 取消方案的影响：
- **正在执行任务**: 不受影响，继续按原计划执行
- **未开始任务**: 排程信息清空，恢复待排程状态
- **业务建议**: 谨慎取消已发布方案，建议在交班时进行

### 9.4 性能优化问题

**Q: 大量任务排程时如何提升性能？**

A: 性能优化策略：
- **分批处理**: 将大批量任务分成多个小批次
- **算法选择**: 大规模场景使用模拟退火算法
- **约束简化**: 减少不必要的约束规则
- **缓存策略**: 复用设备信息和历史计算结果

**Q: 甘特图加载很慢怎么办？**

A: 甘特图优化方案：
- **时间范围**: 缩小查看时间范围
- **任务数量**: 使用筛选减少显示任务
- **虚拟化**: 大量任务时使用虚拟滚动
- **分页加载**: 按时间段分页加载数据

## 📋 10. 开发注意事项

### 10.1 前端开发要点

#### **状态管理**
- 排程方案状态需要实时更新（特别是computing状态）
- 冲突检测结果需要即时展示
- 甘特图数据变化需要及时刷新

#### **用户体验**
- 算法执行时显示进度提示（"正在运行排程算法，预计耗时X秒"）
- 冲突信息要清晰直观，提供解决建议
- 手动调整要有实时冲突检测反馈

#### **性能考虑**
- 甘特图组件选择支持大数据量渲染的库
- 列表分页加载，避免一次性加载过多数据
- 合理使用防抖避免频繁API调用

### 10.2 业务逻辑处理

#### **时间处理**
- 所有时间都是ISO 8601格式，注意时区处理
- 计划装炉时间和出炉时间的校验（出炉时间 > 装炉时间）
- 时间范围选择的合理性校验

#### **数值处理**
- 利用率、装载率、交期达成率是0-1的小数，前端显示时乘以100
- 重量单位统一使用"吨"，注意精度处理
- 优化目标权重总和不能超过1.0

#### **权限控制**
- 不同权限用户看到的操作按钮不同
- 权限校验失败要有友好提示
- 403错误要引导用户联系管理员
