### 步骤3：添加操作按钮权限检查

**文件3**：`components/SchedulePlanTable.vue`

在 `getActionButtons` 方法中添加权限检查：
```javascript
getActionButtons(row) {
  if (!row) {
    return []
  }

  // 引入权限检查工具
  const hasPermission = this.$store.getters.permissions.includes.bind(
    this.$store.getters.permissions
  )

  const buttons = []

  // 查看详情 - 需要 VIEW 权限
  if (hasPermission(PERMISSIONS.VIEW)) {
    buttons.push({
      text: '查看详情',
      action: 'view',
      icon: 'el-icon-view'
    })
    buttons.push({
      text: '查看甘特图',
      action: 'viewGantt',
      icon: 'el-icon-s-data'
    })
  }

  // 发布 - 需要 PUBLISH 权限
  if (row.status === PLAN_STATUS.GENERATED && hasPermission(PERMISSIONS.PUBLISH)) {
    buttons.push({
      text: '发布',
      action: 'publish',
      icon: 'el-icon-success',
      type: 'success'
    })
  }

  // 取消 - 需要 CANCEL 权限
  if (
    (row.status === PLAN_STATUS.DRAFT || row.status === PLAN_STATUS.GENERATED) &&
    hasPermission(PERMISSIONS.CANCEL)
  ) {
    buttons.push({
      text: '取消',
      action: 'cancel',
      icon: 'el-icon-close',
      type: 'danger'
    })
  }

  return buttons
}
```

在 `toolbarButtons` 计算属性中添加权限检查：

## 权限检查层次

1. **路由层**：用户访问页面时检查 `prod.scheduling.view` 权限
2. **界面层**：根据用户权限显示/隐藏操作按钮
3. **操作层**：执行操作前再次验证权限
4. **API层**：后端接口也需要进行权限验证（最后一道防线）

## 注意事项

1. **开发阶段**不要启用权限检查，避免影响开发效率
2. **生产环境**必须启用完整的权限检查体系
3. 前端权限检查主要用于**用户体验优化**，真正的权限校验在**后端**
4. 权限代码要与后端定义的权限代码**完全一致**
5. 定期与后端确认权限配置的变更
