### 3.6. 用户权限管理模块 (USER)

**核心功能:** 管理系统用户、角色及其对系统功能和数据的访问权限，确保系统操作安全合规。

#### 3.6.1. 用户登录认证 (User Authentication)

* **功能描述:** 提供用户身份验证和登录会话管理功能，确保系统安全访问。
* **实现逻辑:**
  * **登录界面:** 提供用户名/密码登录方式，界面简洁美观，支持记住登录状态。
  * **身份验证:** 验证用户凭证的有效性，支持密码加密验证。
  * **会话管理:** 创建和维护用户登录会话，支持会话超时自动退出。
  * **登录控制:** 实现密码错误次数限制，超限自动锁定账户机制。
  * **登录日志:** 完整记录用户登录活动，包括登录时间、IP地址、设备信息、登录结果。
  * **安全功能:** 支持强制下线、单点登录控制、异地登录提醒。
* **操作流程:**
    1. 用户访问系统登录页面。
    2. 输入用户名和密码，可选择记住登录状态。
    3. 系统验证凭证，成功后创建会话并跳转到主界面。
    4. 登录失败时显示错误信息，记录失败次数。
    5. 会话超时或用户主动退出时清除会话。
* **数据需求:** 用户凭证表，登录会话表，登录日志表。
* **界面交互要点:** 登录界面响应式设计，支持PC和移动端。密码输入框支持显示/隐藏切换。错误提示友好明确。
* **关键业务规则:** 密码连续错误5次锁定账户15分钟。会话30分钟无操作自动过期。所有登录活动必须记录日志。

#### 3.6.2. 用户注册管理 (User Registration Management)

* **功能描述:** 管理新用户的注册申请和账户创建流程，支持管理员审批机制。
* **实现逻辑:**
  * **注册申请:** 提供用户注册申请界面，收集基本信息和部门岗位信息。
  * **审批流程:** 支持管理员审批或邀请码机制，确保注册用户的合法性。
  * **账户创建:** 审批通过后自动创建用户账户，分配初始权限和角色。
  * **激活机制:** 支持邮件激活或管理员手动激活新账户。
  * **批量管理:** 支持批量导入用户信息和批量创建账户。
  * **注册记录:** 完整记录注册申请、审批过程和账户创建历史。
* **操作流程:**
    1. 新用户填写注册申请表，包括基本资料、部门归属、岗位信息。
    2. 系统验证信息完整性和唯一性约束。
    3. 提交申请后进入待审批状态。
    4. 管理员审核申请，可批准、拒绝或要求补充信息。
    5. 审批通过后创建账户，分配默认角色，发送激活通知。
    6. 用户激活账户后可正常登录使用系统。
* **数据需求:** 注册申请表，审批记录表，用户账户表。
* **界面交互要点:** 注册表单分步骤填写，实时验证输入。审批界面清晰展示申请信息。支持批量操作界面。
* **关键业务规则:** 用户名和邮箱全局唯一。新用户默认分配基础角色。注册申请保留完整审批轨迹。

#### 3.6.3. 用户管理 (User Management)

* **功能描述:** 管理系统用户的账号信息、基本资料和状态。
* **实现逻辑:**
  * 提供用户账号的创建、编辑、查询、禁用/启用、删除（逻辑删除）功能。
  * 记录用户信息：`用户ID` (唯一, 如工号), `登录名` (唯一), `姓名`, `密码` (加密存储), `所属部门` (关联`3.6.2`), `岗位` (关联`3.6.2`), `联系方式` (手机/邮箱), `账号状态` (活动/锁定/禁用), `关联角色` (多对多, 关联`3.6.3`)。
  * **密码管理:** 支持管理员重置用户密码，用户首次登录强制修改密码，密码过期提醒。需符合`3.6.5`设定的密码策略。
  * **查询与筛选:** 支持按用户名、姓名、部门、状态等条件查询用户。
* **操作流程:**
    1. 管理员登录，进入“用户权限 -> 用户管理”。
    2. 查看用户列表。
    3. 点击“新增”创建用户，填写信息，分配初始角色。
    4. 选择用户进行编辑、状态变更（禁用/启用）、重置密码、删除（标记为禁用）等操作。
* **数据需求:** 用户信息表，用户-角色关联表。
* **界面交互要点:** 用户列表清晰，支持搜索和筛选。编辑表单分组合理。密码输入以星号显示。
* **关键业务规则:** 登录名全局唯一。密码必须加密存储，不可明文查看。用户删除为逻辑删除，保留历史操作记录关联。

#### 3.6.2. 组织结构管理 (Organization Structure Management)

* **功能描述:** 维护企业的部门层级结构和岗位信息。
* **实现逻辑:**
  * **部门管理:**
    * 提供界面创建、编辑、删除部门信息。
    * 记录字段：`部门ID` (唯一), `部门名称`, `上级部门ID` (用于构建层级关系), `部门描述` (可选)。
    * 支持以树状结构展示和维护部门层级。
  * **岗位管理:**
    * 提供界面创建、编辑、删除岗位信息。
    * 记录字段：`岗位ID` (唯一), `岗位名称` (如 车间主任, 调度员, 炉前工, 质检员), `岗位描述`。
  * **用户关联:** 在`3.6.1`用户管理中，为用户指定其所属的`部门`和`岗位`。
* **操作流程:**
    1. 管理员进入“用户权限 -> 组织结构”。
    2. 维护部门树状结构（增删改节点）。
    3. 维护岗位列表。
    4. 在用户管理界面为用户分配部门和岗位。
* **数据需求:** 部门表，岗位表。
* **界面交互要点:** 部门管理使用树形控件直观展示层级。
* **关键业务规则:** 部门和岗位信息是进行数据权限配置（如下属数据查看）和工作流分配的基础。

#### 3.6.3. 角色定义 (Role Definition)

* **功能描述:** 定义不同的用户角色，角色是权限分配的载体。
* **实现逻辑:**
  * 提供界面创建、编辑、复制、删除角色。
  * 记录字段：`角色ID` (唯一), `角色名称` (如 管理员, 调度岗, 操作岗, 质检岗), `角色描述`, `状态` (启用/禁用)。
  * **权限关联:** 每个角色关联一组权限集合（功能权限、数据权限），在`3.6.4`中配置。
  * **角色分配:** 在`3.6.1`用户管理中，将一个或多个角色分配给用户。一个用户可以拥有多个角色，其最终权限是所有角色权限的并集。
  * **(可选) 角色继承:** 支持定义角色之间的继承关系（如 班组长角色 继承 操作岗角色 的所有权限，并增加额外权限）。
* **操作流程:**
    1. 管理员进入“用户权限 -> 角色管理”。
    2. 创建或编辑角色基本信息。
    3. 在“权限配置”(`3.6.4`)界面为该角色分配具体权限。
    4. 在“用户管理”(`3.6.1`)界面为用户分配角色。
* **数据需求:** 角色表，角色-权限关联表，用户-角色关联表。
* **界面交互要点:** 角色列表清晰。
* **关键业务规则:** 角色是权限管理的核心机制 (RBAC - Role-Based Access Control)。用户的权限由其被赋予的角色决定。

#### 3.6.4. 权限配置 (Permission Configuration)

* **功能描述:** 精细化地为角色分配系统中各项功能、操作和数据的访问权限。
* **实现逻辑:**
  * **权限分类:**
    * **功能权限 (Menu/Page/Button Permissions):** 控制用户能看到哪些菜单项、能访问哪些页面、能点击哪些按钮（如 新增、编辑、删除、审批、强制完成等）。通常以树状结构展示系统所有功能点，管理员为角色勾选其允许访问的功能。
    * **数据权限 (Data Permissions):** 控制用户能看到和操作哪些范围的数据。实现方式通常包括：
      * `组织维度`: 只能看本部门/本班组的数据。
      * `创建者维度`: 只能操作自己创建的数据。
      * `设备/区域维度`: 只能看分配给自己负责的设备/区域的数据。
      * `数据类型维度`: 如普通操作员不能查看成本相关数据。
      * 需要设计灵活的数据权限规则引擎，允许管理员为角色配置规则。
    * **操作权限 (Action Permissions):** 对某些敏感操作（如 修改生效工艺、删除历史数据、手动干预自动流程）进行单独授权，并可关联审批流程。
  * **权限分配:**
    * 主要将权限分配给**角色**。选择一个角色，然后为其配置允许的功能权限树节点、数据权限规则和特殊操作权限。
    * （不推荐）允许将特定权限直接分配给用户，作为角色的补充或例外。
* **操作流程:**
    1. 管理员进入“用户权限 -> 权限配置”。
    2. 选择目标角色。
    3. 在功能权限树上勾选允许访问的菜单/页面/按钮。
    4. 配置数据权限规则（如选择可见的部门、设备范围等）。
    5. 勾选允许执行的特殊操作权限。
    6. 保存配置。
* **数据需求:** 系统权限项定义表（功能点、数据对象、操作点），角色-权限关联表。
* **界面交互要点:** 功能权限树结构清晰，易于勾选。数据权限规则配置界面需灵活且易于理解。
* **关键业务规则:** 权限配置需遵循最小权限原则。权限变更应有记录。用户的最终权限是其所有角色权限的并集，加上直接分配给用户的权限。

#### 3.6.5. 安全策略 (Security Policy)

* **功能描述:** 配置系统级的安全相关参数和规则。
* **实现逻辑:** 提供系统配置界面，允许管理员设置以下策略：
  * **密码策略:**
    * `最小密码长度` (如 8位)。
    * `密码复杂度要求` (如 必须包含大小写字母、数字、特殊符号中的至少三种)。
    * `密码有效期` (如 90天后强制过期)。
    * `密码历史限制` (如 不允许使用最近5次用过的密码)。
    * `登录失败锁定` (如 连续输错5次密码后锁定账号15分钟)。
  * **会话管理:**
    * `会话超时时间` (如 用户30分钟无操作自动登出)。
  * **登录控制 (可选):**
    * `IP地址白名单/黑名单`: 限制允许登录的IP范围。
    * `登录时间限制`: 限制用户只能在特定时间段登录。
    * `单点登录 (SSO)`: 若需与企业统一认证平台集成。
  * **操作日志:**
    * 配置需要记录的操作日志范围和级别（如 记录所有关键数据的增删改操作、用户登录登出、权限变更等）。
    * 配置日志的`保存期限` (如 至少1年)。
* **操作流程:**
    1. 系统管理员进入“系统设置 -> 安全策略”。
    2. 配置各项安全参数。
    3. 保存并启用策略。
* **数据需求:** 安全策略配置存储表。
* **界面交互要点:** 配置项清晰明了，配有解释说明。
* **关键业务规则:** 安全策略应符合企业整体的信息安全要求。
