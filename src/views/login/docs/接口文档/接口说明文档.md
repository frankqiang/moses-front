# Moses API 认证模块接口文档

## 概述

本文档详细说明了 Moses API 认证模块的所有接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。本文档严格基于实际代码实现编写，确保前端开发人员能够准确对接。

### API 基础信息

- **基础 URL**: `http://localhost:3000/v1` (开发环境)
- **API 版本**: v1
- **认证方式**: JWT Bearer Token
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### Swagger 文档

项目已集成 Swagger 文档，可通过以下地址访问：

- **开发环境**: http://localhost:3000/v1/docs
- **在线文档**: 提供完整的 API 接口说明、参数定义和示例

## 统一响应格式

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

## 认证接口详细说明

### 1. 用户注册

**接口路径**: `POST /v1/auth/register`

**功能描述**: 注册新用户账户，创建用户信息并返回认证令牌。该接口用于新用户注册，验证用户输入信息的有效性，创建用户账户并返回完整的用户信息和认证令牌。

**认证要求**: 无

**请求参数**:

| 参数名   | 类型   | 必填 | 限制         | 描述                                     | 示例               |
| -------- | ------ | ---- | ------------ | ---------------------------------------- | ------------------ |
| name     | string | 是   | -            | 真实姓名                                 | "张三"             |
| username | string | 是   | 3-50 字符    | 用户名，支持字母、数字、下划线，必须唯一 | "admin"            |
| email    | string | 是   | 有效邮箱格式 | 邮箱地址，必须唯一                       | "user@example.com" |
| password | string | 是   | 最少 8 字符  | 密码，至少包含一个数字和一个字母         | "password123"      |

**请求示例**:

```bash
curl -X POST http://localhost:3000/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "name": "张三",
    "username": "admin",
    "email": "user@example.com",
    "password": "password123"
  }'
```

```json
{
  "name": "张三",
  "username": "admin",
  "email": "user@example.com",
  "password": "password123"
}
```

**成功响应** (HTTP 201):

### 2. 用户登录

**接口路径**: `POST /v1/auth/login`

**功能描述**: 用户身份认证，验证用户名/邮箱和密码，返回访问令牌。该接口用于用户登录系统，验证用户身份并获取访问令牌，用于后续 API 调用的身份认证。支持用户名或邮箱登录，并提供记住登录状态的选项。

**认证要求**: 无

**请求参数**:

| 参数名     | 类型    | 必填 | 限制         | 描述                               | 示例               |
| ---------- | ------- | ---- | ------------ | ---------------------------------- | ------------------ |
| username   | string  | 否\* | 3-50 字符    | 用户名，与邮箱二选一               | "admin"            |
| email      | string  | 否\* | 有效邮箱格式 | 用户邮箱，与用户名二选一           | "user@example.com" |
| password   | string  | 是   | 6-20 字符    | 密码，必填                         | "password123"      |
| rememberMe | boolean | 否   | -            | 是否记住登录状态，可选，默认 false | false              |

\*注：username 和 email 必须提供其中一个

**请求示例**:

```bash
curl -X POST http://localhost:3000/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "admin",
    "password": "password123",
    "rememberMe": false
  }'
```

```json
{
  "username": "admin",
  "password": "password123",
  "rememberMe": false
}
```


- `refreshToken`: 刷新令牌，用于获取新的访问令牌
- `expiresIn`: 访问令牌过期时间（秒）

```json
  }
```

### 3. 用户登出

```bash
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

## 错误码说明

系统使用统一的错误码体系，便于客户端处理和日志追踪。错误码格式：模块前缀\_数字编号。

### 认证相关错误码 (AUTH_xxx)

| 错误码   | HTTP 状态码 | 错误消息                             | 说明                     | 处理建议                     |
| -------- | ----------- | ------------------------------------ | ------------------------ | ---------------------------- |
| AUTH_001 | 401         | 请先登录                             | 未提供访问令牌           | 需要提供有效的访问令牌       |
| AUTH_002 | 401         | 登录已过期，请重新登录               | 令牌已过期               | 使用刷新令牌获取新的访问令牌 |
| AUTH_003 | 401         | 无效的访问令牌                       | 令牌格式错误或签名无效   | 重新登录获取新令牌           |
| AUTH_005 | 401         | 访问令牌已失效                       | 令牌在黑名单中           | 重新登录获取新令牌           |
| AUTH_006 | 429         | IP 地址登录尝试过于频繁，请稍后重试  | IP 登录频率限制          | 稍后重试或联系管理员         |
| AUTH_009 | 403         | 权限不足                             | 用户没有执行操作的权限   | 联系管理员获取权限           |
| AUTH_010 | 401         | 登录失败                             | 登录过程失败             | 检查登录凭据                 |
| AUTH_011 | 401         | 用户名或密码错误                     | 用户名或密码不正确       | 检查登录凭据                 |

| AUTH_015 | 401         | 密码重置失败                         | 重置密码令牌无效或已过期 | 重新申请密码重置             |
| AUTH_032 | 401         | 刷新令牌已过期                       | 刷新令牌已过期           | 重新登录                     |
| AUTH_033 | 401         | 无效的刷新令牌                       | 刷新令牌无效             | 重新登录                     |

### 验证相关错误码 (VAL_xxx)

| 错误码  | HTTP 状态码 | 错误消息           | 说明               | 处理建议               |
| ------- | ----------- | ------------------ | ------------------ | ---------------------- |
| VAL_001 | 400         | 输入数据验证失败   | 参数验证失败       | 检查请求参数格式和内容 |
| VAL_002 | 400         | 缺少必填字段       | 必填参数缺失       | 提供所有必填参数       |
| VAL_004 | 400         | 邮箱格式不正确     | 邮箱地址格式错误   | 检查邮箱地址格式       |
| VAL_005 | 400         | 密码格式不符合要求 | 密码格式不符合要求 | 检查密码长度和复杂度   |

| 错误码  | HTTP 状态码 | 错误消息       | 说明             | 处理建议               |
| ------- | ----------- | -------------- | ---------------- | ---------------------- |
| BIZ_001 | 404         | 资源不存在     | 请求的资源不存在 | 检查请求参数或资源标识 |
| BIZ_010 | 409         | 用户已存在     | 用户已存在       | 使用不同的用户名       |
| BIZ_011 | 409         | 邮箱已被使用   | 邮箱已被使用     | 使用不同的邮箱地址     |
| BIZ_012 | 409         | 用户名已被使用 | 用户名已被使用   | 使用不同的用户名       |

### 系统错误码 (SYS_xxx)

| 错误码  | HTTP 状态码 | 错误消息       | 说明                 | 处理建议               |
| ------- | ----------- | -------------- | -------------------- | ---------------------- |
| SYS_001 | 500         | 服务器内部错误 | 服务器内部错误       | 稍后重试或联系技术支持 |
| SYS_002 | 500         | 数据库错误     | 数据库连接或查询错误 | 稍后重试或联系技术支持 |
| SYS_005 | 503         | 服务不可用     | 服务暂时不可用       | 稍后重试               |

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理

   - `AUTH_`: 认证相关错误，可能需要重新登录或刷新令牌
   - `VAL_`: 验证相关错误，需要检查输入参数
   - `BIZ_`: 业务逻辑错误，需要根据业务规则处理
   - `SYS_`: 系统错误，通常需要重试或联系支持

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息

4. **重试机制**: 对于包含 `retryAfter` 字段的错误，应按照指定时间后重试

5. **日志记录**: 使用 `traceId` 进行错误追踪和问题排查

## 数据模型

### User 用户模型

用户注册时返回的用户信息结构：

```json
{
  "id": "string", // 用户ID，唯一标识
  "username": "string", // 用户名
  "name": "string", // 真实姓名
  "email": "string", // 邮箱地址
  "role": "string", // 用户角色（如："user", "admin"）
  "isEmailVerified": "boolean", // 邮箱是否已验证
  "createdAt": "string", // 创建时间 (ISO 8601格式)
  "updatedAt": "string" // 更新时间 (ISO 8601格式)
}
```

获取用户信息时返回的用户信息结构：

```json
{
  "id": "string", // 用户ID，唯一标识
  "username": "string", // 用户名（当前使用邮箱作为用户名）
  "name": "string", // 真实姓名
  "email": "string", // 邮箱地址
  "avatar": "string", // 用户头像URL（当前为空字符串）
  "roles": ["string"], // 用户角色列表（数组格式）
  "permissions": ["string"] // 用户权限列表（当前为空数组）
}
```

### AuthTokens 认证令牌模型

用户注册和刷新令牌时返回的令牌结构：

```json
{
  "access": {
    "token": "string", // 访问令牌（JWT格式）
    "expires": "string" // 过期时间 (ISO 8601格式)
  },
  "refresh": {
    "token": "string", // 刷新令牌（JWT格式）
    "expires": "string" // 过期时间 (ISO 8601格式)
  }
}
```

用户登录时返回的令牌结构：

```json
{
  "token": "string", // 访问令牌（JWT格式）
  "refreshToken": "string", // 刷新令牌（JWT格式）
  "expiresIn": "number" // 访问令牌过期时间（秒）
}
```

### 字段说明

**日期时间格式**:

- 所有日期时间字段均使用 ISO 8601 格式：`YYYY-MM-DDTHH:mm:ss.sssZ`
- 示例：`"2024-01-20T10:30:00.000Z"`

**JWT 令牌格式**:

- 所有 JWT 令牌均以 `eyJ` 开头
- 示例：`"eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."`

**令牌过期时间**:

- 访问令牌：默认 30 分钟（1800 秒）
- 刷新令牌：默认 30 天
- `rememberMe=true` 时，刷新令牌过期时间会延长

**用户角色**:

- `user`: 普通用户（默认角色）
- `admin`: 管理员用户
- 更多角色可根据业务需要扩展

**用户权限**:

- 当前版本暂未实现细粒度权限系统
- `permissions` 字段返回空数组
- 后续版本将根据角色动态返回权限列表

## 安全说明

### 认证机制

1. **JWT 令牌**: 使用 JSON Web Token 进行身份认证

   - 算法：HS256 (对称加密)
   - 令牌包含用户 ID、角色、过期时间等信息
   - 服务端验证令牌签名和有效性

2. **双令牌机制**: 访问令牌（短期）+ 刷新令牌（长期）

   - 访问令牌：用于 API 调用认证，默认 30 分钟过期
   - 刷新令牌：用于获取新的访问令牌，默认 30 天过期
   - 降低令牌泄露风险，提升安全性

3. **自动刷新**: 支持使用刷新令牌自动获取新的访问令牌
   - 无需用户重新登录，提升用户体验
   - 刷新后旧令牌立即失效，防止重复使用

### 安全特性

1. **密码加密**: 使用 bcrypt 对密码进行哈希加密

   - 加盐处理，防止彩虹表攻击
   - 适度的计算复杂度，平衡安全性和性能
   - 密码不以明文存储，不可逆向解密

2. **速率限制**: 对登录接口实施速率限制，防止暴力破解

   - IP 级别的登录频率限制
   - 超出限制后返回 429 状态码
   - 包含 `retryAfter` 字段，指示重试等待时间

3. **令牌黑名单**: 登出时将令牌加入黑名单，防止重复使用

   - 服务端维护令牌黑名单
   - 每次调用时检查令牌是否在黑名单中
   - 黑名单中的令牌立即失效

4. **邮箱验证**: 支持邮箱验证功能，确保邮箱有效性

   - 注册后可选择验证邮箱
   - 支持重新发送验证邮件
   - 验证令牌有效期限制，防止滥用

5. **密码重置**: 安全的密码重置流程，通过邮件验证身份

   - 通过邮箱发送重置链接
   - 重置令牌有效期限制（通常 10-30 分钟）
   - 重置成功后所有现有令牌失效

6. **登录安全控制**: 多层次的登录安全保护
   - 登录失败次数限制
   - 账户自动锁定机制
   - 登录日志记录（IP、时间、用户代理等）

### 传输安全

1. **HTTPS 加密**: 生产环境必须使用 HTTPS 传输

   - 防止中间人攻击
   - 保护令牌和敏感信息在传输过程中不被窃取

2. **请求头安全**: 使用 Authorization 请求头传递令牌
   - 格式：`Authorization: Bearer <token>`
   - 避免在 URL 参数中传递令牌

### 使用建议

1. **令牌存储**: 建议将令牌存储在安全的地方

   - 优先选择：httpOnly cookie
   - 备选方案：localStorage 或 sessionStorage
   - 防止 XSS 攻击获取令牌

2. **令牌刷新**: 实现自动令牌刷新机制，提升用户体验

   - 在访问令牌过期前主动刷新
   - 处理刷新失败的情况（跳转到登录页）

3. **错误处理**: 统一处理认证错误，避免信息泄露

   - 不暴露系统内部细节
   - 统一的错误消息格式
   - 适当的用户友好提示

4. **日志记录**: 记录关键操作日志，便于安全审计

   - 登录/登出操作
   - 密码重置操作
   - 令牌刷新操作
   - 包含 IP 地址、用户代理、时间戳等信息

5. **安全配置**: 合理配置安全参数

   - 令牌过期时间平衡安全性和可用性
   - 速率限制阈值合理设置
   - 密码复杂度要求适中

6. **安全监控**: 定期监控和检查安全状态
   - 监控异常登录行为
   - 定期轮换令牌签名密钥
   - 安全漏洞扫描和修复
