# Moses API 料框规格管理模块接口文档

## 概述

本文档详细说明了 Moses API 料框规格管理模块的所有接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。**本文档严格基于实际代码实现编写**，确保前端开发人员能够准确对接。

⚠️ **特别注意**：
- **🎯 响应结构一致性**：响应数据结构必须与代码实际返回的结构完全一致，字段名称、数据类型、嵌套层级都不得有任何偏差
- **🔗 关联对象完整性**：如果接口返回包含关联对象（如适用产品信息、创建人信息等），必须完整列出所有关联字段
- **📊 嵌套对象详细说明**：对于复杂的嵌套对象，必须提供详细的字段说明表格，不能仅在主响应示例中展示
- **🧮 计算字段标注**：模型中通过 toJSON 方法添加的计算字段必须在文档中明确标注

### API 基础信息

- **基础 URL**: `http://localhost:3000/v1` (开发环境)
- **API 版本**: v1
- **认证方式**: JWT Bearer Token
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### Swagger 文档

项目已集成 Swagger 文档，可通过以下地址访问：

- **开发环境**: http://localhost:3000/v1/docs
- **在线文档**: 提供完整的 API 接口说明、参数定义和示例

### 权限约定

> **权限点映射**：
> - `mdm.bin-specification.manage`：料框规格管理权限，可执行创建、更新、状态切换等写操作
> - `mdm.bin-specification.view`：料框规格查看权限，可执行分页查询、详情查询等查看操作
>
> **注意事项**：所有接口都需要认证，未认证的请求会返回401错误

## 统一响应格式

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2025-01-09T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2025-01-09T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

## 料框规格管理接口详细说明

### 1. 创建料框规格

**接口路径**: `POST /v1/mdm/bin-specifications`

**功能描述**: 创建新的料框规格档案，包含规格代码、尺寸、载重、材质等基础信息。规格代码必须全局唯一，格式为大写字母、数字和中划线组合。创建成功后，规格默认状态为"启用"。该接口会进行完整的业务验证，包括规格代码格式验证、唯一性校验和数值范围验证。

**认证要求**: 需要 Bearer Token，且用户必须拥有 `mdm.bin-specification.manage` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名                 | 类型          | 必填 | 限制                           | 描述                               | 示例                                     |
| ---------------------- | ------------- | ---- | ------------------------------ | ---------------------------------- | ---------------------------------------- |
| specCode               | string        | 是   | 1-50字符，大写字母/数字/中划线 | 规格代码，全局唯一，自动转换为大写 | LK001                                    |
| specName               | string        | 是   | 1-200字符                      | 规格名称                           | 标准料框                                 |
| length                 | number        | 是   | 0.01-10000，最多2位小数        | 长度(cm)，正数                     | 120.50                                   |
| width                  | number        | 是   | 0.01-10000，最多2位小数        | 宽度(cm)，正数                     | 80.00                                    |
| height                 | number        | 是   | 0.01-10000，最多2位小数        | 高度(cm)，正数                     | 60.00                                    |
| maxLoadCapacity        | number        | 是   | 0.01-100000，最多2位小数       | 最大载重(kg)，正数                 | 500.00                                   |
| material               | string        | 是   | 1-100字符                      | 材质                               | 钢材                                     |
| maxStackLayers         | integer       | 是   | 1-100的整数                    | 最大堆叠层数，正整数               | 3                                        |

| status                 | string        | 否   | 枚举值：启用、禁用             | 状态，可选，默认为启用             | 启用                                     |

### 2. 分页查询料框规格列表

**接口路径**: `GET /v1/mdm/bin-specifications`

**功能描述**: 根据规格代码、名称、材质、状态等条件分页查询料框规格列表，支持多维度筛选和排序。支持模糊查询（规格代码、规格名称）、精确匹配（材质、状态）、范围查询（长度、宽度、高度）和全文搜索。默认按创建时间降序排列，支持自定义排序。

**认证要求**: 需要 Bearer Token，且用户必须拥有 `mdm.bin-specification.view` 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

| --------- | ------- | ---- | ------------------------ | ------------------------------ | -------------- |
| specCode  | string  | 否   | 最多50字符               | 规格代码筛选，支持模糊查询     | LK             |
| specName  | string  | 否   | 最多200字符              | 规格名称筛选，支持模糊查询     | 标准           |
| material  | string  | 否   | 最多100字符              | 材质筛选，精确匹配             | 钢材           |

### 5. 切换料框规格状态

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理
   - `AUTH_`: 认证相关错误，可能需要重新登录或刷新令牌
   - `VAL_`: 验证相关错误，需要检查输入参数
   - `BIN_SPEC_`: 料框规格业务逻辑错误，需要根据业务规则处理
   - `SYS_`: 系统错误，通常需要重试或联系支持

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息

4. **重试机制**: 对于5xx系统错误，建议实现指数退避重试机制

5. **日志记录**: 使用 `traceId` 进行错误追踪和问题排查

6. **用户友好**: 将技术错误码转换为用户友好的提示信息

料框规格是料框管理的基础主数据，定义了车间使用的各种料框的规格信息，为料框注册、库位分配、退火物流调度等业务提供规格参考。

{
  "id": "7a48f12c-8d3e-4f9b-b2e1-6c9a5d8f3b21",
  "specCode": "LK001",

  "length": 120.50,
  "width": 80.00,

  "material": "钢材",
  "maxStackLayers": 3,
  "applicableProductTypes": ["123e4567-e89b-12d3-a456-426614174000"],
  "supplierInfo": "XX金属制品有限公司",
  "status": "启用",
  "isDeleted": false,
  "createdBy": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",

  "updatedAt": "2025-01-09T15:30:00.000Z"

⚠️ **模型文档编写要求**：
1. **完整性检查**：包含模型中所有可能返回的字段
2. **关联对象**：当前版本暂不包含关联对象（适用产品详情、创建人/更新人详情），将在相关模块完善后补充
3. **计算字段**：数值字段（length、width、height、maxLoadCapacity）通过模型的 toJSON 方法转换为 number 类型
4. **字段分类**：包含数据库字段、JSON字段（applicableProductTypes）

### 字段说明

| 字段名                 | 类型          | 必填 | 说明                                                         | 示例                                     |
| ---------------------- | ------------- | ---- | ------------------------------------------------------------ | ---------------------------------------- |
| id                     | string        | 是   | 规格ID，UUID v4格式，系统自动生成                            | "7a48f12c-8d3e-4f9b-b2e1-6c9a5d8f3b21"   |

| maxStackLayers         | integer       | 是   | 最大堆叠层数，范围1-100的整数                                | 3                                        |
| applicableProductTypes | array[string] | 否   | 适用产品类型ID列表，JSON数组格式存储，元素为UUID格式         | ["123e4567-e89b-12d3-a456-426614174000"] |
| supplierInfo           | string        | 否   | 供应商信息，最多500字符，可为null                            | "XX金属制品有限公司"                     |
| status                 | string        | 是   | 状态，枚举值：启用、禁用，默认为启用                         | "启用"                                   |
| isDeleted              | boolean       | 是   | 软删除标志，默认false                                        | false                                    |
| createdBy              | string        | 否   | 创建人ID，UUID v4格式，可为null                              | "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d"   |
| updatedBy              | string        | 否   | 最后更新人ID，UUID v4格式，可为null                          | "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d"   |
| createdAt              | string        | 是   | 创建时间，ISO 8601格式，系统自动生成                         | "2025-01-09T10:00:00.000Z"               |

**日期时间格式**:
- 所有日期时间字段均使用 ISO 8601 格式：`YYYY-MM-DDTHH:mm:ss.sssZ`
- 示例：`"2025-01-09T10:00:00.000Z"`

**特殊字段说明**:
- `applicableProductTypes`: 数据库中以TEXT类型存储JSON数组，模型getter/setter自动进行JSON序列化/反序列化
- `length`, `width`, `height`, `maxLoadCapacity`: 数据库中以DECIMAL(10,2)存储，模型toJSON方法自动转换为number类型
- `specCode`: 自动转换为大写（通过模型setter和静态方法）
- `isDeleted`: 软删除标志，查询时默认过滤已删除记录

**模型索引**:
- 唯一索引：`spec_code` (where is_deleted = false)
- 普通索引：`spec_name`, `status`, `material`, `is_deleted`, `created_at`

**模型关联** (预留，待相关模块完善):
- `creator`: belongsTo User, foreignKey: createdBy
- `updater`: belongsTo User, foreignKey: updatedBy
- `applicableProducts`: belongsToMany AluminumFoilProduct, through: bin_specification_applicable_products

## 安全说明

### 认证机制

所有接口都需要通过 JWT Bearer Token 进行认证：

1. **令牌获取**: 通过登录接口获取访问令牌
2. **令牌使用**: 在请求头中添加 `Authorization: Bearer <token>`
3. **令牌刷新**: 令牌过期后需要重新登录或使用刷新令牌
4. **令牌验证**: 服务器会验证令牌的有效性和用户权限

详细的认证流程请参考登录模块文档。

### 权限控制

料框规格模块实现了基于角色的权限控制（RBAC）：

1. **查看权限** (`mdm.bin-specification.view`):
   - 允许查询料框规格列表
   - 允许查看料框规格详情

2. **管理权限** (`mdm.bin-specification.manage`):
   - 允许创建料框规格
   - 允许更新料框规格
   - 允许切换料框规格状态
   - 包含查看权限的所有功能

### 安全特性

1. **参数验证**:
   - 所有输入参数都经过严格的 Joi 验证
   - 规格代码格式验证，防止非法字符
   - 数值范围验证，防止异常数据

2. **数据唯一性**:
   - 规格代码全局唯一性校验
   - 数据库层面的唯一索引约束

3. **事务处理**:
   - 创建、更新、状态切换等操作使用数据库事务
   - 确保数据一致性，失败自动回滚

4. **软删除**:
   - 使用 isDeleted 标志实现软删除
   - 防止误删除，保留数据历史

5. **审计日志**:
   - 记录创建人和更新人ID
   - 记录创建时间和更新时间
   - 所有关键操作都有日志记录

### 使用建议

1. **规格代码命名**:
   - 建议使用有意义的编码规则，如 `LK` + 3位数字
   - 避免使用特殊字符，只使用大写字母、数字和中划线

2. **尺寸单位统一**:
   - 长宽高统一使用厘米(cm)
   - 载重统一使用千克(kg)
   - 避免单位混用导致的计算错误

3. **状态管理**:
   - 启用状态的规格才能被料框注册使用
   - 禁用规格前确认没有料框实例在使用
   - 临时停用建议使用禁用而非删除

4. **数据维护**:
   - 定期审查供应商信息的准确性
   - 适用产品类型列表及时更新
   - 规格参数变更需要评估影响范围

5. **性能优化**:
   - 列表查询使用合理的分页参数
   - 使用筛选条件减少查询数据量
   - 避免频繁的全量查询操作
