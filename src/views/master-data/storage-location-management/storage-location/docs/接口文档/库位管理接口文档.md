本文档详细说明了 Moses API 库位管理模块的所有接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。**本文档严格基于实际代码实现编写**，确保前端开发人员能够准确对接。

### API 基础信息

- **基础 URL**: `http://localhost:3000/v1` (开发环境)
- **API 版本**: v1
- **认证方式**: JWT Bearer Token
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### Swagger 文档

项目已集成 Swagger 文档，可通过以下地址访问：

- **开发环境**: http://localhost:3000/v1/docs
- **在线文档**: 提供完整的 API 接口说明、参数定义和示例

### 权限约定

本模块涉及以下权限点：
- `mdm.storage-location.manage`：创建、编辑、更新库位信息，更改占用状态
- `mdm.storage-location.view`：查询、查看库位信息

**注意事项**：所有写操作（POST、PATCH）需要 `manage` 权限，所有读操作（GET）需要 `view` 权限。

## 统一响应格式

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

## 库位管理接口详细说明

### 1. 创建库位

**接口路径**: `POST /v1/mdm/storage-locations`

**功能描述**: 创建新的库位，校验库位ID唯一性、库区状态、承重/尺寸/堆叠高度范围以及适用料框规格有效性。库位ID会自动转换为大写格式。

**认证要求**: 需要 Bearer Token，权限：`mdm.storage-location.manage`

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名                 | 类型          | 必填 | 限制                                                                        | 描述                         | 示例              |
| ---------------------- | ------------- | ---- | --------------------------------------------------------------------------- | ---------------------------- | ----------------- |
| locationId             | string        | 是   | 2-100字符，大写字母/数字/-                                                  | 库位ID，全局唯一，自动转大写 | "DA-01-01-A"      |
| storageAreaId          | string        | 是   | UUID格式                                                                    | 所属库区ID                   | "550e8400..."     |
| locationType           | string        | 是   | 枚举值：ground_stacking/fixed_rack/preparation_station/furnace_port_virtual | 库位类型                     | "ground_stacking" |
| coordinateX            | number        | 否   | -99999.99 ~ 99999.99                                                        | X坐标(cm)，用于可视化        | 100.5             |
| coordinateY            | number        | 否   | -99999.99 ~ 99999.99                                                        | Y坐标(cm)，用于可视化        | 200.0             |
| coordinateZ            | number        | 否   | -99999.99 ~ 99999.99                                                        | Z坐标(cm)，用于可视化        | 0.0               |
| lengthLimit            | number        | 否   | 0.01 ~ 10000                                                                | 长度限制(cm)                 | 120.0             |
| widthLimit             | number        | 否   | 0.01 ~ 10000                                                                | 宽度限制(cm)                 | 100.0             |
| heightLimit            | number        | 否   | 0.01 ~ 10000                                                                | 高度限制(cm)                 | 200.0             |
| loadCapacity           | number        | 是   | 0.01 ~ 100000                                                               | 承重限制(kg)                 | 5000              |
| applicableBinSpecCodes | array[string] | 否   | 最多20个，每个1-50字符                                                      | 适用料框规格代码列表         | ["STD-1000"]      |
| maxStackHeight         | integer       | 否   | 1 ~ 50                                                                      | 最大堆叠高度（层数）         | 5                 |

**请求示例**:

```bash
curl -X POST http://localhost:3000/v1/mdm/storage-locations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "locationId": "DA-01-01-A",

    "widthLimit": 100.0,
    "heightLimit": 200.0,
    "loadCapacity": 5000,
    "applicableBinSpecCodes": ["STD-1000"],
    "maxStackHeight": 5
  }'
```

**响应字段说明**:

| 字段名                 | 类型          | 描述                         | 示例                                   |

⚠️ **重要提醒**:
- `locationTypeName` 和 `occupancyStatusName` 是通过模型的 `toJSON` 方法自动添加的计算字段

- 新创建的库位默认占用状态为 `free`（空闲）
- 所有数据库字段都会在响应中返回

### 2. 查询库位列表

**接口路径**: `GET /v1/mdm/storage-locations`

**功能描述**: 支持分页、库区、状态、类型、关键字等条件查询库位列表，包含关联库区信息，支持灵活的排序选项。

**认证要求**: 需要 Bearer Token，权限：`mdm.storage-location.view`

**请求头**:

```
Authorization: Bearer <access_token>
```

**查询参数**:

| 参数名          | 类型   | 必填 | 限制                                                                        | 描述                         | 示例              |
| --------------- | ------ | ---- | --------------------------------------------------------------------------- | ---------------------------- | ----------------- |
| keyword         | string | 否   | 最大100字符                                                                 | 关键词（库位ID）模糊搜索     | "DA-01"           |
| storageAreaId   | string | 否   | UUID格式                                                                    | 库区ID筛选                   | "550e8400..."     |
| occupancyStatus | string | 否   | 枚举值：free/occupied/reserved/disabled/maintenance                         | 占用状态筛选                 | "free"            |
| locationType    | string | 否   | 枚举值：ground_stacking/fixed_rack/preparation_station/furnace_port_virtual | 库位类型筛选                 | "ground_stacking" |
| page            | number | 否   | 最小值1                                                                     | 页码，默认1                  | 1                 |
| limit           | number | 否   | 1-100                                                                       | 每页数量，默认10             | 10                |
| sortBy          | string | 否   | 格式：字段名:(asc\|desc)                                                    | 排序字段，默认按创建时间降序 | "createdAt:desc"  |

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码
2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息
4. **重试机制**: 对于包含 `retryAfter` 字段的错误，应按照指定时间后重试
5. **日志记录**: 使用 `traceId` 进行错误追踪和问题排查

### 日期时间格式

- 所有日期时间字段均使用 ISO 8601 格式：`YYYY-MM-DDTHH:mm:ss.sssZ`
- 示例：`"2024-01-20T10:30:00.000Z"`
- 时区：UTC（协调世界时）

## 业务规则说明

### 库位ID规则
- **格式要求**：只能包含大写字母、数字和中划线
- **长度限制**：2-100个字符
- **唯一性**：全局唯一，不允许重复
- **自动转换**：输入时自动转换为大写
- **建议格式**：库区代码-行号-列号-层号
- **示例**：`DA-01-01-A`、`YA-02-03-B`

### 尺寸和承重限制
- **坐标范围**：X/Y/Z坐标均为 -99999.99 ~ 99999.99 cm
- **长度限制**：0.01 ~ 10000 cm
- **宽度限制**：0.01 ~ 10000 cm
- **高度限制**：0.01 ~ 10000 cm
- **承重限制**：0.01 ~ 100000 kg
- **堆叠高度**：1 ~ 50 层

### 占用状态管理
- **默认状态**：新创建的库位默认为 `free`（空闲）状态
- **状态转换**：必须遵循状态转换规则，不能任意转换
- **禁用限制**：occupied 状态的库位不能直接禁用，需先释放
- **幂等性**：重复设置相同状态不会报错，直接返回成功

### 状态转换规则

系统实现了完整的状态机制，确保状态转换的合法性：

```
free (空闲)
  ├─> occupied (占用)
  ├─> reserved (预留)
  └─> disabled (禁用)

occupied (占用)
  ├─> free (空闲)
  └─> maintenance (维护)

reserved (预留)
  ├─> free (空闲)
  ├─> occupied (占用)
  └─> disabled (禁用)

disabled (禁用)
  └─> free (空闲)

maintenance (维护)
  ├─> free (空闲)
  └─> disabled (禁用)
```

### 库位与库区关系
- 库位必须属于某个已启用的库区
- 禁用的库区无法创建新库位
- 库区信息在查询库位时自动关联返回
- 库位的 `storageAreaId` 创建后不可修改

### 适用料框规格
- 最多可配置 20 个规格代码
- 如果未配置（null 或空数组），表示不限制料框规格
- 配置后，只有匹配规格的料框才能放入该库位
- 规格代码列表不允许重复

## 安全说明

### 认证机制

所有接口都需要通过 JWT (JSON Web Token) 进行认证：
1. 用户登录后获取 access token
2. 在请求头中携带：`Authorization: Bearer <access_token>`
3. Token 过期后需要重新登录获取新的 Token

### 权限控制

库位管理模块实现了基于角色的访问控制（RBAC）：
- **查看权限** (`mdm.storage-location.view`)：查询库位列表、获取库位详情
- **管理权限** (`mdm.storage-location.manage`)：创建库位、更新库位信息、更改占用状态

### 数据安全

- **软删除机制**：删除操作采用软删除，数据不会真正从数据库中删除
- **操作审计**：所有操作都会记录操作人ID和操作时间
- **唯一性保证**：通过数据库唯一索引保证库位ID的唯一性
- **事务保护**：状态变更使用事务确保数据一致性
- **乐观锁**：更新操作使用行锁防止并发冲突

### 使用建议

1. **定期备份数据**：虽然采用软删除，但仍建议定期备份重要数据
2. **权限最小化原则**：只给用户分配必要的权限
3. **监控异常操作**：定期检查操作日志，发现异常及时处理
4. **合理规划库位**：库位ID建议使用有意义的编码规则，便于识别和管理
5. **状态同步**：库位状态变更应与实际物理状态保持同步
