# Moses API 库位管理模块接口文档

## 概述

本文档详细说明了 Moses API 库位管理模块的所有接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。**本文档严格基于实际代码实现编写**，确保前端开发人员能够准确对接。

⚠️ **特别注意**：
- **🎯 响应结构一致性**：响应数据结构必须与代码实际返回的结构完全一致，字段名称、数据类型、嵌套层级都不得有任何偏差
- **🔗 关联对象完整性**：如果接口返回包含关联对象（如库区信息等），必须完整列出所有关联字段
- **📊 嵌套对象详细说明**：对于复杂的嵌套对象，必须提供详细的字段说明表格，不能仅在主响应示例中展示
- **🧮 计算字段标注**：模型中通过 toJSON 方法添加的计算字段（如类型中文名称等）必须在文档中明确标注

### API 基础信息

- **基础 URL**: `http://localhost:3000/v1` (开发环境)
- **API 版本**: v1
- **认证方式**: JWT Bearer Token
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### Swagger 文档

项目已集成 Swagger 文档，可通过以下地址访问：

- **开发环境**: http://localhost:3000/v1/docs
- **在线文档**: 提供完整的 API 接口说明、参数定义和示例

### 权限约定

库位管理模块使用以下权限点控制访问：

- `mdm.storage-area.view`：查看库区信息权限（可执行库区查询、详情等只读操作）
- `mdm.storage-area.manage`：管理库区权限（可执行库区创建、编辑等写操作）
- `mdm.storage-location.view`：查看库位信息权限（可执行库位查询、详情等只读操作）
- `mdm.storage-location.manage`：管理库位权限（可执行库位创建、编辑、状态变更等写操作）

## 统一响应格式

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

## 库区管理接口详细说明

### 1. 创建库区

**接口路径**: `POST /v1/mdm/storage-areas`

**功能描述**: 创建新的库区，校验代码唯一性并初始化启用状态。库区代码会自动转换为大写格式，创建成功后库区默认为启用状态。

**认证要求**: 需要 Bearer Token

**权限要求**: `mdm.storage-area.manage`

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名      | 类型   | 必填 | 限制                           | 描述                           | 示例                       |
| ----------- | ------ | ---- | ------------------------------ | ------------------------------ | -------------------------- |
| areaCode    | string | 是   | 1-50字符，大写字母/数字/中划线 | 库区代码，全局唯一，自动转大写 | "DA"                       |
| areaName    | string | 是   | 1-200字符                      | 库区名称                       | "待退火区"                 |
| areaType    | string | 是   | 枚举值：DA/YA/HC/ZJ/BLT        | 库区类型                       | "DA"                       |
| description | string | 否   | 最大500字符                    | 库区描述信息                   | "用于存放待退火的铝箔料框" |

**areaType 枚举值说明**:

- `DA`: 待退火区
- `YA`: 已退火区
- `HC`: 缓存区
- `ZJ`: 质检区
- `BLT`: 备料台区域

**请求示例**:

```bash
curl -X POST http://localhost:3000/v1/mdm/storage-areas \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "areaCode": "DA",
    "areaName": "待退火区",
    "areaType": "DA",
    "description": "用于存放待退火的铝箔料框"
  }'
```


### 2. 查询库区列表

**接口路径**: `GET /v1/mdm/storage-areas`

**功能描述**: 支持分页、状态、关键字等条件查询库区列表。支持按代码或名称模糊搜索，按库区类型、状态筛选，并提供灵活的排序选项。

**认证要求**: 需要 Bearer Token

**权限要求**: `mdm.storage-area.view`

**请求头**:

```
Authorization: Bearer <access_token>
```

**查询参数**:

| 参数名   | 类型    | 必填 | 限制                     | 描述                                   | 示例             |
| -------- | ------- | ---- | ------------------------ | -------------------------------------- | ---------------- |
| keyword  | string  | 否   | 最大100字符              | 关键词搜索（库区代码或名称），模糊匹配 | "退火"           |
| status   | string  | 否   | 枚举值：enabled/disabled | 库区状态筛选                           | "enabled"        |
| areaType | string  | 否   | 枚举值：DA/YA/HC/ZJ/BLT  | 库区类型筛选                           | "DA"             |
| page     | integer | 否   | 最小值：1                | 页码，默认值：1                        | 1                |
| limit    | integer | 否   | 1-100                    | 每页数量，默认值：10                   | 10               |
| sortBy   | string  | 否   | 格式：字段名:(asc\|desc) | 排序字段，默认：createdAt:desc         | "createdAt:desc" |

**请求示例**:

```bash
curl -X GET "http://localhost:3000/v1/mdm/storage-areas?keyword=退火&status=enabled&page=1&limit=10&sortBy=createdAt:desc" \
```

### 4. 更新库区信息

**接口路径**: `PATCH /v1/mdm/storage-areas/:areaId`

**功能描述**: 更新库区基础信息，支持部分字段更新。可以更新库区名称、描述、状态等信息，但不支持更新库区代码。

**认证要求**: 需要 Bearer Token

**权限要求**: `mdm.storage-area.manage`

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**路径参数**:

| 参数名 | 类型   | 必填 | 限制        | 描述               | 示例                                   |
| ------ | ------ | ---- | ----------- | ------------------ | -------------------------------------- |

### 5. 创建库位

**接口路径**: `POST /v1/mdm/storage-locations`

**功能描述**: 创建新的库位，校验库位ID唯一性、库区状态、承重/尺寸/堆叠高度范围以及适用料框规格有效性。库位ID会自动转换为大写格式，创建成功后库位默认为空闲状态。

**认证要求**: 需要 Bearer Token

**权限要求**: `mdm.storage-location.manage`

**请求头**:

```

```

| storageAreaId          | string        | 是   | UUID v4格式                                                                 | 所属库区ID                   | "554e44..."        |
| locationType           | string        | 是   | 枚举值：ground_stacking/fixed_rack/preparation_station/furnace_port_virtual | 库位类型                     | "ground_stacking"  |

### 9. 更改库位占用状态

**接口路径**: `PATCH /v1/mdm/storage-locations/:locationId/occupancy`

**功能描述**: 更改库位占用状态（占用/释放/预留/维护/禁用），使用事务确保幂等性，校验当前状态并记录操作日志。状态转换遵循预定义的转换规则，如果当前状态已是目标状态则直接返回成功。

**认证要求**: 需要 Bearer Token

**权限要求**: `mdm.storage-location.manage`

**请求头**:

```

```

**路径参数**:

| 参数名     | 类型   | 必填 | 限制        | 描述               | 示例                                   |
| ---------- | ------ | ---- | ----------- | ------------------ | -------------------------------------- |

**请求参数**:

| 参数名          | 类型   | 必填 | 限制                                                | 描述         | 示例       |
| --------------- | ------ | ---- | --------------------------------------------------- | ------------ | ---------- |
| occupancyStatus | string | 是   | 枚举值：free/occupied/reserved/disabled/maintenance | 新的占用状态 | "occupied" |

**状态转换规则说明**:

| 当前状态    | 允许转换到的状态                          |
| ----------- | ----------------------------------------- |
| free        | occupied, reserved, disabled, maintenance |

| reserved    | occupied, free, disabled                  |
| disabled    | free, maintenance                         |
| maintenance | free, disabled                            |

**特殊规则**:

- 如果当前状态已经是目标状态，直接返回成功（幂等性保证）

## 错误码说明

系统使用统一的错误码体系，便于客户端处理和日志追踪。错误码格式：模块前缀_数字编号。

### 库位管理相关错误码 (STR_xxx)

#### 库区相关错误码 (STR_001-STR_019)

| 错误码  | HTTP 状态码 | 错误消息           | 说明                   | 处理建议                             |
| ------- | ----------- | ------------------ | ---------------------- | ------------------------------------ |
| STR_001 | 409         | 库区代码已存在     | 创建库区时代码重复     | 更换库区代码后重试                   |
| STR_002 | 400         | 库区代码格式不正确 | 库区代码不符合格式规则 | 检查代码格式（大写字母/数字/中划线） |
| STR_003 | 404         | 库区不存在或已删除 | 查询的库区不存在       | 检查库区ID是否正确                   |
| STR_004 | 500         | 创建库区失败       | 创建库区时发生系统错误 | 联系系统管理员                       |
| STR_005 | 500         | 更新库区失败       | 更新库区时发生系统错误 | 联系系统管理员                       |
| STR_006 | 500         | 删除库区失败       | 删除库区时发生系统错误 | 联系系统管理员                       |
| STR_007 | 400         | 库区下存在库位     | 有库位的库区不能删除   | 先删除所有库位                       |
| STR_008 | 400         | 库区状态无效       | 提供的库区状态值不合法 | 使用 enabled 或 disabled             |
| STR_009 | 400         | 库区已禁用         | 禁用的库区不能添加库位 | 先启用库区                           |

#### 库位相关错误码 (STR_020-STR_049)

| 错误码  | HTTP 状态码 | 错误消息           | 说明                   | 处理建议                           |
| ------- | ----------- | ------------------ | ---------------------- | ---------------------------------- |
| STR_020 | 409         | 库位ID已存在       | 创建库位时ID重复       | 更换库位ID后重试                   |

### 通用错误码

**参考认证模块文档中的通用错误码部分，包括：**
- 认证相关错误码 (AUTH_xxx)
- 验证相关错误码 (VAL_xxx)
- 业务逻辑错误码 (BIZ_xxx)
- 系统错误码 (SYS_xxx)

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理
   - `AUTH_`: 认证相关错误，可能需要重新登录或刷新令牌
   - `VAL_`: 验证相关错误，需要检查输入参数
   - `STR_`: 库位管理业务错误，需要根据具体业务规则处理
   - `SYS_`: 系统错误，通常需要重试或联系支持

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息

4. **重试机制**: 对于包含 `retryAfter` 字段的错误，应按照指定时间后重试

5. **日志记录**: 使用 `traceId` 进行错误追踪和问题排查

6. **业务异常处理**:
   - STR_001-STR_019: 库区相关错误，提示用户检查库区配置
   - STR_020-STR_029: 库位基础错误，提示用户检查库位信息
   - STR_030-STR_039: 尺寸承重错误，提示用户调整参数至有效范围
   - STR_040-STR_059: 状态转换错误，提示用户检查库位当前状态
   - STR_060-STR_079: 业务规则错误，提示用户按业务要求操作

## 数据模型

### 库区（StorageArea）模型

库区是库位管理的顶层组织单元，用于划分不同功能的存储区域。

```json
{
  "id": "554e4422-beac-48bd-a22b-43b38a3c212b",
  "areaCode": "DA",
  "areaName": "待退火区",
  "areaType": "DA",
  "areaTypeName": "待退火区",
  "description": "用于存放待退火的铝箔料框",
  "status": "enabled",
  "isDeleted": false,
  "createdBy": "8f5a234e-3c9d-4a1f-b67e-9a8b7c6d5e4f",
  "updatedBy": "8f5a234e-3c9d-4a1f-b67e-9a8b7c6d5e4f",
  "createdAt": "2024-01-20T10:30:00.000Z",
  "updatedAt": "2024-01-20T10:30:00.000Z"
}
```

**字段分类说明**:

**数据库字段**:
- `id`: 库区唯一标识（UUID）
- `areaCode`: 库区代码，全局唯一
- `areaName`: 库区名称
- `areaType`: 库区类型枚举值
- `description`: 库区描述
- `status`: 库区状态（enabled/disabled）
- `isDeleted`: 软删除标志
- `createdBy`: 创建人ID
- `updatedBy`: 更新人ID
- `createdAt`: 创建时间
- `updatedAt`: 更新时间

**计算字段**（通过 toJSON 方法添加）:
- `areaTypeName`: 库区类型中文名称

### 库位（StorageLocation）模型

库位是具体的存储位置，包含详细的空间约束和状态信息。

```json
{
  "id": "775g6644-dgce-5acf-c44d-65d5ac5e434d",
  "locationId": "DA-01-01-A",
  "storageAreaId": "554e4422-beac-48bd-a22b-43b38a3c212b",
  "locationType": "ground_stacking",
  "locationTypeName": "地面堆垛区",
  "coordinateX": 100.5,
  "coordinateY": 200.3,
  "coordinateZ": 0,
  "lengthLimit": 250.0,
  "widthLimit": 180.0,
  "heightLimit": 300.0,
  "loadCapacity": 5000.0,
  "applicableBinSpecCodes": ["LK-01", "LK-02"],
  "occupancyStatus": "free",
  "occupancyStatusName": "空闲",
  "maxStackHeight": 3,
  "isDeleted": false,
  "createdBy": "8f5a234e-3c9d-4a1f-b67e-9a8b7c6d5e4f",
  "updatedBy": "8f5a234e-3c9d-4a1f-b67e-9a8b7c6d5e4f",
  "createdAt": "2024-01-20T10:30:00.000Z",
  "updatedAt": "2024-01-20T10:30:00.000Z",
  "storageArea": {
    "id": "554e4422-beac-48bd-a22b-43b38a3c212b",
    "areaCode": "DA",
    "areaName": "待退火区",
    "areaType": "DA",
    "status": "enabled"
  }
}
```

**字段分类说明**:

**数据库字段**:
- `id`: 库位唯一标识（UUID）
- `locationId`: 库位ID，全局唯一
- `storageAreaId`: 所属库区ID
- `locationType`: 库位类型枚举值
- `coordinateX`: X坐标（cm）
- `coordinateY`: Y坐标（cm）
- `coordinateZ`: Z坐标（cm）
- `lengthLimit`: 长度限制（cm）
- `widthLimit`: 宽度限制（cm）
- `heightLimit`: 高度限制（cm）
- `loadCapacity`: 承重限制（kg）
- `applicableBinSpecCodes`: 适用料框规格代码列表（JSON数组）
- `occupancyStatus`: 占用状态枚举值
- `maxStackHeight`: 最大堆叠高度（层数）
- `isDeleted`: 软删除标志
- `createdBy`: 创建人ID
- `updatedBy`: 更新人ID
- `createdAt`: 创建时间
- `updatedAt`: 更新时间

**计算字段**（通过 toJSON 方法添加）:
- `locationTypeName`: 库位类型中文名称
- `occupancyStatusName`: 占用状态中文名称

**关联字段**（通过 include 查询获取）:
- `storageArea`: 关联的库区对象

⚠️ **模型文档编写要求**：
1. **完整性检查**：已包含模型中所有可能返回的字段
2. **关联对象**：已列出通过 include 查询返回的 storageArea 关联对象结构
3. **计算字段**：已标注通过 toJSON 方法添加的计算字段（areaTypeName、locationTypeName、occupancyStatusName）
4. **字段分类**：已区分数据库字段、关联字段和计算字段

### 字段说明

**日期时间格式**:
- 所有日期时间字段均使用 ISO 8601 格式：`YYYY-MM-DDTHH:mm:ss.sssZ`
- 示例：`"2024-01-20T10:30:00.000Z"`
- 时区：UTC（+00:00）

**枚举值说明**:

库区类型（areaType）:
- `DA`: 待退火区
- `YA`: 已退火区
- `HC`: 缓存区
- `ZJ`: 质检区
- `BLT`: 备料台区域

库区状态（status）:
- `enabled`: 启用
- `disabled`: 禁用

库位类型（locationType）:
- `ground_stacking`: 地面堆垛区
- `fixed_rack`: 固定货架
- `preparation_station`: 备料台工位
- `furnace_port_virtual`: 炉口虚拟位

库位占用状态（occupancyStatus）:
- `free`: 空闲
- `occupied`: 占用
- `reserved`: 预留
- `disabled`: 禁用
- `maintenance`: 维护

**数值字段限制**:
- 坐标X: -100000 至 100000 cm
- 坐标Y: -100000 至 100000 cm
- 坐标Z: 0 至 10000 cm
- 长度限制: 0.01 至 10000 cm
- 宽度限制: 0.01 至 10000 cm
- 高度限制: 0.01 至 10000 cm
- 承重限制: 0.01 至 100000 kg
- 最大堆叠高度: 1 至 20 层

## 安全说明

### 认证机制

库位管理模块所有接口均需要 JWT Bearer Token 认证，认证机制与系统其他模块保持一致：

1. **获取令牌**: 通过登录接口获取 access token
2. **令牌使用**: 在请求头中添加 `Authorization: Bearer <token>`
3. **令牌刷新**: 令牌过期前通过刷新接口获取新令牌
4. **令牌失效**: 退出登录后令牌加入黑名单

详细认证流程请参考登录模块文档。

### 权限控制

库位管理模块实现了细粒度的权限控制：

1. **查看权限**:
   - `mdm.storage-area.view`: 可查看库区列表和详情
   - `mdm.storage-location.view`: 可查看库位列表和详情

2. **管理权限**:
   - `mdm.storage-area.manage`: 可创建、编辑库区
   - `mdm.storage-location.manage`: 可创建、编辑库位，变更占用状态

3. **权限检查**: 所有接口在执行前会验证用户是否拥有对应权限

### 安全特性

1. **数据验证**:
   - 使用 Joi 验证器进行严格的请求参数验证
   - 模型层进行数据格式和范围校验
   - 服务层进行业务规则验证

2. **数据完整性**:
   - 使用数据库事务确保关键操作的原子性
   - 唯一性约束防止重复数据
   - 外键约束保证数据关联完整性

3. **操作日志**:
   - 记录创建人和更新人信息
   - 记录创建时间和更新时间
   - 关键操作记录详细日志便于审计

4. **软删除机制**:
   - 使用 isDeleted 标志实现软删除
   - 删除的数据仍保留在数据库中
   - 查询时自动过滤已删除数据

### 使用建议

1. **令牌管理**:
   - 安全存储访问令牌，避免泄露
   - 及时刷新即将过期的令牌
   - 退出登录时清除本地令牌

2. **权限设计**:
   - 按照最小权限原则分配用户权限
   - 定期审查用户权限配置
   - 敏感操作需要额外权限验证

3. **数据操作**:
   - 创建库位前确保库区已启用
   - 变更库位状态前检查业务影响
   - 定期清理不再使用的库位数据

4. **错误处理**:
   - 根据错误码进行相应的用户提示
   - 记录错误traceId便于问题追踪
   - 对系统错误进行降级处理
