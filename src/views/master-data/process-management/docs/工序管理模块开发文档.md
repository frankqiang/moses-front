### **1. 功能开发清单 (What to Develop)**

#### **A. 基础工序定义 (Operation Management)**

1.  **工序主数据列表 (Operation List)**
    *   **功能**:
        *   以表格形式清晰展示所有工序。
        *   **客户端搜索**: 提供按`工序代码`或`工序名称`进行实时文本搜索。
        *   **客户端筛选**: 提供按`工序类型`和`状态`进行多选或单选筛选。
        *   **分页**: 支持前端分页，提高大数据量下的渲染性能。
        *   **列排序**: 支持点击表头对`工序代码`、`工序名称`等列进行升/降序排序。

2.  **工序创建/编辑 (Operation Create/Edit)**
    *   **功能**:
        *   以模态框（Modal/Dialog）形式提供表单，用于新建或编辑工序。
        *   **表单校验**:
            *   `工序代码`: 必填，全局唯一（在mock数据中检查重复），建议限制为大写字母、数字和下划线。
            *   `工序名称`: 必填，不允许为空。
            *   `工序类型`: 必填。
        *   **新建模式**: 表单为空，`工序代码`可编辑。
        *   **编辑模式**: 表单回填所选工序的数据，`工序代码`应设为只读，防止主键被修改。

3.  **工序状态变更 (Operation Status Change)**
    *   **功能**:
        *   在列表的每一行提供“禁用”或“启用”按钮，根据当前状态动态显示。
        *   点击按钮后，应有二次确认提示框（例如 "您确定要禁用'退火'工序吗？"）。
        *   确认后，更新mock数据中的状态，并刷新UI。

#### **B. 工艺路线编排 (Routing Management)**

1.  **工艺路线列表 (Routing List)**
    *   **功能**:
        *   以表格形式展示所有工艺路线的主信息。
        *   支持按`路线代码`、`路线名称`、`适用产品`进行搜索。
        *   支持按`状态`（草稿、待审批、生效、历史/归档）进行筛选。
        *   支持分页和列排序。

2.  **工艺路线创建/编辑 (Routing Editor)**
    *   **功能**:
        *   这是一个独立的页面，用于对单个工艺路线进行完整操作。
        *   **主信息区**:
            *   表单校验：`路线代码`（唯一性、必填）、`路线名称`（必填）。
            *   `适用产品`：提供一个用户友好的多选组件（如标签输入、带搜索的下拉多选），方便用户添加或删除产品。
        *   **工序步骤区**:
            *   **添加工序**: 点击按钮弹出一个“工序选择器”模态框。该模态框应展示所有“启用”状态的基础工序列表，并支持搜索和多选。
                *   **重复工序检查**: 系统会自动检查所选工序是否已存在于当前工艺路线中。如果已存在，将阻止重复添加并给出统一的警告提示，避免消息重叠。
                *   **唯一步骤ID (`stepId`) 生成**: 无论是否为重复的基础工序（业务上不允许），每个添加到工艺路线的步骤都会被分配一个全新的、唯一的 `stepId` (使用 UUID)，确保数据和渲染的唯一性。
                *   **智能消息提示**: 优化了添加工序后的消息提示逻辑，确保成功、警告或信息提示以单一、清晰的方式展示，避免多条提示同时弹出造成的遮挡问题。
            *   **步骤排序**: 每行提供“上移”和“下移”按钮，点击后直接修改`steps`数组的顺序并重新渲染。当步骤在最顶或最底时，相应按钮应禁用。
                *   **智能步骤号管理**：每当步骤被添加、移动或删除时，系统会自动重新计算并分配步骤号（例如，按 `10, 20, 30...` 的规则递增），确保流程顺序的清晰性和连续性。
                *   **流程逻辑自动重置**：为了避免因步骤顺序变化导致的流程逻辑链断裂问题（如 `nextStep` 指向无效步骤），在进行步骤移动或删除操作后，系统会自动清空所有步骤的流程逻辑配置（包括“下一步骤”、“成功后跳转”和“失败后跳转”）。同时，会弹出明确的提示框，强制用户重新审视并配置受影响的流程，确保工艺路线的有效性和健壮性。
            *   **步骤详情配置**:
                *   当用户在主编辑区点击一个步骤时，右侧的属性面板将动态渲染。其核心逻辑是**根据所选步骤的 `operation.type` 和 `timeStandards` 中各个 `type` 字段的值来动态展示和切换UI控件**。
                *   **面板结构 (以选中 `步骤20 - 退火后检验` 为例)**:
                    ```
                    +----------------------------------------------------------------------+
                    | [ 步骤属性配置 ]                                                     |
                    |   --- 步骤 20: 退火后检验 (检验类型) ---                             |
                    |----------------------------------------------------------------------|
                    | [▼] 流程逻辑 (Flow Logic)                                            |
                    |                                                                      |
                    |     * 成功下一步: [ 30 - 分切 ▼ ]                                    |
                    |     * 失败下一步: [ 50 - 表面处理返工 ▼ ]                            |
                    |                                                                      |
                    |----------------------------------------------------------------------|
                    | [▼] 时间标准 (Time Standards)                                        |
                    |                                                                      |
                    |   [ 准备时间 ]                                                       |
                    |     计算规则: [ 使用固定时间 ▼ ]  (选项: 使用固定时间, 使用切换矩阵) |
                    |     * 时间 (分钟) (i): [ 10         ]                                 |
                    |                                                                      |
                    |   [ 加工时间 ]                                                       |
                    |     计算规则: [ 使用固定时间 ▼ ]  (选项: 使用固定时间, 使用公式计算) |
                    |     * 时间:      [ 15         ] [ 分钟/卷 ▼ ] (i)                      |
                    |                                                                      |
                    +----------------------------------------------------------------------+
                    ```
                *   **动态交互逻辑详解**:
                    1.  **面板标题**: `--- 步骤 20: 退火后检验 (检验类型) ---`
                        *   动态显示**步骤号**、**工序名称**和**工序类型**，让用户时刻明确配置对象。
                    2.  **流程逻辑 (Flow Logic) 分组**:
                        *   **判断依据**: `operation.type`
                        *   **如果 `type` 是 "Inspection"**:
                            *   显示“成功下一步”和“失败下一步”两个下拉框。
                            *   下拉框选项为除自身外的所有步骤。
                            *   选择后，更新数据模型中的 `step.flowLogic.onSuccessStep` 和 `step.flowLogic.onFailureStep`。
                        *   **如果 `type` 是 "Production" 或其他**:
                            *   只显示一个“下一步”下拉框。
                            *   选择后，同时更新 `step.flowLogic.nextStep` 和 `step.flowLogic.onSuccessStep`，并将 `onFailureStep` 设为 `null`。
                    3.  **时间标准 (Time Standards) 分组**:
                        *   **[准备时间] 子分组**:
                            *   **`计算规则` 下拉框**:
                                *   **UI**: 绑定到数据模型的 `step.timeStandards.setup.type` 字段。
                                *   **选项**: "使用固定时间" (对应值 `Fixed`), "使用切换矩阵" (对应值 `Matrix`)。
                                *   **交互**: 当用户切换此选项时，下方的输入控件会动态变化。
                                    *   **选择 "使用固定时间"**: 显示一个标签为 `* 时间 (分钟) (i)` 的数字输入框，该输入框绑定到 `step.timeStandards.setup.value`。
                                    *   **选择 "使用切换矩阵"**: `* 时间 (分钟)` 输入框变为 `后备时间 (分钟)`（非必填），下方新增一个标签为 `* 关联矩阵` 的下拉框，绑定到 `step.timeStandards.setup.matrixId`。
                        *   **[加工时间] 子分组**:
                            *   **`计算规则` 下拉框**:
                                *   **UI**: 绑定到数据模型的 `step.timeStandards.processing.type` 字段。
                                *   **选项**: "使用固定时间" (`Fixed`), "使用公式计算" (`Formula`)。
                                *   **交互**:
                                    *   **选择 "使用固定时间"**: 显示复合输入控件 `[ * 时间 ] [ * 单位 ▼ ] (i)`，分别绑定到 `step.timeStandards.processing.value` 和 `unit`。
                                    *   **选择 "使用公式计算"**: 复合输入控件被一个标签为 `* 计算公式 (i)` 的多行文本输入框取代，该文本框绑定到 `step.timeStandards.processing.formula`。旁边可以提供一个“变量助手”按钮。
            *   **步骤删除**: 每行提供删除按钮，并有二次确认。
        *   **版本与状态控制**:
            *   页面底部或顶部的操作按钮（保存、提交审批等）根据当前路线的`status`和`version`动态显示/禁用。
            *   **创建新版本**: 点击后，应深度克隆当前“生效”的路线对象，增加版本号（如 v1.0 -> v1.1），将状态设为“草稿”，并允许用户在此基础上编辑。原v1.0版本状态不变。
            *   **提交审批/批准/驳回**: 点击后，在mock数据中修改`status`字段，并可以模拟一个审批记录的添加。
        *   **历史记录查看**:
            *   提供一个Tab页或区域，用于展示该路线的`changelog`（版本变更日志）和`approvalHistory`（审批历史）。

### **2. 注意点 (Key Considerations)**

1.  **分层设计，逐步实施**: 先完成“基础工序定义”，再做“工艺路线编排”。
2.  **版本控制是生命线**: 任何对“生效”路线的修改都必须通过创建新版本进行。
3.  **与产品主数据的关系**: 工艺路线必须能明确关联到一个或多个产品。
4.  **抽象与具体的分离**: “工序”是可复用的基础定义，“步骤”是工序在具体路线中的一次应用。
5.  **为未来扩展做准备**: 数据结构中预留了`reportingPoint`, `associatedResourceType`, `standardSetupTime`等字段，即使初期UI不完全实现，模型也已具备扩展性。
6.  **用户体验**: 即使没有拖拽，通过“上移/下移”和清晰的属性面板也能提供良好的编辑体验。

        | `stepNumber`   | `number` | 是       | **步骤号**。定义了步骤在工艺路线中的执行顺序。建议由系统自动管理（如10, 20, 30...），以方便插入和排序。它是流程逻辑跳转的依据。       |

        | `timeStandards`| `object` | 是       | **时间标准对象**。一个聚合对象，包含了所有与该步骤的标准时间相关的配置信息，并内置了对动态时间的支持。详见下文。                         |
    *   **二级对象 `flowLogic` 字段详解**
        | 字段名          | 数据类型       | 是否必填 | 描述                                                                                                                                                                                                           |
        |-----------------|----------------|----------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
        | `nextStep`      | `number` \| `null` | 否       | **默认下一步骤号**。主要用于**非检验类型**的工序（如生产、包装），表示该步骤完成后流程应转至的`stepNumber`。通常，它的值会和`onSuccessStep`保持一致。                                                          |
        | `onSuccessStep` | `number` \| `null` | 否       | **成功下一步骤号**。主要用于**检验类型**的工序，表示当检验结果为“合格”时，流程应转至的`stepNumber`。对于非检验工序，此字段代表其唯一的、成功的完成路径。如果一个步骤是流程的终点，此值为`null`。 |
        | `onFailureStep` | `number` \| `null` | 否       | **失败下一步骤号**。**仅用于检验类型**的工序，表示当检验结果为“不合格”时，流程应转至的`stepNumber`（例如，返工、报废或评审工序）。如果检验工序没有失败路径（即失败也算流程结束），此值为`null`。  |
    *   **二级对象 `timeStandards` 字段详解**
        *   **`timeStandards.setup` (准备时间对象)**
            | 字段名       | 数据类型       | 是否必填 | 描述                                                                                                                                                                                          |
            |--------------|----------------|----------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
            | `type`       | `string`       | 是       | **准备时间计算类型**。这是一个**开关**字段，决定了系统如何计算准备时间。枚举值：<br> - `"Fixed"`: 表示使用固定的准备时间。<br> - `"Matrix"`: 表示需要根据上下文，在一个“准备时间切换矩阵”中查找准备时间。          |
            | `value`      | `number`       | 是       | **时间值**。其含义取决于`type`字段：<br> - 当`type`为`"Fixed"`时，此字段存储**固定的准备时间值**。<br> - 当`type`为`"Matrix"`时，此字段存储一个**后备的默认值**，在切换矩阵中找不到匹配规则时使用。     |
            | `unit`       | `string`       | 是       | **时间单位**。明确`value`字段的单位。建议统一为一种基础单位，如`"minute"`。                                                                                                                    |
            | `matrixId`   | `string` \| `null` | 否       | **关联的切换矩阵ID**。**仅当`type`为`"Matrix"`时**，此字段才有意义，它存储了所关联的`setup_matrices`表的主键ID。当`type`为`"Fixed"`时，此字段应为`null`。**这是动态准备时间的预留扩展字段**。   |
        *   **`timeStandards.processing` (加工时间对象)**
            | 字段名     | 数据类型       | 是否必填 | 描述                                                                                                                                                                                           |
            |------------|----------------|----------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
            | `type`     | `string`       | 是       | **加工时间计算类型**。这是一个**开关**字段，决定了系统如何计算加工时间。枚举值：<br> - `"Fixed"`: 表示使用固定的加工时间。<br> - `"Formula"`: 表示需要通过一个文本公式来动态计算加工时间。           |
            | `value`    | `number`       | 是       | **时间值**。其含义取决于`type`字段：<br> - 当`type`为`"Fixed"`时，此字段存储**固定的加工时间值**。<br> - 当`type`为`"Formula"`时，此字段可以被忽略或作为一个无法计算公式时的后备值。      |
            | `unit`     | `string`       | 是       | **加工时间单位**。明确`value`字段的单位，这对于加工时间尤为重要。例如：`"minute/ton"` (分钟/吨), `"minute/roll"` (分钟/卷), `"minute/batch"` (分钟/批次)。 |
            | `formula`  | `string` \| `null` | 否       | **加工时间计算公式**。**仅当`type`为`"Formula"`时**，此字段才有意义，它存储了一个包含变量（如`[thickness_mm]`）的文本表达式。当`type`为`"Fixed"`时，此字段应为`null`。**这是动态加工时间的预留扩展字段**。 |

### **附录：动态时间预留扩展设计说明**

#### **附录A：标准准备时间 (`standardSetupTime`) 的动态化扩展**

*   **设计思想**: 采用“**默认值 + 扩展**”模式。系统承认“准备时间”可能依赖于上一个任务的属性（例如，从生产A产品切换到B产品）。
*   **数据模型预留**:
    *   **保留字段**: `standard_setup_time` (DECIMAL)。在当前版本中，此字段用于存储一个**固定的、默认的**准备时间。
    *   **预留字段**: `setup_matrix_id` (VARCHAR/INT, 可为`NULL`)。
        *   **作用**: 这是一个外键，指向一个未来可能创建的`setup_matrices`（准备时间切换矩阵）表。
        *   **当前状态**: 在当前版本中，该字段值**始终为`NULL`**。系统逻辑不依赖此字段。
*   **未来升级路径**:
    1.  **新建模块**: 创建“准备时间切换矩阵”主数据管理模块，允许用户定义不同产品属性之间切换所需的准备时间（例如，颜色、规格）。
    2.  **修改UI**: 在“工艺路线编辑器”中，允许用户为步骤的准备时间关联一个已定义的切换矩阵。选择后，`setup_matrix_id`字段将被赋值。
    3.  **修改核心逻辑**: 升级**排程引擎**。在计算任务间准备时间时：
        *   **优先检查** `setup_matrix_id` 字段。
        *   如果该字段有值，则根据前后任务的属性，在对应的切换矩阵中查找准确的准备时间。
        *   如果该字段为`NULL`，或在矩阵中找不到匹配规则，则**回退**使用`standard_setup_time`字段中的固定值。

#### **附录B：标准加工时间 (`standardProcessingTime`) 的动态化扩展**

*   **设计思想**: 采用“**默认值 + 扩展**”模式。系统承认“加工时间”可能依赖于当前任务所加工物料的自身属性（例如，厚度、宽度）。
*   **数据模型预留**:
    *   **保留字段**: `standard_processing_time` (DECIMAL) 和 `processing_time_unit` (VARCHAR)。在当前版本中，用于存储一个**固定的、默认的**加工时间及其单位。
    *   **预留字段**: `processing_time_formula` (VARCHAR/TEXT, 可为`NULL`)。
        *   **作用**: 用于存储一个可被解析的文本**计算公式**。
        *   **当前状态**: 在当前版本中，该字段值**始终为`NULL`**。
*   **未来升级路径**:
    1.  **修改UI**: 在“工艺路线编辑器”的步骤详情中，提供一个“高级”或“公式”模式，允许高级用户输入加工时间计算公式（例如：`"10 * [thickness] + 20"`，其中 `[thickness]` 是一个变量）。
    2.  **引入公式引擎**: 在后端引入一个简单的公式解析与计算引擎。
    3.  **修改核心逻辑**: 升级**计划与排程模块**。在计算任务的加工时间时：
        *   **优先检查** `processing_time_formula` 字段。
        *   如果该字段有值，则：
            *   从产品主数据中获取公式所需的变量值（如`thickness`）。
            *   使用公式引擎计算出动态的加工时间。
        *   如果该字段为`NULL`，则**回退**使用`standard_processing_time`字段中的固定值。
