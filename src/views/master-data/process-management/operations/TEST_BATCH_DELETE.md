# 批量删除功能测试指南

## 测试目标
验证工序批量删除功能能够：
1. 明确告知用户哪些工序无法删除及原因
2. 提供具体的工序名称而不是ID
3. 友好的多行错误提示显示

## 测试步骤

### 1. 准备测试数据
在工序管理页面，确保列表中包含以下工序（这些工序在Mock数据中被标记为"正在使用中"）：

- **工序ID**: op-001，**工序代码**: ROLLING，**工序名称**: 热轧
- **工序ID**: op-002，**工序代码**: ANNEALING，**工序名称**: 退火

### 2. 测试场景

#### 场景1：删除正在使用的工序
1. 在工序列表中勾选包含 "热轧(ROLLING)" 和 "退火(ANNEALING)" 的工序
2. 点击批量删除按钮
3. 在确认对话框中点击"确定"

**预期结果**：
- 显示错误提示消息，格式如下：
```
以下工序正在被工艺路线使用，无法删除：
【ROLLING】热轧
【ANNEALING】退火
```
- 消息显示时间：8秒
- 支持多行显示，格式清晰

#### 场景2：删除可删除的工序
1. 在工序列表中勾选其他状态为"启用"且ID不是op-001、op-002的工序
2. 点击批量删除按钮
3. 在确认对话框中点击"确定"

**预期结果**：
- 显示成功删除的消息
- 列表自动刷新，删除的工序消失

#### 场景3：混合删除（部分可删除，部分不可删除）
1. 同时勾选op-001(热轧)和其他可删除的工序
2. 点击批量删除按钮

**预期结果**：
- 仅显示无法删除的工序错误信息
- 可删除的工序不会被删除（Mock API的限制）

## 验证要点

### ✅ 成功标准
- [ ] 错误提示包含工序代码（如【ROLLING】）
- [ ] 错误提示包含工序名称（如热轧）
- [ ] 错误信息清楚说明无法删除的原因（"正在被工艺路线使用"）
- [ ] 多行显示格式清晰，易于阅读
- [ ] 消息显示时间足够长（8秒），用户能充分阅读
- [ ] 不再显示原始ID（如op-001）

### ❌ 问题检查
- [ ] 是否仍然显示原始ID而不是工序名称？
- [ ] 错误信息是否过于简略或不清楚？
- [ ] 多个工序的错误信息是否堆叠在一行？
- [ ] 消息是否消失得太快？

## 代码改进说明

### 主要改进点
1. **错误处理逻辑修正**：修正了Mock API响应结构的解析
2. **显示格式优化**：使用【工序代码】工序名称的格式
3. **多行显示支持**：使用`\n`换行符和`white-space: pre-line`样式
4. **消息持续时间延长**：从5秒延长到8秒
5. **原因明确化**："正在被工艺路线使用"比"正在使用中"更具体

### 技术实现
- 使用`dangerouslyUseHTMLString: true`支持换行显示
- 自定义CSS类`batch-delete-error-message`优化显示样式
- 增强错误信息构建逻辑，确保信息完整性

## 故障排除

如果测试失败，请检查：
1. Mock服务是否正常运行
2. 浏览器控制台是否有JavaScript错误
3. 网络请求是否成功返回
4. Mock数据中op-001和op-002工序是否存在

- 此功能依赖Mock服务模拟后端逻辑
- 实际生产环境中，关联数据检查将由真实的后端API实现
- 测试时请使用Chrome或Firefox浏览器以获得最佳体验
