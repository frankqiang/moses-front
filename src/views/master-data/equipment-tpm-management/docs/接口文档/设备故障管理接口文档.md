# Moses API 设备故障管理模块接口文档

## 概述

本文档详细说明了 Moses API 设备故障管理模块的所有接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。**本文档严格基于实际代码实现编写**，确保前端开发人员能够准确对接。

设备故障管理模块提供完整的故障报告、处理流程、验证关闭和统计分析功能，支持MTTR（平均修复时间）、MTBF（平均故障间隔时间）等关键指标的自动计算。

## 功能特性

- ✅ 故障报告创建与编码自动生成
- ✅ 故障处理全流程管理（待处理→处理中→已解决→已验证→已关闭）
- ✅ 备件使用记录与追踪
- ✅ 重复故障标记与分析
- ✅ 根本原因分析（5Why/鱼骨图）
- ✅ MTTR/MTBF 自动计算
- ✅ 故障趋势分析与统计

### API 基础信息

- **基础 URL**: `http://localhost:3000/v1` (开发环境)
- **API 版本**: v1
- **认证方式**: JWT Bearer Token
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### Swagger 文档

项目已集成 Swagger 文档，可通过以下地址访问：

- **开发环境**: http://localhost:3000/v1/docs
- **在线文档**: 提供完整的 API 接口说明、参数定义和示例

## 故障处理业务流程

```
发现故障 → 创建故障报告 → 分配处理人员 → 开始处理 → 使用备件 → 完成处理 → 验证 → 关闭故障单
                                                                          ↓
                                                                    根因分析 → 预防措施
```

### 状态流转说明

| 当前状态 | 可转换状态 | 操作         | 说明                   |
| -------- | ---------- | ------------ | ---------------------- |
| 待处理   | 处理中     | 开始处理故障 | 分配处理人员并开始处理 |
| 处理中   | 已解决     | 完成故障处理 | 记录处理措施和使用备件 |
| 已解决   | 已验证     | 验证故障处理 | 验证人员确认处理结果   |
| 已验证   | 已关闭     | 关闭故障单   | 完成整个处理流程       |
| 任意状态 | 已关闭     | 关闭故障单   | 异常情况下可直接关闭   |

## 设备故障管理接口详细说明

### 1. 创建故障报告

**接口路径**: `POST /v1/mdm/tpm/equipment-failures`

**功能描述**: 创建新的设备故障报告。当设备发生故障时，由发现人或报告人提交故障信息，系统自动生成故障编码并记录故障详情。支持故障等级、影响程度、故障类型等多维度分类，为后续的故障处理和统计分析提供基础数据。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名                  | 类型   | 必填 | 限制                                          | 描述                | 示例                       |
| ----------------------- | ------ | ---- | --------------------------------------------- | ------------------- | -------------------------- |
| failureCode             | string | 否   | 1-100字符，不提供则自动生成                   | 故障编码            | "GZ-2024-001"              |
| equipmentId             | string | 是   | UUID格式                                      | 关联设备ID          | "f47ac10b-58cc-4372-..."   |
| failureTime             | string | 是   | ISO 8601日期时间格式                          | 故障发生时间        | "2024-01-20T10:30:00.000Z" |
| reporterId              | string | 是   | UUID格式                                      | 故障发现人/报告人ID | "a1b2c3d4-e5f6-7890-..."   |
| failureDescription      | string | 是   | 不能为空                                      | 故障现象描述        | "设备异响，温度过高"       |
| failureLevel            | string | 是   | 枚举: I级-严重/II级-重大/III级-一般/IV级-轻微 | 故障等级            | "I级-严重"                 |
| impactDegree            | string | 是   | 枚举: 停机/性能下降/无影响                    | 影响程度            | "停机"                     |
| failureType             | string | 是   | 枚举: 机械/电气/液压/控制/其他                | 故障类型分类        | "机械"                     |
| failureCausePreliminary | string | 否   | -                                             | 初步故障原因分析    | "轴承磨损严重"             |

### 2. 查询故障列表

**接口路径**: `GET /v1/mdm/tpm/equipment-failures`

**功能描述**: 根据条件分页查询故障列表，支持按设备、故障等级、故障类型、状态、报告人、处理人、时间范围等多维度筛选，支持关键词搜索。返回的数据包含关联的设备信息、报告人信息和处理人信息，可用于故障管理看板和历史记录查询。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>

| --------------- | ------- | ---- | --------------------------------------------- | ------------------------------- | -------------------------- |

| failureLevel    | string  | 否   | 枚举: I级-严重/II级-重大/III级-一般/IV级-轻微 | 故障等级筛选                    | "I级-严重"                 |
| failureType     | string  | 否   | 枚举: 机械/电气/液压/控制/其他                | 故障类型筛选                    | "机械"                     |
| status          | string  | 否   | 多个状态用逗号分隔                            | 故障状态筛选                    | "待处理,处理中"            |
| reporterId      | string  | 否   | UUID格式                                      | 报告人ID筛选                    | "a1b2c3d4-e5f6-7890-..."   |

### 3. 查询单个故障详情

**接口路径**: `GET /v1/mdm/tpm/equipment-failures/{failureId}`

**功能描述**: 根据故障ID返回故障的完整详情，包含所有字段信息、关联的设备信息、报告人、处理人、验证人等完整信息。用于故障详情页面展示和处理流程追踪。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
```

**路径参数**:

| 参数名    | 类型   | 必填 | 描述   | 示例                          |
| --------- | ------ | ---- | ------ | ----------------------------- |
| failureId | string | 是   | 故障ID | "f47ac10b-58cc-4372-a567-..." |

## 错误码说明

### 设备故障相关错误码 (EQF_xxx)

| 错误码  | HTTP状态码 | 错误消息               | 说明                   | 处理建议                                   |
| ------- | ---------- | ---------------------- | ---------------------- | ------------------------------------------ |
| EQF_001 | 409        | 故障编码已存在         | 提供的故障编码已被使用 | 使用不同的故障编码或不提供（系统自动生成） |
| EQF_002 | 404        | 故障记录不存在         | 指定的故障ID不存在     | 检查故障ID是否正确                         |
| EQF_003 | 400        | 故障状态不允许开始处理 | 当前状态不是"待处理"   | 检查故障当前状态                           |
| EQF_004 | 400        | 故障状态不允许完成处理 | 当前状态不是"处理中"   | 需先调用开始处理接口                       |
| EQF_005 | 400        | 故障状态不允许验证     | 当前状态不是"已解决"   | 需先完成故障处理                           |
| EQF_006 | 400        | 故障单已关闭           | 故障单已经是关闭状态   | 无需重复关闭                               |

### 通用错误码

| 错误码           | HTTP状态码 | 错误消息                | 说明                         | 处理建议                   |
| ---------------- | ---------- | ----------------------- | ---------------------------- | -------------------------- |
| VALIDATION_ERROR | 400        | 请求参数验证失败        | 请求参数不符合验证规则       | 检查请求参数格式和必填字段 |
| UNAUTHORIZED     | 401        | 未授权，Token无效或过期 | 未提供认证Token或Token已失效 | 重新登录获取有效Token      |
| FORBIDDEN        | 403        | 无权限执行此操作        | 当前用户没有该操作的权限     | 联系管理员分配相应权限     |
| EQP_001          | 404        | 设备不存在              | 提供的设备ID无效             | 检查设备ID是否正确         |
| USER_001         | 404        | 用户不存在              | 提供的用户ID无效             | 检查用户ID是否正确         |
| SYSTEM_ERROR     | 500        | 系统内部错误            | 服务器内部错误               | 查看日志或联系技术支持     |

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码
2. **错误码模式识别**: 根据错误码前缀进行模式识别处理（EQF_ 表示设备故障相关错误）
3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息
4. **日志记录**: 使用 `traceId` 进行错误追踪和问题排查

  "mttrHours": "number",
  "isDeleted": "boolean",
  "createdBy": "string",
  "updatedBy": "string",
  "createdAt": "string",
  "updatedAt": "string"
}
```

### 字段说明

**基本信息**:
- `id`: 故障记录唯一标识（UUID）
- `failureCode`: 故障编码，全局唯一，自动生成或手动指定
- `equipmentId`: 关联设备ID
- `failureTime`: 故障发生时间（ISO 8601格式）
- `reporterId`: 故障报告人ID

**故障描述**:
- `failureDescription`: 故障现象描述
- `failureLevel`: 故障等级（I级-严重/II级-重大/III级-一般/IV级-轻微）
- `impactDegree`: 影响程度（停机/性能下降/无影响）
- `failureType`: 故障类型分类（机械/电气/液压/控制/其他）

**原因分析**:
- `failureCausePreliminary`: 初步故障原因分析
- `failureCauseDetailed`: 详细故障原因分析
- `rootCauseAnalysis`: 根本原因分析（5Why/鱼骨图）
- `preventiveMeasures`: 预防措施

**处理信息**:
- `repairStartTime`: 处理开始时间
- `repairEndTime`: 处理完成时间
- `repairActions`: 故障处理措施
- `sparePartsUsed`: 使用备件清单（JSON数组）
- `repairerId`: 处理人员ID
- `verifierId`: 验证人员ID

**状态和指标**:
- `status`: 故障处理状态（待处理/处理中/已解决/已验证/已关闭）
- `isRepeatFailure`: 是否重复故障
- `mttrHours`: 平均修复时间（小时），系统自动计算

**系统字段**:
- `isDeleted`: 软删除标记
- `createdBy`: 创建人ID
- `updatedBy`: 最后更新人ID
- `createdAt`: 创建时间
- `updatedAt`: 更新时间
