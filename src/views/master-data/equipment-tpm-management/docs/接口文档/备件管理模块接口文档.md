本文档详细说明了 Moses API 备件管理模块的所有接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。**本文档严格基于实际代码实现编写**，确保前端开发人员能够准确对接。

### API 基础信息

- **基础 URL**: `http://localhost:3000/v1` (开发环境)
- **API 版本**: v1
- **认证方式**: JWT Bearer Token
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### Swagger 文档

项目已集成 Swagger 文档，可通过以下地址访问：

- **开发环境**: http://localhost:3000/v1/docs
- **在线文档**: 提供完整的 API 接口说明、参数定义和示例

### 权限约定

> **备件管理模块权限映射**：
> - `mdm.tpm.spare-part.create`：创建备件主数据权限
> - `mdm.tpm.spare-part.view`：查询备件信息和库存权限（包括查看备件列表、详情、库存、出入库记录）
> - `mdm.tpm.spare-part.manage`：管理备件权限（包括更新备件信息、备件入库、备件出库）
>
> **注意事项**：备件管理模块不涉及审批流程，因此无需审批相关权限。

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

## 备件管理业务流程说明

### 业务流程概述

备件管理模块主要负责设备维护所需备件的全生命周期管理，包括备件主数据管理、库存管理和出入库管理。

```
步骤1：创建备件主数据
   ↓
步骤2：自动创建库存记录（初始库存为0）
   ↓
步骤3：备件入库 → 更新库存数量 → 记录入库流水
   ↓
步骤4：备件出库（领用/退库/报废） → 校验库存充足性 → 更新库存 → 记录出库流水
   ↓
步骤5：查询库存状态 → 低库存预警
   ↓
步骤6：查询出入库记录 → 追溯备件使用情况
```

### 流程说明

- **步骤1-2**：创建备件主数据时，系统自动创建对应的库存记录，初始库存为0。使用接口：`POST /v1/mdm/tpm/spare-parts`
- **步骤3**：备件采购到货后进行入库操作，系统自动更新库存数量并生成入库流水。使用接口：`POST /v1/mdm/tpm/spare-parts/:id/in-stock`
- **步骤4**：维护人员领用备件、退库或报废时进行出库操作，系统校验库存充足性后更新库存并生成出库流水。使用接口：`POST /v1/mdm/tpm/spare-parts/:id/out-stock`
- **步骤5**：查询备件库存状态，系统自动计算可用库存并判断是否低于安全库存。使用接口：`GET /v1/mdm/tpm/spare-parts/:id/inventory`
- **步骤6**：查询历史出入库记录，追溯备件的使用情况和流向。使用接口：`GET /v1/mdm/tpm/spare-parts/transactions`

## 备件管理接口详细说明

### 1. 创建备件主数据

**接口路径**: `POST /v1/mdm/tpm/spare-parts`

**功能描述**: 创建新的备件主数据，包含备件基础信息（编码、名称、规格等）和库存配置（安全库存、上下限等）。系统会自动创建对应的库存记录，初始库存为0。备件编码必须全局唯一，创建时会自动转换为大写。

**认证要求**: 需要 Bearer Token

**权限要求**: `mdm.tpm.spare-part.create`

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名                   | 类型    | 必填 | 限制                  | 描述                        | 示例             |

| sparePartName            | string  | 是   | 1-200字符             | 备件名称                    | "液压油滤芯"     |

### 通用错误码

**参考认证模块文档中的通用错误码部分，包括：**
- 认证相关错误码 (AUTH_xxx)
- 验证相关错误码 (VAL_xxx / VALIDATION_ERROR)
- 业务逻辑错误码 (BIZ_xxx)
- 系统错误码 (SYS_xxx)

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理
   - `AUTH_`: 认证相关错误，可能需要重新登录或刷新令牌
   - `VAL_` / `VALIDATION_ERROR`: 验证相关错误，需要检查输入参数
   - `TPM_SPARE_`: 备件管理业务逻辑错误，需要根据业务规则处理
   - `SYS_`: 系统错误，通常需要重试或联系支持

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息

4. **重试机制**: 对于包含 `retryAfter` 字段的错误，应按照指定时间后重试

5. **日志记录**: 使用 `traceId` 进行错误追踪和问题排查

## 安全说明

### 认证机制

备件管理模块的所有接口都需要通过 JWT Bearer Token 进行认证。Token 应在请求头的 Authorization 字段中提供：

```
Authorization: Bearer <access_token>
```

Token 的获取方式请参考认证模块的登录接口文档。

### 权限控制

备件管理模块实现了基于角色的权限控制（RBAC）：

1. **查询权限** (`mdm.tpm.spare-part.view`): 允许查询备件列表、详情、库存和出入库记录
2. **创建权限** (`mdm.tpm.spare-part.create`): 允许创建新的备件主数据
3. **管理权限** (`mdm.tpm.spare-part.manage`): 允许更新备件信息、备件入库和出库

### 安全特性

1. **输入验证**: 所有接口都使用 Joi 验证器进行严格的参数验证
2. **SQL注入防护**: 使用 Sequelize ORM 的参数化查询，防止 SQL 注入攻击
3. **软删除**: 备件和出入库记录采用软删除机制，数据不会被物理删除
4. **操作日志**: 所有操作都会记录创建人、更新人和操作时间
5. **库存一致性**: 使用数据库事务确保出入库操作的原子性
6. **业务规则校验**:
   - 备件编码唯一性校验
   - 库存充足性校验
   - 库存上下限逻辑校验
   - 领用时必须关联维护任务或故障单

### 使用建议

1. **定期更新Token**: 建议在Token过期前刷新，避免请求失败
2. **错误重试**: 对于网络错误或服务器临时故障，建议实现重试机制
3. **数据缓存**: 对于频繁查询的备件列表，建议在前端实现适当的缓存
4. **库存预警**: 建议定期查询低库存备件，及时补充库存
5. **操作确认**: 对于入库、出库等重要操作，建议在前端实现二次确认
6. **数据备份**: 建议定期导出出入库记录进行备份
