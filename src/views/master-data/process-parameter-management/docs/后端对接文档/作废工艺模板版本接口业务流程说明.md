# 作废工艺模板版本接口业务流程说明

## 文档信息

- **文档版本**: v1.0
- **创建日期**: 2025-10-16
- **适用系统**: Moses API - 主数据管理模块
- **文档类型**: 接口业务流程说明

---

## 1. 接口概述

### 1.1 基本信息

| 项目         | 内容                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| **接口名称** | 作废工艺模板版本                                                        |
| **接口地址** | `POST /v1/mdm/process-templates/{templateId}/versions/{versionId}/void` |
| **权限要求** | `mdm.process-template.approval`（需要工艺模板审批权限）                 |
| **业务模块** | 主数据管理 > 工艺参数管理                                               |

### 1.2 请求参数

#### 路径参数

| 参数名       | 类型          | 必填 | 说明           |
| ------------ | ------------- | ---- | -------------- |
| `templateId` | String (UUID) | 是   | 工艺模板ID     |
| `versionId`  | String (UUID) | 是   | 工艺模板版本ID |

#### 请求体参数

```json
{
  "approvalComment": "string"  // 可选，作废备注说明
}
```

### 1.3 响应示例

**成功响应 (200)**:
```json
{
  "success": true,
  "data": {
    "id": "version-uuid",
    "templateId": "template-uuid",
    "versionNumber": "v1.0",
    "status": "作废",
    "versionDescription": "版本描述",
    "segments": [
      // 12段工艺参数详情
    ],
    "createdAt": "2025-10-16T10:00:00Z",
    "updatedAt": "2025-10-16T11:00:00Z"
  },
  "message": "作废版本成功"
}
```

## 2. 业务流程详解

### 2.1 流程图

```
开始
  ↓
[1] 权限验证
  ↓
[2] 数据存在性检查
  ↓
[3] 引用检查（是否被使用）
  ↓
[4] 状态流转验证
  ↓
[5] 执行作废操作
  ↓
[6] 最新版本处理（如果是生效版本）
  ↓
[7] 记录审批历史
  ↓
[8] 重新计算模板状态
  ↓
[9] 返回结果
  ↓
结束
```

### 2.2 详细步骤说明

#### 步骤1: 权限验证

**执行内容**:
- 验证操作人是否具有审批权限 (`mdm.process-template.approval`)
- 确认操作人ID有效（UUID格式）

**失败情况**:
- 无审批权限 → 返回 403 Forbidden
- 操作人ID无效 → 返回 400 Bad Request

---

#### 步骤2: 数据存在性检查

**执行内容**:
- 验证工艺模板是否存在（未被软删除）
- 验证版本是否存在（未被软删除）
- 验证版本是否属于指定的模板

**失败情况**:
- 模板不存在 → 返回 404 Not Found
- 版本不存在 → 返回 404 Not Found
- 版本不属于该模板 → 返回 400 Bad Request

---

#### 步骤3: 引用检查（关键业务规则）

**执行内容**:
- 检查该工艺模板是否被以下模块引用:
  - 生产计划（ProductionPlan）
  - 生产计划项（ProductionPlanItem）
  - 产品规格（Product）
  - 其他下游模块

**业务规则**:
- ⚠️ **如果被引用，则拒绝作废操作**
- 这是为了避免影响正在进行的生产任务

**失败情况**:
- 模板被引用 → 返回 400 Bad Request，并提供引用详情

---

#### 步骤4: 状态流转验证

**执行内容**:
- 验证当前版本状态是否允许作废

**允许作废的版本状态**:
| 状态               | 中文   | 说明                 |
| ------------------ | ------ | -------------------- |
| `PENDING_APPROVAL` | 待审批 | 审批中的版本可以作废 |
| `EFFECTIVE`        | 生效   | 生效中的版本可以作废 |

**不允许作废的版本状态**:
| 状态       | 中文 | 原因                           |
| ---------- | ---- | ------------------------------ |
| `DRAFT`    | 草稿 | 草稿应使用删除操作，而非作废   |
| `REJECTED` | 驳回 | 驳回状态应修改后重新提交或删除 |
| `HISTORY`  | 历史 | 已经是历史状态，无需作废       |
| `OBSOLETE` | 作废 | 已经作废，不可重复作废         |

**失败情况**:
- 状态不允许作废 → 返回 400 Bad Request

---

#### 步骤5: 执行作废操作

**执行内容**:
- 将版本状态更新为 `作废`（OBSOLETE）
- 将 `isLatestVersion` 标记设为 `false`
- 记录更新人ID和更新时间

**数据库操作**:
```sql
UPDATE process_template_versions
SET status = 'OBSOLETE',
    isLatestVersion = false,
    updatedBy = :operatorId,
    updatedAt = NOW()
WHERE id = :versionId
```

---

#### 步骤6: 最新版本处理

**执行条件**: 仅当被作废的版本原本是生效状态时执行

**执行内容**:

**情况A: 存在其他生效版本**
- 查找该模板下其他生效版本
- 将最新的生效版本（按创建时间倒序）设为最新版本
- 更新模板的 `latestVersionId` 字段

**情况B: 不存在其他生效版本**
- 清除模板的 `latestVersionId` 字段（设为 NULL）
- 此时模板将没有最新版本

**业务影响**:
- 如果清除了最新版本，前端需要提示用户该模板暂无可用版本
- 需要激活其他版本或创建新版本才能继续使用

---

#### 步骤7: 记录审批历史

**执行内容**:
- 在审批记录表中追加作废操作记录

**记录内容**:
| 字段             | 内容                     |
| ---------------- | ------------------------ |
| `versionId`      | 被作废的版本ID           |
| `action`         | VOID（作废操作）         |
| `operatorId`     | 操作人ID                 |
| `operatorName`   | 操作人姓名               |
| `comment`        | 作废备注（来自请求参数） |
| `createdAt`      | 操作时间                 |
| `previousStatus` | 作废前的状态             |
| `newStatus`      | OBSOLETE（作废）         |

**用途**:
- 审计追踪
- 历史记录查询
- 责任追溯

---

#### 步骤8: 重新计算模板状态

**执行内容**:
- 根据该模板下所有版本的状态，重新计算模板的整体状态

**状态计算规则**:

| 版本情况                    | 模板状态                    |
| --------------------------- | --------------------------- |
| 存在生效版本                | `生效` (EFFECTIVE)          |
| 仅存在待审批版本            | `待审批` (PENDING_APPROVAL) |
| 仅存在草稿版本              | `草稿` (DRAFT)              |
| 其他情况（仅历史/作废版本） | `历史` (HISTORY)            |

**优先级**: 生效 > 待审批 > 草稿 > 历史

**示例**:
- 模板有3个版本: 1个生效、1个草稿、1个作废 → 模板状态为 `生效`
- 模板有2个版本: 1个草稿、1个作废 → 模板状态为 `草稿`
- 模板有2个版本: 全部作废 → 模板状态为 `历史`

---

#### 步骤9: 返回结果

**执行内容**:
- 重新加载版本详情（包含12段工艺参数）
- 格式化响应数据
- 返回成功消息: "作废版本成功"

## 3. 典型使用场景

### 场景1: 紧急停用生效工艺

**背景**:
- 发现当前生效的工艺参数存在问题（如温度设置错误）
- 需要立即停用，避免产生不良品

**操作流程**:
1. 调用作废接口，作废有问题的生效版本
2. 系统自动将其他生效版本设为最新（如果存在）
3. 或创建新的正确版本并提交审批

**注意事项**:
- 作废前确保有备用版本可用
- 作废后需要及时通知生产部门

---

### 场景2: 取消待审批版本

**背景**:
- 提交审批后发现版本存在问题
- 不想等驳回流程，直接作废

**操作流程**:
1. 调用作废接口，作废待审批版本
2. 重新创建正确的版本
3. 重新提交审批

**与撤回的区别**:
- 撤回: 可以继续编辑后重新提交
- 作废: 永久标记为作废，无法恢复，需创建新版本

---

### 场景3: 工艺升级优化

**背景**:
- 新工艺版本已生效
- 旧工艺不再适用，需要清理

**操作流程**:
1. 确认新工艺版本已生效且运行正常
2. 作废旧的生效版本
3. 保留历史记录供查询

---

## 4. 业务约束与限制

### 4.1 权限限制

| 约束                 | 说明                                                        |
| -------------------- | ----------------------------------------------------------- |
| **必须具有审批权限** | 只有具有 `mdm.process-template.approval` 权限的用户才能作废 |
| **普通管理权限不足** | 只有 `mdm.process-template.manage` 权限不允许作废           |

---

### 4.2 引用限制

| 约束                     | 说明                                   |
| ------------------------ | -------------------------------------- |
| **不可作废被引用的模板** | 被生产计划、产品等引用的模板不允许作废 |
| **需要先解除引用**       | 必须先修改下游模块的引用，才能作废     |
| **保护生产数据**         | 避免作废后导致生产计划失效             |

---

### 4.3 状态限制

| 约束                 | 说明                                   |
| -------------------- | -------------------------------------- |
| **只能作废特定状态** | 只能作废 `待审批` 或 `生效` 状态的版本 |
| **草稿不可作废**     | 草稿状态应使用删除操作                 |
| **历史版本不可作废** | 已经是历史状态，无需作废               |

---

### 4.4 不可逆性

| 约束                 | 说明                                 |
| -------------------- | ------------------------------------ |
| **作废操作不可撤销** | 一旦作废，无法恢复为原状态           |
| **无法重新激活**     | 作废后的版本不能再次激活使用         |
| **需创建新版本**     | 如需使用类似工艺，需复制或创建新版本 |

---

## 5. 与其他操作的对比

### 5.1 操作对比表

| 操作         | 适用状态     | 可逆性       | 影响范围       | 使用场景             |
| ------------ | ------------ | ------------ | -------------- | -------------------- |
| **作废**     | 待审批、生效 | ❌ 不可逆     | 永久标记为作废 | 紧急停用、清理旧版本 |
| **驳回**     | 待审批       | ✅ 可重新提交 | 退回草稿状态   | 审批不通过，需修改   |
| **撤回**     | 待审批       | ✅ 可重新提交 | 主动撤回审批   | 发现问题，主动撤回   |
| **删除模板** | 草稿、历史   | ✅ 软删除     | 模板及所有版本 | 彻底删除不需要的模板 |
| **删除版本** | 草稿         | ✅ 软删除     | 单个版本       | 删除未提交的草稿版本 |

---

### 5.2 状态流转图

```
草稿 (DRAFT)
  ├─→ 提交审批 → 待审批 (PENDING_APPROVAL)
  └─→ 删除 → (已删除)

待审批 (PENDING_APPROVAL)
  ├─→ 审批通过 → 生效 (EFFECTIVE)
  ├─→ 审批驳回 → 驳回 (REJECTED)
  ├─→ 撤回 → 草稿 (DRAFT)
  └─→ 作废 → 作废 (OBSOLETE) ✓

生效 (EFFECTIVE)
  ├─→ 新版本生效 → 历史 (HISTORY)
  └─→ 作废 → 作废 (OBSOLETE) ✓

驳回 (REJECTED)
  ├─→ 修改后重新提交 → 待审批 (PENDING_APPROVAL)
  └─→ 删除 → (已删除)

历史 (HISTORY)
  └─→ (保留查看)

作废 (OBSOLETE)
  └─→ (永久作废，不可恢复)
```

## 6. 错误处理

### 6.1 常见错误码

| 错误码     | HTTP状态 | 错误信息                   | 解决方案                       |
| ---------- | -------- | -------------------------- | ------------------------------ |
| `PTM_001`  | 404      | 工艺模板不存在             | 检查模板ID是否正确             |
| `PTM_002`  | 404      | 工艺模板版本不存在         | 检查版本ID是否正确             |
| `PTM_005`  | 400      | 版本状态不允许作废         | 只能作废待审批或生效状态的版本 |
| `PTM_009`  | 400      | 工艺模板被引用，不允许作废 | 先解除下游模块的引用           |
| `AUTH_003` | 403      | 权限不足                   | 需要具有审批权限               |

## 7. 最佳实践

### 7.1 作废前检查清单

- [ ] **确认有备用版本**: 如果作废生效版本，确保有其他可用版本
- [ ] **通知相关人员**: 提前通知生产部门、质量部门
- [ ] **检查引用情况**: 确认没有被生产计划引用
- [ ] **填写详细备注**: 在 `approvalComment` 中说明作废原因
- [ ] **备份工艺参数**: 如有需要，先导出工艺参数数据

---

### 7.2 作废后操作建议

1. **及时创建新版本**: 如果需要替代工艺，尽快创建新版本
2. **更新文档**: 更新工艺管理文档，说明作废原因
3. **培训相关人员**: 如果是工艺变更，及时培训生产人员
4. **监控生产影响**: 关注作废后的生产情况，及时调整

---

### 7.3 权限管理建议

| 角色           | 权限配置                        | 说明                         |
| -------------- | ------------------------------- | ---------------------------- |
| **工艺工程师** | `mdm.process-template.manage`   | 可创建、编辑工艺，但不能作废 |
| **工艺主管**   | `mdm.process-template.approval` | 可审批、作废工艺版本         |
| **质量管理员** | `mdm.process-template.view`     | 只能查看工艺，不能修改       |

## 8. 注意事项与风险提示

### 8.1 ⚠️ 重要提醒

1. **作废操作不可逆**: 一旦作废，无法恢复，请谨慎操作
2. **影响生产**: 作废生效版本会影响生产，务必确保有替代方案
3. **引用检查**: 系统会自动检查引用情况，但建议手动确认
4. **最新版本变更**: 作废后可能导致模板没有最新版本，需要及时处理
5. **审批权限**: 作废操作需要审批权限，不是所有管理员都能执行

---

### 8.2 风险等级评估

| 风险项             | 风险等级 | 应对措施                         |
| ------------------ | -------- | -------------------------------- |
| 作废正在使用的工艺 | 🔴 高     | 系统会自动检查引用，拒绝作废     |
| 作废唯一生效版本   | 🟡 中     | 提示用户确认，建议先准备替代版本 |
| 误操作作废         | 🟡 中     | 操作前二次确认，记录详细日志     |
| 权限滥用           | 🟢 低     | 严格控制审批权限，记录所有操作   |

## 10. 常见问题 (FAQ)

### Q1: 作废和删除有什么区别？

**A:**
- **作废**: 针对待审批或生效状态的版本，永久标记为作废，保留记录但不可使用
- **删除**: 针对草稿或整个模板，进行软删除，通常用于清理未完成的数据

---

### Q2: 作废后可以恢复吗？

**A:** 不可以。作废是不可逆操作，如需使用类似工艺，请：
1. 复制作废版本创建新版本
2. 或从其他版本创建新版本
3. 重新审批后使用

---

### Q3: 为什么作废需要审批权限？

**A:** 作废操作影响重大，可能影响生产，因此需要更高级别的权限控制，确保只有有权限的人员（如工艺主管）才能执行。

---

### Q4: 作废生效版本后，生产计划怎么办？

**A:** 系统会检查引用情况：
- 如果被引用，拒绝作废
- 必须先修改生产计划的工艺引用
- 或完成生产计划后再作废

---

### Q5: 可以同时作废多个版本吗？

**A:** 不可以。作废是逐个版本进行的操作，需要：
1. 分别调用接口作废每个版本
2. 每次作废后系统会重新计算模板状态
3. 建议按顺序作废，避免混乱

---

### Q6: 作废版本后，模板状态会变成什么？

**A:** 系统会自动重新计算：
- 如果还有其他生效版本 → 模板保持"生效"状态
- 如果只剩草稿版本 → 模板变为"草稿"状态
- 如果全部作废/历史 → 模板变为"历史"状态

---
