# 作废版本后查看历史数据功能说明

## 文档信息

- **文档版本**: v1.1
- **创建日期**: 2025-10-16
- **更新日期**: 2025-10-16
- **适用组件**: `TemplateDetailDrawer.vue`
- **文档类型**: 功能优化说明

---

## 1. 功能需求

### 1.1 问题场景

**用户反馈**：
> "点击查看详情，调用了详情接口，我觉得这里作为工艺模板就成为了历史，但是还是应该看到历史工艺的参数和版本历史和审批记录。但是你都没有显示。"

### 1.2 业务需求

即使工艺模板的所有版本都被作废（`latestVersion` 为 `null`），用户依然需要能够：
1. ✅ 查看历史版本的工艺参数（12段参数）
2. ✅ 查看版本历史列表
3. ✅ 查看审批记录
4. ✅ 切换查看不同的历史版本

**核心原则**：历史数据应该始终可查看，即使没有生效版本。

## 2. 接口数据结构分析

### 2.1 详情接口返回结构

根据接口文档（`工艺参数管理模块接口文档_v2.0.md`），获取模板详情接口返回：

```json
{
  "success": true,
  "data": {
    "id": "template-uuid",
    "templateCode": "PT-AF1060-ANNEALING-V12",
    "latestVersionId": "version-uuid",  // ⚠️ 可能为 null
    "latestVersion": {                  // ⚠️ 可能为 null
      "id": "version-uuid",
      "versionNumber": "v1.0",
      "status": "生效",
      "segments": [ /* 12段工艺参数 */ ],
      "approvalRecords": [ /* 审批记录 */ ]
    },
    "versions": [                       // ✅ 总是包含所有版本
      {
        "id": "version-uuid-1",
        "versionNumber": "v1.1",
        "status": "草稿",
        "segments": [ /* 完整12段参数 */ ],
        "approvalRecords": [ /* 审批记录 */ ]
      },
      {
        "id": "version-uuid-2",
        "versionNumber": "v1.0",
        "status": "作废",
        "segments": [ /* 完整12段参数 */ ],
        "approvalRecords": [ /* 审批记录 */ ]
      }
    ],
    "applicableProducts": [ /* 适用产品 */ ]
  }
}
```

### 2.2 关键发现

1. **`latestVersion` 字段**：当没有生效版本时为 `null`
2. **`versions` 数组**：始终包含所有版本的完整数据，包括：
   - 版本基本信息
   - 12段工艺参数（`segments`）
   - 审批记录（`approvalRecords`）
3. **数据完整性**：`versions` 数组中的数据足以支持所有查看需求

## 3. 解决方案设计

### 3.1 核心思路

**原有逻辑**：
```javascript
// ❌ 当 latestVersion 为 null 时，currentVersion 也为 null
this.currentVersion = this.templateDetail.latestVersion || null
```

**优化后逻辑**：
```javascript
// ✅ 当 latestVersion 为 null 时，从 versions 数组中选择备用版本
this.currentVersion = this.templateDetail.latestVersion || this.selectFallbackVersion()
```

### 3.2 备用版本选择策略

实现 `selectFallbackVersion()` 方法，从 `versions` 数组中智能选择一个历史版本：

#### 选择优先级

| 优先级 | 状态     | 说明                       |
|--------|----------|----------------------------|
| 1      | 生效     | 优先显示生效版本（理论上不应该出现） |
| 2      | 待审批   | 其次显示待审批版本         |
| 3      | 作废     | 再次显示作废版本           |
| 4      | 草稿     | 然后显示草稿版本           |
| 5      | 驳回     | 最后显示驳回版本           |

#### 排序规则

```javascript
/**
 * 备用版本选择算法
 * 1. 按状态优先级排序（生效 > 待审批 > 作废 > 草稿 > 驳回）
 * 2. 同优先级按创建时间倒序（最新的优先）
 */
selectFallbackVersion() {
  if (!this.templateDetail?.versions?.length) {
    return null
  }

  const statusPriority = {
    '生效': 1,
    '待审批': 2,
    '作废': 3,
    '草稿': 4,
    '驳回': 5
  }

  const sortedVersions = [...this.templateDetail.versions].sort((a, b) => {
    const priorityA = statusPriority[a.status] || 999
    const priorityB = statusPriority[b.status] || 999

    if (priorityA !== priorityB) {
      return priorityA - priorityB
    }

    return new Date(b.createdAt) - new Date(a.createdAt)
  })

  return sortedVersions[0] || null
}
```

## 4. 实现细节

### 4.1 数据加载优化

#### 原有逻辑

```javascript
async initialize() {
  const response = await getProcessTemplateDetail(this.templateId)
  this.templateDetail = response.data
  this.currentVersion = this.templateDetail.latestVersion || null

  // ❌ 额外调用版本历史接口
  if (this.activeTab === 'versions') {
    await this.fetchVersionHistory()  // 重复请求
  }
}
```

#### 优化后逻辑

```javascript
async initialize() {
  const response = await getProcessTemplateDetail(this.templateId)
  this.templateDetail = response.data

  // ✅ 智能选择当前版本
  this.currentVersion = this.templateDetail.latestVersion || this.selectFallbackVersion()

  // ✅ 直接使用详情接口返回的版本数据，避免额外请求
  this.versionHistory = this.templateDetail.versions || []
}
```

**优化效果**：
- ✅ 减少 1 次 API 请求
- ✅ 数据完整性更好（详情接口返回的 versions 包含 segments）
- ✅ 加载速度更快

### 4.2 用户体验优化

#### 添加备用版本提示

在基本信息卡片下方添加警告提示：

```vue
<!-- 备用版本提示 -->
<el-alert
  v-if="isViewingFallbackVersion"
  title="当前查看历史版本"
  type="warning"
  :closable="false"
  show-icon
  style="margin-top: 16px;"
>
  <template #default>
    <p>该模板当前没有生效版本，正在查看历史版本 <strong>{{ currentVersion.versionNumber }}</strong>（状态：{{ currentVersion.status }}）。</p>
    <p style="margin-top: 8px;">建议操作：创建新版本或激活其他版本以恢复正常使用。</p>
  </template>
</el-alert>
```

#### 计算属性

```javascript
computed: {
  /**
   * 是否正在查看备用版本（因为没有最新版本）
   */
  isViewingFallbackVersion() {
    // 如果没有 latestVersion，但有 currentVersion，说明是从 versions 数组中选择的备用版本
    return !this.templateDetail?.latestVersion && !!this.currentVersion
  }
}
```

## 7. 性能优化

### 7.1 API 请求优化

**优化前**：
```
1. getProcessTemplateDetail()      // 获取模板详情
2. fetchProcessTemplateVersions()  // 获取版本历史（额外请求）
3. getProcessTemplateUsage()       // 获取引用情况
```

**优化后**：
```
1. getProcessTemplateDetail()      // 获取模板详情（包含 versions）
2. getProcessTemplateUsage()       // 获取引用情况
```

**优化效果**：
- ✅ 减少 1 次 API 请求（约 200-500ms）
- ✅ 减少网络开销
- ✅ 提升页面加载速度

### 7.2 数据一致性

**优化前问题**：
- 详情接口和版本历史接口返回的数据可能不一致
- 版本历史接口是分页的，可能丢失数据

**优化后优势**：
- ✅ 单一数据源（详情接口）
- ✅ 数据完整性更好（包含 segments）
- ✅ 避免数据不一致问题
