# 工艺模板版本对比功能说明

## 📋 接口概述

**接口路径**: `GET /v1/mdm/process-templates/{templateId}/versions/compare`

**功能描述**: 对比同一工艺模板下两个不同版本的参数差异，返回详细的对比结果，用于版本对比分析。

**认证要求**: 需要 Bearer Token，需要 `mdm.process-template.view` 权限

---

## 🎯 核心功能

这个接口用于对比同一个工艺模板下**两个不同版本**的参数差异，帮助用户了解版本演进过程中做了哪些修改。

---

## 🔄 业务流程

### 1. 参数验证阶段

- 验证模板ID、基准版本ID、对比版本ID的格式是否正确（UUID格式）
- 确认工艺模板存在且未被删除
- 确认两个版本都属于该模板（防止跨模板对比）
- 验证两个版本ID不能相同

### 2. 数据加载阶段

- 加载基准版本（baseVersion）的完整数据，包括12段工艺参数
- 加载对比版本（compareVersion）的完整数据，包括12段工艺参数
- 格式化版本数据，按段序号排序段参数

### 3. 差异分析阶段

**版本基本信息对比**：
- 版本号（versionNumber）
- 版本状态（status）
- 创建时间（createdAt）
- 版本描述（versionDescription）

**12段工艺参数对比**：
- 使用JSON序列化比较完整的段参数数组
- 判断段参数整体是否有变化（changed: true/false）
- 返回两个版本的完整段参数数据供前端详细对比

### 4. 结果返回

返回包含以下内容的对比数据：
- 模板基本信息
- 两个版本的完整数据
- 差异对比结果（differences对象）

## 💡 前端实现指南

### 1. 页面布局设计

#### 左右对照式布局

- **左侧显示**: 基准版本（baseVersion）数据
- **右侧显示**: 对比版本（compareVersion）数据
- **中间分隔线**: 清晰区分两个版本
- **差异标记**: 用醒目颜色（红色/黄色）高亮显示有差异的部分

#### 版本选择器

- 提供两个下拉框分别选择基准版本和对比版本
- 可以预设常用对比组合：
  - "当前生效版本 vs 最新草稿版本"
  - "当前版本 vs 上一版本"
- 支持快速切换对比对象
- 支持版本时间轴可视化选择

### 2. 数据展示逻辑

#### 版本信息区域

展示内容：
- 版本号、状态、创建时间、版本描述
- 采用并排对比方式展示
- 有差异的字段使用特殊样式标识（如背景色高亮）

#### 12段参数对比表格

**表格结构**：
- **行**: 每一行代表一段（共12行）
- **列**: 段序号、参数名称、基准值、对比值、差异标识

**显示参数**：
- 炉温设置（furnaceTemperature）
- 料温设置（materialTemperature）
- 时间设置（timeSet）
- 循环风机速度（circulationFanSpeed）
- 负压风机频率（negativePressureFan）
- 吹洗风机频率（cleaningFan）
- 吹洗时间（cleaningTime）

**差异标记**：
- 参数值不同时显示"已修改"标签或图标
- 使用颜色编码区分修改类型（数值增大/减小）

### 3. 交互功能建议

#### 高亮差异功能

- **自动定位**: 页面加载后自动滚动到第一个有差异的段
- **快速导航**: 提供"上一个差异"/"下一个差异"按钮快速跳转
- **差异计数**: 显示总共有多少处差异（如"发现 5 处差异"）

#### 数值对比增强

- **数值类型参数**: 显示变化幅度和百分比
  - 示例：450℃ → 480℃（+30℃, +6.7%）
- **枚举类型参数**: 直接显示前后值对比
  - 示例：低速 → 中速
- **时间参数**: 显示时间差
  - 示例：2.5h → 3.0h（+0.5h）

#### 导出功能

- **导出格式**: 支持导出对比报告（PDF/Excel）
- **报告内容**:
  - 差异摘要（修改了哪些段，修改了哪些参数）
  - 详细对比表（完整的参数对比数据）
  - 版本基本信息
  - 导出时间和操作人信息

#### 筛选功能

- **仅显示差异**: 提供开关，只显示有差异的段
- **按参数类型筛选**: 只查看温度类参数、风机类参数等
- **按差异程度筛选**: 显示变化幅度超过某个阈值的参数

### 4. UI/UX 设计建议

#### 颜色方案

- **无差异**: 灰色或默认颜色
- **有差异**: 黄色背景高亮
- **数值增大**: 红色文字
- **数值减小**: 绿色文字
- **新增段**: 蓝色背景（如适用）
- **删除段**: 灰色删除线（如适用）

#### 响应式设计

- **大屏**: 左右并排显示
- **中等屏幕**: 可折叠的左右对比视图
- **移动端**: 上下堆叠，支持滑动切换版本

#### 加载状态

- 数据加载时显示骨架屏或加载动画
- 大数据量时考虑分段加载（虚拟滚动）

## 🎬 典型使用场景

### 场景1: 版本审批前

**用户**: 审批人
**目的**: 查看新版本相对于当前生效版本做了哪些修改
**操作流程**:
1. 选择当前生效版本作为基准版本
2. 选择待审批的新版本作为对比版本
3. 查看差异详情，评估修改的合理性
4. 基于对比结果做出审批决策

### 场景2: 历史追溯

**用户**: 工艺工程师
**目的**: 查看某次工艺调整的具体变更内容
**操作流程**:
1. 从版本历史中选择两个关键版本
2. 对比查看具体修改了哪些参数
3. 分析工艺优化的演进路径
4. 总结优化经验

### 场景3: 故障排查

**用户**: 质量工程师
**目的**: 定位可能导致产品质量问题的参数变化
**操作流程**:
1. 选择故障发生前的工艺版本作为基准
2. 选择故障发生时使用的工艺版本进行对比
3. 重点关注关键参数（温度、时间）的变化
4. 定位可能导致问题的参数调整

### 场景4: 版本回退决策

**用户**: 生产主管
**目的**: 决定是否需要回退到之前的工艺版本
**操作流程**:
1. 对比当前问题版本与历史稳定版本
2. 分析具体差异点
3. 评估回退的影响范围
4. 做出回退决策

## ⚠️ 注意事项

### 业务规则限制

1. **同模板限制**: 只能对比同一模板下的版本，不支持跨模板对比
2. **版本唯一性**: 两个版本ID不能相同，后端会拦截
3. **权限控制**: 需要 `mdm.process-template.view` 权限才能访问

### 技术实现注意点

1. **性能优化**:
   - 差异数据量可能较大（12段×10个参数），建议使用虚拟滚动
   - 考虑对比结果的前端缓存，避免重复请求

2. **用户体验**:
   - 建议提供版本时间轴视图，方便用户选择要对比的版本
   - 对比结果加载较慢时，提供进度指示
   - 支持键盘快捷键（如←→切换版本）

3. **数据展示**:
   - 段参数数据已按 `segmentOrder` 排序，前端直接使用即可
   - 注意处理空值和null值的显示
   - 数值类型注意精度显示（如保留2位小数）

4. **扩展功能**:
   - 考虑添加对比快照保存功能，便于后续查阅
   - 支持对比结果的批注和评论
   - 提供对比历史记录

## 📊 错误处理

### 常见错误码

| 错误码                 | HTTP状态码 | 错误消息             | 说明                       | 处理建议                   |
| ---------------------- | ---------- | -------------------- | -------------------------- | -------------------------- |
| FIELD_FORMAT_INVALID   | 400        | ID格式不正确         | 模板ID或版本ID格式错误     | 检查ID格式是否为UUID       |
| PTM_003                | 404        | 工艺模板不存在       | 请求的模板未找到           | 检查模板ID是否正确         |
| PTM_004                | 404        | 工艺模板版本不存在   | 请求的版本未找到           | 检查版本ID是否正确         |
| VALIDATION_ERROR       | 400        | 对比的版本ID不能相同 | 基准版本和对比版本为同一个 | 选择不同的版本进行对比     |
| PTM_VERSION_NOT_BELONG | 400        | 版本不属于该模板     | 版本与模板不匹配           | 确保选择的版本属于当前模板 |
| UNAUTHORIZED           | 401        | 未授权               | Token无效或过期            | 重新登录获取Token          |
| FORBIDDEN              | 403        | 无权限执行此操作     | 缺少view权限               | 联系管理员分配权限         |

### 前端错误处理建议

1. **友好提示**: 将技术错误码转换为用户可理解的提示信息
2. **引导操作**: 错误发生时提供明确的下一步操作建议
3. **日志记录**: 记录错误详情，便于问题排查
4. **降级方案**: 网络错误时提供重试机制
