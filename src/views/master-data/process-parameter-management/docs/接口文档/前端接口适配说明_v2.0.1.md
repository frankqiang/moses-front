## 📌 变更总结

根据后端接口文档 `工艺模板更新接口变更说明_v2.0.1.md`，本次前端适配主要实现了：

1. **职责分离**：严格区分模板级别信息和版本级别信息的编辑
2. **智能接口调用**：根据修改的字段类型自动选择正确的接口
3. **状态限制**：根据模板状态控制是否可编辑模板级别信息

### 1. API层修改

**文件路径**：`src/views/master-data/process-parameter-management/api/process-parameter-management.js`

#### 1.1 新增 `updateProcessTemplate` 函数（第112-136行）

```javascript
/**
 * 4. 更新工艺模板基本信息（模板级别）
 * @param {string} templateId - 模板ID（UUID）
 * @param {Object} payload - 更新参数
 * @param {string} payload.templateName - 工艺模板名称（可选）
 * @param {string} payload.description - 工艺模板描述（可选）
 * @param {Array<string>} payload.applicableProductIds - 适用产品ID列表（可选）
 * @param {string} payload.applicableAlloyGrades - 适用合金牌号（可选）
 * @param {string} payload.applicableThicknessRange - 适用厚度范围（可选）
 * @param {string} payload.applicableWidthRange - 适用宽度范围（可选）
 * @returns {Promise<Object>} 返回更新后的模板详情
 * @description 仅允许在模板状态为"草稿"或"历史"时调用
 */
export async function updateProcessTemplate(templateId, payload) {
  const response = await service({
    url: `${BASE_URL}/${templateId}`,
    method: 'patch',
    data: payload
  })

  return {
    data: response.data,
    message: response.message,
    meta: response.meta
  }
}
```

**功能说明**：
- 用于更新所有版本共享的模板级别信息
- 仅在模板状态为"草稿"或"历史"时允许调用
- 修改会影响该模板下的所有版本

#### 1.2 更新 `updateProcessTemplateVersion` 函数注释（第138-160行）

```javascript
/**
 * 5. 更新工艺模板草稿/驳回版本（版本级别）
 * @param {string} templateId - 模板ID（UUID）
 * @param {string} versionId - 版本ID（UUID）
 * @param {Object} payload - 更新参数
 * @param {string} payload.versionDescription - 版本描述（可选）
 * @param {Array<Object>} payload.segments - 12段工艺参数配置（可选）
 * @returns {Promise<Object>} 返回更新后的版本详情
 * @description v2.0.1版本变更：仅允许修改版本级别信息，不允许修改模板级别信息
 */
```

**变更说明**：
- 移除了模板级别字段的参数说明（templateName、description等）
- 明确标注仅允许修改版本级别字段（versionDescription、segments）
- 添加v2.0.1版本变更说明

#### 2.2 新增计算属性

```javascript
computed: {
  // 判断是否可编辑版本信息
  canEdit() {
    return this.currentVersion && ['草稿', '驳回'].includes(this.currentVersion.status)
  },

  // 判断是否可编辑模板信息（新增）
  canEditTemplate() {
    return this.currentTemplate && ['草稿', '历史'].includes(this.currentTemplate.status)
  },

  // 编辑模式提示文本（新增）
  editModeHint() {
    if (this.canEditTemplate) {
      return '当前可编辑模板信息和版本信息'
    } else {
      return '当前仅可编辑版本信息（版本描述和工艺参数），模板信息不可修改'
    }
  }
}
```

#### 2.3 表单字段禁用控制

**模板级别字段**（根据 `canEditTemplate` 控制）：
- 模板名称（templateName）
- 模板描述（description）
- 适用产品（applicableProductIds）
- 适用合金牌号（applicableAlloyGrades）
- 适用厚度范围（applicableThicknessRange）
- 适用宽度范围（applicableWidthRange）

**版本级别字段**（始终可编辑，在草稿和驳回状态下）：
- 版本描述（versionDescription）
- 12段工艺参数（segments）

#### 2.4 重构 `buildPayloads` 方法（替代原 `transformPayload`）

```javascript
/**
 * 构建模板和版本的 payload
 * @returns {{ templatePayload: Object, versionPayload: Object }}
 */
buildPayloads(formData) {
  const templatePayload = {}
  const versionPayload = {}

  // 模板级别字段（所有版本共享的信息）
  if (formData.templateName !== this.originalData.templateName) {
    templatePayload.templateName = formData.templateName
  }
  // ... 其他模板级别字段

  // 版本级别字段（单个版本独有的信息）
  if (formData.versionDescription !== this.originalData.versionDescription) {
    versionPayload.versionDescription = formData.versionDescription
  }
  // ... 其他版本级别字段

  return {
    templatePayload,
    versionPayload
  }
}
```

**功能说明**：
- 将原来的单一 payload 分离为 `templatePayload` 和 `versionPayload`
- 根据字段类型自动归类到对应的 payload

#### 2.5 重构 `handleSubmit` 方法

```javascript
async handleSubmit() {
  // ... 表单验证逻辑

  try {
    const { templatePayload, versionPayload } = this.buildPayloads(this.formData)
    const updateResults = []

    // 如果有模板级别字段的修改
    if (Object.keys(templatePayload).length > 0) {
      // 检查是否有权限修改模板信息
      if (!this.canEditTemplate) {
        this.$message.error('当前模板状态不允许修改模板级别信息（仅草稿或历史状态允许）')
        this.submitting = false
        return
      }

      // 调用更新模板接口
      const templateResponse = await updateProcessTemplate(this.templateId, templatePayload)
      updateResults.push({
        type: 'template',
        message: templateResponse.message || '模板信息更新成功'
      })
    }

    // 如果有版本级别字段的修改
    if (Object.keys(versionPayload).length > 0) {
      // 调用更新版本接口
      const versionResponse = await updateProcessTemplateVersion(
        this.templateId,
        this.versionId,
        versionPayload
      )
      updateResults.push({
        type: 'version',
        message: versionResponse.message || '版本信息更新成功'
      })
    }

    // 合并成功消息
    const successMessage = updateResults.map(r => r.message).join('；')
    this.$message.success(successMessage || MESSAGE_FALLBACKS.updateTemplate)

    this.$emit('success', { templateId: this.templateId, versionId: this.versionId })
    this.visibleProxy = false
  } catch (error) {
    // ... 错误处理
  }
}
```

**智能接口调用逻辑**：
1. 根据 `buildPayloads` 方法区分出模板级别和版本级别的修改
2. 如果有模板级别修改，先检查模板状态，再调用 `updateProcessTemplate` 接口
3. 如果有版本级别修改，调用 `updateProcessTemplateVersion` 接口
4. 两个接口可以同时调用（如果同时修改了两种类型的字段）
5. 合并两个接口的成功消息返回给用户

## 🎯 业务场景适配

### 场景 1：编辑草稿模板

**前提条件**：
- 模板状态：草稿
- 版本状态：草稿

**前端行为**：
- ✅ 所有字段均可编辑（模板级别 + 版本级别）
- ✅ 保存时根据修改内容智能调用对应接口
- ✅ 可能同时调用两个接口

---

### 场景 2：编辑生效模板的草稿版本

**前提条件**：
- 模板状态：生效（有 v1.0 生效中）
- 版本状态：草稿（编辑 v2.0 草稿）

**前端行为**：
- ❌ 模板级别字段禁用（灰色显示 + 警告提示）
- ✅ 版本级别字段可编辑
- ✅ 保存时仅调用 `updateProcessTemplateVersion` 接口
- ⚠️ 如果用户强制提交了模板级别字段修改，前端会拦截并提示错误

---

### 场景 3：编辑历史模板

**前提条件**：
- 模板状态：历史（所有版本都已过期）
- 版本状态：历史

**前端行为**：
- ✅ 模板级别字段可编辑
- ❌ 版本级别字段因版本状态为历史而不可编辑
- ✅ 可修改模板信息（用于修正历史数据）

---

### 场景 4：编辑驳回版本

**前提条件**：
- 模板状态：待审批或生效
- 版本状态：驳回

**前端行为**：
- ❌ 模板级别字段禁用（因为模板不是草稿或历史状态）
- ✅ 版本级别字段可编辑
- ✅ 保存时仅调用 `updateProcessTemplateVersion` 接口

## ✅ 错误处理

### 前端校验

1. **状态检查**：
   - 提交前检查 `canEdit`（版本状态）
   - 提交模板级别修改时检查 `canEditTemplate`（模板状态）

2. **提示信息**：
   - 字段禁用时显示黄色警告提示
   - 提交失败时显示后端返回的错误信息

### 后端错误处理

如果前端校验未通过但仍然提交了，后端会返回以下错误：

**错误码 PTM_011**：
```json
{
  "success": false,
  "error": {
    "code": "PTM_011",
    "message": "更新版本接口不允许修改模板级别的信息（模板信息为所有版本共享）",
    "details": {
      "rejectedFields": ["templateName"],
      "allowedFields": ["versionDescription", "segments"],
      "hint": "如需修改模板名称、描述等共享信息，请使用更新模板接口"
    }
  }
}
```

前端会显示 `error.message`，用户可看到详细的错误原因。
