# Moses API 角色管理模块接口文档

## 概述

本文档详细说明了 Moses API 角色管理模块的所有接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。**本文档严格基于实际代码实现编写**，确保前端开发人员能够准确对接。

### API 基础信息

- **基础 URL**: `http://localhost:3000/v1` (开发环境)
- **API 版本**: v1
- **认证方式**: JWT Bearer Token
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### Swagger 文档

项目已集成 Swagger 文档，可通过以下地址访问：

- **开发环境**: http://localhost:3000/v1/docs
- **在线文档**: 提供完整的 API 接口说明、参数定义和示例

## 统一响应格式

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

## 角色管理接口详细说明

### 1. 创建角色

**接口路径**: `POST /v1/roles`

**功能描述**: 创建新的角色，支持角色名称、编码、描述、类型、级别、状态、权限配置等信息的设置。角色是权限分配的载体，是RBAC权限管理的核心机制。系统支持系统角色和自定义角色两种类型，并提供完整的权限配置功能。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名 | 类型 | 必填 | 限制 | 描述 | 示例 |
| ------ | ------ | ---- | ---- | ---- | ---- |
| name | string | 是 | 1-100字符，只能包含中文、英文、数字、空格、括号 | 角色名称 | "系统管理员" |
| code | string | 是 | 1-50字符，只能包含字母、数字、下划线、中划线，不能以数字、下划线或中划线开头或结尾 | 角色编码，全局唯一 | "admin" |
| description | string | 否 | 最大1000字符 | 角色描述 | "系统管理员角色，拥有所有权限" |
| type | string | 否 | system\|custom，默认为custom | 角色类型 | "custom" |
| level | number | 否 | 1-999，默认为1 | 角色级别 | 1 |
| status | string | 否 | active\|inactive，默认为active | 角色状态 | "active" |
| isDefault | boolean | 否 | 默认为false | 是否为默认角色 | false |
| permissions | object | 否 | 权限配置对象，默认为空对象 | 权限配置 | {} |

**请求示例**:

```
curl -X POST http://localhost:3000/v1/roles \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -d '{
    "name": "系统管理员",
    "code": "admin",
    "description": "系统管理员角色，拥有所有权限",
    "type": "custom",
    "level": 1,
    "status": "active",
    "isDefault": false,
    "permissions": {
      "menus": ["dashboard", "users", "roles"],
      "pages": ["user-list", "role-list"],
      "buttons": ["create", "edit", "delete"],
      "data": {"scope": "all"},
      "operations": ["read", "write", "delete"]
    }
  }'
```

### 2. 获取角色列表

**接口路径**: `GET /v1/roles`

**功能描述**: 获取角色列表，支持分页、筛选、排序。可以根据角色名称、编码、类型、状态等条件进行筛选查询，支持全文搜索、时间范围查询、权限配置搜索等高级功能。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**查询参数**:

| 参数名 | 类型 | 必填 | 限制 | 描述 | 示例 |
| ------ | ------ | ---- | ---- | ---- | ---- |
| page | number | 否 | 最小为1，默认为1 | 页码 | 1 |
| limit | number | 否 | 1-100，默认为10 | 每页数量 | 10 |
| sortBy | string | 否 | 格式为"field:order"，如"name:asc,createdAt:desc" | 排序字段 | "createdAt:desc" |
| name | string | 否 | 最大100字符，支持模糊查询 | 角色名称筛选 | "管理员" |
| code | string | 否 | 最大50字符，支持模糊查询 | 角色编码筛选 | "admin" |
| type | string/array | 否 | system\|custom，支持多选 | 角色类型筛选 | "custom" |
| status | string/array | 否 | active\|inactive，支持多选 | 角色状态筛选 | "active" |
| level | number/object | 否 | 单值或范围对象{min: 1, max: 5} | 角色级别筛选 | 1 |
| isDefault | boolean | 否 | - | 是否为默认角色 | false |
| search | string | 否 | 最大100字符，在名称、编码、描述中搜索 | 全文搜索 | "管理员" |
| createdFrom | string | 否 | ISO日期格式 | 创建时间起始 | "2024-01-01T00:00:00.000Z" |
| createdTo | string | 否 | ISO日期格式 | 创建时间结束 | "2024-12-31T23:59:59.999Z" |
| createdBy | string/array | 否 | 用户ID，支持多选 | 创建者筛选 | "user-123" |
| populate | string | 否 | creator,updater,users | 关联查询字段 | "creator,users" |
| includeUserCount | boolean | 否 | - | 是否包含用户数量统计 | true |
| hasUsers | boolean | 否 | - | 是否有关联用户 | true |

**请求示例**:

```
curl -X GET "http://localhost:3000/v1/roles?page=1&limit=10&sortBy=createdAt:desc&name=管理&status=active&includeUserCount=true" \
```

### 5. 复制角色

**接口路径**: `POST /v1/roles/{id}/copy`

**功能描述**: 基于现有角色创建新角色，可以指定新角色的名称和编码，其他属性将继承自原角色。复制操作会深拷贝权限配置，新角色类型默认为custom，状态默认为active，不能为默认角色。

**认证要求**: 需要 Bearer Token

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**路径参数**:

| 参数名 | 类型 | 必填 | 限制 | 描述 | 示例 |
| ------ | ------ | ---- | ---- | ---- | ---- |
| id | string | 是 | UUID格式 | 要复制的角色ID | "role-123" |

**请求参数**:

| 参数名 | 类型 | 必填 | 限制 | 描述 | 示例 |
| ------ | ------ | ---- | ---- | ---- | ---- |
| name | string | 是 | 1-100字符，只能包含中文、英文、数字、空格、括号 | 新角色名称 | "管理员副本" |

## 错误码说明

系统使用统一的错误码体系，便于客户端处理和日志追踪。错误码格式：模块前缀_数字编号。

### 角色相关错误码 (ROLE_xxx)

| 错误码 | HTTP 状态码 | 错误消息 | 说明 | 处理建议 |
| ------------ | ----------- | -------- | -------- | -------- |
| ROLE_NOT_FOUND | 404 | 角色不存在 | 指定的角色ID在数据库中不存在 | 检查角色ID是否正确，或提示用户角色已被删除 |
| ROLE_CODE_ALREADY_EXISTS | 409 | 角色编码已存在 | 角色编码在系统中必须唯一 | 提示用户更换角色编码 |
| ROLE_NAME_ALREADY_EXISTS | 409 | 角色名称已存在 | 角色名称在系统中重复 | 提示用户更换角色名称 |
| ROLE_DELETE_HAS_USERS | 409 | 角色正在被使用，无法删除 | 角色正在被用户使用，无法删除 | 先解除用户角色关联，再删除角色 |
| ROLE_SYSTEM_CANNOT_DELETE | 400 | 系统角色不能被删除 | 系统内置角色不允许删除 | 只能禁用系统角色，不能删除 |
| ROLE_DEFAULT_CANNOT_DELETE | 400 | 默认角色不能被删除 | 默认角色不允许删除 | 先取消默认角色设置，再删除 |
| ROLE_SYSTEM_CANNOT_DISABLE | 400 | 系统角色不能被禁用 | 系统内置角色不允许禁用 | 系统角色必须保持启用状态 |
| ROLE_COPY_SOURCE_NOT_FOUND | 404 | 源角色不存在，无法复制 | 要复制的源角色不存在 | 检查源角色ID是否正确 |
| ROLE_STATUS_INVALID | 400 | 状态值无效 | 角色状态值不在允许范围内 | 使用正确的状态值：active或inactive |
| ROLE_PERMISSION_INVALID | 400 | 权限配置无效 | 权限配置格式或内容不正确 | 检查权限配置的格式和字段 |

### 通用错误码

**参考认证模块文档中的通用错误码部分，包括：**
- 认证相关错误码 (AUTH_xxx)
- 验证相关错误码 (VAL_xxx / VALIDATION_ERROR)
- 业务逻辑错误码 (BIZ_xxx)
- 系统错误码 (SYS_xxx / DATABASE_ERROR / INTERNAL_SERVER_ERROR)

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理
   - `AUTH_`: 认证相关错误，可能需要重新登录或刷新令牌
   - `VAL_` / `VALIDATION_ERROR`: 验证相关错误，需要检查输入参数
   - `ROLE_`: 角色相关错误，需要根据业务规则处理
   - `BIZ_`: 业务逻辑错误，需要根据业务规则处理
   - `SYS_` / `DATABASE_ERROR`: 系统错误，通常需要重试或联系支持

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息

4. **重试机制**: 对于包含 `retryAfter` 字段的错误，应按照指定时间后重试

5. **日志记录**: 使用 `traceId` 进行错误追踪和问题排查

## 数据模型

### 角色 (Role) 模型

角色是权限管理的核心实体，定义了用户在系统中的身份和权限范围。

```json
{
  "id": "string",              // 角色唯一标识，UUID格式
  "name": "string",            // 角色名称，1-100字符
  "code": "string",            // 角色编码，1-50字符，全局唯一
  "description": "string",     // 角色描述，最大1000字符
  "type": "string",            // 角色类型：system（系统角色）| custom（自定义角色）
  "level": "number",           // 角色级别，1-999，用于权限层级控制
  "status": "string",          // 角色状态：active（启用）| inactive（禁用）
  "isDefault": "boolean",      // 是否为默认角色，新用户注册时自动分配
  "permissions": "object",     // 权限配置对象，包含各种权限设置
  "userCount": "number",       // 使用该角色的用户数量（查询时可选包含）
  "createdBy": "string",       // 创建者用户ID
  "updatedBy": "string",       // 最后更新者用户ID
  "createdAt": "2024-01-20T10:30:00.000Z",  // 创建时间
  "updatedAt": "2024-01-20T10:30:00.000Z"   // 更新时间
}
```

### 权限配置 (Permissions) 结构

权限配置是一个灵活的JSON对象，支持多种权限类型：

```json
{
  "menus": ["dashboard", "users", "roles"],           // 菜单权限数组
  "pages": ["user-list", "role-list", "user-detail"], // 页面权限数组
  "buttons": ["create", "edit", "delete", "export"],  // 按钮权限数组
  "data": {                                           // 数据权限对象
    "scope": "all",                                   // 数据范围：all|department|personal
    "departments": ["dept-1", "dept-2"],             // 可访问的部门ID数组
    "conditions": {                                   // 数据筛选条件
      "status": ["active"],
      "level": {"min": 1, "max": 5}
    }
  },
  "operations": ["read", "write", "delete", "approve"], // 操作权限数组
  "tags": ["admin", "manager", "operator"]              // 权限标签数组
}
```

### 字段说明

**日期时间格式**:
- 所有日期时间字段均使用 ISO 8601 格式：`YYYY-MM-DDTHH:mm:ss.sssZ`
- 示例：`"2024-01-20T10:30:00.000Z"`

**角色类型说明**:
- `system`: 系统内置角色，不能删除，不能禁用，通常具有特殊权限
- `custom`: 自定义角色，可以自由创建、修改、删除

**角色状态说明**:
- `active`: 启用状态，可以分配给用户，用户可以获得相应权限
- `inactive`: 禁用状态，不能分配给新用户，已分配用户失去权限

**权限配置说明**:
- 权限配置采用白名单机制，只有明确配置的权限才会被授予
- 支持多种权限类型的组合，可以根据业务需求灵活配置
- 权限配置支持层级继承和覆盖机制

## 安全说明

### 认证机制

所有角色管理接口都需要有效的JWT Bearer Token认证。认证失败将返回401状态码。

### 权限控制

- 角色管理功能通常需要管理员权限
- 系统角色具有特殊保护，不能被普通用户修改或删除
- 角色编码和名称具有唯一性约束，防止重复创建

### 数据安全

- 角色删除采用逻辑删除，数据不会真正丢失
- 权限配置支持细粒度控制，确保最小权限原则
- 所有操作都有详细的日志记录，支持审计追踪

### 使用建议

1. **角色设计**: 遵循最小权限原则，避免权限过度集中
2. **编码规范**: 角色编码使用有意义的命名，便于理解和维护
3. **状态管理**: 及时禁用不再使用的角色，保持系统整洁
4. **权限审计**: 定期审查角色权限配置，确保符合业务需求
