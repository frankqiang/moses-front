# Moses API 用户管理模块接口文档

## 概述

本文档详细说明了 Moses API 用户管理模块的所有接口，包括请求方法、路径、参数、请求和响应数据结构、功能描述、错误码和返回示例。**本文档严格基于实际代码实现编写**，确保前端开发人员能够准确对接。

### API 基础信息

- **基础 URL**: `http://localhost:3000/v1` (开发环境)
- **API 版本**: v1
- **认证方式**: JWT Bearer Token
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### Swagger 文档

项目已集成 Swagger 文档，可通过以下地址访问：

- **开发环境**: http://localhost:3000/v1/docs
- **在线文档**: 提供完整的 API 接口说明、参数定义和示例

## 统一响应格式

### 成功响应格式

所有成功的 API 调用都会返回以下统一格式：

```json
{
  "success": true,
  "data": {
    // 具体的业务数据，根据接口而不同
  },
  "message": "操作成功的描述信息",
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

### 错误响应格式

所有错误的 API 调用都会返回以下统一格式：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "用户友好的错误描述",
    "details": {
      "field": "发生错误的字段名（可选）",
      "value": "错误的字段值（可选）",
      "retryAfter": 300,
      "traceId": "req-1234567890-abcdef"
    }
  },
  "meta": {
    "timestamp": "2024-01-20T10:30:00.000Z",
    "requestId": "req-1234567890-abcdef",
    "version": "v1"
  }
}
```

**响应字段说明**：

- `success`: 布尔值，表示请求是否成功
- `data`: 成功时包含业务数据，失败时为 null
- `error`: 失败时包含错误信息，成功时为 null
- `message`: 成功时的操作描述
- `error.code`: 标准化的错误码，用于程序化处理
- `error.message`: 用户友好的错误描述，可直接展示给用户
- `error.details`: 可选的错误详细信息
- `meta`: 元数据信息，包含时间戳、请求 ID 和版本号

## 用户管理接口详细说明

### 1. 创建用户

**接口路径**: `POST /v1/users`

**功能描述**: 创建新的系统用户账号。只有管理员权限的用户可以创建其他用户。创建用户时需要提供基本信息如姓名、用户名、邮箱、密码等，可选择分配部门、岗位和角色。用户名和邮箱必须全局唯一，密码将自动加密存储。

**认证要求**: 需要 Bearer Token，需要 manageUsers 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求参数**:

| 参数名           | 类型   | 必填 | 限制                                                 | 描述                         | 示例                                         |
| ---------------- | ------ | ---- | ---------------------------------------------------- | ---------------------------- | -------------------------------------------- |
| **基本信息**     |        |      |                                                      |                              |                                              |
| name             | string | 是   | 1-255字符                                            | 用户姓名                     | "张三"                                       |
| username         | string | 是   | 3-50字符，只能包含字母、数字和下划线，不能以数字开头 | 用户名，必须全局唯一         | "zhangsan"                                   |
| email            | string | 是   | 有效邮箱格式                                         | 邮箱地址，必须全局唯一       | "zhangsan@example.com"                       |
| password         | string | 是   | 至少8位，必须包含字母和数字                          | 密码                         | "Password123"                                |
| role             | string | 是   | user, admin                                          | 用户角色                     | "user"                                       |
| **组织架构**     |        |      |                                                      |                              |                                              |
| departmentId     | string | 否   | UUID格式                                             | 部门ID                       | "554e4422-beac-48bd-a22b-43b38a3c212d"       |
| positionId       | string | 否   | UUID格式                                             | 岗位ID                       | "554e4422-beac-48bd-a22b-43b38a3c212e"       |
| roleIds          | array  | 否   | UUID数组                                             | 角色ID列表，用于分配多个角色 | ["554e4422-beac-48bd-a22b-43b38a3c212f"]     |
| **档案信息**     |        |      |                                                      |                              |                                              |
| employeeId       | string | 否   | 1-50字符，必须全局唯一                               | 员工工号                     | "EMP001"                                     |
| jobTitle         | string | 否   | 1-100字符                                            | 职位名称                     | "高级软件工程师"                             |

| gender           | string | 否   | male, female, other                                  | 性别                         | "male"                                       |
| address          | string | 否   | 最大500字符                                          | 家庭住址                     | "北京市朝阳区朝阳公园路1号"                  |
| emergencyContact | string | 否   | 1-100字符                                            | 紧急联系人姓名               | "李四"                                       |
| emergencyPhone   | string | 否   | 有效电话号码格式                                     | 紧急联系人电话               | "13800138000"                                |
| notes            | string | 否   | 最大1000字符                                         | 备注信息                     | "新员工，需要安排培训"                       |
| customFields     | object | 否   | 有效JSON对象                                         | 自定义字段，JSON格式         | {"specialty": "Java开发", "level": "Senior"} |

### 2. 获取用户列表

**接口路径**: `GET /v1/users`

**功能描述**: 获取系统中的用户列表，支持多种查询条件和筛选功能。管理员可以查看所有用户，普通用户只能查看有权限的用户信息。支持按姓名、用户名、邮箱、状态、部门、岗位、角色等条件进行筛选查询，支持时间范围筛选和分页排序。

**认证要求**: 需要 Bearer Token，需要 getUsers 权限

**请求头**:

```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**查询参数**:

| 参数名        | 类型   | 必填 | 限制                                       | 描述                                       | 示例                                   |
| ------------- | ------ | ---- | ------------------------------------------ | ------------------------------------------ | -------------------------------------- |
| name          | string | 否   | -                                          | 按用户姓名模糊查询                         | "张"                                   |
| username      | string | 否   | -                                          | 按用户名模糊查询                           | "zhang"                                |
| email         | string | 否   | 有效邮箱格式                               | 按邮箱地址模糊查询                         | "zhang@"                               |
| search        | string | 否   | -                                          | 通用搜索，支持姓名、用户名、邮箱的模糊匹配 | "张三"                                 |
| status        | string | 否   | active, locked, disabled, pending, deleted | 按用户状态筛选                             | "active"                               |
| role          | string | 否   | -                                          | 按角色筛选                                 | "user"                                 |
| roleId        | string | 否   | UUID格式                                   | 按角色ID精确筛选                           | "554e4422-beac-48bd-a22b-43b38a3c212f" |
| roleName      | string | 否   | -                                          | 按角色名称模糊筛选                         | "开发"                                 |
| roleCode      | string | 否   | -                                          | 按角色编码模糊筛选                         | "DEV"                                  |
| department    | string | 否   | -                                          | 按部门名称模糊查询                         | "技术"                                 |
| departmentId  | string | 否   | UUID格式                                   | 按部门ID精确筛选                           | "554e4422-beac-48bd-a22b-43b38a3c212d" |
| position      | string | 否   | -                                          | 按岗位名称模糊查询                         | "工程师"                               |
| positionId    | string | 否   | UUID格式                                   | 按岗位ID精确筛选                           | "554e4422-beac-48bd-a22b-43b38a3c212e" |
| createdFrom   | string | 否   | ISO 8601格式                               | 创建时间范围起始日期                       | "2024-01-01T00:00:00.000Z"             |
| createdTo     | string | 否   | ISO 8601格式                               | 创建时间范围结束日期                       | "2024-12-31T23:59:59.999Z"             |
| lastLoginFrom | string | 否   | ISO 8601格式                               | 最后登录时间范围起始日期                   | "2024-01-01T00:00:00.000Z"             |
| lastLoginTo   | string | 否   | ISO 8601格式                               | 最后登录时间范围结束日期                   | "2024-12-31T23:59:59.999Z"             |
| sortBy        | string | 否   | 字段名:方向                                | 排序选项，如 name:asc, created_at:desc     | "created_at:desc"                      |
| limit         | number | 否   | 1-100                                      | 每页最大结果数                             | 10                                     |
| page          | number | 否   | ≥1                                         | 页码                                       | 1                                      |

**请求示例**:

```
curl -X GET "http://localhost:3000/v1/users?search=张&status=active&limit=10&page=1&sortBy=created_at:desc" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

## 错误码说明

系统使用统一的错误码体系，便于客户端处理和日志追踪。错误码格式：模块前缀\_数字编号。

### 用户管理相关错误码 (BIZ_xxx)

| 错误码  | HTTP 状态码 | 错误消息       | 说明                     | 处理建议           |
| ------- | ----------- | -------------- | ------------------------ | ------------------ |
| BIZ_001 | 404         | 资源不存在     | 用户不存在或已被删除     | 检查用户ID是否正确 |
| BIZ_010 | 400         | 用户已存在     | 用户已存在于系统中       | 使用不同的用户信息 |
| BIZ_011 | 400         | 邮箱已被使用   | 邮箱地址已被其他用户使用 | 使用不同的邮箱地址 |
| BIZ_012 | 400         | 用户名已被使用 | 用户名已被其他用户使用   | 使用不同的用户名   |

### 认证相关错误码 (AUTH_xxx)

| 错误码   | HTTP 状态码 | 错误消息         | 说明                     | 处理建议             |
| -------- | ----------- | ---------------- | ------------------------ | -------------------- |
| AUTH_001 | 401         | 请先登录         | 用户未登录或令牌无效     | 重新登录获取有效令牌 |
| AUTH_006 | 403         | 权限不足         | 用户没有执行该操作的权限 | 联系管理员获取权限   |
| AUTH_013 | 400         | 用户名或密码错误 | 当前密码验证失败         | 检查输入的当前密码   |

### 验证相关错误码 (VAL_xxx)

| 错误码  | HTTP 状态码 | 错误消息           | 说明                         | 处理建议               |
| ------- | ----------- | ------------------ | ---------------------------- | ---------------------- |
| VAL_001 | 400         | 输入数据验证失败   | 请求参数格式或内容不符合要求 | 检查请求参数格式和内容 |
| VAL_004 | 400         | 邮箱格式不正确     | 邮箱格式不符合标准           | 使用正确的邮箱格式     |
| VAL_005 | 400         | 密码格式不符合要求 | 密码不符合强度要求           | 使用符合要求的密码     |
| VAL_006 | 400         | 用户名格式不正确   | 用户名格式不符合规则         | 使用符合规则的用户名   |

### 错误处理最佳实践

1. **统一错误处理**: 前端应根据错误码进行统一处理，而不是依赖 HTTP 状态码

2. **错误码模式识别**: 建议根据错误码前缀进行模式识别处理
   - `AUTH_`: 认证相关错误，可能需要重新登录或刷新令牌
   - `VAL_`: 验证相关错误，需要检查输入参数
   - `BIZ_`: 业务逻辑错误，需要根据业务规则处理
   - `SYS_`: 系统错误，通常需要重试或联系支持

3. **错误消息展示**: 直接使用 `error.message` 字段的内容，无需前端硬编码错误消息

4. **重试机制**: 对于包含 `retryAfter` 字段的错误，应按照指定时间后重试

5. **日志记录**: 使用 `traceId` 进行错误追踪和问题排查

### 字段说明

**日期时间格式**:
- 所有日期时间字段均使用 ISO 8601 格式：`YYYY-MM-DDTHH:mm:ss.sssZ`
- 示例：`"2024-01-20T10:30:00.000Z"`

**用户状态说明**:
- `active`: 活动状态，用户可以正常使用系统
- `locked`: 锁定状态，通常因为多次登录失败
- `disabled`: 禁用状态，管理员主动禁用的账户
- `pending`: 待审核状态，新注册等待审核的账户
- `deleted`: 删除状态，逻辑删除的账户

**角色关联状态说明**:
- `active`: 角色关联有效
- `inactive`: 角色关联暂时无效
- `expired`: 角色关联已过期

## 安全说明

### 认证机制

用户管理模块的接口需要使用 JWT Bearer Token 进行认证，具体认证机制请参考登录模块的相关文档。

### 权限控制

- **getUsers**: 查看用户信息的权限，普通用户只能查看自己的信息
- **manageUsers**: 管理用户的权限，包括创建、更新、删除用户等操作
- 权限验证在中间件层面进行，确保操作安全性

### 安全特性

1. **密码安全**: 密码使用 bcrypt 进行加密存储，不可逆
2. **数据验证**: 所有输入数据都进行严格的格式和内容验证
3. **操作审计**: 用户状态变更等重要操作都会记录审计日志
4. **权限隔离**: 不同权限用户只能访问和操作授权范围内的数据
5. **唯一性约束**: 用户名和邮箱强制唯一性约束

### 使用建议

1. **密码策略**: 建议前端实现密码强度检查，提高用户账户安全性
2. **定期审核**: 建议定期审核用户账户状态和权限分配
3. **批量操作**: 使用批量操作接口时注意操作范围，避免误操作
4. **状态管理**: 合理使用用户状态管理功能，提高系统安全性
